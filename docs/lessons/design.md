# UI 设计 Agent 的验收

## 截不到图就没有视觉结论，只向用户要一次

- 规则：`screenshot` 失败即视为这一轮不具备视觉结论能力：只向用户要一次「请打开这个设计页」，不再重复调用 `screenshot`；本轮所有「某控件没显示 / 看起来不对」都改成待验证项写进回复，不写成结论。页面可用后先截全图，再对本次改动的每个控件用 `view_image`（source 写 "screenshot:1"，region 写改动区域）放大确认一次，之后才写完成总结。
- 起因：2026-10-24 UI 设计验收中截图失败后 Agent 反复重试并照旧汇报视觉效果。
- 防线：人工（`server/design-mcp.test.ts` 只覆盖工具返回值，管不到 Agent 怎么写结论）。

## 出图状态读一两次就够，不 sleep 轮询

- 规则：等背景原画出图最多用一到两次 `get_design` 读 images 的生成状态，不 sleep 轮询。状态是生成中就明确告诉用户「背景在出图，我先做其他项，本轮验收不含背景」，接着做别的。发现 failed 立刻写一句结论（例如「重出失败，画布上仍是 1920×1080 的旧图」），只重试一次：提示词去掉「高分辨率」这类容易崩的词、尺寸降到 1920×1080；再失败就停手等用户决定。
- 起因：2026-10-24 用户等背景图时 Agent 用 sleep 反复轮询，出图失败也没当场说明。
- 防线：人工。

## 图片引用和尺寸按约定写

- 规则：引用图片统一写 `image:<id>`、`screenshot:<n>`、`concept:<id>`，不写文件名或别的叫法；数组和对象按原生 JSON 传，不字符串化。需要 1080p 以上背景时直接按 2048×1152 出图，提交前自检 width/height 都不超过 2048。
- 起因：2026-10-24 用户在 UI 设计验收里定的引用和尺寸口径。
- 防线：`server/design-mcp.ts` 的 source 解析写错直接报错；尺寸上限人工自检。

## 改完先回读数值，check 通过不算完成

- 规则：每次 `update_widgets` 之后立刻回读被改控件的 x/y/宽/高/字号（`screenshot` 返回的控件位置表，或 `get_tree` 读该属性）；回读值等于汇报值才写进总结，不一致就当场重改并说明「上一轮没生效」。完成条件固定为「改完后的全屏截图 + 目标控件放大图 + 回读数值一致」，`check` 通过不是完成条件。
- 起因：2026-10-24 汇报的位置和画布上实际不一致，Agent 按 `check` 通过写了完成总结。
- 防线：人工（回读靠 Agent 自己执行，没有自动检查）。
