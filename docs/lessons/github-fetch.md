# 拉 GitHub 的地方

## 拉 GitHub 只能由用户手动触发，打开页面只显示缓存

- 规则：插件市场、插件更新、版本更新、UEKit 插件目录这类读 GitHub 的地方，打开页面、定时器、缓存过期都不自动请求；只显示上次缓存（写明多久前），从没读过就提示点「刷新」/「检查更新」。安装、换仓库这类用户点的动作可以顺带读。设置里用户自己打开的「自动检查更新」开关（默认关）除外。
- 起因：插件页打开时缓存超过一小时就自动重读市场、自动查更新（market.ts 的 STALE_MS、updates.ts 的 auto），UE 插件页也按 1 小时 / 6 小时自动重读，用户要求全部改成手动（插件仓库 ccec0ef）。
- 防线：`server/plugins/market-cache.test.ts`（cacheOnly 不去 GitHub）；其余人工。

## 从插件市场装的包，版本要和市场条目写的一致，对不上就报错不装

- 规则：按 `plugins.json` 条目下载插件包（升级、一键更新、装依赖）后，先核对包里 `plugin.json` 的版本等于条目的 `version`，对不上直接报错并写明两边版本和下载的 tag / 附件，不装。不能只看「确认安装」成功就算升级成功。
- 起因：插件仓库 UE 0.16.5 改了 `version` 却没改 `tag` / `asset`，发布那次 CI 失败、`ue-v0.16.5` 没发出来；面板照 tag 下到 0.16.4 的包装上，一键更新显示完成、版本不变、按钮又变回「升级到 v0.16.5」，用户反复点也没有任何报错（前一次修 PR #350 只处理了显示）。
- 防线：`server/plugins/github.test.ts`（`checkEntryVersion`）。

## 大文件下载要按「多久没收到数据」换来源，兜底列表要并进全部条目

- 规则：从 GitHub 下大文件（更新包、插件包）不能只靠请求出错时换来源：连上了却不给数据时要按「一段时间没收到字节」放弃这个来源、记下原因、换下一个，并把正在用的来源和放弃过的来源显示给用户。API 不可用退到 Release feed 时，feed 里的每个版本都并进列表，不能只取第一个。GitHub API 来源被限流后进冷却，不再拿它兜底仓库文件白耗配额。
- 起因：多来源兜底（8f72ace）只在请求报错时换来源，面板更新一直「下载中 0.0 MB」不动，页面看不出在等谁；feed 兜底只取最新一版，列表里 v0.29.115 下面直接是缓存里的 v0.29.109。
- 防线：`server/update/fetch-package.test.ts`（卡住换源）、`server/update/index.test.ts`（feed 多个版本并进列表）。

## 「使用代理」开关关着时一律直连

- 规则：设置里的「使用代理」关着时，出网一律直连：不用填的地址，也不用环境变量、系统代理和本机代理端口探测（`server/net.ts` 的 `defaultPlan` 返回 `DIRECT_ONLY`）。自动找代理只在开关打开、地址没填时做。
- 起因：开关关掉只是不用填的地址，系统代理和本机代理探测照旧，用户关了开关、代理软件也没开，更新下载还是去连 127.0.0.1:10808（用户 2026-11-21 纠正）。
- 防线：`server/net.test.ts`「启用代理的开关：关着时一律直连……」。
