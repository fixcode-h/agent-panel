# 给 Agent 的提示词

## 改提示词或文案前先搜断言

- 规则：改给 Agent 的提示词、角色设定、界面文案前，先 `grep` 一下 `scripts/e2e/`、`scripts/ui/` 和 `server/*.test.ts` 里有没有断言原句（界面检查常按按钮、分段的名字找元素），一起改；改了界面文字要把用到它的界面分片都复跑，不只跑自己加断言的那片。
- 起因：baffddd、875a11b、ab95653 都是改了提示词、测试还断言旧写法；86dc598c 把角色页分段缩成「基本 · N」，`scripts/ui/06-settings-agent.mjs` 还按 `/^基本角色/` 找，CI 界面检查失败。
- 防线：`npm run test:e2e`、`node scripts/ui-check.mjs`。

## 提示词要求 Agent 在一个回合里做完

- 规则：派工、执行类的提示词写明「本回合内完成，不以计划或『我先读取一下』结束」，派工失败要有兜底说明。
- 起因：d94526a，Agent 说一句「我先读取」就结束了回合。
- 防线：人工。

## 等待写死亡上限，不只写原则

- 规则：提示词里写“不要轮询”没用，要写成可执行的数字：用工具自带的等待 / 后台推送；确实主动等时单次不超 30 秒、同一件事累计不超 2 分钟；超时就必须判阻塞并给出可选做法，等待期间要求做不依赖它的实事。另外要写“自己已验证过的结论不要再等子任务重复验证”。
- 起因：一条只写「`Start-Sleep` 单次不超 60 秒、累计不超 2 分钟」的规则被完整违反：实际连发 `sleep 90/100/120/150/180` 共 640 秒，最后一条被 abort，任务停在半路；期间 307 秒完全空等。
- 防线：`server/core-agents.test.ts`（「通用约束」里必须有这一段）；已装的旧副本启动时按定义同步（ADR 0061）。

## 回合怎么推进只有一份：可以直接调工具，不单独发说明

- 规则：「回合怎么推进」只写在 `shared/turn-rules.ts`，内置约束、默认对话、Chat 角色都插值引用，不各抄一份。不要再要求「先报告阶段结果再继续」「不要让一整轮只剩工具调用」：CLI 协议里一条回复没有工具调用这一轮就结束了，模型照做会单独发一条说明然后停下。
- 起因：用户 2026-11-02 报「说了要做却没做」；原来的可见进度规则（Pi 任务看不到中间进度时加的）和「说了要做就做完」互相拉扯。
- 防线：`server/agent-role.test.ts`、`server/core-agents.test.ts`（不再出现「报告阶段结果」「一整轮只剩工具调用」）。

## 让 CLI 替用户做选择时，给它判断依据

- 规则：AI 配参数这类「让 CLI 按项目定值」的提示词，每个选项要附上它实际改变什么（`paramEffect` 按取值渲染角色设定取差异）和节点上已有的预设，写明判断顺序「项目事实 → 选项差别 → 默认值」，并告诉它结果要用户确认才生效、不要把取舍拿去问用户。只给标签和一句说明时，CLI 只能把开关原样问回来。
- 起因：c3678e9 的参数提示词只列标签，还要求写「哪些参数需要用户确认」；用户在「通用项目」上看到 AI 把 TDD / 任务记录 / 先识别现场 / 串行全部问回来。
- 防线：`server/agent-params.test.ts`（提示词带取值差异和节点预设）。

## 「自动」类设置交给 Agent 时发解析结果，不把「自动」原样转给模型

- 规则：语言这类「自动」设置，面板自己先解析成确定的值（语言以浏览器识别结果为准，页面回报给服务端存进 `Settings.browserLang`），再按这个值给 Agent 发固定规则；不要把「自动 / 跟随用户消息」这种要模型自己判断的说法写进提示词。服务端拿不到浏览器信息时才退回系统 locale。
- 起因：0428362 把「自动」改成 `auto-zh` / `auto-en`（「按用户消息的语言回复和思考」），界面已经认出简体中文，模型的思考过程仍常是英文；用户 2026-11-07 要求按识别出的语言发。
- 防线：`server/prompt-lang.test.ts`、`server/settings-browser-lang.test.ts`。

## 「谁来做」只写一处，转交类的说法要点名工具和对话

- 规则：父对话提示词里写「把……转给用户」时，要写清在哪个对话、用哪个工具发；子对话要用户做的事（复现、抓日志、给文件）一律让子对话自己发（request_user_action / request_logs），父对话不代发。加新规则前搜一遍同一个提示词里有没有说法相反的旧句子。
- 起因：统筹提示词一处写「它要用户复现并贴日志的，原样转给用户」，另一处写「子对话的等你操作不经过你」；统筹照前一句在父对话里发了等你操作，用户 2026-11-10 报卡片跑到父对话。
- 防线：`server/core-agents.test.ts`（统筹提示词不再有「原样转给用户」）。

## 回复语言只在 invokeCli 注入，保活的每一轮都要补

- 规则：「回复正文和思考过程用哪种语言」的规则和末尾提醒只由 `server/exec/prompt-lang-inject.ts` 在 `invokeCli` 里补：系统提示词（有参数的接在角色设定后，Command Code 走语言 mod）、第一轮输入末尾、保活进程的每一个后续轮次（`keepAlive` / `waitUser` 拿到的文字）。新加调 CLI 的地方不自己拼语言规则；新加「把文字交给已经在跑的 CLI」的通道时，确认它经过 `withLangReminder`（插话走 `steerNote`，已带提醒）。
- 起因：用户 2026-11-20 报父对话思考是中文、子对话是英文。以前语言规则只在 runner 起新进程时放进系统提示词和第一轮末尾；保活的子对话之后收到的父对话传话、子任务结果原样交给 CLI，一长串英文命令输出后思考就换成英文；经验提炼、AI 创建、插件这些直接调 `invokeCli` 的系统提示词里也没有规则。
- 防线：`server/exec/prompt-lang-inject.test.ts`。

## 执行中插话按收件的对话换说法，用户点名的修法要重新评估

- 规则：插话说明只由 `server/exec/steer-note.ts` 的 `steerNote(text, steerFrom(task, msg))` 出，不在调用处拼。派过子对话的父对话收到用户的话，先分清是谁手上的事，子对话的事马上 `send_to_conversation` 转（`quote` 带用户消息 id，面板附原话，子对话的 `chatSaid` 算成用户说的），手上依赖旧方案的动作先停；走诊断流程的子对话把用户点名的修法、函数、文件当成对报告的意见：核实、和现方案比，换方案就交 `phase: plan` 出新一版。新加「把用户的话交给模型」的通道时照这三种身份挑说法，别回到一段通用的「相关就继续当前任务」。
- 起因：用户 2026-11-21 报「管家头衔不随身高」：在父对话执行中说「直接改 GetDecorationActorTopLocation」，父对话回「我转给子对话」却先做完 changelist（还按旧方案写了描述），一直没转；子对话收到「用 PlotActor」只回「这正是方案 A 的方向」，照旧方案做。
- 防线：`server/exec/steer-note.test.ts`、`shared/orchestra/quote.test.ts`、`shared/bug/chat.test.ts`（父对话转来的原话）。

## 文档里的路径一律相对项目根，面板按本机项目根核对

- 规则：提示词、Skill、模板里让 Agent 写进文档的路径（模块文档的「源码」「入口」、证据里的文件）都写相对项目根，不写盘符或 `/` 开头的绝对路径、P4 depot 路径和「:行号」。面板读文档里的路径时先过 `shared/module-docs.ts` 的 `sourcePathOf`（剥行号、换斜杠），按本机项目根查（`server/docs/source-path.ts`）；老文档里的绝对路径认出相对写法后交「文档」改，不当成「不在了」。
- 起因：用户 2026-11-23 报「文档」子任务核对 10 个模块的源码路径全是误报：文档写的是 `G:\Project\<某人的工作区>\...:行号`，P4 共用文档时换人就找不到，`path.join(项目根, 绝对路径)` 也拼不出来。
- 防线：`server/module-map.test.ts`、`shared/module-docs.test.ts`。
