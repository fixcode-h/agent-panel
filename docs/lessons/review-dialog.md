# 审阅弹窗和诊断报告

## 「默认不收起来」这类有两种读法的界面要求，按字面做

- 规则：用户说「X 默认不收起来」「默认不显示」这类话，先按字面理解成「要默认展开 / 默认不显示」去改，不要读成对现状的抱怨再反着改；拿不准时在回复第一句写清选了哪种读法。
- 起因：用户 2026-11-12 说「诊断报告标注默认不收起来」，9f6619d 理解成「现在不收起、要收起」，把论证这一步也改成默认收起；用户 2026-11-13 纠正为要默认展开。
- 防线：`scripts/ui/02b-subagent.mjs` 断言诊断报告的标注栏默认展开。

## 任务页里吸底的东西要让出输入框上方浮着的卡片；同一份确认只给一个入口

- 规则：任务页的确认、提醒卡片浮在输入框上方（`FloatAbove`），会盖住消息区和流程图节点详情的底部。新加吸底（`sticky bottom-0`）的入口时按 `floatPad` 让出高度（`TaskFlow` 的 `floatPad` 传给 `StageReportBar` 的 `bottom`），内容区底部也多留这一段。节点详情里已经有入口能处理的请求（等确认的阶段报告，`stepConfirms`），停靠区不再浮一张同样的卡片（`ConversationDock` 的 `floatRequests`）。只读弹窗不留「选中文字标注」的提示和点不动的整体意见框。
- 起因：8b0ec78 加的节点详情报告栏吸在底部，被浮着的「看一下结果再继续」确认卡片盖住叠在一起；报告栏点开又是只读的，用户以为不能标注了（用户 2026-11-26）。
- 防线：`scripts/ui/02b-subagent.mjs` 的「阶段报告入口」：只读弹窗没有标注提示、等确认时报告栏上是「查看结果」且没有浮着的同一份确认、选文字能标注、在报告栏里确认后回到「查看报告」。
