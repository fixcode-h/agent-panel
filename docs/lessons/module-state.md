# 模块顶层的可变状态

## 写明是哪一类，按对话记的收进 task-state

- 规则：`server/`、`shared/` 顶层的 `let`、`new Map/Set` 在那一行（或上一行）写 `// 模块状态：<类>，<一句话>`，类只用这几种：常量（加载后不改）、缓存（丢了重算）、排队（串行写、同一件事只做一份）、会话（跟着进程或连接一起没）、配置副本（启动时读、改了写回）、接线（启动时登记的回调）、运行时（丢了会出错或要靠补救，写清重启后怎样）。「运行时」这一类是重构文档第 11 条下一步要收进注入对象或落盘的，新代码尽量不加；`grep -rn '模块状态：运行时' server shared` 就是清单。
- 规则：以对话 id 为键、只在内存里的运行时状态（「说过一次」的提醒记录、排队待交的消息、每轮快照……）不在模块顶层 `new Map()`，用 `server/runtime/task-state.ts` 的 `taskMap(owner)` / `taskSet(owner)` 建；自己有清理函数的用 `onForgetTask` 登记。对话彻底删掉时 `forgetTask` 一次清完，删除那里不再一个个点名，也不会有只增不减的表。
- 起因：2026-11-12 第 11 条清点，顶层 265 处可变状态，其中 25 处属于「运行时」；第二步把其中 13 处按对话记的收进 task-state（钩子那几张表以前对话删了也不清），剩下的不按对话记（目录、文件、通知渠道、引擎宿主），仍写着「模块状态：运行时」。
- 防线：结构检查（`moduleState`）。
