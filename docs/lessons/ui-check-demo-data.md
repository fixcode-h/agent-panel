# 界面检查：改演示数据

界面检查的其他规则在 [ui-check.md](./ui-check.md)。

## 改演示数据用 patchDemoOnce，别在页面里改完 localStorage 再导航

- 规则：要在打开页面前改演示数据（开开发者模式、把对话改成执行中），用 `scripts/ui/task-page.mjs` 的 `patchDemoOnce(p, 名字, (db) => …)`：它在下一次导航、页面脚本运行之前改一次。不要 `p.evaluate` 改 `localStorage` 再 `goto`：当前页的演示后端（种子任务收尾、执行中的对话）还会把内存里的旧数据写回去，机器慢时改动被盖掉，断言看起来像功能坏了。
- 规则：两条相关断言在同一次运行里一起失败（例如「加载面板没出现」+「后台胶囊没出现」都依赖开发者模式），先查它们共用的前置状态有没有真的生效，再看功能本身。
- 起因：PR #253 的 `ui (a)` 偶发报「打开对话时没有出现加载面板」「后台还在连的实时更新没有留下任何入口」，同一提交推 dev 时通过；列表项出现前几毫秒种子数据还在写盘，开发者模式被盖回 false。
- 防线：`node scripts/ui-check.mjs 02-task`（多开几份并行跑加压）。
