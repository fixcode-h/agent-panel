# 界面检查（scripts/ui-check.mjs）

漏翻、文案类的界面规则在 [ui.md](./ui.md)；e2e 和假 CLI 在 [testing.md](./testing.md)。

## 按名字定位控件要 exact，且等控件终态而不是等文案

- 规则：`getByRole('button', { name })` / `getByText` 默认子串匹配，页面上别处有这几个字就会被抢走（页内锚点、分组标题都可能）。要点真按钮就加 `exact: true`，改完数一遍命中数量确认。
- 规则：等「操作做完了」等可控件的终态（按钮换成删除图标、`data-status` 变了、进度条消失），不等一句文案出现；另加一条「点击真落到了这个操作上」的断言（按钮进入 busy 或已经到终态），否则点错地方时只看到「等终态超时」，分不清没开始还是没跑完。
- 起因：「设置-本机生图-已下载」用 `name: '下载'`，第一个命中的是「下载和连接」小节的页内锚点，点它只滚了页，下载从没开始，单跑 100% 失败。
- 防线：`node scripts/ui-check.mjs 06`（去掉 `exact` 直接报「点击落到别处了」）。

## 退场动画里的元素不算数，等「活着的」条数和具体元素

- 规则：数列表 / 提示的条数时先排除正在退场的那几个（sonner 是 `data-removed="true"`）。拿 DOM 总数当基准会把它们算进去：基准被抬高后「回到基准」永远等不到，而它们还没移除时又会假阳性地满足判据。
- 规则：判「关掉了一条」等具体元素句柄 `el.isConnected === false`；判「补位发生了」等存活条数回到期望值。重新造工况先清空、再一次性连发满额（各自到期时间接近），不拿前面留下的、剩余寿命各不相同的提示当背景。
- 规则：验证「补位」这种会跟自动到期抢目标的链路时，判据前把鼠标悬停在提示上能让 sonner 的 4 秒计时整个冻住（`expanded` 是页面级状态，实测悬停 6.4s 仍是 4 条，移开后再约 3.4s 才到期）；但冻结点必须在**投递之前且中间不离开提示区**：需要右键点菜单、点别处时鼠标一离开，`onMouseLeave` 就把 `expanded` 置回 false、计时恢复（实测先弹 1 条再 hover 补满，第 1 条仍在 4.0s 到期）。离不了提示区时就把判定链缩短到远小于 TTL。
- 规则：取快照不要在 Node 侧逐个句柄 evaluate（N 次 round-trip 会拉长判定链，到期窗口就在这段里），一次 `p.evaluate` 拿存活标记、再按同一索引挑句柄。
- 规则：比「还是那几条」时在页面里用 `p.evaluate` 传句柄比 DOM 节点，不要在 Node 侧用 `===` / `includes`——`elementHandles()` 每次返回新的包装对象，永远不相等。条数相等也要确认身份：一条到期 + 一条新进也能凑满额。
- 规则：页面里用 rAF 循环等条件时要同时给脚本侧硬超时（`Promise.race` + `setTimeout`）：页面不可见 / 主线程被长任务占住时 rAF 不回调，`page.evaluate` 又会一直挂着（它不吃 `setDefaultTimeout`），到时候不是「等超时」而是整个分片挂死。
- 起因：「提示-补位」用 `mounted` 当基准，并发时偶发失败：基准包含了正在播 200ms 退出动画的那条；换成清空重建后，又踩了「背景提示陆续到期、各自触发一次补位」而认错目标。
- 防线：`node scripts/ui-check.mjs 10`（反向验证：去掉 `finishToast` 的补位 → 报「没有补上来」；去掉 `enqueueToast` 的名额上限 → 报「现在 5 条，排队没生效」）。
