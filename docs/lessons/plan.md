# 执行计划

## 子对话的收尾是计划的最后一步，由面板加

- 规则：子对话的收尾（独立分支 `submit_merge` 合回父对话所在的分支；P4 工作区按 [C++]/[XLSX]/[Lua]/[Other] 分进各自的 pending changelist 再请验收；共用目录、没有版本管理时直接请验收）由 `applyPlan` 的 `wrapUp` 自动放在计划最后（`shared/plan.ts` 的 `ensureWrapUp`），Agent 漏写、删掉、挪到前面都会放回去；这三种收尾（`PANEL_WRAPS`）都只由面板在父对话收下后标完成（`markChildWrapUp`），Agent 自己标不算。提示词里不要再写「收尾不列进计划」，P4 分桶规则写在对话提示词（`wrapUpPart`）里，不要只靠 project-vcs 技能或「版本控制」角色。
- 起因：用户纠正——以前提示词要求「合回父分支是收尾动作，不写进计划步骤」，子对话改完就停，P4 改动全留在 default 或塞进同一个 changelist。
- 防线：`shared/plan.test.ts` 的收尾用例、`server/engine-steps.test.ts` 的提示词断言。

## 必须照做的规则交给面板执行

- 规则：P4 分 changelist 这类有明确规则的收尾，由面板工具执行（`p4_split_changelists`），Agent 只给描述；只写进提示词时 Agent 会合并成「[C++/Lua] …」。
- 防线：`server/p4-split.test.ts`。

## 对话能不能走完不靠模型自觉：一轮结束时按计划状态推

- 规则：一轮正常结束时计划没做完、也没在等任何结果（`planStalled`），面板推它接着做（`nudgePlan`），同一进度只推一次；判定只看计划状态，不按回复文字猜。父子之间「未完成」不发消息，推过仍停住才报一次；继续执行时被连带打断的子对话由面板拉起来，父对话交回原来的子对话，起不来才另建。见 ADR 0032。
- 起因：80dbe4c 只给子对话加了推进，父对话同样「我跑 test:failed」后停住；父对话 20 分钟收到 13 条「未完成」，看子对话没动静又另建子对话重做。
- 防线：e2e `09-subagent-runtime`「计划做一半就收尾」「父对话被停下后继续」；`shared/task-idle-ask.test.ts`。

## 做没做完只按计划（对话）和最后的总结（子任务）判定，不按回复里的字眼猜

- 规则：对话这一轮结束时，有计划看计划做完没有（`nudgePlan`）；没计划但这一轮动手（跑命令、改文件）`PLAN_ACTS` 处以上，推一次让它把做过的和还要做的列成计划（`nudgeNoPlan`），推满还停着写「没做完就停下了」警告（`unfinished`）。子任务不列计划、没有总结卡，最后一条回复要有「## 总结」标题行（`shared/helper-summary.ts`），没有就在同一个会话里推一次，还没有就交回并留警告；评审按验收结论判定。不要再加「已 / 完成 / 我先 / 接下来」这类按字眼猜的规则。
- 起因：f3b5320 的 `announcedOnly` 按字眼猜，「现在删除远端这 12 个已合并分支。」里的「已」被当成结论，没推；子任务说完「继续读操作原语与快照/选择器。」就交回，也没人推（用户 2026-11-02 纠正：按计划判定，子任务按最后的总结判定）。
- 防线：e2e `03-chat`「动了手却没列计划就收尾」、`09-subagent-runtime`「子任务没交最后的总结就结束」；`shared/helper-summary.test.ts`。

## 计划和子对话按标题对应时不按包含关系猜

- 规则：`linkKids` 只认 id、或步骤标题和子对话标题一致（去掉「子对话：」前缀）；只是含着子对话标题的，要 Agent 自己写成等待中、子对话还没做完、也没挂在别的步骤上才认。已完成的子对话只给写了 id 且等待中的、或完全同名又没被别的步骤认领的步骤收口，不把只含同样字眼的新步骤当场标完成。
- 起因：审计发现（df820f2 起）已完成的子对话「类型检查」把后加的「合并后跑全量类型检查」直接标完成；2bb92363 收紧时连完全同名也不收口，步骤停在待做、推进时 Agent 会重做。
- 防线：`shared/plan.test.ts`「按标题认子对话」。

## set_plan 的 partial 回包只给变化

- 规则：partial 更新只回变了的行（新步骤带 id）加进度和下一步，完整计划每轮提示里都有；新开、整份提交、带了对不上的 id 时才回全文。「没交上来」只点名还在进行中和被跳过的，排在后面还没轮到的不点。
- 起因：审计发现（df820f2 起）每次 partial 回整份计划、点名全部待做步骤，20 步计划逐步更新约 4 万字。
- 防线：`shared/plan.test.ts`「set_plan partial 只回变了的行…」。
