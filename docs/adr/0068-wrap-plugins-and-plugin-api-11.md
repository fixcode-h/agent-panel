# ADR 0068：GitHub 链接包装成标准插件包，插件接口 11 只加声明式字段，网页页签走沙箱路径

状态：已接受 · 2026-11-15

## 背景

- 用户 2026-11-15 想把感觉不错的开源项目（第一个是 tt-a1i/archify）贴一个 GitHub 链接就变成面板插件，设计稿《GitHub项目一键变插件与网页页签》当天定稿。
- 面板已经能从 GitHub 装插件（ADR 0059），但要求仓库根上有 `plugin.json` 或 `plugins.json`。大多数开源项目只是一个技能集、一个 MCP 服务、一个命令行工具或一个网页应用，没有面板的清单。
- 这类项目「装上就能用」，为每个都写一个真插件（Blender 那样）是浪费；另起一套「轻插件」运行时会有两套开关、两套删除、两套更新。
- 包装来的东西以用户权限运行，又多半没人审过，所以从分析到安装都要让用户看清会做什么。

## 决策

### 1. 包装器只是生成器，产物是标准插件包

- `server/plugins/wrap/`：取仓库（`fetch.ts`）→ 配方（社区配方或识别器 `detect.ts`）→ 生成插件包（`generate.ts`）→ 扫描 → 预览（`preview.ts`）→ 确认后跑白名单安装动作（`actions.ts`）→ 写盘。
- 生成出来的包和市场里下载的一样：开关、删除、退回上一版、按项目生效全部沿用 ADR 0059 和接口 9。面板运行时不知道它是包装来的，只看清单字段 `wrap` 显示「包装 · GitHub」徽标、查更新。
- 等确认的安装从 `server/plugins/api.ts` 挪到 `server/plugins/install-pending.ts`，四种来源共用；`writePackage` 加了 `prepare`，在临时目录里跑安装动作，失败整个安装作废、旧版本不动。
- 放弃：另起轻插件运行时；为每个上游项目写真插件（深度集成的仍然写真插件，两条路并存）。

### 2. 配方是声明式数据，动作只有白名单

- 配方格式在 `shared/plugins/wrap/recipe.ts`（zod）：复制哪些路径、技能 / 命令 / 角色从哪来、MCP、环境变量、PATH、托管进程、网页页面、安装动作。不能写脚本。
- 安装动作只有五种：`npm-ci`（`--ignore-scripts`）、`npm-package`（npm 上发布的固定版本，装进包里的 `cli/`）、`uv-tool`（装进包里的 `.tools`）、`release-asset`（核对 GitHub 给的 sha256）、`npm-run`（跑上游构建脚本，预览里标成高级、要勾「我看过了」）。
- 配方来源的优先级：「AI 帮我包装」给的 > 更新时沿用装着的（包里存了 `wrap-recipe.json`）> 插件市场 `wraps/<owner>__<repo>.json` 的社区配方 > 识别器。社区配方格式不对直接报错，不悄悄退回识别器。
- 放弃：默认用 AI 读 README 生成清单——慢、每次不一样、会被 README 里的提示注入带偏。只在识别器认不出时作为可选兜底，产物是同一种配方，照样过预览和扫描；回复里的 JSON 由服务端按 schema 校验，不对时让对话自己修正一次。

### 3. 分析阶段零执行，版本固定到提交

- 识别、生成、扫描都在下载下来的源码包上做，确认前不起任何进程。
- 发了 Release 的取最新 Release 的标签，否则取默认分支；都解析成具体提交再下载，清单记 `wrap.commit`。更新永远是「从提交 A 到提交 B」。
- 识别器优先用发布的包（npx / uvx 固定版本），不从源码构建；`examples/`、`docs/`、`website/` 这类目录里的东西列出来但默认不勾。

### 4. 扫描加包装专用规则，只扫要装进包的文件

- `shared/config-scan/wrap-rules.ts`：安装钩子脚本、混淆 / 超长单行 JS、内嵌可执行二进制、外部域名汇总、文档里的 `curl … | sh`。和通用配置扫描合在一起显示，同样能点「这条没问题」。
- MCP 条目另过 `scanMcpServer`（没固定版本的 npx / uvx）。

### 5. 默认最小生效范围，来源分级写在界面上

- 带 MCP、托管进程或 PATH 的默认「按项目」，只有技能和环境变量的默认「全局」（用户 2026-11-15 确认），预览里能改。
- 预览右上角标来源：社区配方「插件市场审核过」，任意链接和 AI 写的「未经市场审核」；没有许可证的提示「只建议自己用」。

### 6. 更新只列变化，一键更新跳过权限变了的

- `server/plugins/wrap/updates.ts` 按 `wrap.track` 查上游（Release 标签变了、分支或标签指到新提交）。
- 更新预览沿用装着的配方（社区配方的重读市场里的最新版），和装着的那一版比出新增权限（MCP、托管进程、环境变量、PATH、构建脚本）和新增扫描发现（包里存了 `wrap-scan.json`）。
- 插件页「一键更新」只自动更新两样都没变的包装插件；变了的标成「没有自动更新」，用户点「升级」单独确认。

### 7. 插件接口 11 只加声明式字段

- 清单加 `env`（含 `PATH.prepend`）、`mcp`、`services`、`webPages`、`wrap`（`shared/plugins/runtime-schema.ts`），都可选；用了的包要写 `api: 11`，旧面板装它会提示先升级面板。接口 10 已被插件依赖 `requires` 占用。
- 插件不能写面板和 CLI 的凭据变量（`reservedEnv`），配方里写了直接不过校验。
- 运行时（环境变量注入、MCP 每轮注入、托管进程起停）见 ADR 0059 的接口列表和 `server/plugins/` 里对应的文件。

### 8. 网页页签：本机内容走沙箱路径，外部网址先预检，不做通用反向代理

- 包装出来的工具（archify 这类）产出 HTML，要在对话右栏看。面板自己全站 `X-Frame-Options: DENY`，本机 HTML 又不能和面板同源（脚本能调面板接口）。
- 沙箱没有另开端口，挂在主端口 `/sandbox/f/<令牌>/<相对根目录的路径>`（`server/web-view/sandbox.ts`），排在令牌检查前面：沙箱页面是不透明源，浏览器不给它带面板 Cookie，地址里的 32 字节令牌就是凭据。令牌只认发它时的根目录（对话工作目录、对话目录、项目目录、插件目录；2026-11-18 补上项目的文档根和这个对话的 Agent 在项目外写出的文件所在目录，别处的文件先回 `confirm`，用户点「仍要打开」才按它所在目录发），6 小时过期；响应带 CSP `sandbox`（不给 `allow-same-origin`）和 `frame-ancestors 'self'`。同一个端口，外网隧道也能用。
  - 放弃：设计稿里的「主端口 + 1」另开沙箱端口——多一个监听，远程访问时还要再转发一个端口。
- 插件托管进程不经沙箱转发，直接给 `http://127.0.0.1:<端口>`：网页应用的 `/assets` 这类绝对路径挂上前缀会全部失效。代价是外网访问时打不开。页面开着时前端每 45 秒报一次保活，空闲停按它算。
- 外部网址由服务端预检 `X-Frame-Options` / `frame-ancestors`：允许嵌入的直接嵌；被拒的给阅读模式（服务端取正文转 Markdown，原 HTML 不进页面）和新窗口。浏览器扩展 1.6.0 可以按站点去掉这两个头，只对面板页面里的子框架生效，默认关。
- 放弃：通用反向代理去掉响应头——外站脚本会变成和面板同源，等于把面板交出去，还会被各种绝对路径、WebSocket、CSP 弄坏。

## 后果

- 「装上就能用」的开源项目不用写插件代码；深度集成的仍写真插件。
- 识别器不可能覆盖所有项目：认不准时靠社区配方和「AI 帮我包装」，不靠不停加识别规则。上游改了结构时生成器报「找不到 <路径>」，停下来不装半个。
- 这些措施降低的是「不小心装了坏东西」和「审过之后被换」的风险，不是沙箱：带代码的包装插件和 ADR 0059 里带代码的插件一样以用户权限运行。
- 读仓库信息走 GitHub 接口，匿名每小时 60 次；设了 `GITHUB_TOKEN` 时带上。
