# ADR 0060：数据目录有版本号，旧格式只在启动时迁移一次；对话消息改成追加写

状态：已接受 · 2026-11-12

- 影响：`server/migrations/`、`server/task-store.ts`、`server/task-messages-file.ts`、`server/data.ts`（导入）
- 起因：重构文档第 6、7 条（项目文件 `需要重构的地方.md`）

## 背景

- 旧格式的转换散在好几处，而且没有「已经迁过了」的记录，每次读都要再跑一遍：任务存储的两代旧布局（`tasks.json`、`items/`）每次启动都检查，`turnSeenAt` 的补法每读一个任务记录就做一次。
- 对话消息存在 `<id>.messages.json` 一个 JSON 数组里，每次落盘都整份重写。文件常常几 MB，为了扛住它叠了合并窗口、增量指纹、慢写告警、内存份数和字数上限好几层；同时跑十几个子对话时事件循环被序列化 JSON 占满。

## 决策

1. **数据目录写 `data-version.json`**（`{ version, history }`）。启动时拿到单实例锁之后、读任何数据之前，`runMigrations()` 按版本号依次跑还没跑过的迁移，每跑完一个写回版本号。没有这个文件的安装按 0 算。
   - 迁移放 `server/migrations/NNNN-名字.ts`，在 `server/migrations/index.ts` 的 `MIGRATIONS` 里按顺序登记，版本号只增不改。
   - **迁移必须幂等**：失败时版本号停在它之前、面板照样启动（读数据的地方对没迁完的格式有兜底），下次启动整个版本重跑；导入数据备份后从 0 重跑一遍（备份可能是任何旧版本导出的）。
   - **改文件之前先备份**到 `backup/<NNNN>-<名字>/`（保持相对路径）：要改的整份复制（`ctx.backup`），转换后不再要的旧文件整个挪过去（`ctx.moveToBackup`，几 MB 的对话不占双份空间）。只留最近 3 个版本的备份目录。
   - 数据是更新版本写的（降级）时一个文件都不动，打日志；迁移最多留 `MIGRATIONS_KEEP` 个，删掉老的之后，版本更老的安装拒绝直接升级，提示先装中间版本。
2. **对话消息改成 `<id>.messages.jsonl`**，一行一条完整的消息。
   - 新消息追加一行；原地更新的消息（工具行的输出、流式文字）追加一条同 id 的新版本，读的时候按 id 归并（后出现的盖掉前面的，位置按第一次出现）。
   - 删了消息或换了顺序（返工、回退）、覆盖记录超过 `max(2MB, 有效内容)`、关键节点时覆盖记录超过有效内容一半，就整份原子重写（压实）。
   - 读的时候丢掉坏行：只坏了最后半行（崩溃时正在写）照常读；中间有坏行时先复制一份原文件到 `broken/` 再跳过，下次写时整份重写。文件不以换行结尾时，下次追加先补一个换行。
   - 每次追加都 fsync；不知道盘上是什么样（刚启动没读过、被挤出内存、读到坏行）时不追加，整份重写。
3. 第一批迁移：`0001-task-layout`（两代旧任务布局，原来在 task-store 每次启动检查）、`0002-task-meta-cleanup`（补 `turnSeenAt`、删旧的运行时字段 `cliAlive`、`jobs`、`drafting`、`childrenWorking`、`childrenNeeds`、`childrenCli`、`askedAt`）、`0003-messages-jsonl`（对话文件换格式）。

## 放弃的方案

- **继续整份重写、只调大合并窗口**：窗口越大崩溃时丢得越多，而且单次写的代价随对话长度线性增长，治标。
- **每条消息一个文件**：对话动辄几百条，文件数爆炸，备份导出和搜索都要扫目录。
- **迁移失败就拒绝启动**：失败多半是文件被杀毒软件占着这类瞬时问题，拒绝启动让用户什么都做不了；读数据的地方本来就要兼容「没迁完」，所以只记下来下次再试。

## 后果

- `shared/schema.ts` 里的四个 `z.preprocess`（`migrateWorkflow`、`migrateTestStep`、`migrateProject`、`migrateTask`）、`server/settings.ts` 的默认值迁移、`server/verdict-migrate.ts` 还没有搬进来：它们也被导出导入、演示后端用，搬之前要确认那些入口都先跑过迁移。之后按版本号逐个搬。
- 内置角色和工作流的历史快照（`shared/builtin/legacy*.ts`）等用户定了「改过的要不要先备份」再处理。
- 退回不认识 JSONL 的旧版本时，旧版本看不到完整对话（只剩任务记录里的用户消息）；转换前的 `.messages.json` 在 `backup/0003-messages-jsonl/` 里，手动挪回去能恢复。
