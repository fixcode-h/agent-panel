# ADR 0054：项目经验：整个对话完成后自动学「做某类事最快的路」，按需检索

状态：已接受（2026-11-05 用户看过设计稿后定，已实施） · 2026-11-05

- 设计稿：[docs/openspec/changes/project-knowledge/design.md](../openspec/changes/project-knowledge/design.md)
- 和 [ADR 0039](./0039-project-lessons-in-docs.md) 的项目教训分工：教训管防错，经验管提速

## 背景

项目教训什么都往里塞：路径、叫法、命令技巧也被记成教训，每次新会话都要带上。可这些东西没有对错之分，只是「下次能少搜几遍」。另外，新项目里 Agent 每次都要从头搜整个项目，同一个「表格相关的代码在哪」反复搜。

## 决策

- **范围**：经验只记五类（找位置、叫法对照、命令、验证、做法），写到目录为止，一两句；不记某次改动的细节、代码怎么写、一次性的事。判定写在 `shared/experience.ts` 的 `EXPERIENCE_SCOPE`，学习提示词、`record_experience` 的说明、AI 评审共用。教训的记录提示（`shared/lessons.ts` 的 `RECORD_HINT`）同步收窄：路径、叫法、命令技巧不再记成教训。
- **存储**：项目文档根下的 `agent-knowledge/experience/<id>.md`，一条一个文件（Git 项目是 `<项目>/docs`，P4 / SVN 是共用文档根，见 ADR 0052）。读写在 `server/project-experience.ts`，复用教训的写入队列和原子写。
- **学习时机**：只在整个对话完成后学：顶层对话一轮结束后计时（默认 10 分钟），到点时整棵对话树都是「已完成」才学；期间追问就重新计时。
- **省 token**：先用 `shared/experience-gate.ts` 只看工具调用（`ToolUse.kind`）算这次进入落点目录前绕了几步、命令是不是失败几次才成，不调模型；超过阈值（三档 12 / 8 / 5 步）、落点没被已有经验覆盖、当天没到上限，才调一次模型提炼，最多 2 条。模型用设置里指定的，默认跟随对话的 Agent 和模型。
- **校验**：路径必须存在、字段有长度上限；同一件事合进旧条目，不重复加。学到或失败都在对话里留一行系统提示，失败不重试（AGENTS.md）。
- **检索**：不预加载。新会话开头只有一行「有 N 条，先用 `project_experience` 查」，开了「附上相关经验」时本地关键词匹配附最多两条标题和位置。`project_experience` 按关键词（中文两字切分）和要改的文件排序，最多给 3 条全文。
- **学习命令**：`/learn <要学的>` 让角色先查已有经验，只读调查后调 `record_experience` 记一条。
- **AI 评审**：项目设置 →「项目经验」里让模型逐条判断符不符合范围、是不是写得太细，面板先核对路径还在不在；不符合的预先勾上，用户确认后删掉或精简。
- **开关**：设置 →「经验」有总开关（关了不学、不查、不提），以及自动学习、开头附相关经验、勤不勤、等待时间、每天上限、模型。

## 不做

- 教训目录搬到 `agent-knowledge/lessons/`：要改的测试多，先不动，以后单独做。
- 候选状态（学到的先待用户确认）：用户定的是「学到就加」，靠 AI 评审事后清理。

## 后果

- 新增面板工具 `project_experience`、`record_experience`（后者收进 `more_tools`，子任务没有）。
- 经验文件进项目仓库，和模块文档一起提交，换机器、换人都能用。
