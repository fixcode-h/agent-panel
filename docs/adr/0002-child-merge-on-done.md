# ADR 0002：子对话测试跑通即由面板合回父对话分支

状态：被替代（被 [0003](./0003-child-complete-before-recycle.md) 替代「合进去就把子对话标记完成」；被 [0005](./0005-conversation-states.md) 替代「`submit_merge` 后面板直接合并」，改为请父对话 `finish_child` 收尾；其余结论仍有效） · 2026-10-23

## 背景

用户要求（2026-10-23）：子对话完成后默认把独立分支（worktree）的代码直接合并到父对话所在的分支；「子对话完成」的标记就是测试跑通。要定两件事：谁来合并，编译测试放在哪里。

## 事实核对

| 位置                                          | 现状（改动前）                                                                      |
| --------------------------------------------- | ----------------------------------------------------------------------------------- |
| `server/tasks.ts` `submitMerge` / `integrate` | 子对话调用 `submit_merge` 后面板按父对话排队（`mergeLock`）试合并、提交，冲突就撤回 |
| `server/tasks.ts` PATCH `/:id` `resolved`     | 标记完成要用户手动点，没合并时 409，标记后删独立分支                                |
| `server/tasks.ts` `reportToParent`            | 子对话做完只提醒父对话「要它调用 submit_merge 才算进去」，没调用就一直不合          |
| `shared/engine.ts` `buildPart`                | 编译、测试在子对话自己的独立分支里跑（093a41e 起，合并时不再编译）                  |

## 决策

**合并由面板做，编译测试留在子对话的独立分支里；`submit_merge` 就是子对话的完成标记。**

- 子对话测试跑通后调用 `submit_merge`，必须在 `tests` 里写跑了什么、结果如何，空的直接拒绝。
- 面板提交、排队合回父对话所在的分支；合进去就把子对话标记完成，这一轮结束后回收独立分支和 CLI 进程。冲突撤回并推回给子对话。
- 子对话一轮做完、独立分支里还有没合的改动却没调用：面板推一条消息催它一次；再不合就照常回报父对话，由父对话决定。
- 父对话计划里等这个子对话的步骤，由合并结果收口，不在「这一轮说完了」时就算完成。

候选方案和没选的理由：

- **父对话合并**：父对话按约定只统筹、不碰文件（见 `docs/lessons/builtin.md`），让它跑 git 合并要花一轮模型调用，几个子对话同时完成时还要自己排队。
- **子对话自己合并**：子对话看不到也不该写父对话的目录，几个子对话并发合并会互相踩；推送也一律被拦。
- **合并后在父对话分支上再编译一次**：093a41e 已经按用户要求去掉「合并时编译」，合并前的编译要在共享目录里串行，慢且会读到别人改到一半的文件。整体回归由父对话另开子对话去跑。

## 操作清单 / 契约

| 工具           | 参数                    | 结果                                                                 |
| -------------- | ----------------------- | -------------------------------------------------------------------- |
| `submit_merge` | `tests`（必填）、`note` | 马上返回排队情况；合并结果推回子对话，合进去时子对话 `resolved=true` |

## 与现有实现的关系

改 `server/tasks.ts`（`submitMerge`、`childMerged`、`closeChild`、`nudgeMerge`、`settleChildTurn`、`reportToParent`）、`server/orch-mcp.ts`（参数）、`shared/engine.ts`（提示词）。手动「标记完成」和手动合并按钮保留，共用 `closeChild`。已完成的子对话再收到消息时取消完成标记，分支按 b3945d5 的方式重建。

## 运行时

合并结果是面板消息（`panel: 'build'`），不冒充用户。合并成功时子对话还在这一轮里就实时交给它，已经停下的只记一条，不为它再开一轮。合并后又改了文件的不回收，取消完成标记。

## 分期

一次做完。

## 风险与代价

- 合并只靠 git 判冲突，两个子对话各自测试通过、合在一起语义冲突时不会当场发现：靠父对话在几个子对话合进来后另开子对话跑完整测试。
- `tests` 是子对话自报的，面板不核实；认下这个代价，换来不在合并时重跑编译。
- 保活的旧 CLI 进程拿的是没有 `tests` 的旧工具列表，调用会被拒并说明要补 `tests`。
