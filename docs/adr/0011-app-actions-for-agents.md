# ADR 0011：Agent 操控软件一律走「动作注册表」，对 Agent 只暴露两个 MCP 工具

状态：已接受（定了就不换：以后加能力只加动作，不再讨论 CLI 还是 MCP） · 2026-10-24

- 取代：[ADR 0001](./0001-ai-operate-panel-mcp-or-cli.md) 里「每个操作一个 `panel_*` 工具」的形态；0001 选 MCP 的结论保留
- 影响范围：新增 `server/app-actions/`（注册表、各组动作、HTTP 入口）、`web/src/lib/ui-actions.ts`；改动 `server/ask-mcp.ts`（挂两个工具）、`server/exec/invoke.ts`、`server/exec/runner.ts`（把调用者传进去）、`server/page-events.ts`（多一种推给页面的信号）、`server/tasks.ts`（补「停全部子任务」「停后台命令」两个接口）、`server/index.ts`（接上宿主）

## 背景

用户 2026-10-24 的要求，原话要点：

1. **用户命令是第一位的**：用户明确下指令时必须能执行。关闭全部子对话、关闭全部子任务、关闭所有后台任务、删除某个对话、初始化某个项目，都要留好功能接口，允许对话里的 CLI 去做。
2. **让 AI 控制软件**：点开设置、改设置里的参数、打开 UI 设计模式、创建一个 UI 设计对话然后生成一个背包页面……诸如此类的软件操作，都提供接口给 Agent 调用。
3. 用可扩展的框架结构，保证以后扩展方便。
4. 「好好思考使用 CLI 还是 MCP，订好了就不换了」。

ADR 0001 已经选了 MCP，但一直停在「提议」，而且它的形态是一个操作一个 `panel_*` 工具：每加一个操作要改工具表、提示词和派发；界面操作（打开设置、进入设计模式）它没有覆盖。这一份把形态定死并落地。

## 决策

### 1. 传输：Agent 一律走 MCP，不做给 Agent 用的命令行

| 维度       | MCP（选定）                                                                     | CLI 命令（不选）                                                                        |
| ---------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 能不能连上 | 五个 CLI 都已接好面板 MCP，地址是本机回环，CLI 自己连                           | Codex 沙箱默认禁网、禁起子进程；Claude Code 等的权限模式下每条 shell 命令都可能弹审批   |
| 参数       | JSON 原样传，有 schema                                                          | JSON 塞进命令行，Windows 上经 `cmd.exe` 转发引号和换行会坏（`docs/lessons` 里踩过多次） |
| 谁在调     | 令牌即这一轮：天然知道调用者是哪个对话，「关掉**我的**子对话」不用模型自己报 id | 要靠环境变量把对话 id 和令牌塞给子进程，子进程再传给子进程就乱了                        |
| 权限边界   | 令牌只在这一轮有效，这一轮结束即作废                                            | 只要拿到地址和令牌，任何进程任何时候都能调                                              |
| 出错       | `isError` + 中文原因，模型能看懂、改参数重试                                    | 退出码 + stderr，模型常误读                                                             |
| 维护       | 不依赖用户 PATH、shell、Node 版本                                               | 要随包发一个可执行入口，还要处理各平台                                                  |

**人和脚本**用同一份动作表的 HTTP 入口：`GET /api/actions` 列动作、`POST /api/actions/<name>` 执行（走 `tokenGuard`，开了访问令牌就要令牌）。真有人要命令行时，薄壳只调这个入口，不另写逻辑。

### 2. 形态：两个固定的 MCP 工具 + 动作注册表

对 Agent 只多两个工具，永远不再增加：

| 工具          | 参数              | 做什么                                                                    |
| ------------- | ----------------- | ------------------------------------------------------------------------- |
| `app_actions` | `group?`          | 列出能用的动作：名字、一句话说明、级别、参数（从 zod 生成）               |
| `app_do`      | `action`、`args?` | 执行一个动作，返回结构化结果；参数不对、对象不存在时返回 `isError` 和原因 |

没选「一个动作一个工具」（ADR 0001 的形态），理由：

- **扩展不碰 MCP**：加一个能力 = 在 `server/app-actions/<组>.ts` 里加一项 `defineAction`。工具表、派发、提示词都不用改。
- **上下文不随能力膨胀**：动作会越来越多（设置每一栏、设计的每种操作），一个动作一个工具会让每次调用都背几十份 schema；两个工具的说明是常数，模型需要时再 `app_actions` 查。
- **保活的会话不会调到不存在的工具**：工具名不变，动作增删只影响 `app_actions` 的结果（0001 里 `submit_build` 改名留兼容分支就是这个坑）。

一个动作的定义：

```ts
defineAction({
  name: 'task.stop_children', // <组>.<动词>，组名就是文件名
  title: '停止全部子对话',
  description: '给模型看的说明：什么时候用、会怎样',
  level: 'danger', // read | write | danger
  input: z.object({ id: z.string().optional() }), // 参数的唯一来源：校验和给模型看的说明都从它来
  run: async (a, ctx) => ctx.api('POST', `/tasks/${id}/children/stop`), // 尽量复用界面按钮用的那个接口
})
```

### 3. 动作怎么执行：复用界面的接口，界面操作推给页面

- **改数据的动作调面板自己的 HTTP 接口**（进程内 `app.request`）：和用户在界面上点按钮走同一段代码，`userStop`「停掉附属的一切」、删除连子对话一起删这些规则自动一致，不会出现「AI 停的和用户停的不一样」。接口缺的（停全部子任务、停后台命令）先补接口，再写动作。
- **界面操作推给打开着的页面**：服务端经 `/api/app/events` 推一条 `ui` 信号，页面在 `web/src/lib/ui-actions.ts` 的处理表里找到对应的处理函数执行（切页面、打开设置某一栏、打开项目设置、开始 AI 初始化）。没有页面开着时动作返回错误，说清「面板页面没有打开」。
- **服务端数据变了要让页面跟上**：AI 改了设置后推一条 `ui` 信号让页面重新读设置，开着的设置窗口用新值重建，不会被自动保存用旧值盖回去。

### 4. 用户命令第一，权限按级别

| 级别     | 含义                                     | 规则                                                                                               |
| -------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `read`   | 只读                                     | 随时可用                                                                                           |
| `write`  | 可以改回来的（改设置、切页面、新建对话） | 用户要求或者完成任务需要时用                                                                       |
| `danger` | 停止、删除这类不可撤销的                 | **只在用户明确要求时用**；用户明确要求了就直接执行，不再弹确认（用户命令第一）。说明里写清会丢什么 |

硬边界（不管级别）：

- 不能删除、停止**自己这一轮所在的对话**和它的父对话（会把自己连根拔掉）；停自己用户有停止按钮。
- 停止走 `userStop`：在运行的对话**只有**用户明确要求时才被停，且停掉它附属的一切（ADR 0012）。动作说明里写明这一条，模型不会为了「收拾」去停别人的对话。
- 不提供推送、建 PR、发布、P4 提交（同 ADR 0001「明确不提供的操作」）。
- 设置里的密钥类字段（`apis`、`clis` 里的账号和 API、访问令牌、外网访问）不读不写。

### 5. 谁能用

对话（父对话和子对话）的 CLI 调用都挂；派出的子任务（`helper`）不挂：子任务是一次性的小活，不该操控软件。没有对话上下文的入口（HTTP）调用时，需要对话 id 的动作必须显式给 `id`。

## 第一批动作

| 动作                    | 级别   | 做什么                                                                         |
| ----------------------- | ------ | ------------------------------------------------------------------------------ |
| `task.list`             | read   | 列对话：项目、父对话过滤                                                       |
| `task.get`              | read   | 一个对话的状态、子对话数、后台命令、子任务                                     |
| `task.children`         | read   | 子对话列表和各自状态                                                           |
| `task.create`           | write  | 在项目里新建一个独立对话（不是子对话，子对话用编排工具 `create_conversation`） |
| `task.send`             | write  | 给另一个对话发消息（不能发给自己）                                             |
| `task.rename`           | write  | 改对话标题                                                                     |
| `task.stop`             | danger | 停止一个对话及它附属的一切                                                     |
| `task.stop_children`    | danger | 停止一个对话的全部子对话（默认自己的）                                         |
| `task.stop_subtasks`    | danger | 终止一个对话派出的全部子任务（默认自己的）                                     |
| `task.stop_background`  | danger | 停止一个对话和它子对话的全部后台命令（默认自己的）                             |
| `task.delete`           | danger | 删除一个对话，连同它的子对话                                                   |
| `project.list`          | read   | 列项目                                                                         |
| `project.open_settings` | write  | 打开某个项目的设置弹窗，可指定一栏                                             |
| `project.init`          | write  | 打开项目设置并开始「AI 初始化项目」；推荐的设置仍由用户在弹窗里应用            |
| `settings.get`          | read   | 读全局设置（不含密钥类字段）                                                   |
| `settings.set`          | write  | 改全局设置的若干项（不含密钥类字段），开着的设置窗口跟着刷新                   |
| `ui.open_settings`      | write  | 打开设置窗口，可指定一栏                                                       |
| `ui.navigate`           | write  | 切到某一页（项目、对话、工作流、Agent、UI 设计……）                             |
| `design.projects`       | read   | 列 UI 设计的项目                                                               |
| `design.list`           | read   | 列某个设计项目里的设计                                                         |
| `design.create`         | write  | 新建一个 UI 设计（可选马上在页面上打开）                                       |
| `design.open`           | write  | 在页面上打开一个设计（进入 UI 设计模式）                                       |
| `design.chat`           | write  | 给设计的 AI 发一条要求（例如「生成一个背包页面」），设计里的 AI 开始改         |

「创建一个 UI 对话然后生成一个背包页面」= `design.create`（`open: true`）+ `design.chat`。

## 运行时

- 注册：`server/app-actions/index.ts` 汇总各组，启动时检查重名；`registry.ts` 负责列出、校验（zod）、执行、记日志（`log.info('action', …)`，带调用者和耗时）。
- 宿主：`server/index.ts` 在接口都挂好后 `setActionHost({ api, ui })`：`api` 是进程内 `app.request`，`ui` 是 `signalPages`。
- MCP：`openAskBridge` 多收一个 `app`（调用者：对话 id、项目 id、父对话 id），`tools/list` 有它时多两个工具，`tools/call` 一个分支交给注册表。
- 提示词：有 `app` 时在输入后附一行用法（`APP_HINT`），说明「用户让你操作软件时先 `app_actions` 再 `app_do`」。
- 页面：`page-signal.ts` 收 `ui` 事件，交给 `ui-actions.ts` 的处理表；处理函数由 `App.tsx` 用 `NavCtx` 和 `DataProvider` 的能力注册。

## 分期

一次做完第一批（上表）。之后按需加动作，每加一个只改 `server/app-actions/<组>.ts`（界面操作再在 `ui-actions.ts` 加一个处理函数），并补单测。

## 风险与代价

| 风险                                  | 对策                                                                                 |
| ------------------------------------- | ------------------------------------------------------------------------------------ |
| 模型自作主张停掉、删掉别的对话        | `danger` 的说明写死「只在用户明确要求时」；不能动自己和父对话；每次执行写日志        |
| 两个通用工具，模型不知道有哪些动作    | 提示词一行用法 + `app_actions` 按组列出；`app_do` 报「没有这个动作」时附上可用动作名 |
| 进程内调接口绕过 `tokenGuard`         | 只有注册表能这么调，动作是白名单；密钥类设置不读不写                                 |
| 界面操作时没有页面开着                | 返回错误说明，模型转告用户打开面板                                                   |
| AI 改设置和开着的设置窗口自动保存打架 | 改完推信号，窗口用新值重建                                                           |

## 开放问题

1. **要不要给子任务（helper）也挂只读动作**：倾向不挂，先不挂；真有需要再按级别放开。
2. **HTTP 入口要不要配一个命令行薄壳**：等真有「脚本里调」的需求再做，只调 `/api/actions`。
