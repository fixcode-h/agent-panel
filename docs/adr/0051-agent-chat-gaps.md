# ADR 0051：补齐 Agent / Chat 两种模式的必备能力：默认独立分支、撤回连同文件、审批放行、Chat 衔接与记忆

状态：已接受（2026-11-04 用户看过分析报告后定：顶层对话默认开独立分支、Chat 要跨对话记忆、ExitPlanMode 交给实现方定、Chat 不单独收紧权限） · 2026-11-04

## 背景

2026-11-04 对两种模式做了一次能力盘点（Agent 模式 = 项目里的对话，Chat 模式 = Chat 页没有项目的对话，见 ADR 0037、0038）。主干的执行、推进、收尾、恢复已经齐了，缺的是两类：

- **用户敢不敢放手**：同一项目几个对话同时改同一目录没有保护（`server/turn-changes.ts` 整目录快照求差，别的对话的改动会算进来、会被一起撤掉）；撤回只截对话、代码不回；审批卡只有文件名、同一类命令一遍遍点。
- **Chat 和项目接不上**：Chat 里聊出来的东西转不到项目里；Chat 里不能 @ 项目文件；没有重新生成；没有跨对话的偏好；生成的文件看不到；不渲染公式。

另有两处覆盖面不全：Codex、Command Code 不报费用，项目「按费用的上限」对它们无效；权限选「只读规划」时 Claude Code 的 ExitPlanMode 落成一段 JSON 的通用审批。

## 决策

1. **顶层对话默认开独立分支**（`Project.isolateNew`，默认 true）：新建输入框的「独立分支」默认打开，项目设置里能关。旧字段 `isolateDefault` 界面从来不能改，存的 false 只是写盘带的默认值：换名后 zod 剥掉，旧项目一律按新默认。服务端仍是「传了 isolate 才建」，默认值只在输入框（e2e 和其他入口的语义不变）。分叉的顶层对话不再回到项目目录：原对话在独立分支里就从它的分支再开一个，否则按项目默认；换了目录续接不上的 CLI 带上留下的对话开新会话。
   - 2026-11-05 修订：用户改回默认不勾。字段换名为 `Project.isolateByDefault`（默认 false），旧字段 `isolateNew` 存的 true 多半只是写盘带的默认值，换名后 zod 剥掉、旧项目一律按新默认不勾；项目设置里仍能打开，分叉在原对话没开分支时也跟着这个设置。
2. **撤回可以连同文件一起撤**（`/rewind` 的 `files`）：用每一轮记下的 `turnChanges`，和「撤销整个对话」同一套 `undoSpans`；撤不干净时什么都不动、列冲突。被撤那几轮建的计划作废，开的子对话停下并归档。第一条也能撤（`turnBefore` 一轮都不留，下一轮开新会话）。回复下面的「重新生成」= 撤回最后一条（连同那一轮的文件）再原样发一次。
3. **审批卡带改动、能在这个对话里一直允许**（`shared/allow-rules.ts`）：Claude Code 的 Edit / MultiEdit / Write 把要改的内容拼成 diff 放进请求；请求带一条规则键，用户点「一直允许」就记进 `Task.allowRules`，同一个对话里同类请求自动允许并留一行记录。规则故意窄：命令按程序名（git、npm 这类带子命令），文件按所在目录，其他工具按名字；串联、管道、重定向、子 shell、删除、提权不给规则。只作用于这一个对话，不做全局放行。
4. **Chat 转到项目、@ 项目文件**：Chat 标题栏「在项目里继续」把这段聊天整理成记录（和「引入会话」同一份）放进目标项目新建对话的输入框，用户写一句再发，不替用户开跑；Chat 的 @ 在所有项目里一起搜、标上项目名。
5. **「关于我」和跨对话记忆只给 Chat**（`server/chat-memory.ts`，数据目录的 `chat-memory.json`）：设置里写的「关于我」和 Chat 里 `remember` 工具记下的长期偏好，每个 Chat 对话的提示词都带上（`shared/chat-prompt.ts` 的 `memoryPart`）。最多 50 条、每条 300 字，满了丢最早的一条并告诉模型；不记密码密钥。项目里的对话不带：它们有项目说明文件和项目教训，个人记忆混进去会污染项目上下文。
6. **费用按用户填的单价折算**（`ModelCatalogEntry.price`、`shared/model-price.ts`）：CLI 报了费用照旧用它报的；没报的按模型目录里填的单价算，没填就是 0（界面写「费用未知」，费用上限的说明写清）。不内置任何价格。
7. **ExitPlanMode 显示成方案审批，EnterPlanMode 继续关着**：用户在权限里选「只读规划」时，规划完的审批卡标题写「按这个方案开始改？」、内容是方案原文，每次都问、不给「一直允许」；模型不能自己切进只读规划（理由见 `shared/clis/claude.json` 的 `why`）。
8. **其他**：回复里的 `$…$`、`$$…$$`、`\(…\)`、`\[…\]` 先出带原文的占位，停下后懒加载 KaTeX 排版（金额里的 `$` 不算）；Chat 右栏「生成的文件」按改文件类工具调用列出、能下载；Markdown 导出复用整理记录；Chat 页的 ⌘⇧O 新建聊天；Chat 角色选择器不列「聊天约束」；Chat 列表不列子对话。

## 放弃的做法

- **检测到同目录有别的对话在跑时提示或排队**：用户选了更彻底的默认开独立分支；提示会被忽略，排队会让用户以为对话卡住。
- **服务端默认建独立分支**：定时任务、动作接口、e2e 里一百多处建对话的入口语义都会跟着变，默认值放在用户看得见的输入框里更可控。
- **内置各家模型的单价**：价格会变、会过期，写错比空着更糟——费用上限会悄悄失准。
- **全局的放行规则 / 按通配符配权限**：一次点击影响所有对话太重；需要全局时再在设置里做，先看这一版用起来怎么样。
- **记忆也给项目里的对话**：项目有自己的教训和说明文件，个人偏好混进去会让同一个项目在不同人手里行为不一样。

## 后果

- 每个新对话默认多一个 git worktree：做完要合并或丢弃（已有的独立分支流程照旧），磁盘占用变大；非 git 项目不受影响。
- 换了目录（独立分支）分叉的 Codex 对话不再走原生 `thread/fork`，改为开新会话带上留下的对话，上下文是文字形式。
- 「一直允许」让同一对话里同类操作不再经过人，自动允许的每一次都在对话里留一行。
- 本期没做、留在待办里的：单个对话自己的用量上限、自建 Chat 角色里临时换模型、可配置的重试策略。
