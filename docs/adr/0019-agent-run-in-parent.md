# ADR 0019：角色可以「禁止子对话执行」，子对话点名它时转交父对话创建子任务

状态：已接受 · 2026-10-27

## 背景

子对话收尾时经常要补文档（派「文档」）。补文档是长活：要读代码、写模块 README、改 `MODULE-MAP`、写 ADR，
子对话派出去以后只能等，卡在收尾前的最后一步空耗；而这件事本来和子对话要交付的代码没有依赖关系。

用户 2026-10-27 的要求（原话）：

> 子对话启动子任务补文档这个调整下吧，放到父对话中启动子任务去补充文档吧，避免子对话被补充文档给阻塞在那里，完成不了，空耗，然后你看看还有哪些也可以放到父对话中，在对应的角色中定义其能在什么类型对话中调用，支持修改，增加设置只在父对话中执行，来标记这个角色支持在什么类型的对话中启动，如果在不受支持的对话中启动那么应该是委派到父对话中，看看父对话是否支持……子对话可以请求只在父对话执行的角色，但是会被自动转发到父对话中创建子任务执行，且子对话当前计划步骤立即标记完成，一般是不影响的子任务会这么操作

同一轮补充：这个开关的文案统一叫「禁止子对话执行」（不是「只在父对话执行」），说明里要写清**只对子对话生效**。

同类机制已经有两处：UE 编译归父对话（[ADR 0004](./0004-ue-build-by-parent.md)）、测试步骤可以设成只在父对话里跑、合并后再由父对话执行（[ADR 0018](./0018-test-steps-run-in-parent.md)）。这两处都是「子对话请求父对话做重活」；这次把同样的问题从「测试步骤」推广到**角色**：
不阻塞、不需要模型记得申请，规则在代码里。

## 事实核对

| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `shared/engine.ts` `spawn()`                     | 所有派子任务的唯一出口：角色校验、`submitMerge` 时禁派「版本控制」、评审交接单校验、`MAX_HELPERS_PER_STEP` 名额、计划步骤 `bindWait` 都在这里                                                        |

| `shared/builtin/agents.ts` `docsync`             | 「文档」是必备角色（`CORE_AGENTS`），启动时自动装、默认 `common: true`                                                                                                                               |

## 决策

**角色新增 `runIn: 'any' | 'parent'`（默认 `any`），界面上叫「禁止子对话执行」。子对话点名 `parent` 的角色时不在本地建子任务，
转交父对话创建；子对话点名的计划步骤立即标完成、不挂等待，收尾不被这个外部子任务拦住。**

- 数据：`AgentInput.runIn`，`z.enum(['any', 'parent']).catch('any').default('any')`。
  旧数据没有这个字段，`catch` 按 `any` 读，不迁移。内置定义里只有「文档」（`docsync`）是 `parent`；其他内置角色（含「版本控制」「测试验收」）保持 `any`。
- 判定位置：**引擎的 `spawn()`**，不是 `server/orch-mcp.ts`。所有派子任务都要经过 `spawn`（工具、演示分支、将来的入口），
  放工具层会漏；而且角色校验、名额、计划步骤收口本来就在 `spawn` 里，转发语义要和它们保持一致。
- 谁能接：**由服务端的 `host.forwardSpawn` 判断**，引擎只负责「叫一声、拿到结果」。
  - 调用方没有父对话（`task.parentTaskId` 为空，或宿主没有转交能力）→ 返回明确错误，不静默本地执行；
  - 找不到父对话、父对话已归档、父对话自己也是被派出来的子对话 → 返回明确错误；
  - 父对话正常 → 交出去。
- 排队与执行：
  - 父对话的 AI 正在处理这一轮（`live` 里的 `orch` 只在 `runAgent` 期间挂着）→ 直接把子任务派进这一轮：它进这一轮的 `st.helpers`，`gate` 会等它、结果能交回；父对话任务里立刻出现子任务，子任务卡片挂在一条「子对话 X 请求创建子任务 Y」的正式记录上；
  - 其它阶段（等下一句、等子任务结果、跑计划）→ 请求排进这个父对话的队列，并 `wakeConv` 发一条短提示；父对话下一轮**开始调 AI 前**，`onOrchestra` 回调里把它派出去（`spawn(..., { local: true })`），正式记录也在那里写。唤醒只发短提示、正文只写一处，父对话里不会出现两条一模一样的请求。
    **不依赖父对话的 AI 想起来调 `spawn_agents`**：它这一轮看到的是一条「面板已经替你派出」的说明，只需要在有结果后处理结果。
- 子对话这一侧：整批都是转交的 → 不建任何子任务、不调 `bindWait`，点名的步骤 `finishStepNow` 立即标完成、note 写「已转交父对话」，
  并在对话里写一条系统消息「已转交父对话创建「补文档」（id: …）」。
  一批里既有本地派又有转交 → 本地照常建、照常挂等待，转交的那几个在说明里列出来，步骤**不**立即完成（本地还有子任务在跑）。
- 名额：转交出去的不占 `MAX_HELPERS_PER_STEP`；`resume` 不能跟着转交（父对话那边是新任务，接不上子对话的会话），带了 `resume` 的转交请求直接报错。
- 重启 / 丢消息：排队只在内存里（和后台命令队列、父对话测试队列一致）。`wakeConv` 那条系统消息是持久化的，重启后父对话还能看到是谁请求的；
  父对话一直不跑时请求留在队列里，下一次它建 Orchestra 时派出。
- 失败回传：转交失败的错误只回给子对话的 `spawn_agents` 调用（`error` 文本），不写父对话；
  父对话那一侧派出失败（例如名额满了）会写一条系统消息说明，不让它静默消失。
- 默认值只在「文档」上开，理由：
  - 「版本控制」在独立分支的子对话里本来就禁止派（面板的收尾走 `submit_merge`），改成 `parent` 会让子对话更容易误派，反而添乱；
  - 「测试验收」的重活已经有 ADR 0018 的「测试步骤在父对话执行」兜住，它自己不是长活；
  - 「评审」必须在子对话里看本地 diff、结论交回子对话，不能在父对话里跑。
    用户自己可以给任意角色打开这个开关（包括内置角色），下一次 `spawn_agents` 立即生效。

没选的做法：

- **在 `server/orch-mcp.ts` 拦下来转发**：工作流节点、演示分支、`runEngineTurn` 里的 `spawn` 调用都不走工具层；
  而且工具层拿不到「这一批里哪些是 parent 角色、名次算不算名额」这些 `spawn` 已经算过的信息。
- **只给父对话发一条消息、让它的 AI 自己调 `spawn_agents`**：模型可能不调、可能改标题、可能漏掉 `step`；这等于把「不阻塞」交给提示词。
  现在只把「派出」这件事交给面板，AI 只负责处理结果。
- **把「测试步骤」那个 `runInParent` 字段直接复用到角色上**：那是 `TestStep` 的字段，语义是「这条步骤谁来跑」；
  角色上要的是「这个角色能在哪类对话里启动」，含义和生效处都不同，混用会让设置页和提示词对不上。
- **让转交出去的任务也挂进父对话的计划**：父对话的计划是它自己的推进节奏，被一个外部请求插进一条等待会让它的收尾也被拖住；
  这次只在父对话里留一条说明 + 子任务卡片，不碰父对话的计划。
- **等父对话那边有了结果再把子对话的步骤标完成**：那就还是阻塞，和这次的目的相反。

## 操作清单 / 契约

| 对象                                                 | 约定                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AgentInput.runIn`                                   | `'any' \| 'parent'`，默认 `any`；`catch('any')` 兜住旧数据和写坏的值                                                                                                                                                                                                                                                                     |
| UI（`AgentDetail.tsx`）                              | 复选框「禁止子对话执行」，说明写清只对子对话生效、转发后步骤立即完成；内置角色也能改                                                                                                                                                                                                                                                     |
| `syncCore` / `sameCore`                              | `runIn` 不在内置定义覆盖的字段里（`runIn: cur.runIn` 保留用户值），`sameCore` 把它算进比较                                                                                                                                                                                                                                               |
| `upgradeRunIn(a, key)`                               | 已装副本的一次性升级：`docsync` 从 `any` 改成 `parent`，升级记录写进 `AgentInput.upgrades`（id `docsync.run-in-parent`）；之后用户改回 `any` 不会被再改回来                                                                                                                                                                              |
| `EngineHost.forwardSpawn(spec)`                      | 同步返回 `{ ok, info, id? }`：排队也算交出去了；接不了返回 `ok: false` + 原因。**不能改成异步**：`Orchestra.spawn` 是同步的（工具层、演示分支、测试都在同步用）                                                                                                                                                                          |
| `Orchestra.spawn(tasks, step?, opts?)`               | 新增 `opts.local`：这批就是给这个对话本地执行的，不再按 `runIn` 转发（父对话派出转交来的任务时用，避免转一圈又回来）                                                                                                                                                                                                                     |
| `EngineHost.onOrchestra(orch \| undefined)`          | 每次开始调对话 AI / 调完时回调（不是「每轮建立 Orchestra 时」）；服务端据此只在 AI 正在处理时直接派，在下一轮开始调 AI 时消费队列                                                                                                                                                                                                        |
| `server/task-store.ts` `known(id)`                   | 同步读内存里的任务（正在跑的、读过的、启动时加载过摘要的），给必须同步判断的 `forwardSpawn` 用；不读盘、不改返回对象                                                                                                                                                                                                                     |
| `shared/plan.ts` `finishStepNow(task, stepId, note)` | 立即把一步标完成（找不到 / 已完成时不改计划，返回原因），供转交成功后收口                                                                                                                                                                                                                                                                |
| `server/tasks.ts` `forwardSpawn` / `attachOrchestra` | 父对话判定、直接派 / 排队、`wakeConv`、系统消息、父对话那一侧的失败说明                                                                                                                                                                                                                                                                  |
| 系统消息                                             | 父对话：`子对话「X」请求创建子任务「Y」（角色：Z）。这个角色禁止子对话执行，面板已经替你派出，结果会交回你，不用再调 spawn_agents。` + 要求原文（**只写一处**，排队唤醒时另发一句不含请求正文的短提示）；派出失败时补一条 `上面那条没能派出：<原因>。这件子任务需要另外安排`，明确更正上一条；子对话：「已转交父对话创建「Y」（id: …）」 |
| `spawn_agents` 说明                                  | `agent` 字段在子对话里补一句「点名这类角色时不会在这里跑，会转交父对话创建，点名的步骤立即完成，不用等它的结果」                                                                                                                                                                                                                         |

## 与现有实现的关系

- 和 ADR 0004 / 0018 是同一条思路的三个层次：编译 → 测试步骤 → 任意角色。前两者由父对话触发后台命令、走独占队列；
  这次转发只**创建子任务**（不启动后台命令），所以不占用父对话的独占队列，也不改变 UE 编译和父对话测试的排队顺序：
  转发来的子任务在父对话里跑，它自己起的编译 / 测试照旧按 ADR 0004 / 0018 排队。
- 和「子对话不能再派子任务」的关系不变：子任务（`o.helper`）仍然不能派子任务；这条转发只对**子对话**生效，
  子对话里的 `spawn` 依然可以派本地子任务，只是 `parent` 角色的请求被转交。
- 和「子对话不能再派版本控制」的关系：那条校验在转发判断之前，独立分支里的子对话派「版本控制」仍然直接报错，
  不会因为把「版本控制」改成 `parent` 就绕过去。

## 运行时

1. 角色设置里勾上「禁止子对话执行」→ `AgentInput.runIn = 'parent'`；内置角色保存时 `syncCore` 保留这个值。
2. 子对话（`task.parentTaskId` 有值）的 Agent 调 `spawn_agents`，点名的角色是 `parent`：引擎在 `spawn` 里把它从本地批次里摘出来，逐个调 `host.forwardSpawn`。
3. 服务端：父对话在跑 → `live.orch.spawn([...], undefined, { local: true })`，并在父对话里写一条来源说明（子任务卡片挂在它上面）；
   没在跑 → 入队 + `wakeConv`（只发一句短提示），父对话下一轮开始调 AI 时 `onOrchestra` 派出，正式请求记录也在那里写。
4. 子对话侧：整批都转交时 `finishStepNow` 收口点名的步骤、写系统消息、`spawn_agents` 返回「已转交父对话…」；子对话继续下一步、正常收尾。
5. 父对话侧：子任务跑完，结果按普通子任务交回父对话（`helperBatch`），父对话在自己的会话里接着处理；不推给子对话。
6. 接不了（没有父对话 / 父对话是子对话 / 找不到 / 已归档）：`spawn_agents` 返回带原因的 `error`，子对话的步骤不标完成，模型自己决定怎么做。

## 分期

一次做完。出口条件：单测（字段默认值、转发而不是本地建、步骤立即完成、接不了时报错、`any` 行为不变、混合批、`resume` 拒绝）
和 e2e（子对话派「文档」→ 父对话有子任务、子对话计划步骤已完成、子对话能正常收尾；嵌套子对话接不了时报错）都过。

## 风险与代价

- **父对话被外部请求插队**：父对话正在跑时，转交来的子任务会直接加进当前这一轮，和它自己的事并行。父对话的资源只有一份，
  请求多了会拖慢它；这次不做限流（`MAX_HELPERS_PER_STEP` 仍按节点算，转发的不占本地名额）。先观察真实使用。
- **内存队列会丢**：面板重启时排着的转交请求丢掉，父对话只剩一条「谁请求了什么」的系统消息，需要它自己处理。接受：转交的本来是不阻塞的事，
  丢了也不会让子对话卡住；加上「谁请求的、要做什么」都写在消息里，人工或 AI 都能补。
- **整批里有一件没交出去时整批算失败**：能交出去的那几件已经在父对话里派出去了（子对话里也照常写「已转交父对话创建…」的系统记录），但子对话拿到的是 `error`、点名的步骤不标完成，模型会再补做，可能重复派一件。选「宁可让模型补一次」而不是「少做一件却显示完成」。
- **步骤立刻标完成可能与实际不符**：父对话派出失败时，子对话那一步已经完成（失败说明只出现在父对话里）。
  这是「不阻塞」的代价：子对话的完成判定不该依赖另一侧的结果；确实要核对时看父对话的子任务卡片。
- **「文档」角色被用户改回 `any` 后不再转发**：这是用户的选择，设置页说明里写清了；升级只做一次，不会把用户改回去的值再改回来。
- **内置角色也能改这个开关**：和「设定由面板维护」不冲突——`runIn` 是运行方式（哪类对话里启动），不是角色设定；
  `syncCore` 明确保留用户的值。

## 开放问题

- **哪些角色适合再设成 `parent`**：这次只开「文档」。如果真实使用里发现「依赖与安全」「每日工作总结」这类也可以不占子对话的时间，
  再单独评估——它们的产出是否需要子对话本地上下文（diff、分支）决定能不能转交。
- **父对话一次转交太多**：现在没有「每个父对话最多排几个转交请求」的上限。需要时在 `forwards` 队列上按父对话计数，
  返回「父对话排着的转交请求太多」这种明确错误。
- **要不要在界面上显示「这个角色禁止子对话执行」**：现在只在角色编辑页的勾选框里；角色卡片、选择器里的角标要加的时候再看用户是否分不清。
