# ADR 0075：后台作业注册表（能跑一阵子的事一处看全、能取消）

状态：已接受 · 2026-11-23

## 背景

「可统一能力盘点」第 2 项：编译、安装、下载、扫描、重建这些能跑一阵子的事，每类各管各的状态和显示——UE 编译和安装挂在 globalThis 上防插件热升级丢表，模型下载几个设置页各自轮询，文件索引自己推。用户不知道后台在跑什么，也没有地方统一取消。用户 2026-11-23 让 Claude 定汇总放哪：定为侧栏底部的状态条，点开是列表。

## 决策

1. `shared/jobs/types.ts`：作业的 zod 契约（来源、项目、种类、标题、状态、当前步骤、进度、能否取消、日志行数）。
2. `server/jobs/registry.ts`（开放给插件）：`startJob({ source, projectId?, kind, title, cancel? })` 返回句柄（`log` / `progress` / `end` / `canceled`）。表在面板进程里，插件升级重新加载不丢；状态变化停手 200 毫秒合并成一次整份推送（页面事件 `bg-jobs`）；日志在内存里留最近 4000 行，按行号增量取（`/api/bg-jobs/:id/log?from=`）。结束了的留 30 条。
3. 网页：`useBgJobs()`；侧栏底部有作业在跑时出现一行（一条显示标题和进度，几条显示条数），点开「后台任务」弹窗：左边列表，右边日志和取消、清除已结束的。
4. 第一期接入：UE 插件的编译和安装（`ue/server/jobs.ts` 把作业镜像到面板表，UE 页自己的作业条照旧）。模型下载、CLI 安装、文件索引等后面逐个接。

候选方案：

- **插件 SDK 加 `ctx.jobs`**：暂不做。开放模块已经能让插件直接用同一份，不用为此升插件接口版本。
- **作业日志写文件**：暂不做。现在的作业日志都不大，内存里留尾巴就够；以后有长日志的作业再加文件路径字段。

## 影响

- 新的长任务一律 `startJob` 登记，不另做一份作业表和进度轮询（AGENTS.md「先找能共用的」）。
- UE 插件依赖开放模块 `server/jobs/registry.ts`，旧面板上加载不到时不登记，UE 页照常。
