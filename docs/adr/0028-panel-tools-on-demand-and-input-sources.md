# ADR 0028：多 Agent 协作省 token 第二批：工具按需、子任务瘦身、输入构成

状态：已接受 · 2026-10-29

## 背景

[ADR 0027](./0027-resumed-session-prompt-delta.md) 只解决了续接会话重发规则的问题。同一轮审计还找出另外几处，用户 2026-10-29 要求全部处理：

- 面板工具每次请求都整份带上：主理在真实 Pi 下 28 个工具，说明约 17.8k 字。
- 角色设定和面板规则重复：主理角色里已有处理顺序和分诊表，面板每轮还发「这条消息怎么处理」「分派前只收集到模块为止」。子对话的「通用约束」已有提问和收尾建议的规则，面板又发一遍。
- 子任务开头带着整套授权、收尾和合并规则，读了用不上。父对话允许推送时，子任务还会读到「做完就推送并合并主干」。
- 几个子任务一起交回时，每个的结果都整份进父对话。
- 保活进程里的下一条消息原样交给 CLI，计划提醒、子对话收件箱这些状态段落带不进去（ADR 0027 的开放问题）。
- CLI 自己压缩上下文却不报 `compacted` 时，已发规则的记录不作废（ADR 0027 的风险）。
- 看不出一轮的 token 花在规则、消息还是工具输出上。

## 决策

1. **不常用的面板工具收进 `more_tools`**（`shared/panel-tools.ts`）。
   - `DEFERRED_TOOLS` 共 12 个：教训、就地改动、同级对话、停子任务、后台命令查询和停止、关运行、P4 分单、软件操作。这一轮可用的里有 2 个以上时才收起来。
   - `more_tools` 的说明列出这些工具的名字和一句用途。只写 name 时返回用法和参数，带 arguments 时按名字执行。按原名直接调用照样能用，因为提示词里点名的工具不能失效。
   - `get_status`、`send_message`、`read_messages` 不收：Pi 桥接靠它们核对工具清单。
   - 界面把经 `more_tools` 的调用按真正的工具显示。只查用法的那一次显示「查看工具用法」。
2. **角色已经写了的规则，面板不再重复**。
   - 主理（`builtin:orchestrator`）不再发两节分派规则，只留一行面板会强制的「同一段话不能交给两个子对话」。
   - 子对话按角色正文判断：角色和它引入的角色里有「子对话停下来等用户时必须先提问」「子对话的收尾建议也交给用户选」，面板就不发对应段落，只补随项目变化的「子对话的完成标准」。用户删掉了这两节时，面板照旧补上。
3. **子任务开头瘦身**。
   - 派出的子任务（不含「版本控制」）把授权段换成一行 `HELPER_POLICY`，也不带编译和合并流程。UE 项目照旧带「不要编译」。
   - 要求里加了一句：交回时可能只带开头，所以结论写在最前面。
4. **子任务结果分层交回**。
   - 一批交回的结果按 `HELPER_BATCH_CHARS`（12,000）平分，每个至少 `HELPER_SHARE_MIN`（1,500）。超出的只带开头，并写明全文存在哪个文件（`saveHandoff`）。
   - 评审类不截：结论表要完整。
5. **保活进程也同步状态**。
   - runner 在保活进程里收到用户的下一条消息时，调 `AgentCall.nextPrompt`。它按当前状态重拼对话提示，和这个进程已经收到的段落比（占位会话 `LIVE`），只发消息和变了的段落。
   - `/` 开头的原生命令照旧原样交给 CLI。
   - 这一轮结束时，把进程收到的段落记到真实会话 id 名下。
6. **静默压缩也作废记录**。用量里的上下文从 2 万以上一下子降到不足一半（`compactedSilently`），按压缩处理，调 `forgetPromptSent`。
7. **一轮的输入构成**（`TaskTurn.sources`）。按来源记字数：
   - 面板规则（含每轮末尾的语言提醒）
   - 消息
   - 子任务和计划交回的结果
   - 工具输出（这一轮回复里工具输出的总长）
   - 新会话开头的角色设定和教训（runner 经 `onInput` 报回）

   对话轮次下面画一条按比例分色的细条，悬停看各块的数字。记的是字数，不是 token。工具定义的长度不在里面。

## 实测

真实 Pi 加记录请求的假 OpenAI 接口，数字是字符数：

| 请求               | 改前（ADR 0027 之后） | 改后                        |
| ------------------ | --------------------- | --------------------------- |
| 主理的工具说明     | 约 17,750（28 个）    | 14,495（19 个）             |
| 主理第一条用户消息 | 约 8,600              | 8,086                       |
| 子对话第一条消息   | 7,888                 | 7,365                       |
| 保活进程里的下一条 | 原样（不带状态）      | 约 100（消息 + 变了的段落） |

## 没选的方案

- **工具说明全部按需取**：模型要先知道有哪些工具才会去取，常用的收起来每轮要多一次往返。
- **子任务结果交回时让模型先摘要**：要多跑一轮模型，还可能丢掉结论。改成在要求里让子任务把结论写在前面。
- **输入构成换算成 token**：各 CLI 的分词不同，面板拿不到逐段的 token 数。用字数看比例足够判断钱花在哪。

## 风险与代价

- 模型可能不知道收起来的工具怎么用：说明里列了名字和一句用途，也可以按名字直接调，提示词点名的照样能用。
- 子任务结果被截时，父对话要的细节得去读文件，多一次工具调用。评审类不截。
- 按正文判断角色有没有写某条规则，用户改了标题措辞时面板会重复发一遍。宁可重复，不能漏掉。
