# ADR 0061：内置副本改过也直接覆盖，不再留历史快照

状态：已接受（2026-11-12 用户在决策卡上选「直接覆盖不备份」） · 2026-11-12

- 部分替代：[ADR 0015](./0015-builtin-roles-follow-definition.md) 第 2 条（覆盖前备份）和第 4 条里「用户改过的工作流不动」「没指纹的按 LEGACY_WORKFLOWS 比」
- 起因：重构文档第 6 条，内置目录下的 legacy 快照文件约 3300 行历史快照只用来认出「本机副本没改过」

## 决策

1. **内置角色**照旧每次启动按定义同步；用户改过的设定直接覆盖，**不再备份**。
2. **内置工作流**按「定义有没有更新」决定：副本的 `builtinHash` 记着上次写进去的是哪一版，和当前定义一样就不动（用户之后改的留着）；不一样（定义更新了，或者是没记过指纹的老副本）就覆盖成新版，坐标保留，不备份。
3. **删除类的清理**（合并掉的工作流、关掉插件时的插件工作流）只删「记过指纹且内容还是那一版」的副本；没记过指纹的老副本认不出改没改过，留着不删。合并掉的角色没人用了就删（服务端删前照旧备份进 `config/backup/`，那是删除，不是覆盖）。
4. 删掉 legacy、legacy-workflows、legacy-workflows-0044 三个快照文件，以及只为认旧版本存在的 `matchesLegacy`、`migrateGeneralWorkflow`。`MERGED_AGENTS` 挪到 `shared/builtin/merged.ts`。

## 放弃的方案

- **改过的先备份再覆盖**：用户选了不备份；备份要保留快照来认「改过」，快照每改一次定义就要登记一版，漏登记就出错。
- **每次启动都覆盖工作流**：那样用户在新版上做的修改下次启动就没了，等于工作流不能改。只在定义更新时覆盖。

## 后果

- 改内置角色、工作流定义时不用再登记旧版本。
- 想长期保留自己版本的用户要复制一份（复制出来的不带内置来源）。
