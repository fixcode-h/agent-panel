# ADR 0065：日报改成紧凑排版，补上状态、验证、影响、遗留和协助

状态：已接受（2026-11-14 用户看过优化方案后定，已实施） · 2026-11-14

- 影响范围：`shared/summary.ts`（分项字段、提示词、材料）、`shared/summary/render.ts`（拼报告、纯文本）、`shared/builtin/agents.ts`（「每日工作总结」写法和自己跑时的输出格式）、`web/src/components/summary/EntryList.tsx`、`web/src/components/summary/ReportView.tsx`、`web/src/index.css`（`.chat-md-report`）、`web/src/lib/demo-summary.ts`
- 取代：ADR 0056 决策第 1 条的模板（三级标题 + 加粗小标题 + 每块前后空行）；ADR 0043 第 4 条里「测试过没过不写」改成「验证只写一句结论」。0056 的分点、关键代码只收真实改动，0043 的单子链接、再次生成、不写版本管理操作、去 AI 腔照旧

## 背景

用户 2026-11-14 说工作总结不够完善：空行太多；日报的目的是让别人看到今天做了什么、这么做有没有问题。优化方案（项目文件 `agent-panel/工作总结日报优化-2026-11-14.md`）对照常规日报列了缺项，用户确认后只改了一处：「明天计划」只起一个标题，内容自己填。

## 事实核对

| 位置               | 改之前                                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| `renderReport`     | 一个需求、一个修好的问题、一个没修好的问题拼出 39 行，16 行是空行；问题条目是三级标题 + 三个加粗小标题 + 三组编号，两套序号嵌在一起 |
| `CARD_FIELDS_SKIP` | 总结卡的「验证」「要你处理」不交给 CLI                                                                                              |
| `SummaryEntry`     | 没有状态、现象、验证、影响、遗留、协助；需求做没做完看不出来                                                                        |
| 报告页「复制」     | 复制 Markdown 原文，贴进企业微信 / 飞书时 `###`、`**` 原样出来                                                                      |

## 决策

1. **模板**（`shared/summary/render.ts` 的 `renderReportBody`）：标题 → 一句概要（面板按分项直接数，不让 CLI 写）→ 需求 → 问题 → 遗留与风险 → 明天计划（周报叫下周计划，只有标题）→ 需要协助 → 附：关键代码。只在节和节之间空一行；条目是 `1. 标题（状态 · 单子）`，下面缩进 `- 现象：`、`- 原因：`、`- 修复：`、`- 验证：`、`- 影响：`；一个标签下三点以内连成一句，多了换下一级编号。需求先做完的后进行中的，问题先修好的后没修好的。
2. **关键代码挪到附录**：正文写「修复（代码见附 N）」，读正文的人不用翻过代码；代码照旧展开、不折叠。
3. **分项加字段**：`status`（需求 done / doing）、`symptom`、`verify`、`impact`、`remaining`、`help`，都是每行一点、默认空。老报告不迁移：字段有默认值，正文是生成时拼好的，原样显示，再次生成按新模板出一份新的。
4. **验证只写一句结论**：怎么验证的、结果如何，没验证写没验证和原因；「跑了哪些命令和检查」这类流水账照旧不写。材料里交出总结卡的「验证」「要你处理」，只去掉改动清单。
5. **复制默认纯文本**（`reportPlainText`）：去掉 `#`、加粗、反引号，二级标题换成「一、」「二、」，代码去围栏缩进四格；旁边一个「复制 Markdown」按钮复制原文。
6. **预览收紧**：报告预览加 `.chat-md-report`（间距收到七成，字号不变）。

候选方案：

- **完成和进行中的需求分成两节**：放弃。节越多空行越多，状态写在标题括号里一眼也能看到；教训草稿的正文解析也只认「## 需求」。
- **明天计划由 CLI 从遗留和进行中的事推出来**：放弃。用户要求只留标题自己填。
- **复制做成下拉菜单**：放弃。两种复制都常用，一个主按钮 + 一个图标按钮少点一次。

## 风险与代价

- CLI 偶尔会把验证写成流水账：角色规则约束，报告正文能直接编辑。
- 进行中的需求只认 `doing`，CLI 写成别的一律按做完了：宁可状态不准，也不让条目丢掉。
