# ADR 0048：主理改名协调器，先查模块文档再派单，规则每条只留一个出处

状态：已接受（2026-11-03 用户确认设计稿 `docs/openspec/changes/coordinator-docs-first/design.md`，按期实施，见「分期」） · 2026-11-03

- 影响范围：`shared/builtin/agents.ts`（协调器、执行、通用约束、排查分析）、`shared/engine.ts`（父对话提示词、`send_to_conversation` 的返回）、`shared/push-auth.ts`、`server/exec/real-turn.ts`、`server/tasks/drive.ts`、`scripts/rules-check.mjs`
- 取代：[0023](./0023-role-layers-and-triage.md) 里「主理」的叫法和主理挂载的「方案设计（就地用）」「评审（大方案复核）」

## 背景

用户 2026-11-03 要求：主理改名协调器；协调器分析用户消息时先从模块文档里找对应的模块，没有模块文档的先派子任务建好再开子对话；模块删了文档也删；模块文档要简要；评估角色设计、流程是否贯通、规则分散多处是否偏移，去掉繁杂步骤。设计稿里核对出同一条规则最多写了 9 处，已经有三处互相矛盾（整体验证由谁做、子 Agent 失败谁接手、模块文档谁能写）。

## 决策

1. **改名**：内置 `orchestrator` 的名字改成「协调器」（key 不变，`syncCore` 启动时同步，旧数据不迁移）；`analyzer` 改名「排查分析」，和「方案设计」（`analyst`）分开。
2. **先分析、再查文档**：协调器先判断这条消息要不要定位；要的话先从原话提炼关键词，再读 `MODULE-MAP.md` 和对应模块的 README，对不上就看一、二级目录，不全仓搜。不建文件索引、不加查询工具、不做 `/initDocs`。
3. **模块文档按需建**：模块第一次要交给子对话、还没有文档时，先由「文档」分析这个模块写简要文档，再开子对话（面板保证，设计稿 §5.2，后续期实施）。
4. **三层分工、规则单一出处**：面板管必须照做的（工具返回、门禁、自动步骤），角色设定管职责和边界，技能管做法。`scripts/rules-check.mjs` 第 20 条：内置角色设定、面板提示词、方法类技能之间，30 字以上的同一句不许出现在两个文件里。
5. **协调器设定精简**：删掉「交回子对话之后怎么确认它接到了」（`send_to_conversation` 送到后返回自带 `SENT_NOTE`）、`tier: low` 一条（对话里派子任务不写 tier 时本来就按被派角色自己的档位）、和通用约束重复的推送 / 完成条件 / Bug 记录口径；「方案设计」只能派出，去掉「评审」复核大方案（只保留给用户确认一道）。
6. **三处矛盾**：合回后的整体验证只有一种说法（面板跑「合并后由父对话跑」的步骤，用户点名时派「测试验收」）；子 Agent 失败先交回原来那个重做，父对话不自己改代码。

## 没选的方案

- **SQL 数据库存模块文档**：用户直接用 CLI 打开项目时看不到，不能 git diff、合并，换机器就没了。
- **结构索引 + `find_module` 工具、`/initDocs`**：用户 2026-11-03 定暂不做；大项目里没用到的模块不花钱，模块第一次用到时再建文档。

## 实施记录

- **先建文档由面板拦下，而不是面板自己等**：模块分析要几分钟，CLI 的一次工具调用一分钟就超时，没法在 `create_conversation` 里同步等。改成有模块还没文档时拒绝建子对话，返回写清先并行派「文档」（`params: {"task": "模块分析"}`），分析结果会自动推回协调器的这一轮，它再用同样的参数建；写 `skip_docs` 理由可放行。都有文档时面板把路径附进派单。
- **用户项目里面板不改写 `MODULE-MAP.md`**（真实 API 实测后改的）：起初每轮结束时面板重新生成地图，结果父对话目录里留下没人提交的改动（会挡住子对话合回），几个子对话各自重新生成同一张表也会冲突。改成协调器的提示词里每轮带「已有模块文档」一节，从模块 README 的元数据现读；模块 README 是唯一来源，地图只在仓库自带生成脚本时生成。
- **文件行数上限按功能拆**（用户 2026-11-03 纠正，见 `docs/lessons/file-caps.md`）：`shared/children/lookup.ts` 从 `engine.ts` 拆出，`server/orch-fields.ts`、`server/docs-first-tool.ts` 从 `orch-mcp.ts` 拆出。
