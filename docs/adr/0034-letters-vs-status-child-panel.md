# ADR 0034：父子之间分清「信」和「状态」，子对话只在输入框上方的面板里看

状态：已接受 · 2026-10-30

## 背景

用户 2026-10-30 发来两张截图：父对话里同一件事连着三四行「接收消息 · 汇报」（AI 自己 `message_parent` 一条、面板一轮结束又报一条、再加一条「已中断：父对话结束时一起结束」），右栏「协作」卡又把同一批消息按时间列了一遍，「父… → 401…」看不出方向。面板先出了一份方案（父子对话消息方案，三张草图），用户确认时改了两处（原话）：

> 按照这个方案，但是侧边栏的子对话去掉，调整输入框上方的子对话显示，改成链接中的草稿2，当然需要优化下，看看怎么结合两个面板合并在一起，然后剩下的按照你的设计方法来

即：右栏（会话栏）不再列子对话；方案里给右栏画的「子对话」卡（草图二：按子对话列状态、展开才看往来的信）放到输入框上方，和原来那里的子对话列表合成一个面板。

## 事实核对

| 位置                                                  | 改动前                                                                                                                |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `server/tasks/child-messages.ts` `noteParent`         | 随父对话停下（`stopReason === 'parent'`）的子对话上报「已中断」：不叫醒父对话，但仍写进父对话消息流和收件箱           |
| `server/tasks/peer.ts` `messageParent`                | 子对话 AI 不带 `question` 的 `message_parent` 马上写进父对话并进收件箱；一轮结束 `reportChild` 再发一条，同一件事两封 |
| `server/tasks/child-messages.ts` `trackUserToChild`   | 用户直接对子对话说话：给父对话发一条【用户直接交代子对话】                                                            |
| `Task.inbox`                                          | 同一个子对话没读的汇报一封封堆着                                                                                      |
| `web/src/components/tasks/PeerMessage.tsx` `PeerLine` | 行首写「接收消息 / 发送消息」，对方名字在行尾「来自 X（标题）」，截断就看不出方向                                     |
| `web/src/components/session/CollabCard.tsx`           | 会话栏「协作」卡：从两边消息拼出的时间线（`shared/collab-timeline.ts`），和对话流重复                                 |
| `web/src/components/session/StatusCard.tsx`           | 会话栏「状态」卡里逐个列在等的子对话，和输入框上方的子对话栏重复                                                      |
| `web/src/components/tasks/TaskView.tsx` `ChildrenBar` | 输入框上方子对话一行 + 浮层列表（运行中 / 全部），只有状态，看不到每个子对话和父对话之间的往来                        |

## 决策

**对方看到后不需要做任何事的，就不是信，不发。** 状态（执行中、等你回答、未完成、已中断、已完成、失败）只有一个家：输入框上方的子对话面板和父计划那一步，就地更新；信（交代任务、回答、提问、汇报、收尾、全局规则）才进对话流、进收件箱、叫醒对方。

### 一、服务端降噪

| 子对话发生了什么                    | 改成                                                                                                               |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 随父对话一起停下（已中断）          | 不发。`noteParent` 只把计划那一步退回进行中并落盘，不写对话流、不进收件箱；继续时由面板连带拉起（ADR 0032）        |
| AI 自己 `message_parent` 的阶段汇报 | 不单独发，记在 `Task.pendingReport`；这一轮 `reportChild` 发状态时并进去当「最近的结果」，发出后清空。一轮只交一封 |
| 提问、收尾建议、`wait_fix` 报错     | 照旧马上发（要父对话动手）                                                                                         |
| 用户直接在子对话里交代              | 不发消息。父计划那一步挂等待并写「你直接交代了新要求：…」，原话记在 `Task.userDirect`，下一封汇报里带上            |
| 同一子对话没读的汇报又来一封        | 收件箱里替换掉旧的（`inbox[].report`），对话流里旧那行 `peer.superseded`，界面变淡写「已被新的汇报取代」           |

`message_parent` 的工具说明和子对话提示词同步改成：要父对话决定或协调时 `question: true`，阶段进展不用单独发。

### 二、对话流里的信

- 每行开头固定是「方向箭头 + 对方」：收到写 `← 子对话标题`，发出写 `→ 子对话标题`，然后是类型小标签和内容标题。「接收消息 / 发送消息」几个字去掉。
- 交代任务那行原地带回执：子对话后来回了信就写「已完成 · 看汇报 ↓」（失败、提问各有说法），点了滚到那一封；还没回就按子对话现在的状态写「对方在处理」或「已送达」。
- 回执不另记数据，从父对话自己的消息里算（`web/src/lib/tasks.ts` 的 `childLetters` / `replyOf`），旧对话照样有。

### 三、子对话只在输入框上方的面板里看

- 会话栏去掉「协作」卡；「状态」卡那句话仍把子对话算进去，但不再逐个列子对话。
- 输入框上方的子对话一行加「n 封未读」（父对话收件箱里还没读到的）。点开的面板就是草图二：头上「子对话 n 个 · m 封未读」，按子对话列状态（有未读的写「汇报待父对话处理」），每行右边的展开按钮列它和父对话之间的信（只有信，没有状态），有未读的默认展开；原来浮层的「运行中 / 全部」、分组、未提交改动和「继续」都保留。
- 子对话这一侧在输入框上方多一行「父对话 · 交代任务 · 标题」，点开看任务原文和最新回答（草图里的「父对话」卡）。
- 含面板推进、来源标签的完整时间线挪进对话菜单「父子往来记录」，默认不出现。

### 没选的方案

- **按草图把「子对话」卡放在右栏**：用户明确要求右栏不放子对话；输入框上方本来就有子对话栏，两处列同一批子对话正是这次要去掉的重复。
- **给每封信落一个共享 id 和送达状态字段**：发件方是工具调用、收件方是消息，加 id 要改两边的记录格式和旧数据迁移。回执能从已有数据算出来（交代之后的第一封回信 + 子对话现在的状态），先这样做。
- **几个子对话同时有结果时服务端合成一封**：收件箱本来就在父对话下一轮开始时一起交给它；对话流里合成一行留作后续（见开放问题）。

## 与现有实现的关系

- 延续 [0005](./0005-conversation-states.md)：上报仍只有 `reportChild` 一个出口，这次是把 AI 自己的汇报也收进这个出口。
- 延续 [0008](./0008-peer-messages.md)：收件方仍带 `peer`、两边仍共用 `PeerLine`；行的写法从「发送 / 接收消息」改成「箭头 + 对方」。
- 延续 [0032](./0032-conversations-keep-going.md) 的「只发必要消息」：再收掉连带中断、阶段汇报、用户直接交代三种。

## 运行时

1. 子对话 AI 调 `message_parent`（不带 `question`）→ `pendingReport` 累加，工具结果说明会在一轮结束一起交。
2. 一轮结束 → `reportChild` 拼【子对话状态】，结果取 `pendingReport`（没有才取最后一条回复）→ `noteParent`；没读的同一子对话旧汇报被替换。
3. 父对话页把 `task.messages` 算成 `childLetters`、`task.inbox` 数成未读，交给 `PeerMailCtx`；信行、子对话面板读同一份。

## 分期

一次做完。出口：类型检查、lint、单测（`server/tasks/child-messages.test.ts` 改写连带中断、新增汇报替换）、e2e `04`/`05`/`15`、界面检查 `02-task`（新增子对话面板展开往来、对话菜单「父子往来记录」）。

## 风险与代价

- 阶段汇报要等这一轮结束才到父对话：子对话一轮跑很久时父对话中途看不到进展。认下；需要父对话动手的事走 `question: true`，马上到。
- 子对话一直处在「等结果」这类不发信的状态时，`pendingReport` 留到下一封才交出。
- 回执从现有数据推算：同一个子对话交代了两次、第一封回信在第二次交代之后到，第一行也会显示成「已回复」。

## 开放问题

- 父对话忙时几个子对话同时交回，对话流里合成一行「3 个子对话有结果」：倾向在 `Messages.tsx` 把相邻的收到的汇报合成一组；先保持一封一行。
