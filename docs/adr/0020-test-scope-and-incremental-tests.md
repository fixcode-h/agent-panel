# ADR 0020：测试步骤按范围分档，子对话只跑增量，全量交给父对话合并后跑

状态：已接受 · 2026-10-28

## 背景

ADR 0018 把「很吃资源的步骤」（e2e）挪到了合并后由父对话跑，但普通检查仍然由每个子对话自己整套跑一遍。
测试步骤越加越多之后，一个只改了 6 个文件、只动了一个页面的子对话，实际耗时是：单元测试全量跑了 3 次
（2m42.9s / 2m17.7s / 1m34.4s，后两次都是个别计时用例抖动后重跑全量）、界面检查全量跑了 3 次
（2m31.8s / 2m34.6s / 3m24.1s），加上单文件复跑和构建，测试时间约 13 分钟。

用户 2026-10-28 的要求（原话）：

> 现在测试是真多，可以增量测试的就增量吧，比如有些可以分片测试的那么就只测这个对话修改的部分，不要全部测试，
> 能不全量测试的可以增量测试的就增量测试，然后全测试可以在完成子对话后在父对话做全量测试，有问题再启动子对话修复

现状（改动前）：

- `TestStepFields` 有 `appliesTo`（适用改动 glob）、`quick`（小改动也跑）、`merge`（合并时编译）、
  `runInParent`（禁止子对话执行）。`runInParent` 表达的是「谁来跑」，和「跑多大范围」是两件事，但实际需求里它们总是一起出现。
- `appliesTo` 只写进提示词让 Agent 自己判断，**执行流程里没有按改动清单自动跳过的地方**。
- 没有任何「改动 → 具体测试文件 / 界面检查分片」的定位工具：Agent 只能二选一——整条命令跑全量，或者不看命令原文自己拼。
- 界面检查（`scripts/ui-check.mjs`）已经支持按分片文件名前缀筛选，但没人告诉子对话该筛哪几个。

## 事实核对

| 位置                                                        | 现状                                                                                           |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `shared/schema.ts` `TestStepFields`                         | 步骤字段的唯一来源；`scope` 新增在这里，`runInParent` 由它替代                                 |
| `shared/test-steps.ts` `parentRunSteps` / `parentRunRoleOf` | 「谁替子对话跑」的唯一筛选和角色判断，改成读 `scope === 'parent'`                              |
| `shared/test-steps.ts` `stepApplies`                        | 匹配判定的唯一实现；改成 `always` 直接为真、`changed` 才看 globs、`parent` 在父对话侧为真      |
| `shared/test-steps.ts` `verifyBlock` / `testStepsBlock`     | 提示词的唯一出口；新增 `CHILD_INCREMENTAL_RULE` 和 `FLAKY_TEST_RULE`                           |
| `server/parent-tests.ts` `createParentTests`                | 合并后排队跑 `parent` 步骤的队列，这次原样复用（结果和耗时回传、失败退回子对话）               |
| `scripts/ui-check.mjs`                                      | 已经支持按分片前缀筛选（`node scripts/ui-check.mjs 09-summary`），产物过期会直接失败           |
| `scripts/ui/` 12 个分片                                     | 每个分片覆盖一页或一类组件，但「哪个源码属于哪个分片」只写在各自文件头的注释里，没有可读的映射 |

## 决策

**测试步骤新增 `scope: 'always' | 'changed' | 'parent'`，合并原来的 `runInParent`；新增改动 → 测试的定位工具；
提示词按范围写死「子对话只跑增量、全量由父对话合并后跑」。**

### 1. 三档范围

| scope     | 语义                                                       | 典型步骤                    |
| --------- | ---------------------------------------------------------- | --------------------------- |
| `always`  | 每次改动都跑，不看 `appliesTo`                             | 类型检查、lint              |
| `changed` | 改动清单命中 `appliesTo` 才跑；没写 `appliesTo` 表示总是跑 | 相关单测、编译、构建        |
| `parent`  | 子对话不跑，合并后由父对话在全量里跑                       | 全量单测、全量界面检查、e2e |

- `parent` **就是原来的 `runInParent`**，不保留两个字段：「谁跑」和「跑多大范围」在实际使用里是同一件事，分成两个字段只会有
  「勾了但范围是 changed」这种没有意义的组合。
- 迁移（`shared/schema.ts` 的 `migrateTestStep`，在 `TestStep` / `TestStepFields` 的 `preprocess` 上）：
  `runInParent: true` → `parent`；**命令明显是跑全量的（`test:unit` / `test:e2e` / `ui-check` / playwright 这类）→ `parent`，
  这条判断放在 `appliesTo` 之前**——老默认步骤的形态就是「全量命令 + 适用改动」，先按 globs 判成 `changed`
  会让存量项目照旧每个子对话跑一遍全量，这次优化对老项目等于没生效；其余写了 `appliesTo` 的 → `changed`；
  `merge` 步骤 → `changed`；剩下的是 `always`。
  appliesTo 为空的老步骤仍然是「总是跑」——升级不会让原来会跑的步骤变成从不跑。
  这是有意的行为变化：存量项目里的全量单测 / 全量界面检查 / e2e 升级后由父对话合并后跑，设置页里可以改回 `changed`。
- `always` 的步骤不再配 `appliesTo`：两处规则同时写会打架（一处说每次都跑、一处说改了某类文件才跑）。默认步骤里
  类型检查和 lint 直接标 `always`、清空 globs。
- `quick`（小改动也跑）保留：它决定「小改动时跑哪几条」，`scope` 决定「谁跑、跑多大」，两者正交。

### 2. 增量定位：`scripts/changed-tests.mjs`

- 输入是改动清单，输出四类：要跑的单测文件、要跑的界面检查分片、**映射不出来的改动**、不涉及测试的改动。
- 定位规则（`scripts/lib/changed-tests.mjs`，纯逻辑）：同名测试 → 反向 import（哪些测试 import 了它）→ 同目录回退
  （目录里的测试超过 6 个就不回退，直接报映射不出来——公共目录全跑等于全量）→ 界面检查分片（`scripts/ui/covers.mjs` 前缀表）。
- **映射不出来必须说出来**：「这批改动没有对应的增量测试，跑全量或交给父对话」，不静默跳过、也不为了保险整套跑。
- 界面检查脚本自己改动：改哪个分片跑哪个，改 `harness.mjs` / `covers.mjs` / `ui-check.mjs` 跑全部分片。
- 分片命令用完整分片名筛选（`09-summary`），不写 `09`：后者会同时跑 09-hint / 09-plans / 09-summary。

### 3. 提示词口径（关键）

- 子对话（`parentRun = 'child'`）：注入 `CHILD_INCREMENTAL_RULE`——先用改动清单定位、只跑 `always` + 命中的 `changed`、
  **不跑全量**；`parent` 的步骤不跑原命令，但单测和界面检查要用定位到的增量命令覆盖命中的单测文件 / 界面分片
  （否则子对话会一条测试都不跑）、e2e 没有增量替代直接交给父对话；映射不出来就交给父对话。
  分片示例写完整分片名（`09-summary`），写 `09` 会多跑 09-hint / 09-plans。
- 所有对话：注入 `FLAKY_TEST_RULE`——计时类用例偶发失败时**单跑失败的那个文件最多 3 次**，不重跑整套。
- 父对话：`parent` 步骤照常由它跑全量（复用 `server/parent-tests.ts` 队列）；子对话合并后由面板自动跑、结果回传。

### 4. 数据与兼容

- `runInParent` 不保留，老数据在解析时一次性换算；设置页显示 / 修改 `scope`（三选一）。
- 迁移时「命令是全量」的判断是启发式（`test:unit` 这类），可能把某个项目里很快的单测也标成 `parent`。
  代价是那条步骤从「子对话自己跑」变成「合并后父对话跑」，不会漏跑；用户可以在设置页改回来。
- AI 生成测试步骤（`shared/assist.ts`）的字段说明和示例同步加 `scope`。

## 取舍

- **不把定位接进执行流程**：面板不替 Agent 跑命令，`appliesTo` 的比对原本就写在提示词里由 Agent 执行；
  这次也只提供工具 + 提示词口径，没有在服务端按清单删步骤。原因：步骤命令是任意 shell，服务端拆不开
  「`npm run test:unit` → 跑哪几个文件」，只能靠项目自己的脚本（本项目就是 `scripts/changed-tests.mjs`）。
- **全量放合并后**：合并前子对话看到的测试结果少了，失败要靠父对话回传。换来的是每个子对话省下几分钟、
  多个子对话同时收尾时不再抢同一台机器。这是用户明确要的方向。
- **没有覆盖表就不猜**：界面分片和前端的依赖关系没法从源码可靠推断，`scripts/ui/covers.mjs` 是一张手写表；
  表里没有的界面改动一律报「跑全量」。宁可多跑一次全量，也不因为漏了一条映射少跑一个会坏的页面。
- **没有引入 per-file 的测试清单字段**：定位规则放在脚本里，项目可以换 / 扩展；写进 `TestStep` 会让步骤模型变成
  「每个项目一套测试基础设施」，和现在「一条步骤一个命令」的模型冲突。

## 后果

- 子对话的测试范围从「全部步骤」降到「`always` + 命中的 `changed`；`parent` 不跑」。
- 父对话合并后跑的步骤不变（`parentRunSteps` 仍然只筛 `parent`、非 `merge`、启用的），排队和失败回传链路没有改动。
- 新增 `docs/agent-test-steps.md`「按范围分档」「改动 → 增量测试」两节；`docs/modules/{shared,web}` 的测试步骤说明同步更新。
- 回归用例：`shared/test-steps.test.ts`（scope 三档、迁移、子对话提示词）、`scripts/lib/changed-tests.test.mjs`（定位规则）。
