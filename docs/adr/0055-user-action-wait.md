# ADR 0055：等你操作：要用户去做的事不走提问

状态：已接受（2026-11-05 用户看过设计稿和示例后定，已实施） · 2026-11-05

- 设计稿：[docs/openspec/changes/user-action-wait/design.md](../openspec/changes/user-action-wait/design.md)

## 背景

提问被拿来做所有「要用户参与」的事：协调器问用户「去跑一次 PIE 把日志发回来」，选项其实是操作，不是决定。点完选项提问就结束了，可事情才刚开始；之后贴回来的日志只是一条普通消息，面板不知道它回答的是哪件事，对话看起来像结束了或卡住了。

## 决策

- **边界**：提问只用来让用户拿主意（选做法、补他脑子里的信息、授权不可逆的操作）。要用户离开对话去做一件事、做完交回结果（在本机或设备上操作、复现一次、登录授权、给只在他手里的文件或日志）用新的面板工具 `request_user_action`。工具说明、`ask_user` 说明、子对话提示词、协调器提示词、`end_turn` 说明一起改口径。
- **不占进程**：发起后这一轮照常结束（和交出后台命令一样），对话状态归到「等你处理」（`ConvFacts.action`），结束前钩子、收尾判定按 `userWaiting` 放行。计划里正在做的那一步挂上 `PlanWait.kind = 'user'`，结束时按 `settleWait` 收口；做不了算等的结果没成功。
- **输入框就是交回框**：面板贴在发起它的对话的输入框上方（提问面板的位置和底色），能收起成一行转圈。输入框挂着可以点掉的「交回给」标签，发送就算交回：消息原文照常显示，交给 CLI 的那份前面加一句【面板】说明。面板上只留「完成了」「做不了…」「跳过」；这三种由面板把结果作为一条 `panel: 'action'` 消息推回去开新一轮。
- **只看用户按了什么**：不看贴的内容像不像日志（ADR 0041、0049 的不按文字判断状态）。
- **子对话发起的直接交给用户**，不看「提问」开关，协调器不代答。父对话不另出卡片，子对话那一行写「等你去操作」，后面一个「去操作」在右栏打开它（用户在示例上批注定的）；子对话栏不加胶囊。
- **一次只挂一件**，`fallback` 必填，没有超时，等了多久写在面板和会话栏状态里。用户停止对话时撤掉。
- **提问卡上的出口**：对话里的提问多一个「这需要我去操作」，按拒绝结束提问，告诉 Agent 改用 `request_user_action`。面板不替用户判断。

## 不做

- Bug 对话（`/bug`）要用户复现、交验证结果仍走诊断报告的评审弹窗，`request_user_action` 在这里直接拒绝。
- 子任务、工作流节点、Chat 页没有这个工具：缺东西写进结果交回，由派它的对话发起。
- 自动盯日志文件、一次交回给多个对话：留到以后。

## 后果

- 新增面板工具 `request_user_action`（`server/user-action-tool.ts`），任务数据多了 `userActions`（`shared/user-action.ts`），发消息接口多了可选的 `userAction`，新增 `POST /tasks/:id/user-action/:aid`。
- 计划相关的结构从 `shared/schema.ts` 拆到 `shared/plan-schema.ts`（行数上限），对外照旧从 schema.ts 引。
