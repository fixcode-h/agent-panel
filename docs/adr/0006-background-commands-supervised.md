# ADR 0006：后台命令由对话监管到真正结束

状态：已接受 · 2026-10-24

## 背景

用户 2026-10-24 反馈了三件连在一起的事：

- 子对话用 `run_background` 装 Playwright 浏览器，对话里那一行显示「运行命令 … 完成 0.09s」，像是跑完了；对话说「本轮先停在这里」就结束了。用户要的是：放到后台的命令在界面上一直转圈，显示真实用时和结果，对话等结果回来，不能「交出去就算完成」。
- 下载明明完成了，对话却一直没收到结果，模型自己在前台 `sleep 15` 轮询。
- 所有后台命令都要这样；跑得久的要主动让对话检查，避免命令卡死没人管。

## 事实核对

| 位置（改动前）                                | 现状                                                                                                                                      |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `server/exec/parsers.ts` `genericTool`        | 只认裸名字的面板工具；`panel_run_background` 这类带前缀的名字被 `/run/` 匹配成 CLI 自己的命令（kind `run`），界面认不出是后台命令，不转圈 |
| `web/src/components/tasks/ToolRow.tsx`        | 认出来的后台命令会转圈，但时间停在调用返回的那一刻；跑完后这一行还是「已放到后台」，看不到结果                                            |
| `server/background.ts`                        | 只有完成时推结果；没有「多久没输出」「跑了多久」的监视；超时固定两小时；对话停不掉单独一条                                                |
| `server/tasks.ts` 后台结果的推送              | `sendToChild` 的返回值没看，推送失败只 `log.warn`，结果可能悄悄丢                                                                         |
| `shared/task.ts` `taskBusy`、`task-unread.ts` | 不看后台命令：这一轮说完、命令还在跑时，侧栏显示成做完了、还标「完成未读」                                                                |
| `shared/clis.ts` Claude Code                  | 自带的 `Bash run_in_background`、超时自动转后台、`Monitor` 都开着，那些命令面板看不见                                                     |

## 决策

### 一、后台命令仍然马上返回，对话停在「等结果」，不阻塞这一轮

`run_background` 不改成阻塞调用：阻塞期间用户的消息要等命令跑完才处理（`engine.ts` 的提示一直这么说），Codex 这类 CLI 的 MCP 调用还有超时。
「对话等结果」用 ADR 0005 已有的 `waiting` 状态表达：这一轮说完了，但对话在等会推回来的结果。界面上做到看得见：

- 发起命令的那一行一直转圈、按命令真正开始跑的时间走表；排队时写「排队中」。
- 侧栏把还有后台命令的对话算成在跑（`taskBusy` 看 `jobs`），不标「完成未读」。
- 命令置终态（成功、失败、被停止、超时）时，面板把那一行换成真实用时、结果和输出结尾（`settleJobTool`）；`request_build` 的几条编译结果依次接在那一行后面。

没选：把调用改成阻塞到命令结束。用户的消息会被卡住，和「不要在前台干等」的规则冲突。

### 二、面板盯着每条命令直到真正结束

`createBackground` 对每条在跑的命令：

- 记 `lastOutputAt`（stdout、stderr 都算，进度多写在 stderr）。10 分钟没有任何输出 → 提醒对话一次「可能卡住了」，附最后的输出，有了新输出再重新计。
- 跑满 15 分钟提醒对话看一眼进度，之后 30、60、120 分钟……间隔翻倍：一直在刷输出的死循环、重试不停的下载靠这个认出来，正常的长编译不会被反复打扰。
- 限时 `timeout_minutes`（默认 120，最多 480），到点停掉并按失败推回。
- 新工具 `stop_background`：对话确认卡住时停掉一条；`check_background` 带上已跑多久、多久没输出。

提醒和结果走同一个出口 `pushJobNote`：子对话按 `sendToChild`，顶层对话正在跑就实时送达、空闲就开新一轮。推送失败等 3 秒重试一次，再失败就记进对话、`holdForNextTurn`，并写日志，不悄悄丢。

没选：卡住了面板自动停掉重跑。是不是卡住要看命令（解压大文件就是很久没输出），由对话判断。

### 三、所有长命令都走面板

- 带服务名前缀的面板工具名先认出来再按名字猜类型（`panelToolName`），旧数据里被记成「运行命令」的后台命令按面板的回复认回来。
- Claude Code 设 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` 并禁用 `Monitor`：CLI 自己的后台命令不受面板监管，进程被回收结果就没了。
- 面板退出前停掉还在跑的后台命令，把那一行收口成「面板退出时还没跑完，已停止」，重启后不会一直挂着「已放到后台」。

## 运行时

- `BgJob` 新增 `createdAt`、`lastOutputAt`、`stalled`、`timeoutMs`、`nextCheckMs`；记录仍只在内存里。
- `createBackground` 的 deps：`onSettle`（置终态）、`onNotice`（提醒）、`stallMs` / `checkFirstMs` / `now`（测试用）。

## 风险与代价

- 每次提醒会唤醒对话、多花一轮 token：间隔翻倍，同一段沉默只提醒一次。
- 面板重启后后台命令仍然丢失（记录不落盘），只做到收口说明，不续跑。
- 改工具行是改历史消息：只改输出、用时、失败标记，靠 `messageStamp` 里的输出指纹推到界面。

## 补充（2026-10-24 晚）

- 用户又看到一条后台命令 `<0.1s` 就显示完成：Command Code 在工具结果前插了 `<repair_note>`，界面按「开头是已放到后台」认编号，认不出就当普通工具显示完成。改成：那一行只要输出里还有没拿到结果的编号（`bgPendingIds`，不锚定开头）就一直转圈；结果段带编号（`【后台命令 <编号> 已结束】`）接在后面才算完成。面板被强杀后不认识的编号收口成「结果丢失」，不会永远转圈，也不会看着像做完了。
- 用户要求所有命令都静默跑、不弹命令行窗口：提示里禁止新开窗口（`start`、`cmd /k`、`Start-Process`、`wt` 这类），`run_background` 遇到这类写法直接拒绝并说明。面板自己起的进程本来就都带 `windowsHide`；CLI 自己的命令工具面板拦不到，靠提示约束。

## 补充（2026-11-05）：限定用途、补常驻服务

用户报「写文件命令怎么也用后台命令了」。核对下来是三件事：

- 长命令守卫（`longDeny`）按段里的字样匹配：heredoc 正文、commit 说明、`grep`/`cat` 的参数里出现 `e2e`、`test:unit`、`--watch` 都被拦下，提示「用 run_background」，Agent 就把写文件、查文件交给了后台命令。
- `run_background` 的命令不过任何工具前守卫：只读角色、推送授权、危险命令、凭据、测试归属在 CLI 命令工具上生效，换成后台命令就绕过去了。
- 开发服务器、监听用不了：十分钟没输出就催、两小时被停、对话一直显示在等结果、计划那一步永远等待中。

决策：

- 命令判断统一走 `shared/command-scope.ts`（去 heredoc 正文、看段开头的程序名、快命令清单）。守卫只拦真正在跑的长命令。
- `run_background` 只收要跑很久的命令（编译、测试、打包、安装依赖、下载、搜索大范围、等外部结果）和常驻服务：写文件、几秒就完的命令拒收并说明该用什么（`backgroundMisuse`）；放行前过和 CLI 命令工具同一套守卫和用户钩子（`server/hooks/dispatch.ts` 的 `commandGuard`，长命令守卫除外），不依赖 CLI 支不支持钩子。
- 新增常驻服务（`service`，开发服务器、监听没写也自动认）：不提醒、限时默认 8 小时、计划不挂等待、不算对话在等它（`awaitedJob`），运行区照样列出能停；中途退出把结果推回。那一行不写「已放到后台（编号…）」，交出去就收口。

没选：把写文件命令在后台里照跑并提醒。写文件绕开了 CLI 的编辑工具，面板记不到改了哪些文件，改文件的守卫（独立分支越界、Bug 方案范围）也管不到。

## 补充（2026-11-07）：全项目全文搜索也算长命令

用户报 Agent 在前台跑 `grep -rl … "G:/…/Project"` 扫整个 UE 项目 2 分钟，没用后台命令。grep 在快命令清单里，长命令守卫放过；面板工具说明只把编译、测试、安装、下载列成长命令，「大范围搜索放后台」只写在 project-structure skill 里。而 `grep -r` 不读 .gitignore、不认项目的搜索排除目录，会把编译产物和缓存全读一遍。

决策：长命令守卫再认一种——从项目根（或更上层）起的全文递归搜索（`grep -r`、`findstr /s`、`find … | xargs grep`、`gci -Recurse | sls`，判断在 `shared/wide-search.ts`），放前台时拒绝，让它放后台或改用 rg 限定子目录；起点是子目录、自己带了 `--exclude-dir` / `-prune` 的、rg、git grep 照常放行。面板工具说明和聊天约束把这类搜索列进 `run_background` 的用途。

没选：把 grep 整个移出快命令清单。查单个文件、子目录的 grep 几秒就完，一律拦会把正常查找也推到后台，回到 11-05 的老问题。

## 补充（2026-11-11）：重新划定哪些命令必须放后台，大项目搜索改走 rg

用户反馈大项目里搜索会扫整个项目、超时也没结果，并要求重新规划哪些命令走后台。核对 Claude Code 2.1.322（原生安装）：它已经没有单独的 Grep / Glob 工具，搜索都在命令工具里跑，`rg` 是它自带的 ripgrep（读 `RIPGREP_CONFIG_PATH`），`grep` 换成自带的 ugrep（只认 .gitignore），`find` 换成 bfs（都不读面板的排除配置）。命令工具默认两分钟超时，rg 输出接到管道时整块缓冲，被杀掉时已经搜到的命中一起丢掉，这就是「超时也没结果」。

决策：

- 面板交给 CLI 的 ripgrep 配置（`shared/search-exclude.ts` 的 `rgConfigLines`）在排除目录之外再跳过 .uasset、图片、模型、压缩包这类二进制文件（命令行显式 `-g` 时后写的优先，照样能搜），并加 `--line-buffered`，超时前搜到的照样留下。提示词让 Agent 搜内容用 rg、按名字找资源用 find，扫整个大项目时放后台。
- 长命令守卫按程序认「一定要跑几分钟」的一类（`shared/command-scope.ts` 的 `heavySegment`）：UE 的 Build.bat / RunUAT / UBT / 命令行编辑器、msbuild / devenv、`cmake --build`、Docker 构建、不带包名的整份装依赖（`npm ci`、`pnpm i`、`yarn`、`pip install -r`）、Gradle / Maven 打包。放前台时拒绝，让它交给 `run_background`。

分三档：

| 档                     | 例子                                                                                    | 怎么处理                                   |
| ---------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------ |
| 必须后台（守卫拦）     | 完整测试、e2e、界面检查、开发服务器、上面的编译打包和整份装依赖、从项目根起的 `grep -r` | 前台跑时拒绝，交给 `run_background`        |
| 看项目（提示词说明）   | `npm run build`、`tsc`、`cargo build`、加一个包的 `npm install`、扫大目录的 rg          | Agent 自己判断，慢的项目在守卫参数里补前缀 |
| 前台直接跑（后台拒收） | 读写文件、列目录、限定目录的搜索、git 本地操作                                          | 后台命令拒收，直接用命令工具               |

没选：给 Claude Code 的 Grep 工具改写参数补排除项。新版已经没有这个工具（只有显式开启时才有），做了也只对老版本有用。
