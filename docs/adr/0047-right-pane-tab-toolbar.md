# ADR 0047：对话右栏的按钮跟着页签走，子对话不再单画一行标题栏

状态：已接受（2026-11-03 用户确认按文档实施，同日落地） · 2026-11-03

- 影响范围：对话页右栏（`web/src/components/tasks/TaskFiles.tsx`）、右栏里的子对话面板（`web/src/components/tasks/TaskView.tsx` 的 `pane`）、子对话切换下拉（`web/src/components/tasks/ChildSwitcher.tsx`）、页签条（`web/src/components/ui/tab-bar.tsx`）
- 不影响：中间打开的对话和运行页签（`ConversationTabs`）、Chat 页标题栏、AI 分析窗口（`embed.slot`）

## 背景

右栏打开子对话后，上面叠着两行：

1. 页签条：`项目文件`、`本对话改动 (1)`、`✓ 根目录工具配置搬进 co… ×`。
2. 子对话自己的标题栏（高 56px）：`切换子对话`下拉、状态图标、标题、`✓ 已解决`、钉住的「状态」「对话进程」、`更多操作`。

切到「项目文件」「本对话改动」时，页签条下面又是一行信息栏：分支、改动数，右端是查找（或平铺 / 分组切换）和刷新。

用户 2026-11-03 提出：

- 这些按钮挪到右侧页签条的右端。
- 选中子对话页签时只显示子对话的按钮，切到文件页时只显示文件页的按钮。
- 切换子对话的下拉放到子对话页签上。

现在的问题有三个：

- 子对话页签上已经有状态图标和标题，标题栏又画了一遍，重复的一整行占掉 56px。
- 按钮分散在两行，用户找按钮得看两个地方。
- 切换子对话的入口放在标题栏最左边，离子对话页签很远。

| `TaskFiles.tsx` 的「项目信息行」                             | 只在文件、改动页出现：左边是分支 · `n 个改动`；右端在文件页放「查找文件」，在改动页放「平铺 / 按目录分组」，两页都有「刷新文件」                                                                                             |

## 决策

**右栏页签条的右端是「当前页签的工具区」，只放选中页签自己的按钮。子对话面板不再画自己的标题栏，切换子对话的下拉挂在子对话页签上。**

### 1. 工具区跟着页签换

```
┌ 项目文件 ─ 本对话改动 (1) ─ ✓ 根目录工具配置… ▾ × ─────────── [工具区] ┐
```

| 选中的页签 | 工具区里的按钮（从左到右）                                                             |
| ---------- | -------------------------------------------------------------------------------------- |
| 项目文件   | 查找文件、刷新文件                                                                     |
| 本对话改动 | 平铺 / 按目录分组（有改动时）、刷新文件                                                |
| 模型       | 没有按钮（`ModelPreview` 自己的操作留在预览区内）                                      |
| 子对话     | 工作流的「对话 / 流程图」切换（工作流子对话才有）、解决 / 已解决、钉住的按钮、更多操作 |

- 工具区包一层 `role="toolbar"`，读屏名按页签写，如「文件操作」「子对话操作」。它在 `role="tablist"` 外面，Tab 键先走页签、再走工具区。
- 切页签时只换工具区里的内容，页签条高度和位置不动。

### 2. 子对话面板不画标题栏

- 状态图标、标题已经在页签上，标题栏整行去掉，子对话内容上移 56px。
- 改名：双击子对话页签（`TabItem` 已有 `onDoubleClick`），页签就地变成输入框（`InlineRename`），回车或失焦提交、Esc 取消，由 `TaskFiles` 直接调 `api.renameTask`。
- 模拟 / 导入标记：放在工具区最左边（子对话面板挂进来的第一组），工具区窄于 600px 时只留图标，悬停看说明。实现时没放进页签的 `tag`：标记是子对话面板自己算的，页签拿到的子对话摘要里没有这两个字段。
- 「解决」按钮现在只在悬停标题栏时出现。改成悬停页签条或焦点进工具区时出现，触屏照旧常显。
- 子对话里的按钮清单不变，仍由 `taskHeaderItems` 生成，钉住规则也一样。只是画的位置换成工具区。

### 3. 切换子对话的下拉在子对话页签上

```
[✓ 根目录工具配置搬进 co… ▾ ×]
```

- 页签标题后、关闭按钮前加一个 `▾`（`ChevronDown`），点开就是现在 `ChildSwitcher` 的菜单：分组、排序、当前项打勾都不变。
- 点页签本身还是选中页签，点 `▾` 只开菜单，两个点击区分开。
- 父对话只有一个子对话时不画 `▾`：列表里只有它自己，没得切。

### 4. 文件页的信息行只留信息

信息行保留分支和 `n 个改动`，右端的查找、显示方式和刷新挪进工具区。这一行就成了纯信息。

## 候选方案（没选）

| 方案                                              | 为什么没选                                                                  |
| ------------------------------------------------- | --------------------------------------------------------------------------- |
| 子对话标题栏保留，只把文件按钮挪上去              | 子对话的状态图标和标题还是画两遍，56px 的重复行还在，用户提的主要问题没解决 |
| 子对话按钮常驻页签条，切到文件页也显示            | 正是用户不想要的：看文件时出现子对话的按钮，分不清点了作用在谁身上          |
| 切换下拉放在页签条最左边（`TabBar` 的 `leading`） | 和子对话页签离得远；没开子对话时这个位置是空的，开了才出现会挤动其他页签    |
| 去掉信息行，分支放进页签的悬停提示                | 看分支是常用操作，藏进悬停里要多一步；这一行很矮（30px），留着成本很小      |
| 子对话页签点一下直接弹出切换列表                  | 和「选中页签」冲突，已经选中时点它做什么不好猜                              |

## 操作清单

| 改什么               | 做法                                                                                                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TabItem`            | 加一个 `extra` 槽，画在标题和关闭按钮之间，用来放 `▾`；点击时 `stopPropagation`，不触发选中                                                                                       |
| `TabBar`             | `trailing` 包一层 `role="toolbar"`，加 `trailingLabel` 读屏名；工具区宽度不够时的收缩规则见「风险」                                                                               |
| `TaskFiles`          | 按 `tab` 生成工具区：文件页、改动页自己画按钮；子对话页给一个挂载点（`ref` 回调存进 state），交给子对话面板                                                                       |
| `TaskView`（`pane`） | 不画 `header`；收到挂载点时，用 `createPortal` 把 `headerActions` 挂进去（和 `embed.slot` 同一种做法）。挂载点在子对话页签没选中时加 `hidden`，不卸载，菜单和对话进程的锚点都还在 |
| `ChildSwitcher`      | 触发按钮可以换成 `▾` 样式（加 `variant` 或 `trigger` 参数），菜单内容不动；`list.length < 2` 时不画                                                                               |
| 改名                 | `TaskFiles` 自己处理：子对话页签双击换成 `InlineRename`，提交时调 `api.renameTask`，结果 `upsertTask` 回列表                                                                      |

## 与现有实现的关系

- 按钮清单（`header-items.tsx`）、钉住（`HeaderPins.tsx`）、「更多操作」菜单的内容都不变，只换了画的位置。
- `embed.slot` 这套 portal 写法沿用，不新造机制；AI 分析窗口的行为不变。
- 中间的对话页签条（`ConversationTabs`）、Chat 页的标题栏不受影响。
- 「子对话开着时盖一层看文件」（`childFiles`，见 `docs/modules/web/conversation.md`）不受影响，那个按钮在父对话的标题栏上。

## 运行时

- 工具区的内容只看 `TaskFiles` 的 `tab` 状态，不新增存储。
- 子对话面板一直挂着（和现在一样），工具区挂载点跟着它一直存在，切页签只改 `hidden`。所以开着的下拉菜单、对话进程面板在切走时一起藏起来，切回来状态还在。
- 窄屏（xl 以下）右栏是盖在对话上的抽屉，工具区规则一样。

## 分期

一次做完，一个提交，界面检查一起改。

出口条件：

- `scripts/ui/02-task.mjs`、`02b-subagent.mjs` 改成在子对话页签上找 `切换子对话`，并新增几项断言：
  - 切到文件页时，工具区里没有子对话的按钮；
  - 切回子对话页时，没有文件页的按钮；
  - 子对话面板里没有 `h-14` 的标题栏；
  - 双击页签能改名。
- 深浅两套主题截图检查通过，`ui-shots/` 里看 640px、1024px 两种右栏宽度。

## 风险与代价

- **宽度不够**：右栏常见宽度 600 多像素。三个页签加上子对话的整套按钮（「已解决」胶囊约 80px、两个钉住按钮、更多、工作流切换约 140px）会放不下。按顺序收缩：
  1. 「已解决」胶囊只留图标；
  2. 工作流切换只留图标；
  3. 钉住的按钮收进「更多操作」（它们本来就在菜单里，不会丢功能）；
  4. 没选中的文件页签只留图标，悬停显示名字。

  「更多操作」始终留着。收缩规则用容器查询（`@container`）写在页签条上，不按窗口宽度判断。

- **按钮位置变了**：用户习惯在子对话标题栏右上角点「更多」，现在挪到页签条右端。挪动距离只有一行，位置还是右上，代价可接受。
- **改名入口不明显**：没了标题，只能双击页签改名。「更多操作」菜单里本来就有「重命名」，入口不会丢。
- **界面检查要跟着改**：几个按选择器找 `切换子对话` 和 `group/hdr` 的检查要改，漏改会在 CI 上红。

## 开放问题

实施时（2026-11-03）都按倾向定了：

1. **只有一个子对话时显示 `▾` 吗**：不显示（`ChildSwitcher` 的 `variant="chevron"` 在 `list.length < 2` 时不画）。
2. **双击页签改名走哪条路**：没有走上下文交回子对话面板，改成 `TaskFiles` 直接调 `api.renameTask`，代码更少，子对话面板不用多接一个入口。
3. **收缩阈值**：600px 起「已解决」和模拟 / 导入只留图标，560px 起工作流切换只留图标，520px 起钉住的按钮收起（对话进程除外：它的面板要贴着按钮弹出），440px 起没选中的文件页签只留图标。子对话页签允许收缩（最少 5rem），窄到 340px 时标题截断，`▾` 和 `×` 仍然看得见。
4. **模型页签要不要把预览区的操作也挪上来**：这次不动。
