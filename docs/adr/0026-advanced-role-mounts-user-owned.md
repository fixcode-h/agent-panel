# ADR 0026：内置高级角色的挂载交给用户，角色页按高级 / 基本分页

状态：已接受 · 2026-10-29

## 背景

用户 2026-10-29 提出三件事：角色页把高级角色和基本角色分开展示；高级角色以后能继续补充、能挂自定义角色，默认挂上的也能改说明、能删掉；基本角色再扩充一些必要的。

按 [ADR 0015](0015-builtin-roles-follow-definition.md) 和 [ADR 0023](0023-role-layers-and-triage.md)，内置角色（含主理、执行、分析三个高级角色）的设定由面板维护：挂哪些能力、每个挂载的规则跟内置定义，用户只能改用法和参数取值，自己加的挂载在保存时被 `syncCore` 去掉。这和第 2 条直接冲突。

## 决策

1. **挂载可以由用户接管**（`AgentInput.mountsCustom`）。内置高级角色的「能力」页和自建的一样能加、删挂载、改说明（`rule`）和常驻加载；改了就标 `mountsCustom: true`，之后保存和启动同步都整份按用户的（`syncCore`），不再按内置定义增删。没接管的照旧跟定义走（只保留用户改的用法和参数取值），新版本新增的默认挂载会自动挂上。
2. **恢复默认挂载**：接管后「能力」页顶上一行说明和「恢复默认挂载」按钮，把挂载换回内置定义在本机该挂的那份（`defaultMounts`）并清掉标记。
3. **其他设定不变**：名称、角色设定、Skill、参数定义、角色层仍按 ADR 0015 由面板维护；必备角色仍然不能删除、不能停用。改的只是「挂哪些能力」这一项的归属。
4. **角色页分页**：列表栏顶上「高级角色 · N / 基本角色 · N」分段（`RoleLayerTabs`，条数跟筛选走），每页里照旧按「必备 / 分类 / 未分类」分组；选中的角色在哪一层就停在哪一页，搜索时当前页没命中、另一页有就翻过去；在哪一页点新建就建哪一层。
5. **基本角色扩充**（按 [agent-catalog.md](../agent-catalog.md) 的判定标准）：新增「界面走查」（`uiqa`，通用，执行默认挂成派出）和「本地化」（`i18n`，执行默认挂成自动判断）；「开发」的 `task` 加「重构」，「评审」的 `target` 加「安全」——这两个只是已有能力块的变体，按规则加参数不加角色。

## 没选的方案

- **只允许改说明、不允许增删**：满足不了「挂自定义角色」，用户还是得复制一份主理才能加能力，复制出来的又不是必备角色，项目对话默认用不上。
- **逐条记录用户的增删（删了哪些默认的、加了哪些）再和定义合并**：能让没删的默认挂载继续跟版本更新，但规则多一层、界面也说不清「哪些还在跟」。接管后整份归用户、需要时一键恢复，行为更好预期。
- **安全评审、重构单独建角色**：和评审、开发是同一个能力块，按 catalog 的「不为变体新建角色」加参数。

## 后果

- 接管了挂载的用户收不到之后内置定义里挂载的调整（例如新版本给执行多挂一个能力），要点「恢复默认挂载」才能拿到；界面上那一行说明就是提醒。
- 用户删掉执行的「评审」挂载不影响收尾评审门禁：门禁在 `submit_merge`（ADR 0013 / 0022），派评审靠名字，不靠挂载。
