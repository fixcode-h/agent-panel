# ADR 0082：自建工具（/createtool）

状态：已接受 · 2026-11-25

## 背景

用户 2026-11-25 提：项目里有一批反复要跑的命令（导表、Lua 编译、打包），每次都要 Agent 重新读文档、自己拼命令，拼错了还要再来。希望有个命令让 Agent 自己读文档和脚本，把它总结成一个带中文名、说明、什么时候用、参数的工具，以后所有对话的 Agent 都知道、能直接调；做好后由用户选存到项目（放文档目录、团队共用）还是全局。设计稿：`docs/openspec/changes/custom-tools/design.md`。

## 决策

- **一个工具 = 一条命令（或一段脚本）+ 参数定义 + 中文说明**（`shared/custom-tools/schema.ts`）。项目的存 `文档根/AgentPanel/Tools/<id>.json`，走项目数据（ADR 0078，P4 先签出）；全局的存 `<数据目录>/tools/<id>.json`。项目里同 id 的盖住全局的。存一版版本 +1，最多留 5 个旧版本。
- **Agent 只有一个入口**：面板工具 `custom_tool`（list / show / run / test / save），不把每个自建工具各做成一个 MCP 工具（ADR 0067 的个数和长度上限，各 CLI 延迟加载的做法也不同）。提示词里只加一行清单（最多 8 个、600 字，按最近用过的排）。**2026-11-28 改为每个工具各自列出，见下面「直接调用」一节。**
- **命令由面板展开，不让模型拼**：参数按定义校验（未知参数报错、类型、选项、范围、路径不出项目），值按当前 shell 加引号，cmd 里带 `"` `%` 的值、任何换行直接拒绝；展开后的命令照样过命令守卫。
- **授权**：已保存的工具默认不弹卡，Agent 调用直接跑（用户 2026-11-26：工具是用户自己存下、看过的命令，和普通工具调用一样）；工具设了 `confirm: true`（管理页「影响和输出」→「运行前先问我」）才弹授权卡，Agent 刚拼、还没保存的草稿试跑（不是只读的）照旧弹卡。「本对话不再询问」按授权类型 `ctool`（同一个工具，项目和全局分开算）。人在管理页点的试运行不弹卡。
- **长任务**：限时超过两分钟的（或标了总是后台的）交给后台命令，跑完推回，不让 Agent 轮询；结果只回退出码、按报错正则挑出的报错、输出最后几行和日志路径。
- **保存由用户点**：`save` 在对话里弹保存弹窗（请求 purpose `custom-tool`），显示草稿、试跑结果、重复检测（同 id、名字像、命令去掉参数后一样、同一段脚本），用户选项目 / 全局、能直接改名字和说明，或写意见让 Agent 再改；点完工具调用才返回。
- **管理**：「技能与 MCP」页加「工具」页签，编辑、试运行、复制 / 移到另一边、删除；「/」菜单多一组「自建工具」，选中后展开成让 Agent 用 `custom_tool` 跑它（出错了它能接着处理）。
- 同时补了内置命令 `/build` `/run` `/merge` `/pr` `/refactor` `/perf` `/deps` `/changelog` `/doctor`（都是展开成要求，面板不另写执行逻辑）。

## 直接调用（2026-11-28 修订）

用户 2026-11-28：「我已经有自建工具了，为什么 Agent 不能直接填入参数直接执行那个工具？自建工具就是期望可以类似 Agent 内置工具一样调用。」
复盘（设计稿 `designs/自建工具直接调用-问题分析与方案.md`）：所有工具挤在 `custom_tool` 一个入口，模型看不到参数，提示词清单还写着「参数不清楚先 action=show」，DeepSeek Flash 每次都 list → show → run，还被引去翻目录找程序。

- **每个能用的自建工具各自列成一个工具 `tool_<id>`**（`-` 换成 `_`，`shared/custom-tools/direct.ts`）：title 是中文名，说明写做什么、什么时候用 / 别用、代替哪些程序；inputSchema 按参数定义生成（类型、选项、范围、默认值，`additionalProperties: false`），**有默认值的参数不算必填**，参数全有默认值的工具不填参数一步调用。
- 执行和 `custom_tool action=run` 是同一条路（`server/panel-tools/custom-tool.ts` 的 `callCustom` → `server/custom-tools/agent.ts` 的 `runOne`）：参数校验、守卫、「运行前先问我」、P4 签出、长任务放后台都不变。
- 面板工具注册表多一类「动态工具」（`DynamicTools`，`server/panel-tools/registry.ts` 的 `DYNAMIC_TOOLS`）：按这一轮的数据生成定义、按名字认执行；自建工具是第一个来源。它们是用户自己做给 Agent 用的，不计入 ADR 0067 面板工具的个数上限，但直接列出最多 12 个（按最近用过排，和提示词清单同一份），名字超过 40 字的不列（CLI 拼上 `mcp__<服务名>__` 后 API 限 64 字）；没列出的照旧 `custom_tool action=run`。
- `custom_tool` 留作管理入口：list / show、跑没列出的、test / save 做新工具、locate 登记程序。提示词清单、情境规则「改用自建工具」、改道代答都改成写 `tool_<id>`，并带「清单里没有这个名字时用 custom_tool action=run」的兜底。
- 识别：带面板服务名前缀的 `tool_<id>`（`mcp__panel__tool_x`）在 `panelToolName` 里认作 `custom_tool`，显示（对话里写工具的中文名）、钩子分类、能力路由都按同一个面板工具算；裸名字 `tool_xxx` 不认（可能是别家 CLI 自己的工具）。
- 这一轮新保存的工具下一轮起出现在清单里（清单在这一轮开始时算好）；保存回执里说明这一点。

## 影响

- 工具的 `capability` 字段先只是标记：等能力路由（ADR 0081）做「改动生效」时，把项目的编译、热重载工具当成一条路。
- 「依据的文件改了提示复核」「对话里命令卡片存成工具」「经验里的命令指向已有工具」放到二期。
- 演示版的保存、运行用 shared 里同一份校验和展开，命令不真的执行。
