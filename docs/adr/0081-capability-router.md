# ADR 0081：能力路由（找文件、找代码只有面板的 find）

状态：已接受 · 2026-11-25

## 背景

用户 2026-11-25 报：IDEA 已经开着 EmmyLua，工作流里搜 Lua 函数还是用 rg / grep 扫文件。查下来几层原因叠在一起：

- 能用的查找工具散在各处说明里：提示词「搜索（这个项目）」一节列代码索引工具、IDE 调用规矩推在情境规则里，内置角色、Skill、工作流又各写一遍「先代码索引 MCP 再 rg」，有的还点名早已删掉的 `search_lua`，互相打架；
- 外部服务的发现有漏：项目 MCP 配置只看工作目录（EmmyLua 装在上一层的版本管理根）、工具表只靠缓存；
- 工具按需加载、IDE 要 projectPath、开了「仅路由器」要经 execute_tool 转调、建索引时要等——都要模型照做，弱模型做不到。

用户定的方向：不提醒、不拦截，具体走哪条路用户和模型都不用知道，面板知道各条路的状态，由面板决定；rg / grep 是最后的兜底。也不只是查找，其他「同一件事有几条路」的能力以后走同一个框架。设计稿：统一查找方式（第 2 版 + 第 8 节）。

## 决策

**能力路由**（`server/capability-router/`）：一个能力 = 一组按 rank 排好的路（`RouteSource`：accepts / ready / run）。`route()` 依次看每条路能不能用：正在启动、建索引的在面板里等（最多一分钟，ADR 0067 第 5 节）、用不了和出错的跳过并记原因；结果怎么合由能力给（`isEmpty`、`enough`）。每次路由记一条路由记录（`log.ts`，每个项目最近 100 条，设置页以后从这里取）。不按能力名写分支。

**第一个能力：查找**。

- Agent 只有一个入口：面板工具 `find`（取代 `file_index`，旧名照样执行）。找文件 `file / list / refresh / status` 查文件名索引；找代码 `symbol / refs / outline / members / include / text` 交给路由。语言按扩展名、目录、名字写法推（`shared/capability-router/find/request.ts`），推不准时外部路都试。
- 外部路由插件登记（插件接口 21 `ServerPlugin.findSources`，只描述工具名、参数、结果怎么读）。面板自己当 MCP 客户端去调（`server/mcp-client/`，http / stdio，连接按「服务 + 目录」复用、空闲 5 分钟关），服务从各 CLI 的全局配置、面板库、工作目录和项目目录往上 4 层的项目配置里找；JetBrains 的 projectPath、仅路由器、「定不了项目」时按工作目录挑项目都在 `find/external.ts` 里处理。UE 插件登记 UEToVS（C++）和 lua_code（Lua）。
- 最后一条路是面板自己按文本找（`find/text-source.ts`）：候选文件从文件索引取（尊重排除目录、不走磁盘），声明的行排前面；独立分支里读对话目录那份。Lua 的引用外部路查到后还要用文本补一遍（字符串调用、反射），两边合并，结果不比只用 rg 少。
- 提示词只剩一句「找文件、找代码用面板的 find」，不列各家工具；内置角色、工作流、Skill 里不再点名查找工具（`scripts/rules-check.mjs` 第 24 条）。

## 影响

- 加一条查找的路：插件在 `findSources` 里登记，不改提示词。加一个新能力（下一个是「改动生效」：Live Coding / 编译、Lua 热重载）：给出 sources 和合并规则走 `route()`。
- 外部查找工具仍挂在 CLI 上（Agent 直接调也能用），还没从 Agent 那边藏起来；接管 shell 里的 rg / grep（第二期）、设置页「查找路由」和路由记录（第三期）后续做。
- 插件接口 21：旧面板不调 `findSources`，UE 插件在旧面板上没有这几条路、行为和以前一样。

## 补充：文本兜底先用 rg（2026-11-26）

用户看到 find 按文本找 23 秒后回「没有找到」，Agent 又自己跑 rg 才找到，问「兜底的不就是 rg 么，find 失败那么就是不存在」。原因是文本兜底只逐个读索引里的文件，UE 工程 20 秒读不完就停，「只查了一部分」的说明还被路由丢掉。现在文本兜底先用本机的 rg 查全（`server/capability-router/find/rg-scan.ts`，排除目录和 Agent 自己跑的 rg 一致，再按同一套规则认声明、引用），不靠索引；没有 rg 才逐个读索引里的文件，查不完时说明只查了一部分。这样 find 回「没有找到」就是真的没有。
