# ADR 0035：子对话收尾的必备步骤不跟着版本管理方式变

状态：已接受 · 2026-10-31

## 背景

用户 2026-10-31 报：P4 项目里的子对话改完代码不评审，直接算做完。原话：

> 有些必备的操作不能因为版本管理的方式不同就不一样，就算没有版本管理有些操作要执行的还是要执行

## 事实核对

| 位置                                      | 改动前                                                                                   |
| ----------------------------------------- | ---------------------------------------------------------------------------------------- |
| `server/tasks/run.ts` 的 `submitMerge`    | 只给 `parentTaskId && isolated` 的子对话，P4、共用目录、没有版本管理的子对话没有这个工具 |
| `server/tasks/merge.ts` `submitMerge`     | 评审门禁、测试记录、交接要点、待回答的提问、后台命令都在这里校验，没有独立分支直接拒绝   |
| `shared/plan.ts` `wrapUpKind`             | 子对话：独立分支 `merge`，P4 `p4`（Agent 分完 changelist 自己标完成），其余没有收尾      |
| `server/tasks/merge.ts` `finishChildStep` | 共用目录的子对话不要求先请求收尾，条件满足就直接标完成                                   |
| `server/tasks/children.ts` `nudgeMerge`   | 做完没请收尾的提醒只对独立分支                                                           |
| `shared/builtin/agents.ts` 执行角色       | 「要合回父对话分支的子对话」才按收尾前评审的顺序做                                       |
| `shared/engine.ts` `reviewPart`           | 不是 Git 仓库时评审拿不到改动，只有交接单                                                |

结果：评审、交接、父对话验收全挂在 `submit_merge` 上，而它只开给独立分支，其他版本管理方式整条链都被跳过。

## 决策

评审、测试记录、交接要点、父对话验收、做完没请收尾的提醒是交付的必备步骤，所有项目子对话都做；版本管理方式只决定最后一步做什么：

| 子对话                       | 收尾（`wrapUp`） | 最后一步                                 |
| ---------------------------- | ---------------- | ---------------------------------------- |
| Git 独立分支                 | `merge`          | 面板提交，父对话合回原分支               |
| P4 工作区                    | `p4`             | 先 `p4_split_changelists` 分好，再请验收 |
| 共用目录的 Git、没有版本管理 | `deliver`        | 改动已在父对话目录里，直接请验收         |

- `submit_merge` 开给所有项目子对话，校验一条不少；要不要评审按「改没改文件」判（独立分支一定改过，共用目录看 `task.changes`），只读排查不评审。
- 三种收尾都在 `PANEL_WRAPS` 里，只由面板在父对话收下后标完成（`markChildWrapUp`），Agent 自己标不算。
- 共用目录的子对话改过文件却没请求收尾时，`finish_child` 拒绝；请求后父对话验收，面板标完成再走 `advanceChildTo`。
- 一轮结束时共用目录的子对话改过文件（或计划只剩收尾）却没请收尾，面板提醒一次（`nudgeShared`）；被用户停下、父对话收尾、归档删除的不提醒。
- 不是 Git 仓库时评审的提示词列出这个对话改过的文件（`changedFilesPart`），P4 提示可以用 `p4 diff -du` 只读看差异。

## 放弃的做法

- 给 P4 和没有版本管理另做一个收尾工具：工具名不同，Agent 和提示词又要分两套写，正是这次出问题的根源。
- 共用目录不评审、只要求测试记录：用户明确说必备步骤不能因为版本管理不同就不一样。

## 影响

- 共用目录、P4、没有版本管理的子对话计划里多一步「收尾：请父对话验收」或改名后的 P4 收尾，计划进度分母多 1。
- 没列计划、只改了文件的子对话靠一次提醒；提醒后仍不请求，按原样上报父对话，父对话 `finish_child` 会被拒绝，直到它请求收尾。
