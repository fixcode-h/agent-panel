- 运行区的位置与分隔线（`web/src/components/tasks/Messages.tsx` 的 `RunningFooter`、`FoldedRun` 的 `running` / `Msgs` 的 `tail`，数据判定在 `RunningNow.tsx` 的 `runningRows` 和 `web/src/lib/run-row.ts` 的 `runRow`）：运行区（没收尾的工具、后台命令、子任务、子对话、运行中的工作流（含手动跑的、计划触发的））挂在**这一段最后一条回复（总结）下面**，和总结之间用一条 `border-t border-line/60` 的细线分隔；以前它插在总结上面（`head` 把折叠开关和运行区合成一块塞进 `AgentMessage` 的 `slot`），看不出哪段是总结。分割线必须和内容在同一个判断里：`runningRows(...).empty` 与 `runRow(...)` 都算过没东西时（`if (rows.empty && !run) return null`）整个 `RunningFooter` 返回 `null`，不会在总结下面留一条孤零零的横线。工作流那一行画什么、画不画只有 `runRow(task, msgs, newest)` 一个来源：判空、`border-t border-line/60` 分隔线、渲染 `<RunRow info={run} />` 三处读的都是它（这一行的判定见下一条）。`toggle`（「展开过程 / 收起过程」）留在原位（第一条 Agent 消息的名字下面、展开后也不跑到名字上方），只把运行区拆出去；收起态把运行区挂在 `tail` 那段 `Msgs` 后面，展开态挂在整段 `Msgs` 的 `tail`，两态位置一致、切换不闪跳。运行区**总是缩进在头像后**（`flex gap-3` + 26px 头像位，和工具调用、总结文字同一个左边缘）：它现在挂在 `Msgs` 的 `tail`（fragment 直挂 `ChatReply` 的容器），外面已没有缩进层，不缩就会比总结文字往左突出 26+12px、分割线也从容器最左端开始。判空和渲染必须读同一个值：`RunningFooter` 先算一次 `shownTools = live ? [] : tools`，`runningRows` 和 `<RunningNow tools={shownTools}>` 都用它（以前判空用 `tools`、渲染传 `live ? - 运行区的工作流行（判定在 `web/src/lib/run-row.ts` 的 `workflowRunState` / `runRow`，组件是 `web/src/components/tasks/Messages.tsx` 的 `RunRow`，状态判定读 `shared/task.ts` 的 `runRunning`，打开入口是 `child-open.ts` 的 `useRunViewOpen`）：这一行「工作流」代表**当前这条对话自己正在跑的那次运行**，手动跑的和对话里 `start_plan` 起的共用同一份判定。数据只取这个 `task` 自己的 `task.runs.at(-1)`（运行号用 `rec.id`，没有记录时回退 `currentRun(task)`）和 `topSteps(task, run)` 的顶层节点，所以谁的对话在跑工作流就显示在谁的运行区里；父对话的运行区里子对话仍然只列子对话行（`visibleChildren`），不替子对话多列一行父对话级的工作流行。原来这个函数叫 `planRunState`、开头 `if (task.mode !== 'chat') return undefined` 把工作流任务整个挡掉，只覆盖计划触发的那次；去掉这道门控后改名 `workflowRunState`：在跑时画「工作流 · 名字 · 2/7 个节点 · 1m20s」（名字取 `rec.workflowName` → `task.workflowName` → 「工作流」，耗时按 `startedAt`、`useNow` 每秒走，和后台命令行同一套），完成或没有运行返回 `undefined`（那一行消失），失败 / 被停止留一行说明和失败节点（失败节点用 `text-danger`，`failed` 让整行按失败标记；整行点了展开失败节点，被停止且没有失败节点时点不动）；**这一轮里没有无 step 的 agent 回复时也不列**——包括工作流任务首次运行还没有对话轮，和旧任务只有带 `@main` 的编排器消息、这一轮又没有追问回复的情况；这两种形态的进度由页面中部的运行卡片承担。计划触发的那次和手动跑的用同一套文案，没有另加「计划的第 n 步」这类特殊说明。`run` 号同时给进度和「打开这次运行的视图」用：跑着时整行可点，经 `PaneNavCtx` 的 `runView` 打开——父对话开右栏 `RunPanel`，子对话面板里就地换成 `paneRun`（`TaskView.tsx` 的 `openRunIn`，两个 provider 都传了它），和运行卡片「打开这次运行的对话」是同一个入口，没有新造弹窗；它和 `PaneNav.runTool`（认「启动工作流」那条工具调用，入口 `useRunToolOpen`；字段名原来就叫 `run`，为避免和 `runView` 混淆改成了 `runTool`）是两个入口，别混用。回归：`scripts/ui/02-task.mjs` 的「运行区-工作流在跑」（把演示里已完成的工作流任务改成在跑，断言出现带 `2/N 个节点` 和 `1m\d+s` 耗时的行）、「运行区-工作流在跑-打开运行视图」（点整行打开右栏「运行 n」）、「运行区-工作流跑完消失」（改回完成后刷新，那一行消失、运行区不画、不留空横线）；判定抽到 `web/src/lib/run-row.ts` 就是为了能脱离组件单测，`web/src/lib/run-row.test.ts` 有 12 条：工作流任务自己跑和对话里 `start_plan` 起的两种任务都能列、完成消失、失败 / 被停止留行、只数顶层节点（子节点不算进度）、旧任务没有运行记录时按 `runRunning` 回退、不是最新的一轮不列（这一轮里没有最后一条对话消息）、`lastChatId` 跳过带 step 的消息落到更早那条无 step 的消息、旧任务只有 `@main` 编排器消息且这一轮没有追问回复时不列、没有任务或没有运行时返回空（运行区据此不画分隔线）。「最新一轮」的兜底只认没有节点的消息（`lastChatId`），不用 `@main` 当兜底：工作流任务的追问回复由 `server/exec/runner.ts` 的 `runAgent` 按 `call.step?.id ?? - 运行区的「最新一轮」判定（`web/src/lib/latest-turn.ts` 的 `latestTurnIndex`，接在 `TaskView.tsx` 的 `latest` 和 `Messages.tsx` 的 `RunningFooter` 上）：运行区只挂在**最新的一轮回复**下面，而「最新」不能直接取「最后一段」。`TaskView.tsx` 的 `toBlocks` 会把「没有节点的用户消息」单独 push 成一个 `{kind:'msg'}` 段，所以用户点发送的一瞬间 `blocks` 从 `[..., turn]` 变成 `[..., turn, msg]`：按最后一段算的话，原来那一轮就不算最新，`Messages.tsx` 的 `kids` / `jobs` 变假、`runningRows` 列空、`RunningFooter` 整个返回 `null`（连分割线一起），运行区（子对话行、后台命令行、工作流那一行）整块消失，等 AI 说出第一句、新的一轮成为最后一段才又回来——用户报的就是这个「发送时闪一下」。`latestTurnIndex(blocks)` 从尾部往前跳过连续的 `msg` 段，停在遇到的第一轮 `turn` 上（遇到 `steps` / `run` 段返回 -1，不把运行区挂到早就结束的旧轮下面）；`TaskView` 用 `useMemo` 算 `latestTurn` 后传 `latest`。`latest` 和 `last` 的语义继续分开：`last` 仍然只在「对话停着且这一轮是最后一段」时为真，管操作按钮常显、`foldStats` 那套；`Messages.tsx` 里 `jobs` 归到和 `kids` 同一个 `latest`（以前 `jobs` 在对话停着时看 `last`，尾部多一个用户消息就和 `kids` 分叉，两行一起闪），`runRow` 改成收 `newest = last || latest`（辅助对话、设计对话没有 `latest`，仍然只按 `last` 判）。回归：`web/src/lib/latest-turn.test.ts`（尾随一条 / 连条用户消息、AI 已开口、尾随节点段、尾随工作流运行卡片、只有用户消息、空对话），以及 `scripts/ui/02-task.mjs` 的「任务-发送消息时运行区不消失」（MutationObserver 采样整个发送过程里运行区子对话行数的最小值，等「消息出现在消息区」这个可观测状态，不赌时序）。Bug 记录见 [bugs/running-zone-flashes-while-sending](bugs/running-zone-flashes-while-sending.md)。
