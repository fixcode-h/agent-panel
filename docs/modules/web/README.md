- 运行区子任务行（`web/src/components/tasks/RunningNow.tsx` 的 `HelperRow`，数据来自 `shared/task.ts` 的 `helperActive` / `helperRunning` / `stepMs` / `splitStepJobs` 和 `web/src/components/tasks/HelperCards.tsx` 的 `chatHelperIds`）：对话派出的、还没结束的子任务（在跑或排队）和子对话用同一种样式的一行：转圈、「子任务」、标题、角色、执行中 / 排队中、正在做什么、耗时，行尾是终止按钮（`HelperCards.tsx` 的 `StopHelper`）；角色只在不是内置「子任务」角色（`origin !== 'builtin:helper'`）时显示。点标题打开只读的 `HelperWindow`（实时对话流、没有输入框），行本身不整段可点。顺序读 `shared/task.ts` 的 `sortHelpers`（和输入框上方「子任务」列表同一个函数）：在跑的排在排队的前面，同一组里**最新的在最上面**（按 `TaskStep.startedAt` 倒序，时间相同或旧记录没有开始时间时按 id 的派出序号倒序兜底，见 `newestFirst`），用户最后派出的那个不用往下翻。子任务起的后台命令并进这一行（`helperJobs`），一个子任务只占一行，标签写「后台命令 <名字>」或「n 条后台命令」；子任务已经结束、命令还在跑的，才由 `StepJobsRow` 单独列一行（展开看每条命令）。
- 对话这一轮没在跑时的状态行（`web/src/components/tasks/TaskView.tsx` 的 `ChatWaitLine`，判定复用 `shared/task.ts` 的 `childWait`）：先说清在等**什么**，只有真的停在等下一句时才是「等待你的下一条消息」。判定就是 `childWait(task, { background: task.jobs?.length, cliAlive: task.cliAlive })`，按「等用户回答 / 等确认 → 等后台命令 → 等派出的子任务 → 等工作流 → 等下一句」的顺序取第一个成立的，文案全用已有的（`等待 {n} 个子任务完成`、`等 {n} 个后台命令`、`等工作流跑完`、`等待你的下一条消息`），等别人的结果时左边是转圈的 `Loader2`、等下一句才是对话气泡 + `WaitDots`。行上带 `data-chat-wait={kind}`，界面检查按它取这一行、不按文字猜。以前这里只判 `!working && task.awaitingUser && task.cliAlive`、完全不看子任务 / 后台命令 / 工作流，于是「派出的子任务还在跑命令」时也说「等待你的下一条消息」（还配一个「空闲」，见 `LiveStats` 的 `waiting`，等别人的结果才传、等下一句不传，那时它确实空闲），用户以为对话在等他、其实是它在等子任务（见 [bugs/chat-wait-says-next-while-helper-running](bugs/chat-wait-says-next-while-helper-running.md)）。两个细节：`next` 还要 `awaitingUser` 为真才显示（只预热完、还在启动时不写成在等你）；`answer` / `confirm` 返回 `null`，等用户回答由对话里的提问卡片表达，不在状态行重复。**不要在这里另写一套「有没有东西在跑」**：项目里已经有 `convState` / `childWait` 两个判定，再加第三个就会重演「各处 filter 一遍、条目数对不上」的老问题。

- 设置页（`web/src/pages/SettingsPage.tsx`）的「同时运行的后台命令」取 `Settings.backgroundLimit`（默认 64，范围 1–64）；对话设置弹窗（`web/src/components/tasks/ConversationSettingsDialog.tsx`）管名称、目标、全局规则、子对话用的 Agent / 模型和「停止全部子对话」，没有再放并发数设置（也没有「同时执行的子对话」）。
- 设置页右侧的节内小节导航（`web/src/components/settings/section-nav.tsx`）：**没有 Provider**，状态放在模块级变量里（`entries` / `container` / `snapshot` / `listeners`），对外只有三个东西 —— `setSectionScroll`（回调 ref，直接挂在内容区的滚动 div 上：`<div ref={setSectionScroll} className="min-h-0 flex-1 overflow-y-auto px-5 pb-10 md:px-8">`）、`useSectionAnchor(label)`（`Group` 内部用，挂载时把自己登记进 `entries`、卸载时移除）、`SectionToc`（菜单本体，`useSyncExternalStore(subscribe, () => snapshot)` 订阅模块状态，`subscribe` 的 cleanup 返回 `void`，不能把 `Set.delete` 的 boolean 直接返回出去）。不套 Provider 是因为套上要把那一整列内容的缩进重排一遍（上千行缩进变化），会掩盖真正的改动；设置弹窗同时只有一个实例，模块级状态不会串。`Group`（`web/src/components/settings/parts.tsx`）有 `title` 时自动把自己注册成一个小节、id 由 `useSectionAnchor` 生成，标题就是菜单文字；`SectionToc` 只有两个以上小节才显示，挂在设置页 header 下面、滚动容器上面（在滚动容器之外所以一直可见，窄屏横向一行可滚动，不另占竖直空间、不浮在内容上遮挡）。判定逻辑（`activeIndex` / `atBottom` / `jumpTop`，含 `SCROLL_GAP = 12`、`BOTTOM_SLACK = 2`）是 `web/src/lib/section-nav.ts` 里的纯函数，`.tsx` 只负责 DOM 和状态。高亮按每个小节 `section` 的 `getBoundingClientRect().top` 相对容器顶部传给 `activeIndex`，滚到容器最底部时按 `atBottom` 强制算最后一个（`BOTTOM_SLACK`，否则最后一段短内容高亮不到）；点小节用 `container.scrollTo({ behavior: 'smooth' })`，位置由 `jumpTop` 算（小节顶部 - `SCROLL_GAP`）。视觉上故意和左栏一级导航区分：只有文字没有图标、字号 `text-[0.75rem]`、选中态是底部一条 2px 圆角高亮线（`after:bg-accent`），左栏那套是 `bg-sel` + 图标。回归：`web/src/lib/section-nav.test.ts`（4 条：当前小节取越过容差线的最后一个、滚到底算最后一个、到底判定、跳转留白不滚成负数）。设置页「常规」拆成的小节标题（顺序即渲染顺序）：执行与超时 / 会话保活 / 后台命令 / 界面与启动 / 输入与文件 / 提示与通知；哪些 `Group` 有 `title` 就自动进菜单，别的分节（CLI、生图等）本来就有 `title`，也一起生效。
- 设置页「可用的模型」行（`web/src/components/settings/ApiSection.tsx` 的 `ApiCard`）：「测试连接」前面是一个模型下拉（`Select`，`aria-label` 是 `t('测试连接用的模型')`），选项取 `modelsForProtocol(a.models, a.protocol)`，第一个就是默认模型；没有模型时下拉禁用、选项里只有一句引导「先点『从接口获取』或手动填写模型」。点「测试连接」时用**选中（或第一个）的模型真的发一次请求**（`api.probeApiModel` → `POST /accounts/api-probe`），成功提示「模型 X 可用」，失败把服务端返回的原文显示在卡片里并弹 toast，不自动重试；一个模型都没有时退回原来的「只验证能列出模型」，提示里写明这次只验证了连接。选中的模型用 `probeTarget`（`web/src/lib/api-probe.ts`）算：选过且还在列表里就用它，被移除或换了协议后回到第一个。切换下拉时同时清掉上一次的测试结论（`pickProbeModel`），免得把「模型 A 可用」误读成 B 也通过了。回归：`web/src/lib/api-probe.test.ts`、`server/api-config.test.ts` 的「API 探针」几条。
- 设置页的「网络代理」挪到新的「连接」分组下的「网络与代理」分节（`sectionsFor` 里 `{ id: 'network', label: t('网络与代理'), icon: Network, group: t('连接') }`，排在「外部访问」后面），组件是 `web/src/components/settings/NetworkSection.tsx`，内容是「启用代理」开关（`Settings.networkProxyEnabled`，默认 true）+「代理地址」输入（`Settings.proxy`，开关关掉时输入框 `disabled`）。在线演示（`VITE_DEMO`）时不显示这一页（和「外部访问」一样被 filter 掉）。开关的语义以服务端为准：`server/net.ts` 的 `configuredProxy(settings)` 在 `networkProxyEnabled` 为 false 时返回空串，于是 `planFor` 走「环境变量 `HTTPS_PROXY` → 直连」，失败后的本机代理自动探测（`localProxies`）照旧执行——关掉只跳过设置里这个地址，不关闭环境变量和自动探测（说明文字按这个实际行为写）；`server/net.ts` 里两处服务端报错文案随之从「设置 · 常规 · 网络代理」改成「设置 · 网络与代理」。
- 项目设置「AI 初始化」页（`web/src/components/projects/ProjectInitPanel.tsx`、`ProjectSettingsDialog.tsx`）：初始化推荐随项目保存，重开时用 `buildGroups` 的 `same` 判定算差异，「应用推荐（n 项）」只改草稿、点「确认」才保存，无差异时提示「已和当前设置一致」；没有保存过推荐时只提供重新初始化。
- 在线演示：`vite build --mode demo` 时把 API 换成浏览器里的模拟实现（`web/src/lib/demo-*.ts`），正式包里不能有这些内容。
