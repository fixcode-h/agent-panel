[web 模块](README.md)的子页面：设置页的搜索、内容区写法、用量统计、回收站、节内导航、可用模型、网络代理，项目设置的「AI 初始化」。模块的状态块、入口、依赖和回归验证见 [README.md](README.md)，Bug 记录见 [bugs.md](bugs.md)。

2026-10-31 从 `README.md` 原样挪出（文字没改），各条的日期和结论以当时为准。

## 职责与实现

- 设置页的搜索（左栏顶部，Ctrl / ⌘ + F 聚焦）：跨所有页搜设置项的标题、说明、问号里的详细说明（`hint`）和小节名，点结果切到那一页、滚到那一行并闪一下。索引在构建时由 `scripts/lib/settings-index.mjs` 的 Vite 插件（`virtual:settings-index`）从 `SettingsPage.tsx` 和 `components/settings/*.tsx` 抽出：`cur.id === 'xxx' && …` 里的 `<Row title desc>` / `<Group title>` 归 xxx 页，用到的组件跟着归页，`cur.cli && …` 记成 `@cli`、界面上落到默认 CLI；只认字面量文案（`'…'`、`t('…')`），动态标题搜不到。所以**新设置项照常写 `<Row title={t('…')} desc={t('…')} hint={t('…')}>` 就能被搜到**；同一页不同小节可以同名（Markdown 样式每组都有「字号」），索引按「页 + 小节 + 标题」去重，不用另外登记；放在 settings/ 以外的目录时要把文件加进 `settingsSourceFiles`。判定和高亮在 `web/src/lib/settings-search.ts`。回归：`scripts/lib/settings-index.test.mjs`、`web/src/lib/settings-search.test.ts`、`scripts/ui/05-settings.mjs` 的「设置-搜索」。
- 设置页右侧内容区的写法（用户 2026-10-31 定的改版方案，公共件都在 `web/src/components/settings/parts.tsx`）：① `Row` 的标题是 2～6 个字的名词短语，组名里有的词不重复；`desc` 只写一行（20 字左右）说「开了会怎样」，边界情况、原理、和别的项的关系写进 `hint`，渲染成标题旁的问号（`HelpTip`）。② `Group` 是组名在外、内容在一张浅底圆角卡片里（`.settings-card`，底色从 `--color-fg` 混出来，不描边），卡片里的行、折叠和自定义内容之间一道细线；内容是大块自定义排版时传 `plain`。③ 数字项用 `NumberField`：单位在框里，0 表示不限 / 关闭的传 `empty` 占位字（存储仍是 0）。④ 控件栏定宽 280px、靠右：开关靠 `.settings-row` 的 CSS 贴右，下拉是 ghost 样式自带 `ml-auto`，窄输入框写 `ml-auto block w-…`。⑤ 从属于总开关的项写 `indent`，总开关关着时不渲染；路径、端口、镜像、额外参数这类不常改的放进 `Advanced`（原生 `details`），`revealSetting` 跳到里面的项时会先展开。
- 设置页的用量统计（`web/src/components/usage/UsageSection.tsx`）：工具条上先选分组（`USAGE_GROUPS`：按时间 / 按项目 / 按对话），按时间时再选粒度（按天 / 按周 / 按月）和时间区间；按项目 / 对话固定汇总近 `USAGE_LOOKBACK_DAYS` 天、隐藏区间选择器，表格第一列换成项目名（被删或不属于项目时写清）或对话标题，其余列和表尾合计口径不变——同一份聚合、同一个 `usageCost`，不出现第二个叫「费用」的数字（教训 `lmvkw5gib0c5n`）。分组报表单独请求，切回按时间不用重新取。回归：`shared/usage.test.ts`（三种分组合计一致、空项目归到空 key、窗口过滤）、`scripts/ui/05-settings.mjs` 的「设置-用量统计-按项目 / 按对话」。
- 回收站（设置 →「数据」→ `web/src/components/settings/TrashSection.tsx`，接口见 [server README](../server/README.md)「对话回收站」）：列出已删除的对话（标题、删除时间、剩余天数由服务端按同一个保留期算好、含几个子对话），两个操作——恢复（`api.restoreTask`；返回 `worktreeCleared` 时用 toast 明确说「独立分支目录已经清理，恢复后需要重新执行」）和永久删除（点两次确认：第一次把按钮换成「再点一次」，鼠标移出这一行就撤回）。恢复 / 永久删除后重新拉回收站列表并 `reloadTasks()`，侧栏、标题计数立刻跟着变。侧栏右键菜单、任务页的删除按钮和「批量删除未运行的对话」都走同一个 `DELETE /tasks/:id`，所以都是先进回收站；三处确认框的文案也都写清了「{days} 天内可以在设置 →「数据」→ 回收站里恢复」，天数取自 `TRASH_RETENTION_DAYS`，不写死。
- 设置页（`web/src/pages/SettingsPage.tsx`）的「同时运行的后台命令」取 `Settings.backgroundLimit`（默认 64，范围 1–64）；对话设置弹窗（`web/src/components/tasks/ConversationSettingsDialog.tsx`）管名称、目标、全局规则、子对话用的 Agent / 模型和「停止全部子对话」，没有再放并发数设置（也没有「同时执行的子对话」）。
- 设置页右侧的节内小节导航（`web/src/components/settings/section-nav.tsx`）：**没有 Provider**，状态放在模块级变量里（`entries` / `container` / `snapshot` / `listeners`），对外只有三个东西 —— `setSectionScroll`（回调 ref，直接挂在内容区的滚动 div 上：`<div ref={setSectionScroll} className="min-h-0 flex-1 overflow-y-auto px-5 pb-10 md:px-8">`）、`useSectionAnchor(label)`（`Group` 内部用，挂载时把自己登记进 `entries`、卸载时移除）、`SectionToc`（菜单本体，`useSyncExternalStore(subscribe, () => snapshot)` 订阅模块状态，`subscribe` 的 cleanup 返回 `void`，不能把 `Set.delete` 的 boolean 直接返回出去）。不套 Provider 是因为套上要把那一整列内容的缩进重排一遍（上千行缩进变化），会掩盖真正的改动；设置弹窗同时只有一个实例，模块级状态不会串。`Group`（`web/src/components/settings/parts.tsx`）有 `title` 时自动把自己注册成一个小节、id 由 `useSectionAnchor` 生成，标题就是菜单文字；`SectionToc` 只有两个以上小节才显示，挂在设置页 header 下面、滚动容器上面（在滚动容器之外所以一直可见，窄屏横向一行可滚动，不另占竖直空间、不浮在内容上遮挡）。判定逻辑（`activeIndex` / `atBottom` / `jumpTop`，含 `SCROLL_GAP = 12`、`BOTTOM_SLACK = 2`）是 `web/src/lib/section-nav.ts` 里的纯函数，`.tsx` 只负责 DOM 和状态。高亮按每个小节 `section` 的 `getBoundingClientRect().top` 相对容器顶部传给 `activeIndex`，滚到容器最底部时按 `atBottom` 强制算最后一个（`BOTTOM_SLACK`，否则最后一段短内容高亮不到）；点小节用 `container.scrollTo({ behavior: 'smooth' })`，位置由 `jumpTop` 算（小节顶部 - `SCROLL_GAP`）。视觉上故意和左栏一级导航区分：只有文字没有图标、字号 `text-footnote`、选中态是底部一条 2px 圆角高亮线（`after:bg-accent`），左栏那套是 `bg-sel` + 图标。回归：`web/src/lib/section-nav.test.ts`（4 条：当前小节取越过容差线的最后一个、滚到底算最后一个、到底判定、跳转留白不滚成负数）。设置页「常规」拆成的小节标题（顺序即渲染顺序，用户 2026-10-31 从 8 个合并成 5 个）：界面 / 输入 / 运行 / 后台会话 / 通知与安全；哪些 `Group` 有 `title` 就自动进菜单，别的分节（CLI、生图等）本来就有 `title`，也一起生效。
- 设置页「可用的模型」行（`web/src/components/settings/ApiSection.tsx` 的 `ApiCard`）：「测试连接」前面是一个模型下拉（`Select`，`aria-label` 是 `t('测试连接用的模型')`），选项取 `modelsForProtocol(a.models, a.protocol)`，第一个就是默认模型；没有模型时下拉禁用、选项里只有一句引导「先点『从接口获取』或手动填写模型」。点「测试连接」时用**选中（或第一个）的模型真的发一次请求**（`api.probeApiModel` → `POST /accounts/api-probe`），成功提示「模型 X 可用」，失败把服务端返回的原文显示在卡片里并弹 toast，不自动重试；一个模型都没有时退回原来的「只验证能列出模型」，提示里写明这次只验证了连接。选中的模型用 `probeTarget`（`web/src/lib/api-probe.ts`）算：选过且还在列表里就用它，被移除或换了协议后回到第一个。切换下拉时同时清掉上一次的测试结论（`pickProbeModel`），免得把「模型 A 可用」误读成 B 也通过了。回归：`web/src/lib/api-probe.test.ts`、`server/api-config.test.ts` 的「API 探针」几条。
- 设置页的「网络代理」挪到新的「连接」分组下的「网络与代理」分节（`sectionsFor` 里 `{ id: 'network', label: t('网络与代理'), icon: Network, group: t('连接') }`，排在「外部访问」后面），组件是 `web/src/components/settings/NetworkSection.tsx`，内容是「使用代理」开关（`Settings.networkProxyEnabled`，默认 true）+「代理地址」输入（`Settings.proxy`，开关关掉时输入框 `disabled`）。在线演示（`VITE_DEMO`）时不显示这一页（和「外部访问」一样被 filter 掉）。开关的语义以服务端为准：`server/net.ts` 的 `configuredProxy(settings)` 在 `networkProxyEnabled` 为 false 时返回空串，于是 `planFor` 走「环境变量 `HTTPS_PROXY` → 直连」，失败后的本机代理自动探测（`localProxies`）照旧执行——关掉只跳过设置里这个地址，不关闭环境变量和自动探测（说明文字按这个实际行为写）；`server/net.ts` 里两处服务端报错文案随之从「设置 · 常规 · 网络代理」改成「设置 · 网络与代理」。
- 项目设置「AI 初始化」页（`web/src/components/projects/ProjectInitPanel.tsx`、`ProjectSettingsDialog.tsx`）：初始化推荐随项目保存，重开时用 `buildGroups` 的 `same` 判定算差异，「应用推荐（n 项）」只改草稿、点「确认」才保存，无差异时提示「已和当前设置一致」；没有保存过推荐时只提供重新初始化。初始化对话跑完、结果交回项目时走 `api.saveProjectInitResult`（`PUT /projects/:id/init-result`，`ProjectSettingsDialog.tsx` 的 `deliver`）：**只写 `initResult` / `initializedAt`，服务端自己读最新项目再用 `shared/project-init.ts` 的 `withInitResult` 合并**；对话可能跑好几分钟，整份项目 PUT 回去会把用户这期间应用的推荐覆盖回旧值、界面又变回「N 项待应用」（[bugs/init-apply-overwritten-by-snapshot](bugs/init-apply-overwritten-by-snapshot.md)）。对话右侧报告面板（`ProjectInitReport.tsx` 的 `apply`，逐项 / 整组 / 全部应用）是另一条路径：应用前按 `api.projects()` 取一次最新项目当基线，再保存；`api.projects()` 失败会回落到面板打开时的草稿，这条兜底仍带着「GET → 整份 PUT」的竞态，见该 Bug 记录的「已知限制」。测试步骤区域的说明文案写「改了这里，进行中的对话下一轮、下一次子对话合并就按新步骤执行」：
  **范围三档**（2026-10-28，[ADR 0021](../../adr/0020-test-scope-and-incremental-tests.md)）：测试步骤编辑器每条多一个「范围」选择器——`always` 每次改动都跑、`changed` 命中「适用改动」才跑、`parent` 全量、子对话不跑、合并后由父对话跑（合并了原来的「禁止子对话执行」复选框，非 Git 项目在选项文字里说明由执行者自己跑）。改了测试步骤和验证范围相关代码后，界面检查的 `07-projects` 分片断言头部说明和「范围 / 总是跑」；本次改动的增量定位由 `scripts/changed-tests.mjs` 算（分片覆盖表 `scripts/ui/covers.mjs`）。
  执行侧确实现读项目设置（见 server 模块 README 的 `currentTestSteps`），不再是「新建对话时快照、之后不影响」；改这句时连同 `shared/locales/en/tasks.ts` / `settings.ts` 的英文一起改。
