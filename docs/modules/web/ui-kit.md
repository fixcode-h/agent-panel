## 职责与实现

- 组件库（`web/src/components/ui/`，样子在「设置 → 组件」`web/src/components/settings/ComponentsSection.tsx` 里按当前配色画出来，新部件要在那里加一格）：页面只拼部件，不手写按钮 / 弹窗外壳 / 颜色。边界靠底色分、不描边，颜色只用 `web/src/index.css` 的 token；深色下靠 `seg-track` / `seg-thumb` / `sunken`（凹下去：弹层搜索框、进度条轨道）/ `chip-idle`（没选中的小块，深色提亮）拉开对比。常用写法：
  - 按钮：`Button` 的 `variant`（primary / secondary / ghost / danger / danger-outline / `link`（文字链接，`tone` 取 accent / muted / warning，不套高度和留白）/ `on-canvas`（深色画布上））；只有图标的用 `IconButton`（`icon` 传 lucide 组件、`label` 同时进 aria-label 和 title，`size` sm 28px / xs 24px / 2xs 20px，`tone="danger"`，`reveal="hover"` 行悬停才出现、行上要有 `group`）；图标开关用 `ToggleIconButton`（`pressed` / `onPressedChange`，aria-pressed，开着换强调色不加底色）。
  - 动效和悬停（照 Claude Code 网页版的 cds 令牌，定义在 `index.css` 的 `:root`）：时长 `--dur-fast` 60ms（悬停、所有退场）/ `--dur-snap` 120ms（菜单、提示进场）/ `--dur-base` 200ms（开关、输入框）/ `--dur-sheet` 300ms（弹窗、抽屉），曲线 `--ease-snap` / `--ease-overshoot` / `--ease-spring`，Tailwind 里写 `duration-(--dur-snap) ease-(--ease-snap)`，不写死 `120ms ease-out`。现成的工具类：弹出菜单、下拉、浮层 `anim-pop`（从触发点缩放，Radix 关闭时自动 60ms 退场；非 Radix 浮层用 `[--pop-origin:…]` 指定生长方向）、遮罩 `anim-scrim`、弹窗本体 `anim-dialog`、按钮按压 `press`、拖文件进来 `drop-ring`。悬停底用 `bg-hover`（前景色 6%）、按下 / 展开用 `bg-active`（10%），菜单外框用 `border-pop-edge`；选中项仍是 `bg-sel`。系统开了「减少动态效果」时这些时长都变成 1ms。`Segmented` 切换时选中块会滑过去，平时选中底仍画在按钮身上。只有一段文字的悬停提示是反色小块（`hint-simple`），富提示仍用 `hint-surface`。
  - 字号、圆角和排版（同样取自 cds 令牌，定义在 `index.css` 的 `@theme`）：字号写角色名 `text-micro` 10 / `text-caption` 11 / `text-footnote` 12 / `text-body` 13 / `text-prose` 14 / `text-heading` 15 / `text-subtitle` 17 / `text-title` 20 / `text-display` 28 / `text-hero` 34（px，跟着设置里的字号缩放；不带行高，要行高另写 `leading-*`）；圆角 `rounded-sm` 5 / `rounded-md`、`rounded-lg` 7 / `rounded-xl` 10 / `rounded-2xl` 14 / `rounded-3xl` 20，8px 以下的小色块按自身大小写。手写 `text-[…rem]`、5px 以上的 `rounded-[…]` 会被 `rules-check` 拦。中文排版在 `body` 上开了 `text-spacing-trim` 和 `text-autospace`（代码里关掉），段落 `text-wrap: pretty`、标题 `balance`。可滚动的列表加 `scroll-fade`（还能往哪边滚，哪边边缘渐隐 16px）；展开收起用 `ui/collapse.tsx` 的 `Collapse`（高度过渡，收着的内容不渲染）；新插进列表的行加 `row-enter`；原地切换的图标、字样用 `.swap`（`ui/copy-icon.tsx` 的 `CopyIcon`）。
  - 选择：两三个互斥项用 `Segmented`（`size="sm"`、`fill`、深色画布上 `tone="canvas"`）；选项多或要多选用 `ChipGroup`（`multiple` 时 value 是数组；单选按 radiogroup / radio 读，多选按 group + aria-pressed 读）。
  - 输入：`Input` / `Select` 的 `size="sm"`（32px，和 sm 按钮同高；不传和原来一样）；弹层顶部的搜索框用 `MenuSearch`；原地改名用 `InlineRename`（回车 / 失焦提交、Esc 取消，Esc 在 window 捕获阶段拦下，放在弹窗里不会把弹窗一起关掉；一次编辑只回调一次）。
  - 弹层：表单弹窗 `Modal`（`size` 每档固定宽度并带最小高度：sm 420（确认、改名，不设最小高）/ md 520（默认，最小高 320）/ lg 800（= 旧的 `wide`，宽表单，最小高 480）/ term 1600（命令行、工具输出窗口，最小高 560）/ xl 1100（差异、文件、工作流运行、审阅，最小高 640）/ full（只给 Chat、ComfyUI、AI 处理这类本身是应用的窗口）/ fit（一次编辑的差异，xl 宽、跟着内容高）；`bare` 只要外壳、内容自己画；`closeOnOutside` 给只看不填的弹窗）；遮罩统一用 `MODAL_OVERLAY`（透明度在 `--scrim`），手写 `D.Overlay` 时也用它；侧边抽屉 `Sheet`（Radix Dialog，`side` / `width` / `actions` / `footer`，`modal={false}` 不压遮罩）；输入框上方弹出的一层 `ComposerPopover`（父元素 relative，`stretch` 撑满输入框、`scroll` 内部滚动）。
  - 其他：页内切换的页签 `TabBar variant="underline"`（TabItem 自动跟着画，2px 圆头强调色下划线、不出底色）；进度条 `Progress`（`value` / `max` 夹紧到 0–100%，`tone`，`size` xs / sm，role=progressbar）；卡片 `Card`（`padding` none / xs / sm / md / lg，`interactive` 整张可点，`as` 选标签）。
  - 深色画布（设计页画板、预览台）：不跟主题变的一组 token `--canvas` / `--canvas-bar` / `--canvas-fg` / `--canvas-strong` / `--canvas-subtle` / `--canvas-hover` / `--canvas-sel` / `--canvas-line`（Tailwind 里是 `bg-canvas`、`text-canvas-fg` 等），底色按配色的 `--rail` 带一点色相；上面的按钮用 `variant="on-canvas"`，分段用 `tone="canvas"`。回归：`scripts/ui/05-settings.mjs` 的「设置-组件-新部件」。
- 全局提示（toast）统一从 `web/src/lib/toast.ts` 取（`import { toast } from '@/lib/toast'`），不再直接 `import { toast } from 'sonner'`；只有 `web/src/App.tsx` 还从 sonner 引 `Toaster`（本体只能从 sonner 拿）。`scripts/rules-check.mjs` 第 12 条拦回退，确实要直接拿 sonner 的（例如在入口里实现透传）在那一行或上一行写 `sonner-toast-ok: 原因`。多这一层只为排队：**sonner 的 `visibleToasts` 不是排队**——它按 `index + 1 <= visibleToasts` 把超出的设成 `data-visible="false"`（opacity 0、不吃指针），但这些提示照样在数组里、照样按 4 秒计时，到期直接丢弃，后面的不补位。要「同屏几条、其余等前面的消失后再出现」只能自己控制投递时机，实现在 `web/src/lib/toast-queue.ts`：`TOAST_VISIBLE_LIMIT = 4`（提示绝大多数是一句话，4 条约占右上角 320px，1080 高的窗口还剩 2/3 露出对话；批量操作连发十几条时，超出的按先后排队），`enqueueToast(publish)` 名额没满就投递、满了推进 `waiting` 队尾，`finishToast(id)` 在 sonner 真的移除一条时腾名额、补位队首（同一个 id 只结算一次——`onAutoClose` 和 `onDismiss` 两个回调都会来），`clearToastQueue()` 把屏幕上的名额和排队的全丢掉（`toast.dismiss()` 关掉全部时用，否则排队的那几条之后会莫名弹出来），`toastQueueState()` 给单测看快照。`toast.ts` 的透传语义：`success` / `error` / `warning` / `info` / `message` 和裸 `toast()` 都经过队列，`duration`（含 `Infinity`）、`action`、`description` 里的 JSX 原样交给 sonner，调用方自己写的 `onDismiss` / `onAutoClose` 照常调用（包在 `withQueue` 里，先结算队列再调原回调）；`dismiss(id)` 关指定那条并补位，`dismiss()` 关全部并清空队列，`getHistory` 直接透传。返回值仍是 sonner 的 id，排队时返回 `undefined`（现有调用点都没用返回值，也没有 `loading` / `promise` / `custom` 调用）。
  - 视觉和顺序（`web/src/App.tsx` 的 `Toaster`）：`position="top-right"` + `expand` + `closeButton`。最新的一条在最上面、依次往下，是 sonner 在 top 位置的默认行为（新提示插到数组头部、`--offset` 按前面的高度累加），不用额外参数；`expand` 必须开，不开时 sonner 把非 front 的提示压成一条边、内容透明，和「依次展示下来」相反。**`visibleToasts` 必须显式设成 `TOAST_VISIBLE_LIMIT` 同一个数**：不设时 sonner 默认 3，队列放进来的第 4 条会被它设成 `data-visible="false"` 默默藏掉，DOM 里 4 条、用户只看到 3 条。
  - 提示样式（`web/src/index.css`）：`[data-close-button]` 默认 `display: none`（大多数提示只是告诉用户「做完了」，常显的 ✕ 抢正文的注意力），`:hover` 和 `:focus-within` 时 `display: flex` 并挪到右上角里侧（`top: 6px; left: auto; right: 6px; transform: none`——sonner 默认把它压在右上角外侧，会盖住第一行文字），`@media (hover: none)` 下常显（触屏没有悬停，否则手机上永远关不掉）。`[data-sonner-toast][data-styled='true']` 的 `transition-duration` 压到 `0.2s`：sonner 在 200ms（`TIME_BEFORE_UNMOUNT`）就卸载退出的提示，默认 `.4s` 的过渡播不完就被掐掉、看起来是「闪一下没了」。`prefers-reduced-motion` 交给 sonner 自己的媒体查询关动效，这边不要用 `!important` 盖回去。这些规则都带 `html` 祖先提优先级：sonner 用 JS 往 head 末尾插样式（排在打包样式表之后），同特异性压不住。
  - 回归：`web/src/lib/toast-queue.test.ts`（名额内直接投递、超出排队先不投递、按先进先出一次只补一条、同一 id 只结算一次、外来 id 不影响名额、连续十条不排队、清空后不再补位）、`scripts/ui/10-toast.mjs`（位置在右上角、最新的在最上面、同屏上限 4 条且每条真可见、悬停显示关闭按钮、移开收起、键盘聚焦也能出现、关一条后排队的补位、过渡时长 <=200ms、关掉全部不留残余）。`web/src/lib/ai-window-close.test.ts` 从 `@/lib/toast` 取 `toast`。
  - 和最小化浮条的关系：提示在右上角，不再压住右下角的最小化浮条（`web/src/components/ui/minimized-chat.tsx`，`DEFAULT_INSET` 贴右下角）。给浮条截图或做悬停断言时不用再先等提示消失（提示在右下角时两者会重叠，那些等待只对那个布局有意义）。
