## 职责与实现

- AI 分析的归属与窗口（[ADR 0014](../../adr/0014-ai-analysis-home.md)）：所有「AI 分析」「AI 处理」都走 `web/src/lib/ai-window.ts`——`createAnalysisTask` 按 `shared/analysis-home.ts` 的 `analysisHome` 定放哪（项目里的顶层对话和它名下的子任务另开一个项目顶层对话、子对话里的分析开成它顶层对话的子对话、项目相关的开项目对话、其余开 Chat；2026-11 改，见 ADR 0014 的「补充」），角色取必备角色「分析」；`openAiWindow` 打开唯一的窗口 `components/ai-window/AiWindow.tsx`（TaskView 嵌在里面，可最小化、可接着问；「去对话里看」按对话自己的 `parentTaskId` / `projectId` 选「在父对话里打开 / 在项目对话里打开 / 在聊天里打开」，子对话用 `showChildInPane` 记下右栏子对话再跳过去）。报错按钮 `openAiFix` 传 `home` 指明归属。已有项目的「AI 初始化项目」走 `web/src/lib/assist-conv.ts`：`/assist/prompt` 取第一句话、对话结束后 `/assist/resolve` 解析推荐。
- 看对话的大窗口外壳（`web/src/components/ai-window/ChatWindow.tsx`）：AI 分析窗口（`AiWindow`）和子任务窗口（`HelperCards.tsx` 的 `HelperWindow`）共用同一个外壳——尺寸（设计稿 AiWindow 的 1300×828）、标题栏（黑底图标、类型名、对象标签、「来自…」、状态胶囊、对话自己的操作、管窗口的按钮 `WIN_BTN`），两边改样式只改这一处。子任务窗口没有右侧的项目文件 / 本对话改动栏，输入框的位置换成同样外形的只读说明（子任务做完 CLI 已退出，不能追问）。分析对话的第一条（面板拼好的报错 / 记录）不管在窗口里还是「在…里打开」放大到对话页，都画成折叠的「分析对象」卡片（`TaskView.tsx` 里 `UserMessage` 的 `subject`，只看 `isAnalysisTask`，不看 `embed`）。
- 最小化浮条全场只留一个（`web/src/lib/chat-dock.ts`，用户要求「同时只能存在一个最小化弹窗」）：`components/ui/minimized-chat.tsx` 的 `MinimizedChat` 挂载时调 `addDock(key)` 登记、卸载时注销，用 `useSyncExternalStore` 读栈，**只有栈顶那个渲染**，其余 `return null`（DOM 不挂载，但组件实例和状态都在，等栈顶让位就自己露出来）。三类浮条——AI 排查（`AiWindow`，id `ai-fix`）、AI 优化（`components/assist/AssistDialog.tsx`，id `assist`）、转成弹窗的对话（`components/tasks/TaskDock.tsx`，id `mini-task`）——因此自动共用这一条约束。**登记单位是实例号（`useId()`）而不是业务 id**：`AssistDialog` 在好几个页面各挂一份、id 都是 `assist`，按 id 判会让两个实例都以为自己是栈顶、一起显示，互斥就被绕过了。`dockSnapshot` 必须返回**同一个数组引用**（栈只在登记 / 注销时换新数组），写成 `slice()` 会让 `useSyncExternalStore` 认为快照一直在变、撞 React error #185 无限重渲染。因为任意时刻只有一个，`slot` 向上错开的机制连同 `slotPos` / `GAP` 一起删了：没拖过的浮条一律贴右下角（`DEFAULT_INSET`）；位置仍按业务 id 分别记进 `minimized-chat-pos`。回归：`web/src/lib/chat-dock.test.ts`（登记顺序、重复登记只提栈顶、同 id 两个实例只显示一个、快照引用稳定、注销后下一个露出来、StrictMode 挂载-卸载-再挂载只留一条）、`scripts/ui/06-settings-agent.mjs` 的「AI处理-浮条只留一个」「AI处理-浮条让位后回来」。
- 浮条的外观与交互：整条是一个胶囊（`h-11`），**不挂任何原生 `title`**——主体按钮几乎盖满浮条，`title` 一悬停就弹灰框（用户报的就是这个「展开」提示），拖动提示同理，浮条本体已有 `cursor-grab` 自解释；可访问名字走 `aria-label`（展开 / 关闭）。**关闭按钮在右上角、鼠标进浮条才出现**（`CLOSE_SIZE` / `CLOSE_INSET_X` / `CLOSE_INSET_Y` 定小圆直径和它在右上角的内缩距离，`CLOSE_RESERVE` 是主体按钮右侧给它让出的宽度）：按钮铺满整个右上角一块（外扩一点点，移出去的余量仍落在按钮里，不会淡出到点不到），里面是一个带边框的小圆，用 `opacity-0 group-hover:opacity-100 focus-visible:opacity-100 [@media(hover:none)]:opacity-100`（照 `TaskView.tsx` 标题栏「解决」的写法：键盘能聚焦到、触屏没有 hover 所以常显）；用 `opacity` 而不用 `hidden` / `invisible`，隐藏态仍能点。**浮条保持 `h-11`、尺寸不变**：它是 `position: fixed`，本身已是关闭按钮的定位参照（不再加 `relative`，会把 `fixed` 顶掉），绝对定位不占流，`clampPos` 的 `offsetWidth/offsetHeight` 和拖动判定（`data-dock="close"` + `intent` + `clickGuard`）都不受影响。回归：`scripts/ui/06-settings-agent.mjs` 的「AI处理-浮条-不悬停」「AI处理-浮条-悬停」、`scripts/ui/02-task.mjs` 的「任务-转成弹窗-悬停显示关闭」（用 `getComputedStyle` 的 `opacity` 判，不用 `isVisible`——`opacity-0` 也算 visible；位置断言量的是那个 20px 小圆（`[data-dock="close"] > span`）而不是热区矩形——热区永远贴 `top-0 right-0`，光量热区的话小圆以后挪到左下也照样能过）。浮条和 sonner toast 都在右下角，会互相遮挡：断言悬停或拍特写前先等 toast 消失；特写截图走 harness 的 `shotOf()`，它把 clip 夹进视口（浮条夹回视口只留 `EDGE=8px`，直接按矩形加留白算会跨出页面、Playwright 直接报错、整个分片报废）。
- 对话「转成弹窗」（`web/src/lib/mini-task.ts` + `web/src/components/tasks/TaskDock.tsx`）：对话页标题栏 `…` 后面那个按钮（`TaskView.tsx`，`PictureInPicture2` 图标）把当前对话收成右下角的浮条，页面回到上一级（项目里的回项目页、Chat 的回新聊天页）。按钮只在**对话页本体**显示：`pane` 右栏子对话、`embed` 的 AI 窗口里都不给（右栏本来就在对话旁边、AI 窗口自己已有最小化按钮），导入的任务不给，**子对话也不给**——浮条的标题和状态靠 `useData().tasks` 找对话，而 `GET /tasks` 只回顶层对话（`server/tasks.ts` 里 `list.filter((t) => !t.parentTaskId)`），子对话收起来会一出现就写「对话已关闭」。收起状态只存一份 `MiniTask`（id + projectId），**再最小化另一个对话就天然替换掉前一个**，和 `chat-dock` 的跨类别互斥合起来保证屏幕上最多一个浮条。`TaskDock` **要读当前路由**（`mini-task.ts` 的 `shownInPage`）：页面正显示的就是这条对话时不挂浮条——用户从侧栏把它点开、或点了浮条的展开，同一份内容都不能同时以页面和浮条两种形态出现。状态文字复用 `ChatDockState`（`mini-task.ts` 的 `dockStateOf` 从 `shared/task.ts` 的 `taskBusy` / `taskState` 派生，和侧栏、标题栏同一份判定，不另发请求）：`running` → 进行中、`needs`（等你处理）→ 等你处理、`failed` → 失败、`done` → 已完成，其余（停下 / 未完成 / 已合上）→ 已结束；`needs` 和 `failed` 单独分出来是因为用户收起就是为了跟浮条看进度，都写成「已结束」会让他以为这一轮正常跑完了。对话从列表删掉后显示「对话已关闭」，展开时不再跳转。`onClose` 只收浮条、不停对话（照 `closeAiWindow` 的语义）；收起期间跑完会在浮条上亮红点。挂在 `App.tsx` 顶层，切走页面、对话页卸载了浮条还在。回归：`web/src/lib/mini-task.test.ts`（只有一个、路由、状态映射、`shownInPage`）、`scripts/ui/02-task.mjs` 的「任务-转成弹窗」「任务-转成弹窗只留一个并展开」「任务-转成弹窗-从列表打开后浮条消失」。
- AI 分析的右侧功能面板（[ADR 0016](../../adr/0016-analysis-report-side-panel.md)）：`web/src/lib/analysis-report.ts` 的 `findReport` 认出报告（`run` 执行分析 / `lessons` 教训评审 / `init` 初始化，后者只在 `Task.analysis === 'init'` 时认 JSON 块），`TaskView` 把 `AnalysisPanel` 放进右栏（`reportOn`：没开子对话、运行时占右栏，`task-report:<id>` 记收起；窄屏和 `pane` 用 `reportCover` 盖在对话上）。三种内容：`Evolution.tsx` 的 `EvolutionReport`（修复经 `FixButton` 在当前对话发 `【修复】` 消息，`fixState` 认状态）、`LessonReview.tsx` 的 `LessonReviewReport`、`projects/ProjectInitReport.tsx`（`/assist/resolve` 解析这条回复，`buildGroups` / `RecGroups` 和设置页共用，应用直接 `updateProject`）。标题标签 `tasks/AnalysisMark.tsx`，判定 `isAnalysisTask`。功能面板和中间对话的分界可拖动（用户 2026-10-26 要求，和文件面板同一套）。没有拖动记录时默认**各占一半**（用户 2026-11 要求）：`TaskView` 的 `useHalfPane` + `lib/pane-width.ts` 的 `paneHalfWidth(rowWidth, min)` 按本栏容器量一半，容器还没挂上时按窗口减掉左栏（`RAIL_WIDTH`）估算，窄到一半小于 `min` 时按下限；文件面板共用同一套（`pane:task-panel`），只是 `min` 不同：宽屏并排时 `TaskView` 挂 `ResizeHandle` + `useHalfPane('report-panel', REPORT_PANE_MIN, paneMax 按本栏算)`，宽度记在本机（`pane:report-panel`），和文件面板的 `pane:task-panel` 分开记（两个面板宽度偏好不同）；上限是 `paneMax(rail.current, min)`：从**本栏自己**的 ref 的父容器宽度里扣掉中间至少 320，和文件面板共用模块顶部的 `PANE_GAP`——不能从 document 里取第一个 `[data-task-panel]`，AI 分析窗口是 Portal 挂在 body 末尾的，背景对话页的右栏同样还挂着，量错容器上限就跟着错。窄屏和 `pane` 里的 `reportCover` 是盖在对话上的抽屉，没有并排可拖，那时不挂拖动条、宽度按 `REPORT_COVER_WIDTH`（440）封顶在容器内。`AnalysisPanel` 本身是 `w-full` 弹性布局，里面的卡片都是 `min-w-0` + `truncate`、代码块 `overflow-auto`，拖窄不撑破、拖宽内容自然铺开。回归：`web/src/lib/analysis-report.test.ts`、`scripts/ui/03-library.mjs` 的「AI分析-\*」（含「AI分析-功能面板宽度」拖动、记忆、双击恢复、窄屏无拖动条）、`scripts/ui/07-projects.mjs` 的「AI初始化-右侧设置面板」。
- 排查的结构化结论（`shared/diagnosis.ts`）：`AI 排查`（`fixPrompt`，「直接动手做」的 act 除外）要求回复末尾写 `diagnosis` 代码块（根因 + 把握 + 影响 + 证据 + 修复 + 相关文件）；`findReport` 认成 `diagnosis`，`AnalysisPanel` 的页签换成「结论 / 证据 n / 修复 n / 相关文件 n」（`tasks/DiagnosisReport.tsx`）。结论页三个按钮：「在当前对话里修」把 `diagnosisFixPrompt` 发回被分析的对话（`Task.analysisOf`，`createAnalysisTask` 在 `scope.kind === 'task'` 时记下；没有时就在分析对话里发 `【修复】`），「开新任务修」在同项目新建对话，「记成教训」复用 `RecordLessonDialog`；证据和相关文件的路径点开走对话页的 `FileDialog`（`useFileOpen`）定位到行。块写坏（JSON 不合法、缺根因）时右栏写明原因并摆出原文，对话区也不去掉原文（`stripDiagnosis` 只去掉读得出来的块）。AI 分析窗口里嵌的对话不再画自己的页签行：`TaskView` 的 `embed.slot` 给了窗口标题栏的位置，对话的状态和操作按钮 `createPortal` 挂过去（中间开着子对话、运行页签时仍画页签行）；状态胶囊后面的用时来自 `analysisTiming`（最近一轮的起止，没有轮次时用 `runMs` + `runStartedAt`，拿不到不显示），由 `ai-window.ts` 的轮询记进 `timing`，分析中每秒跳一次。窗口尺寸、卡片和页签照设计稿 AiWindow：窗口最大 1300 宽、高为视口减 72（到 960 为止），四周露出背后的页面；功能面板页签用 `TabBar` 的 `fit`（高 44、选中加粗），结论 / 证据 / 修复的卡片是白底细描边（不用阴影，面板底色和卡片太接近），修复卡片头上写 `+n / −n` 行数，相关文件整行可点；嵌入的分析对话第一句（面板拼好的报错 / 记录）用 `UserMessage` 的 `subject` 画成「分析对象」卡片，不当用户气泡。「修复」页签底部的「应用这 N 处修改」（N 是带 file + before + after、这次还没应用成功的条数，一条都没有时退回「在当前对话里修」）调 `POST /tasks/:id/apply-fixes`：服务端（`server/tasks.ts`）在**被分析对话**（`analysisOf`）的 `taskDir` 里改——它有独立分支时就是 worktree；没有 `analysisOf` 时改分析对话自己的目录；被分析对话不在了直接报错，不退回别的目录；对象正在执行时 409。逐条判定在 `shared/diagnosis.ts` 的 `replaceFix`（原文恰好出现一次才换，CRLF 文件按 CRLF 再找；找不到、多处、缺原文都写原因），落盘和越界检查在 `server/files.ts` 的 `applyFixesInDir`（走 `into`，字面和真实路径都不能出目录），演示版在 `demo-backend.ts` 改 `DEMO_CONTENTS`。前端把所有还没成功的条目都发过去，每张修复卡片显示「已应用」或「没能应用：原因」。证据卡右上的标签来自 `evidence.kind`（`problem` 问题所在 / `reference` 正确口径 / `repro` 复现 / `context` 旁证，写错按没写），排查提示词（`diagnosisPromptRules`）里说明了这个字段和「before 要原样照抄、只出现一次」。左侧对话区在 AI 分析窗口里另有一套样子（`lib/ai-look.ts` 的 `AiLookCtx`，只由 `TaskView` 在 `embed` + 分析对话时打开）：过程折叠默认展开（`fold.ts` 的 `segOpenOf` 带默认值），追问气泡圆角 12、浅一档底色（`ChatMessage.tsx` 的 `UserMessage`），输入框换成追问的占位文字和深一档细线——附件、模型、提问开关都保留，所以没有做成设计稿那样的单行输入框。思考和工具行（`Thinking`、`RowShell`）不另画，和普通对话完全一样（用户 2026-10-31 要求）。回归：`web/src/lib/analysis-report.test.ts`、`server/fix.test.ts`、`scripts/ui/02c-element-pick.mjs` 的「AI排查-结论 / 证据」、`scripts/ui/03-library.mjs` 的「AI 分析」页签行断言。
