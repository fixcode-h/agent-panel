## 职责与实现

- 输入框下的上下文卡（`web/src/components/tasks/TaskMeta.tsx` 的 `ContextChip` / `ContextRow`，纯函数在 `web/src/lib/tasks.ts` 的 `lastCompaction` / `compactionText`）：胶囊上是占用最高的那个 Agent / 节点的「已用 / 窗口」，浮层里每个 Agent / 节点一行，行里除模型、已使用百分比外，最近压缩过时多显示一行「多久前压缩过 · 压缩前 X · 压缩后 Y」；**没有压缩记录的会话 / 节点不显示这一行**。取值按行的归属：工作流按节点（消息 `step` 等于节点 id，或以 `id + '/'` 开头——节点派出的子节点也算这个节点的），对话按 Agent（`message.agentId`），从 `task.messages` 里取最近一条带 `kind: 'compact'` 工具调用的消息，时间取该消息的 `at`；消息顺序在续接、补写时不保证按时间，所以按 `at` 比而不是按数组顺序。前后大小读 `ToolUse.compact`（结构化字段），不解析 `label` 里的中文；缺哪项就不写哪项——老数据没有结构化数值时只剩「多久前压缩过」，CLI 没报数值时只剩「压缩过」，都没有时整行不渲染（窄卡片里放不下时截断，悬停看全文）。回归：`web/src/lib/tasks.test.ts` 的「压缩记录：按节点 / Agent 取最近一次，缺时间、缺数值时降级显示」、`scripts/ui/02-task.mjs` 的「任务-上下文压缩」「任务-上下文无压缩」。

- 输入框附件：加进来先显示，路径查找、拷贝 / 上传都在后台（`web/src/components/chat/Attachments.tsx` 的 `useAttachments`，状态和发送口径在 `shared/attachment-view.ts`）：选文件、拖入、粘贴时浏览器只给文件名和大小，先用 `POST /uploads/locate` 在本机找回原路径（剪贴板截图没有路径，直接走浏览器上传）；小于设置里「大文件」（`largeBytes`，默认 10 MB）的文件再调 `POST /uploads/copy` 后台拷一份到数据目录，更大的、或者拷不了的直接引用原路径。卡片上文件与图片统一显示 `@路径 · 大小 · 状态`（查找中 / 拷贝中 / 已拷贝 / 引用路径 / 上传中），图片的缩略图只做视觉辅助，文字仍以 `@路径` 开头。**拷贝不拦发送**：状态是 `copying` 或 `ref` 时 `sendAttachments` 用原路径（`ref: true`）交给 Agent，只有还没拿到路径的（`locating` / `uploading`）才拦，`ChatComposer` / `TaskView` 的提示文案读 `files.waiting`（和卡片上的状态同一套 `itemStatus`）；拷不了（文件被占用、权限、源文件没了）不弹错，降级成引用原路径。删卡片（`remove` / `removeNames`）会调 `POST /uploads/discard` 把已拷好的副本删掉，还在拷的等它完成后丢掉；发送成功清空输入框时，仍在拷的也按同样方式丢掉（这条已经按原路径发出去了）。复制口径：`copyText` 和输入框内 Ctrl+C（`copyOfChip`）把卡片写成 `@路径`，和卡片上显示的是同一份（`itemPath`：引入时的原路径优先）；发送时另用拷好的副本，这是有意的分工。粘贴时 `findPaths` 把 @ 算进命中范围、换回卡片，发给 Agent 的仍是纯路径（`withAttachments` 换成 `a.path`）。**去重按原路径记在 `claimed` 里**（`Attachments.tsx`），同批 locate / 两次并发添加同一个文件也只留一张卡片，`copyInto` 完成时把附件名换回卡片上的名字（重复文件名加了序号时发送才匹配得上）。粘贴的图片按剪贴板截图直接上传（`useDropPaste` 的第三个参数 `paste` → `add` 的 `clipboard`），拖入和选择文件一律先 `locate`——真实文件也可能叫 `image.png`，不能只看文件名。回归：`shared/attachment-view.test.ts`、`server/composer.test.ts`、`server/uploads-copy.test.ts`、`scripts/ui/01-composer.mjs` 的「附件-拷贝中也能发送」「附件-拷贝失败改引用」和图片卡片上的 @路径断言。
