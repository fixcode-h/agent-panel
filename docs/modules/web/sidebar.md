[web 模块](README.md)的子页面：侧栏的项目行和对话行、UI 设计侧栏、UI 项目主页。模块的状态块、入口、依赖和回归验证见 [README.md](README.md)，Bug 记录见 [bugs.md](bugs.md)。

2026-10-31 从 `README.md` 原样挪出（文字没改），各条的日期和结论以当时为准。

## 职责与实现

- 侧栏的项目行和对话行只有一份外观：`web/src/components/ui/sidebar.tsx` 的 `SidebarProjectRow` / `SidebarProjectName`（展开箭头、文件夹、项目名、行尾「N 个执行中」或对话数，悬停时让位给拖动手柄和新建按钮）和 `sidebarTaskRowClass` + `SidebarTaskRowBody`（工作流对话前的图标、标题、行尾状态或时间）。真实侧栏（`Sidebar.tsx`、`SidebarTasks.tsx` 的 `TaskRow`）和设置 → 组件的「侧栏」示例都用它们，示例不再手搭一份（以前手搭的示例和真实侧栏各走各的，用户报「侧栏跟组件对不上」）。拖动手柄不悬停时宽度收成 0，否则隐藏的手柄还占着 16px，行尾胶囊离右边空出一截。
- UI 设计侧栏的项目行（`web/src/components/layout/SidebarDesigns.tsx` 的 `DesignList`）：**点项目名打开 UI 项目主页，只有最前面的箭头按钮切换折叠**。整行 `div` 只是排成一行的容器，没有 `onClick`（点空白既不折叠也不跳页）；箭头按钮 `h-6 w-6` 自己有 `onClick={toggleFold}`、`aria-expanded`、`aria-label`（收起 / 展开），项目下没有设计时 `invisible` + `disabled`；项目名是 `button`，`onClick` → `go(designHomeRoute(p.id))`，`aria-label` / `title` 写「打开项目「{name}」，右键查看更多操作」；右侧「新建设计」的 `Plus` 按钮直接 `go`，不再需要 `stopPropagation`（行上没有折叠动作了）。项目和分类（`项目id:分类id`）共用一份 `folded` 集合，增删走 `web/src/lib/design-projects.ts` 的 `toggleFoldKey`，分类行的键用 `kindFoldKey`。历史上这条行反过两次：先是「只有小箭头能点、点项目名没反应」，后来改成「整行可点只折叠」，用户要的是「点项目名进主页、只有箭头折叠」。回归：`scripts/ui/04-design.mjs` 的「UI设计-项目主页」「UI设计-箭头收起」（点项目名后分类行仍在、URL 进 `#/design/home/<项目id>`；点箭头才让 `[data-kind="game"]` 卸载），纯逻辑在 `web/src/lib/design-projects.test.ts`。Bug 记录见 [bugs](bugs.md)。
- UI 项目主页（`web/src/components/design/DesignProjectHome.tsx`，参考 Agent 的 `ProjectWorkspace` 的信息结构）：路由借用 `page: 'design'` 的 `id`，`id === DESIGN_HOME`（`'home'`）时是项目主页、项目 id 放在 `sub`，和已有的 `id === 'new'`（新建设计）同一套约定，没改 `Route` 类型和地址栏格式——`web/src/pages/DesignPage.tsx` 的 `DesignPage` 按这三段分流（主页 / 新建设计 / 设计器）。主页头部是项目名 + 概况（共几个界面、游戏 / 网页各几个、最近改动时间、可选项目目录），顶栏三个入口：新建设计（`go({ page: 'design', id: 'new', sub })`）、项目设置、美术提示词（都开 `DesignProjectDialog` 并指定 `section`）；下面按类型分组列出这个项目的界面（每行图标、标题、类型、等你处理 / 执行中 / N 分钟前），点一行进设计器；没有界面时是虚线框加新建按钮。数据口径在 `web/src/lib/design-projects.ts`：`projectDesigns`（按 `updatedAt` 倒序，同时间按标题）、`groupByKind`（只分组、不重排，组内顺序沿用 `projectDesigns` 的结果）、`projectSummary`、`kindLabel`（写成函数，切语言跟着变）。两个容易踩的点：① 主页根节点带 `data-design-home={项目id}` 锚点、项目行的折叠箭头带 `data-fold={项目id}`，界面检查的断言必须限定在这些锚点上——侧栏先于页面渲染、设计行也有同名文字，不限定作用域时主页没画出来也会通过；② `designProjects` 初值是 `[]`（`web/src/lib/data.tsx`），由 `reloadDesigns` 异步填充，所以主页要等 `designProjectsLoaded`（同 `tasksLoaded` 的写法，`finally` 里置真，取失败也算已问过）为真且仍找不到项目才判「已经不在了」，否则直接从地址栏进主页会先闪一下不存在的提示。「最近改动」只看设计（`updatedAt`），改名项目本身不会让它变，这是取舍不是 Bug。
