- 技能的文件结构（`web/src/components/library/SkillFiles.tsx`）：后端给的是**扁平条目 + 完整 path**（`shared/library.ts` 的 `LibraryEntry { path, type: 'file' | 'dir' | 'link', size? }`，包在 `LibraryTree { entries, truncated? }` 里由 `LibraryFile.tree` 返回），`web/src/lib/library-tree.ts` 的 `toTree` 只还原层级（算 `depth`、挂 `children`），**前端不再排序**——后端（`server/library.ts` 的 `extraFiles`）已按「目录在前、同级 localeCompare」广度优先排好，再排一遍会把目录优先规则弄乱；同文件还有 `visibleRows`（按收起集合展开）、`countFiles`、`entryName`。主文件置顶且**不在树里**（后端 `extraFiles` 按大小写无关排除 `SKILL.md`，它只走 `content` 字段），只在详情页顶部编辑，文件树里的 `SKILL.md` 行只做锚点滚动；附加文件在这个组件里读 / 改 / 存，右键菜单（`ContextMenu`，写法同 `SidebarTasks`）新建文件 / 新建目录 / 重命名 / 删除，删除走 `ConfirmDialog` 二次确认。文件树的读写收敛成 `FilesApi` 接口（`read` / `save` / `remove` / `rename` / `reload`），组件本身不认识 HTTP，这是留给项目技能共用的接缝（`readOnly` 时不给增删改）；**目前只有 `LibraryDetail.tsx` 接了一份实现，项目技能 `web/src/components/projects/ProjectSkillsSection.tsx` 还是自己那套编辑弹窗，尚未接过来**。三种不能编辑的情况按后端 `LibraryEntryContent` 的字段分别提示：`binary` 为真（后端按内容里有没有 `\0` 判定）显示「二进制文件（{size}），不能编辑。」、`link` 为真（软链接，写进去会顺着链到别处）显示「这是个链接，不能在这里改内容。」，都**不渲染空编辑器**；超过 `LIBRARY_FILE_MAX_BYTES`（1 MiB，读写在 `server/library.ts` 的 `checkSize` 里同一处判断，报错带 `LIBRARY_FILE_MAX_KIB`）时禁用保存并提示；`tree.truncated` 为真时提示「文件太多，只显示了前面一部分。」。**后端没有单独的建目录接口**：前端「新建目录」是写一个 `目录/.gitkeep`，父目录由后端 `writeLibraryEntry` 的 `mkdir(..., { recursive: true })` 建出来。`LibraryFile.tree` 声明为可选只是为了兼容旧响应，`LibraryDetail.tsx` 的 `entriesOf` 在 `tree` 为空时退回旧的扁平 `files`。在线演示的 `web/src/lib/demo-library.ts` 补了 `treeOf`（按路径算目录，含空目录 `references/templates`）和 `/library/entry*` 的模拟实现，错误文案与真接口一致，演示版和正式包的详情页不分叉。
