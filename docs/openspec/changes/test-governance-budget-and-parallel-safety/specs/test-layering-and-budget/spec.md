# Spec Delta · test-layering-and-budget

## Purpose

定义测试分层、各层用例硬预算、淘汰规则与耗时/稳定性验收指标，让测试规模可核对地受控，而不是靠删测试换速度。

## ADDED Requirements

### Requirement: Test layer classification

每个测试文件 MUST 被归入纯函数层、集成层、e2e 层之一。分层依据是文件的运行时特征：启动 HTTP 服务、建临时目录或读写真实文件、执行 git、开子进程、监听端口，满足任一项即归集成层；e2e 层只包含 `scripts/e2e/` 下由总入口调度的分片。同一文件不得跨层。

#### Scenario: 起服务或子进程的测试归入集成层

- **WHEN** 一个 `*.test.ts` 文件启动 Hono 应用、`mkdtempSync` 建临时目录或 `spawn` 子进程
- **THEN** 分层检查把它计入集成层，并计入集成层预算

#### Scenario: 纯逻辑测试归入纯函数层

- **WHEN** 一个测试文件只 import 被测模块与断言库，不启动服务、不读写真实文件、不开子进程
- **THEN** 分层检查把它计入纯函数层，并计入纯函数层预算

#### Scenario: e2e 分片只按目录归属

- **WHEN** 一个测试文件位于 `scripts/e2e/` 且被 e2e 总入口作为分片调度
- **THEN** 它计入 e2e 层，不重复计入单测的两层

### Requirement: Per-layer test budget

每一层 MUST 有独立的用例数硬上限，数字集中在一个可被脚本读取的常量里。新增用例导致某层超预算时，MUST 在同一提交里合并或淘汰等量旧用例，并写明覆盖了哪个能力、被删用例靠什么替代；检查脚本在超预算且无替换记录时 MUST 以非零退出。

#### Scenario: 超预算新增且未替换时被拒绝

- **WHEN** 纯函数层已到上限，提交新增 3 个用例但没有减少任何旧用例
- **THEN** 预算检查以非零退出，并打印该层当前数量、上限和超出的条目

#### Scenario: 等量替换后通过

- **WHEN** 新增 3 个用例的同时按淘汰规则删掉 / 合并了 3 个旧用例，并在提交说明里写清覆盖关系
- **THEN** 预算检查通过，该层数量不超过上限

#### Scenario: 预算上限只有一处定义

- **WHEN** 需要调整某层上限
- **THEN** 只改常量文件一处，分层检查、预算检查、CI 和文档引用同一个值，不在别处再写一份数字

### Requirement: Test retirement criteria

删除或合并用例 MUST 属于以下三类之一并留下证据：被测能力已删除、被更强断言完全覆盖、长期 flaky 且修复成本高于价值。仅以「跑得慢」为理由 MUST 被拒绝。用户报过的 Bug 回归用例、数据丢失与不可逆路径、凭据与安全边界用例 MUST 保留。

#### Scenario: 以耗时为理由删除被拒绝

- **WHEN** 提交说明把删除测试的理由写成「跑得慢」或「缩短验证时间」
- **THEN** 检查或评审按本需求判为不合规，不得合并

#### Scenario: 被更强断言覆盖时允许删除

- **WHEN** 旧用例的输入矩阵已被另一条用例全部覆盖，且新用例断言更严格
- **THEN** 允许删除，并在提交说明记录被删用例名与新用例的对应关系

#### Scenario: 用户报过的 Bug 回归不可删除

- **WHEN** 待删用例对应 `docs/modules/*/bugs/` 里的用户报 Bug
- **THEN** 删除被拒绝，除非同时提供等价回归用例并通过

### Requirement: Verification time budget

本地六步整体验证 MUST ≤ 4 分钟；其中单测 ≤ 3 分钟、e2e ≤ 3 分钟、界面检查 ≤ 2 分钟。分项上限是单步的墙钟上限，整体 4 分钟是**分组并行编排后的墙钟**：测试组（单测 / e2e / 界面检查）同时跑，静态组（类型检查 / 代码检查 / 构建）同时跑，不是分项相加。MUST 提供一条命令按此编排跑六步并输出每步耗时与总墙钟，任一分项或总墙钟超限时以非零退出；判定取连续 3 次运行的中位数。

#### Scenario: 一条命令按分组并行编排六步

- **WHEN** 运行验收命令
- **THEN** 输出类型检查、代码检查、单测、e2e、构建、界面检查各自耗时和并行后的总墙钟，并给出是否全部在预算内

#### Scenario: 分项不求和

- **WHEN** 单测 3 分钟、e2e 2 分钟、界面检查 2 分钟，三者并行
- **THEN** 总墙钟按约 3 分钟判定通过；不得把分项相加成 7 分钟再据此判失败或放宽预算

#### Scenario: 超预算时失败并指出步骤

- **WHEN** 单测耗时 3 分 20 秒
- **THEN** 验收命令以非零退出，输出里标明「单测超预算（3m20s > 3m）」以及超标步骤的完整命令

#### Scenario: 连续三次取中位数

- **WHEN** 同一台机器连续跑三次验收命令
- **THEN** 判定使用三次总墙钟的中位数，并在报告里同时列出三次原始值

### Requirement: Flakiness-free acceptance

连续 5 次全量运行六步 MUST 全部通过，且没有任何用例出现「一次失败、另一次通过」。任一次运行失败，或某个用例靠隔离重跑才通过，MUST 判本次验收不通过，并输出每次运行的失败集合。

#### Scenario: 五次全部通过

- **WHEN** 连续 5 次全量运行结束
- **THEN** 报告显示 5/5 通过且 flaky 列表为空，验收通过

#### Scenario: 靠重试救回不算通过

- **WHEN** 某次运行中一个用例首次失败、隔离重跑通过
- **THEN** 该用例进入 flaky 列表，本次验收判不通过，并输出用例名与首次失败信息

### Requirement: CI test job budget

CI 的 `test` job MUST 在最近 20 次 `dev` 分支运行的 P95 时长 ≤ 10 分钟。统计 MUST 用完整 commit sha 匹配运行记录；超限时 MUST 输出最慢的步骤和耗时，而不是只报总时长。

#### Scenario: P95 统计可执行

- **WHEN** 运行 CI 耗时统计命令
- **THEN** 输出最近 20 次 `test` job 的每一次时长、P95 值和最慢步骤

#### Scenario: 超过上限时失败

- **WHEN** P95 为 12 分钟
- **THEN** 统计命令以非零退出，并列出耗时最长的步骤

### Requirement: Migration preserves coverage

把用例迁到正确层级时 MUST NOT 减少用例名集合，按淘汰规则登记的删除除外。迁移前后 MUST 有对比证据：同一次全量运行收集到的用例名集合差异只包含登记项。

#### Scenario: 只改名或移动时不丢用例

- **WHEN** 一批测试文件改名并移动到集成层目录后跑全量
- **THEN** 用例名集合与迁移前相同，报告显示差异为 0

#### Scenario: 登记过的淘汰允许出现在差异里

- **WHEN** 迁移同时按淘汰规则删除了 5 个用例
- **THEN** 集合差异恰好是这 5 个用例名，且每条都能对应到提交说明里的替代覆盖
