## 0. 用户的要求

2026-11-05 用户提了两轮：

1. 确认弹窗没有补充日志的按钮，计划里要列出日志怎么补；标了疑问之后应该是「继续探讨、出下一版」，不是只有确认。要更接近真实的修 Bug 过程。
2. 定下的流程：
   - 整体意见的输入框能贴入日志文件。
   - 复现给了日志还没分析出原因，就进下一版加日志，再验证，直到准确找出问题才到根因。
   - 根因页面用户可以同意，也可以否决，带上补充和疑问让 AI 再分析；AI 认为有道理、证据确实不完善，就回到论证，下一轮加日志、分析日志，看能不能得出结论。
   - 用户同意根因才进方案页面设计方案，然后修代码，最后进验证：等用户给日志，AI 分析，确认没问题就结束；用户点结束也可以跳过验证。
   - 验证确认后要删掉加的排查日志，但修改的代码里必要的日志要加上。

## 1. 原来的问题

| 缺口                   | 原来                                             | 后果                                                             |
| ---------------------- | ------------------------------------------------ | ---------------------------------------------------------------- |
| 取证没有自己的入口     | 根因没证实时只能点「确认方案，开始修」才能加日志 | 用户不知道点了是让它修还是让它加日志                             |
| 日志计划是一段自由文字 | `next` 一个字符串                                | 加在哪、打什么、为了区分哪个假设、怎么复现、贴回什么，常常写不全 |
| 没有「等你复现」       | 加完日志后对话停着，用户贴日志是一条普通消息     | 面板不知道它在等日志                                             |
| 根因和方案是一版       | 用户只能一起确认                                 | 根因还不可靠就开始讨论修法                                       |
| 修完没有验证这一步     | 修完直接请父对话收尾                             | 用户没有机会复现确认                                             |
| 疑问只能「再查」       | 有标注时「确认」仍是主按钮                       | 看起来没有「继续探讨」这条路                                     |
| 确认时的标注被丢掉     | 确认那一支只带整体意见                           | 带着补充信息确认，Agent 收不到                                   |

## 2. 新流程

### 2.1 阶段

每一版报告带 `phase`：

| 阶段                     | 什么时候交                        | 用户能做什么                                             | 用户同意后                                                                                            |
| ------------------------ | --------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 论证 `evidence`          | 根因还没证实                      | 同意加日志；我有日志，直接分析；继续分析（带疑问）；取消 | 只放行日志计划里的文件加 `[排查-` 日志；能自己复现就跑，不能就调 `request_logs`，弹窗变成「等你复现」 |
| 等你复现（论证的同一版） | Agent 加好日志后                  | 交日志，继续分析（框里贴文字或附文件）；有疑问           | 它只分析这一段日志：还没定论交下一版论证，证实了交根因                                                |
| 根因 `cause`             | 证据链三环齐了，`confirmed: true` | 同意根因；否决，再分析（带疑问和补充）                   | 设计修复方案。否决时它认为证据不够就回到论证，否则交新一版根因逐条回答                                |
| 修复方案 `plan`          | 用户同意了根因                    | 确认方案，开始修；有疑问，出下一版；改用方案 X           | 写失败测试、按方案修，只改方案里的文件；修完记 `result`                                               |
| 验证 `verify`            | 修完、记下结果后                  | 交日志，确认修好；结束，跳过验证；还有问题               | 它分析日志，没问题就删掉排查日志、补上必要的正式日志，请父对话收尾；有问题回到论证或出新方案          |

论证可以来回多轮，阶段条写「论证 · 第 k 轮」。

### 2.2 面板怎么兜住

- **交报告的检查（`diagnosisProblem`）**：论证要 `logPlan`（每处 file、print）、`collect.steps`、`collect.expect`，而且要在这一次里写（每轮的日志不能沿用上一轮）；根因要证据链、引入点，标准级别要变更时间线和一致性；方案要先有用户同意的根因，要修法、`files`、验证计划，标准级别要影响面和两个方案；验证要先有确认过的方案，要复现步骤、看到什么算修好了，`result` 里要有回归测试。
- **能改哪些文件（`editScope`，钩子 `bugDeny` 用）**：等用户时不改；同意加日志后只放行日志计划里的文件；同意根因后不改（先交方案）；确认方案后放行方案里的文件和论证时加过日志的文件（要删临时日志）。
- **收尾（`diagnosisGate`）**：最新一版要是验证，且用户给了日志或点了结束；改动不超出方案和日志文件；`result` 里回归测试和影响面验证齐；`[排查-` 日志留着收不了尾（原有检查）。
- **交给 Agent 的话（`phaseFeedback`）**：按阶段和用户的选择分别写；确认时的标注也带上；用户贴的日志文字放进消息，附件随消息一起交过去。贴的文字超过 2 万字，页面自动存成附件。

### 2.3 新工具 `request_logs`

用户同意加日志、Agent 加好之后调用：写实际加的位置和复现步骤。那一版回到等用户（`awaiting`），弹窗自动再弹一次，显示「等你复现」。

## 3. 弹窗

- 顶部阶段条：论证（第几轮 / 等你复现）→ 根因 → 修复方案 → 修复 → 验证。
- 报告第一节「结论」：现在在哪一步、要你做什么，根因一句话。之后按阶段先放这一步要看的：论证先放日志计划、怎么复现、贴回什么、每种结果说明什么；根因先放证据；方案先放候选方案；验证先放验证步骤和修复结果。
- 版本切换写阶段：「第 2 版 · 根因」。
- 右下整体意见框：等日志的阶段能粘贴文字、粘贴或拖进日志文件、点「附日志文件」在本机选（大文件直接引用原路径，不拷贝）。
- 按钮按阶段换（见 2.1）；标了疑问或改方案时，「继续分析 / 否决 / 有疑问」变成主按钮，「确认」退成次要。

示例见 [Bug 确认弹窗示例](https://claude.ai/artifact/So4QWtswQoSqT4eodVL57e)（第一轮设计时画的，按钮文字以实现为准）。
