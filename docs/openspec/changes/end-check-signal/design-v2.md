# 面板提醒：对话里不再显示，Agent 用 end_turn 结束，不限次数（设计稿 v2）

状态：已确认并实施（用户 2026-11-05），定稿和下文不一致的地方以「定稿」这一节为准 · 2026-11-05

## 定稿（用户 2026-11-05 确认后的改动）

- **结束时允许输出**：不强制「只调 end_turn、不写字」，也不让 CLI 调完 end_turn 就停（§3.3 第 1 条不做）。提醒里请它做完后最多一句话简短收尾；end_turn(done) **之后的那一次输出**默认不显示，原文留在「状态」里。被提醒之后、end_turn 之前写的话照常显示（§3.3 第 2 条的后半、§7 第 3 条不做）。
- **没列计划时的提醒保留原来的门槛**（§7 第 2 条改了）：这条输入以来动手 3 次以上（读文件、搜索每 3 次折 1 次），或者一个工具都没调就要结束，才问。小事、纯问答照旧不打扰，主动调 end_turn 的直接放行。问过以后只回了话、没再动手的不会再问，所以不限次数也不会在这一档空转。
- **空转保护照做**（§7 第 1 条）：计划没做完、收尾请求没处理这几档提醒不限次数，连着 3 次提醒之间一个工具都没调就停下，留一条警告，子对话上报父对话。
- 「面板提醒次数」设置去掉；`Settings.nudgeMax` 只为兼容旧文件留着。
- 实现：判断和显示在 `shared/end-turn.ts`，工具在 `server/end-turn-tool.ts`，记录在 `Task.turnEnds`，状态面板的卡片是 `web/src/components/tasks/ReminderTrail.tsx`。

## 0. 一页结论（按用户 2026-11-05 的三点要求）

1. **面板提醒不再出现在对话里**。结束前钩子拦住的那一行（`panel: 'hook'`）和一轮结束后补发的提醒（`panel: 'nudge'`），都不再画成 Agent 回复里的过程行。它们只记在对话菜单「状态」（状态诊断）里，那里能看到次数，也能逐条看每次提醒和 Agent 的反应。
2. **Agent 用 `end_turn` 工具结束**。新的面板工具 `end_turn`，`outcome` 取 `done` 或 `blocked`：
   - 做完了：只调用 `end_turn`（`outcome: done`），之后不再输出任何内容。这一条是强制的，面板用结构手段兜住（见 §3.3），不靠模型自觉。
   - 没做完：照常接着干，不用调工具表态。
   - 做不下去：调用 `end_turn`（`outcome: blocked`），`need` 写缺什么，对话停在「等你」。
   - `end_turn` 本身也不在对话里显示，只记在状态面板里。
3. **面板提醒不限次数**。设置里的「面板提醒次数」去掉，推进的保护不再因为次数推满而停下。会不会空转的风险和建议的处理见 §5、§7。

不读回复文字这条硬规则不变：结束没结束、做没做完、卡没卡住，只看 `end_turn`、`set_plan`、`submit_*` 这些工具调用和面板状态。

## 1. 现在的问题（简述，详见 v1 §1、§2）

- 没列计划时，Agent 没有办法用工具说「做完了」。面板只能数这条输入以来动了几次手，到 3 次就一律问一次，每条新输入都会重新问。
- 拦住的那一行是系统消息。`fold.ts` 的 `summaryStart` 碰到它就停，前面完整的总结被收进折叠，外面只剩被逼出来的那句「做完了……」。
- 唯一的控制手段是「面板提醒次数」，调低会连计划推进一起关掉。

## 2. 结束的规则

### 2.1 什么时候算结束

一轮准备结束时（Stop 钩子或一轮结束后的兜底），按顺序判断：

| 情况                                                                           | 面板怎么做                                 |
| ------------------------------------------------------------------------------ | ------------------------------------------ |
| 预热、Chat 页一问一答、被用户叫停                                              | 放行（和现在一样）                         |
| 在等别人：提问、`suggest_next_step` 的建议、后台命令、子任务、子对话、收尾请求 | 放行（和现在一样）                         |
| 这条输入以来调用过 `end_turn`                                                  | 放行（`why: 'declared'`）                  |
| 子对话请父对话收尾了、父对话还没处理                                           | 拦住，让它先处理（和现在一样，不再限次数） |
| 子对话做完了没请 `submit_merge`                                                | 拦住（和现在一样，不再限次数）             |
| 计划没做完                                                                     | 拦住，说明做到第几步、接着做哪一步         |
| 其余（没调 `end_turn` 就要结束）                                               | 拦住，发收尾自检提醒（§2.2）               |

「其余」这一档不再看动手满不满 3 次：提醒在对话里看不见了，代价只剩一次很短的请求。规则统一以后，Agent 只要记住一件事：结束要调 `end_turn`。小事也不例外，提示词会让它在最终回复之后主动调用，主动调了就不会被提醒（§2.3）。

### 2.2 提醒的说法

收尾自检（用户给的原话）：

> 【面板】（收尾自检）这次的事做完了吗？没做完就直接调用工具接着做，不用先说明；做完了就调用 end_turn（outcome: done），不要再写确认或重复总结；做不下去就调用 end_turn（outcome: blocked），need 写缺什么。

计划没做完：

> 【面板】你的计划才做了 x/y，也没有在等任何结果，先别结束。接着做「下一步」：直接调用工具去做，不用先说明；一步做完就用 set_plan 标完成，直到计划做完再调用 end_turn（outcome: done）。确实做不下去就调用 end_turn（outcome: blocked），need 写卡在哪一步、需要什么。

原来推满之前附加的那句「做不下去就说明卡在哪」（`lastNudge`）去掉，统一改成调 `end_turn(blocked)`。

### 2.3 提示词：主动结束

`shared/engine.ts` 的回合推进说明和 `server/orch-hint.ts` 的工具清单加上：

- 这次的事做完了：先写好最终回复（总结、结论），然后调用 `end_turn`（`outcome: done`）作为最后一个动作，之后不要再输出任何内容。
- 要用户在几个做法里选：用 `suggest_next_step`，不要只写在文字里。它算在等用户，不需要再调 `end_turn`。
- 做不下去：调用 `end_turn`（`outcome: blocked`），`need` 写缺什么。

主动调用的话，总结写在 `end_turn` 前面，照常显示。被提醒之后再调用的话，总结已经在提醒之前写完了，这时只调工具、不写字。

### 2.4 `end_turn` 工具

面板工具（和 `set_plan`、`suggest_next_step` 同一条通道，`server/orch-mcp.ts`，名字加进 `shared/panel-tools.ts`）：

```ts
end_turn({
  outcome: 'done' | 'blocked',
  need?: string, // blocked 时必填：缺什么（展示给用户，不参与判断）
})
```

| 调用时的状态                                | 工具返回                                                                                       |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `done`，计划没做完                          | 报错：「计划还有 n 步没做完，做完或用 set_plan 标成跳过再结束」，不算结束                      |
| `done`，子对话改了文件、没请 `submit_merge` | 报错：「先调用 submit_merge 请父对话收尾」，不算结束                                           |
| `done`，其余                                | 「已结束，不要再输出任何内容」，记一次结束                                                     |
| `blocked`，`need` 为空                      | 报错：「need 写清缺什么」                                                                      |
| `blocked`                                   | 对话标成等用户（和 `ask_user` 一样亮「等你」），留一条「卡住了：need」的警告；子对话上报父对话 |

## 3. 界面

### 3.1 对话里不显示的东西

| 消息或工具                                | 现在                       | 改成                                 |
| ----------------------------------------- | -------------------------- | ------------------------------------ |
| 结束前钩子的拦截记录（`panel: 'hook'`）   | 过程行「⟳ 面板让它接着做」 | 不显示，记在状态面板                 |
| 一轮结束后补发的提醒（`panel: 'nudge'`）  | 过程行「🔔 面板提醒」      | 不显示，记在状态面板                 |
| `end_turn` 工具调用                       | （新工具）                 | 不显示，折叠行也不计入，记在状态面板 |
| `end_turn(done)` 之后的文字               | （新工具）                 | 不显示，原文记在状态面板（§3.3）     |
| 提醒之后、`end_turn(done)` 之前的那段文字 | 显示，挤掉总结             | 不显示，原文记在状态面板（§3.3）     |
| `end_turn(blocked)`                       | （新工具）                 | 总结下面一张黄色提示「卡住了：need」 |

这些消息照常存进对话（`workSince` 要用拦截记录当分界线，状态面板也从这里取），只是渲染时跳过。折叠的判断（`foldStats`、`summaryStart`）也要先把它们过滤掉，否则隐藏的消息还会打断总结的认定。

效果：

```
现在                                         改后
───────────────────────────────────────      ───────────────────────────────────────
▸ 查看 12 个文件 · 搜索 9 次 · 1 段说明      ▸ 查看 12 个文件 · 搜索 9 次
⟳ 面板让它接着做 （收尾自检）这次的…        …（Agent 的完整分析）
  思考过程 735ms                             建议
做完了：面板侧已确认是「结束前钩子」…         面板侧的建议是先不动代码……
                                               你要我继续哪一项？
                                             （到这里结束，后面没有任何面板的东西）
```

提醒之后 Agent 真的接着干了活：这一轮照常折叠，最后的回复是干完活后写的那段。折叠行不写提醒次数，提醒只在状态面板里看。

### 3.2 状态面板（对话菜单 →「状态」）

`LifecycleDetail` 里已经有「面板提醒」计数（`shared/lifecycle.ts` 的 `eventKind`），现在只数「计划推进」「收尾提醒」「收尾自检」三类日志。要改的：

- 计数也算上「结束前钩子：…拦住」这几类日志。一轮里拦了几次就是几次。
- 卡片上去掉「面板已提醒 n/max 次」里的 `/max`，只写次数。
- 新增一张「面板提醒」卡片，按时间列出每次提醒：

```
┌ 面板提醒 · 3 次 ───────────────────────────────────────────────┐
│ 08:41:12  收尾自检        → end_turn(done)                    ▾ │
│ 08:12:03  计划 2/5        → 接着做了 7 次工具，计划到 4/5     ▾ │
│ 08:05:47  收尾自检        → end_turn(blocked)：缺 UE 编辑器路径 ▾ │
└────────────────────────────────────────────────────────────────┘
  点开：交给 Agent 的提醒原文；被隐藏的那段文字（如果有）
```

- 「→」后面的结果按结构算：提醒之后调了 `end_turn` 就写它的 `outcome`；动了手就写工具次数和计划进度变化；什么都没做又要结束，就写「没动手又要结束」。
- 「结束」也单独记一行（主动调用的 `end_turn` 也算），这样能看出这次是主动结束还是被提醒后结束。
- 数据来源：对话里的 `panel: 'hook' | 'nudge'` 消息和 `end_turn` 工具调用，不另存一份。

### 3.3 「完成就只调 end_turn、不输出」怎么强制

模型调完工具，CLI 会把结果交回给它，它通常还会再说一句「好的，已完成」。光写在提示词里管不住，所以分两层：

1. **能直接停的 CLI，调完就停**。CLI 定义（`shared/clis/*.json` 的 `hooks`）加一个能力字段，例如 `stopAfterTool`，声明这家 CLI 能不能在某个工具调用之后立刻结束这一轮。面板给 `end_turn` 装一个工具后钩子，返回停止：
   - Claude Code：PostToolUse 返回 `continue: false`（官方文档写明会让 Claude 在钩子之后停止处理），要用本机版本实测一次，确认之后不再触发 Stop、也不再有输出。
   - Codex、Pi、Command Code：逐家查文档、实测。支持的写进定义，不支持的不装。按 CLI 定义的字段走，不按名字写分支。
2. **兜底：按位置隐藏，不看内容**。这一轮里 `end_turn(done)` 之后的文字不显示；被提醒之后、到 `end_turn(done)` 为止，这一段 Agent 没调别的工具的话，这一段的文字也不显示。判断只看这些文字和 `end_turn`、提醒记录的相对位置，不看写了什么，所以不算「按文字判断」。隐藏的原文放进状态面板那条提醒的展开里，需要时能查到。

主动结束时（没被提醒），总结写在 `end_turn` 前面，规则 2 不会碰到它，照常显示。

## 4. 设置

- 「面板提醒次数」（`settings.nudgeMax`）删除：
  - 设置页那一项去掉，`Settings` 里留着字段（`catch` 兜住旧文件），读到也不用，下一版再删 schema。
  - `DriveBudget` 不再按次数截断，只用来记次数（状态面板用）。
  - `shared/conv-mode.ts` 的 `nudgeMax`（Chat 页固定 1 次）跟着去掉：Chat 页本来就不拦。
  - 依赖「推满了」的逻辑要改：推满后留警告、上报父对话（`drive.ts`）这几处，改成由 `end_turn(blocked)` 触发。状态诊断的「推满了还停着」异常改成按空转保护触发（§5）。
- 内置钩子「没做完不收尾」的开关保留。关掉以后，结束前不拦，一轮结束后也不补提醒，对话停下就算停下。

## 5. 风险：不限次数会不会空转

不限次数以后，结束只能靠 `end_turn`、等别人、或者用户叫停。有一种情况会一直转下去：模型被提醒以后什么都不做，也不调 `end_turn`，就又要结束。每次都是一整轮模型请求，在中转站上会一直花钱，用户在对话里还看不见（提醒被隐藏了）。

建议加一道**空转保护**。它不是次数上限，Agent 在推进就不受影响：

- 连续 3 次提醒之间，Agent 一个工具都没调（只写了字或者什么都没写），就认定空转。
- 空转时面板停止提醒，对话标成「未完成」，留一条警告「面板提醒了 3 次，它都没动手也没调 end_turn」。子对话上报父对话。状态面板这一行标红。
- 只要中间调过任何工具（改文件、跑命令、读文件都算），计数就清零。

这一道要不要，见 §7 第 1 条。

## 7. 待确认

1. **空转保护（§5）要不要**：推荐要。连续 3 次提醒都没动手就停下并告诉你。它不限制正在推进的 Agent，只防止花钱空转、而你在对话里又看不见。
2. **没列计划时，小事也要求 `end_turn`（§2.1）**：推荐要求。规则统一、提醒看不见，代价是 Agent 忘记调用时多一轮很短的请求。另一种做法是保留「动手 3 次以上才提醒」的门槛。
3. **被提醒后、`end_turn(done)` 之前的文字也隐藏（§3.3 第 2 条）**：推荐隐藏，原文留在状态面板。这正是截图里那种「做完了：……」。
