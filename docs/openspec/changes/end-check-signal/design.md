# 收尾自检：让 Agent 用工具「交卷」，确认完成不再挤掉总结（设计稿 v1）

状态：已被 [v2](./design-v2.md) 替代（用户 2026-11-05 改了要求） · 2026-11-05

相关：[ADR 0049](../../../adr/0049-hooks-continue-in-turn.md)（结束前钩子）、[ADR 0041](../../../adr/0041-conversation-self-drive.md) 第 3.4 节（收尾自检）、`server/tasks/before-end.ts`、`web/src/lib/fold.ts`

## 0. 一页结论

用户 2026-11-05 反馈：Agent 已经查完、写好总结并在文字里问了「你要我继续哪一项」，面板的结束前钩子还是拦了一次「（收尾自检）这次的事做完了吗？」。Agent 只好再答一句「做完了……」。这一行「面板让它接着做」画成了过程行，前面那段完整的总结被收进折叠，外面只剩这句确认。

面板收尾时是有状态的：计划、提问、子对话、后台命令、收尾请求都会看。缺的是**没列计划时，Agent 没有办法用结构化的方式说「这次做完了」**。面板只能数「这条输入以来动手了几次」，到 3 次就一律问一次，每条新输入都会重新问。这是规则对「做完了」看不见，不是不判断。

要改四处，都不读回复文字：

1. **加一个「交卷」工具 `end_turn`**（暂名），参数 `outcome: done | blocked`。没列计划又动手较多时，提示词让 Agent 交最终回复前调用它。结束前钩子看到这条输入以来调用过它（或调用过 `suggest_next_step` / `ask_user` / `finish_plan` / `submit_merge`）就直接放行。
2. **自检的说法改成「做完了就调用 `end_turn`，不要重复总结」**。万一还是问了，确认那一轮只有一次工具调用、没有文字，原来的总结仍然是最后的回复。
3. **自检会自己降频**：同一个对话里，自检之后 Agent 没动手就确认做完（误报），这种情况记一次。连着 2 次误报以后，这个对话里只读的调查（没改文件）不再自检，改过文件的照常问。
4. **界面**：自检确认完成时，不把前面的总结折起来，只在总结下面加一行小字「面板收尾自检 · 已确认完成」。自检以后 Agent 真的接着干了活，才像现在这样折叠。拦住的那一行按原因分开命名（「面板收尾自检」和「面板让它接着做」）。

另外，「没列计划时的收尾自检」单独成为一个设置，不再和「面板提醒次数」绑在一起。现在想少被问，只能把次数调成 0，计划推进的保护也会一起关掉。

## 1. 现象复盘（用户截图）

```
…（Agent 的完整分析：10000007 的来源、互斥机制、建议）
建议
  面板侧的建议是先不动代码……
  10000007 那边，建议先确认……你要我继续哪一项？      ← Agent 在文字里问用户
⟳ 面板让它接着做 （收尾自检）这次的事做完了吗？……   ← 结束前钩子拦了一次
  思考过程 735ms
做完了：面板侧已确认是「结束前钩子」的收尾自检……      ← 被逼出来的确认，成了「最后回复」
```

问题有三个：

- 多了一轮模型请求，而且是带着全部上下文的完整请求。Agent 也被迫去解释面板的行为（它在回复里写了「这是 ADR 0049 的已知取舍」）。
- 上一轮也问过（Agent 原话「两次 acts=78/29」）。只要不列计划，每问一个问题都会多这一轮。
- 真正的总结被收进了折叠，展开才看得到。

## 2. 根因（读代码）

### 2.1 没计划时，面板手里没有「做完了」的结构化信号

`server/tasks/before-end.ts` 的 `decide` 在没列计划时按下面的顺序判断：

| 条件                                           | 结果                                      |
| ---------------------------------------------- | ----------------------------------------- |
| 预热、Chat 页、在等提问 / 后台 / 子对话 / 收尾 | 放行                                      |
| 这条输入以来动手 + 读取 ÷ 3 < 3，且调过工具    | 放行（`small`）                           |
| 一个工具都没调                                 | 问一次（`check-no-tools`）                |
| 其余（做了 3 次以上）                          | 问，同一条输入最多 2 次（`check-worked`） |

能放行的信号只有「在等别人」和「做得少」两类，没有一项表示「做完了」。查了 78 次的调查，结束时一定会被问一次。这在 ADR 0049 §6 里是有意的：它为了接住「做到一半就停」，代价是做完了也要多问一次。用户现在碰到的就是这个代价，而且每条输入都要付一次。

### 2.2 Agent 用文字问用户，面板看不到它在等人

截图里 Agent 最后写的是「你要我继续哪一项？」。面板已经有 `suggest_next_step`（给用户几个选项）和 `ask_user`。调用了这两个，`tk.requests` 就不为空，`waitingOn` 会判成 `asking` 直接放行。这次 Agent 没用它们，面板又不许读文字，所以只能当成「可能没做完」。

### 2.3 界面：拦住的那一行打断了「总结」的认定

`web/src/lib/fold.ts` 的 `summaryStart` 从最后一条带文字的 Agent 消息往前找总结，碰到非 Agent 消息就停（`if (m.role !== 'agent') break`）。钩子留下的那一行是 `role: 'system', panel: 'hook'`，于是：

- 最后的回复变成了自检后那句「做完了……」；
- 自检前那段完整总结被算成「中间的说明」，收进折叠（折叠行写「1 段说明」）。

钩子的那一行用的是过程行的样式（`PANEL_KIND.hook`：⟳「面板让它接着做」），看起来和工具调用一样。

### 2.4 想少被问，只能连计划保护一起关

自检的次数上限是 `Math.min(2, nudgeMax)`。要不问，只能把「面板提醒次数」设成 0，可这样计划没做完就停时也不会再推了（截图里 Agent 自己也这么说）。内置钩子「没做完不收尾」可以整个关掉，关掉的话四种保护会一起没有。

## 3. 设计

### 3.1 「交卷」工具 `end_turn`

面板工具（和 `set_plan`、`suggest_next_step` 同一条通道，`server/orch-mcp.ts`）：

```ts
end_turn({
  outcome: 'done' | 'blocked', // done：这次的事做完了；blocked：做不下去，需要用户给东西
  need?: string,               // blocked 时写缺什么（展示给用户，不参与判断）
})
```

- **什么时候调用**：提示词（`shared/engine.ts` 的回合推进说明、`server/orch-hint.ts`）写明，没列计划、这条输入以来动过手，交最终回复前调用一次。小事、纯问答不用调（本来就不会被问）。
- **要用户选下一步的**，照旧用 `suggest_next_step`，提示词里强调「结论里问用户的话必须用它，不要只写在文字里」。它也算交卷。
- **`blocked`**：面板把对话标成等用户（和 `ask_user` 一样亮「等待」），留一条警告，写上 `need`。父对话收到「子对话卡住」的上报，不再推它。
- **结束前钩子**：这条输入以来（自检过的从自检之后算）调用过 `end_turn`、`suggest_next_step`、`ask_user`、`finish_plan`、`submit_merge` 任一个，就放行（`why: 'declared'`）。只看工具调用，符合硬规则。
- **一轮结束后的兜底**（`drive.ts` 的 `nudgeNoPlan`）用同一个判断。
- **代价**：多一次很轻的工具调用，没有文字。比被拦一次（一整轮请求加一段文字）便宜得多。
- **防滥用**：计划没做完时调用 `end_turn(done)` 不放行（计划那一档优先，照现在推）。改了文件、没交 `submit_merge` 的子对话也照现在拦。`end_turn` 只回答「没计划时做没做完」这一个问题。

> 为什么不复用 `finish_plan`：它的意思是「把计划收掉」，没计划时调用它语义不对，模型也容易误以为要先 `set_plan`。

### 3.2 自检的说法

现在的说法是「做完了就用一两句话确认结果」，会逼出一段新文字，挤掉总结。改成：

> 【面板】（收尾自检）这次的事做完了吗？没做完就直接调用工具接着做，不用先说明；做完了就调用 end_turn（outcome: done），不要再写确认或重复总结；做不下去就调用 end_turn（outcome: blocked），need 写缺什么。

按 AGENTS.md「提交前」第 3 条，要搜测试里断言这句原文的地方（`before-end.test.ts`、e2e `03-chat`）。

### 3.3 自检会自己降频（按结构化结果，不看文字）

在对话上记一份很小的统计（`Task.endCheck`）：

```ts
endCheck?: { asked: number; falseAlarm: number; streak: number } // streak：连续误报次数
```

- **误报**：自检之后到这一轮结束，除了 `end_turn` 没有别的工具调用（只确认、没动手）。
- **接住**：自检之后有改文件、跑命令这类动手。`streak` 清零。
- **降频规则**：`streak ≥ 2` 时，这个对话里「这条输入以来没改过文件」的情况不再自检（`why: 'quiet-readonly'`）。改过文件照常问，因为改到一半就停是最该接住的。一次自检被接住就恢复。
- 只在没计划这一档用，计划推进不受影响。

### 3.4 设置

内置钩子「没做完不收尾」加一个参数（`shared/hook-builtins.ts` 的 `params`，可以按项目设）：

| 「没列计划时的收尾自检」 | 行为                                        |
| ------------------------ | ------------------------------------------- |
| 自动（默认）             | 交卷就放行；连续误报 2 次后，只读调查不再问 |
| 改过文件才问             | 没改文件一律不问                            |
| 每次都问                 | 现在的行为（仍然认交卷）                    |
| 不问                     | 没计划时不自检；计划推进、收尾请求照常      |

「面板提醒次数」以后只管计划推进。没计划时的自检固定为同一条输入最多 1 次（现在是 2 次），由上面这个参数控制。

### 3.5 界面

`hookMarker` 带上拦住的原因（新增可选字段 `hookWhy`，取值就是 `BeforeEndDecision.why`），界面据此分开显示：

| 原因                              | 行名                       | 图标     |
| --------------------------------- | -------------------------- | -------- |
| `check-worked` / `check-no-tools` | 面板收尾自检               | ✓ 圆圈勾 |
| `plan-open`                       | 面板让它接着做（计划 x/y） | ⟳ 现在的 |
| `wrap-pending` / `merge-owed`     | 面板让它先收尾             | GitMerge |

**确认完成时，总结不折叠**。`fold.ts` 的 `summaryStart` 加一条规则：自检那一行之后、到这一段结束为止，Agent 没有动手（只有 `end_turn` 这类收尾工具，或者只写了文字），那么这一行和后面的确认都当作「收尾动作」，接着往前找总结。效果：

```
修改前                                      修改后
──────────────────────────────────────      ──────────────────────────────────────
▸ 查看 12 个文件 · 搜索 9 次 · 1 段说明     ▸ 查看 12 个文件 · 搜索 9 次
⟳ 面板让它接着做 （收尾自检）这次的…       …（Agent 的完整分析）
  思考过程 735ms                            建议
做完了：面板侧已确认是「结束前钩子」…        面板侧的建议是先不动代码……
                                              你要我继续哪一项？
                                            ┌──────────────────────────────────┐
                                            │ ✓ 面板收尾自检 · 已确认完成    ▾ │  ← 小字一行，点开看
                                            └──────────────────────────────────┘     面板的问话和确认的话
```

- 交卷了（调了 `end_turn`），面板根本不会拦，也就没有这一行，界面和普通完成一样。
- 自检后 Agent 真的接着干活了：照现在折叠，折叠行上多写「面板收尾自检 1 次」，最后的回复是干完活后的那段。
- `end_turn(blocked)`：总结下面一张黄色提示「卡住了：<need>」，和现在的未完成警告一个样式。
- 这一行按 `docs/lessons/ui.md` 做：灰色小字、不占过程行的浅底、不用强调色。它是面板的说明，不是 Agent 的动作。

## 5. 测试

- `server/tasks/before-end.test.ts`：调了 `end_turn` 就放行；计划没做完时 `end_turn` 不放行；连续 2 次误报后只读调查放行、改过文件照问；被接住后恢复；四个参数档位。
- `web/src/lib/fold.test.ts`：自检后只有确认时，总结从自检前那段开始；自检后动了手时，照旧折叠。
- e2e `03-chat`：假 CLI 加一种「调 `end_turn` 再结束」的输入，断言不出现自检、只起一次 CLI。
- 界面检查：对话分片加一张「自检确认完成」的截图。
- 真机：Claude Code + deepseek 跑一次「查 20 个文件后回答」，日志里应该是「结束前钩子：放行 why=declared」。

## 6. 没选的方案

- **按回复文字判断（是不是有总结、是不是以问号结尾、文字够不够长）**：违反硬规则（ADR 0041、0049），误判面大。
- **只读调查一律不自检**：ADR 0049 §6 正是为了接住「排查做到一半就停」才把读取算进去的，直接去掉会回到老问题。降频是看这个对话里的实际结果再放松。
- **把「面板提醒次数」调低**：会连计划推进一起关，见 §2.4。
- **把钩子那一行藏起来**：用户要能看到面板做了什么（ADR 0049 定的小标记），问题出在它把总结挤进了折叠，不在它显示出来。
- **用 CLI 的停止原因**：Claude Code 的 Stop 钩子输入里没有结构化的停止原因，只有回复文字，用不上。
