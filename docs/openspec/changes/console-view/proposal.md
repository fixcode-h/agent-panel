# Proposal：对话的「控制台模式」——像 CLI 终端那样显示输出，和对话模式随时互切

状态：设计稿，待用户拍板（见 `design.md` 第 9 节的待定项 D1–D5）。

## Why

现在网页对话是「聊天气泡 + 工具卡片」的排版：署名栏、圆角卡片、折叠的「n 段说明」，信息密度低，
习惯在终端里用 Claude Code / Command Code 的人看着不像在用 CLI，一屏能看到的步骤也少。
用户希望对话可以直接切成「控制台」样式：等宽字体、一行一个动作、工具输出缩进挂在下面，
看起来就是 CLI 在终端里的输出；并且两种样式可以随时互相切换。

## What Changes

- 对话区新增一种显示方式「控制台」，和现有的「对话」并列，对话顶部一个切换按钮 + 快捷键，随时切，不打断执行。
- 控制台模式**只换显示，不换数据和执行方式**：读的还是同一份 `TaskMessage`，CLI 仍按现在的 JSON / RPC 协议跑，
  所以切换是瞬时的、可逆的，提问卡片、子对话、撤回分叉、用量统计这些面板功能都还在。
- 不做「把 CLI 的真实 TUI 搬进网页」（PTY + xterm.js），理由和对比见 `design.md` 第 3 节。
- 输入框在控制台模式下换成提示符样式（`>`），功能不变（附件、斜杠命令、语音、插话）。

## 不做什么

- 不改 CLI 的调用参数和输出解析，不新增后端协议。
- 不把对话导出为终端录像（asciinema 这类）。
- 第一期不覆盖工作流流程图里的节点详情、设计页的 AI 对话（第二期再看）。
