# 自建工具（/createtool）· 设计稿

> 状态：第一期已实现（2026-11-25，用户「一起做吧，你决定吧」），决策见 ADR 0082；全局工具存数据目录 tools/、只读的不弹授权卡、十个命令一起加。二期项见第 7 节、第 6.3 节。
> 起因：用户 2026-11-25 要一个 CreateTool 命令——Agent 按项目特点或用户要求，读文档和代码，总结出一条可以反复用的命令行或脚本（导表、Lua 编译……任意类型），配上中文名、说明、什么时候用、参数；创建完由用户选「加入项目」还是「全局」，项目的存在 docs 下大家共用；接进面板的工具大一统（能力路由，ADR 0081），所有对话的 Agent 都知道、都能调。同一条消息里还问了「还缺什么命令，要不要一起补」，见第 9 节。
> 涉及：面板 `fixcode-h/agent-panel`。插件仓库、UEKit、UEToVS、EmmyLua 都不改。
> 效果图：项目文件 `designs/自建工具CreateTool-效果图/`（5 个画面，深浅色各一张）。

## 0. 结论

1. **加一个内置命令 `/createtool`**，和 `/learn`、`/plan` 一样出现在「/」菜单里，每个 CLI 都能用（面板展开成要求）。Agent 照着它：先看已有的工具和插件工具里有没有能做的，再读文档和代码，写出工具草稿，试跑一次，最后交给面板保存。
2. **保存时弹窗让用户定**：预览中文名、说明、什么时候用、参数、实际会跑的命令和试跑结果；选「加入项目」（默认，存 `文档根/AgentPanel/Tools/`，跟仓库走、大家共用，P4 项目自动签出）或「全局」（存本机数据目录 `~/.agent-panel/tools/`，所有项目可用）。和已有工具重复时，同一个弹窗里给「更新那一个 / 另存一个新的」。
3. **Agent 只多一个面板工具 `custom_tool`**（list / show / run / test / save），不是每个自建工具各变成一个 MCP 工具。所有 CLI 都挂着面板 MCP，所以 Claude Code、Codex、Command Code、Pi 一样能用。提示词里只放一行短清单「有哪些、什么时候用」，超出预算的让 Agent 用 `list` 查。
4. **执行全由面板做**：按参数定义校验、按 shell 规则转义（不拼字符串），过和 CLI 命令同一套守卫，会改文件或影响外部的弹统一授权卡（带「本对话不再询问」，按工具记），改文件前按 P4 规则签出，一分钟内跑完的在工具里等结果，超时转成后台作业跑完推回。输出只回尾部和解析出的报错位置，完整日志写文件给路径；出错原样给 Agent 和用户看，不悄悄重试。
5. **管理放在「技能与 MCP」页**，加一个「工具」页签，分「项目自己的」和「从全局继承」两组，和技能、MCP 同一套列表；能试运行、编辑、看版本、在项目和全局之间移动、删除。
6. **接进能力路由**：自建工具注册表和插件工具一样是一份注册表；工具可以声明自己属于哪个能力（例如「改动生效 · Lua」），等「改动生效」能力做的时候，路由直接把它当成一条路，不用 Agent 记得去调。

## 1. 现在缺什么

| #   | 现状                                                                 | 问题                                                                                        |
| --- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 1   | 项目里导表、Lua 编译、打包这类命令，Agent 每次都要重新找脚本、猜参数 | 每个对话都要从头读一遍文档和脚本；弱模型猜错参数、在错的目录里跑                            |
| 2   | 经验（ADR 0054）有「命令」一类，能记下「导表用哪个命令」             | 只是一段文字，Agent 还得自己拼命令、自己判断成没成功；不能参数校验、不能授权、P4 不会先签出 |
| 3   | 自定义命令（「/」菜单里的命令文件）是发给 Agent 的提示词             | 是「让 Agent 去做一件事」，不是「一个可以直接执行的动作」，Agent 调不到                     |
| 4   | UE 插件把编译、Lua 编译做成了 MCP 工具                               | 只覆盖插件作者想到的；项目自己的脚本（每个项目都不一样）没法加进去，除非写插件              |

自建工具补的就是第 4 条和第 1 条之间的空：项目自己的脚本，变成一个 Agent 能直接调、面板能管住的动作，而且不用写代码。

## 2. 目标和非目标

目标：

- 用户一句话（或一次对话里用过的命令）就能变成工具，不用写 JSON。
- 所有对话（普通对话、工作流节点、子对话、各个 CLI）都知道并能调用，行为一致。
- 参数有校验，执行有授权、有超时、有日志，P4 项目改文件前自动签出。
- 项目级的工具跟着仓库走，同事拉下来就能用。

非目标：

- 不做多步骤的流水线（那是工作流）；一个工具就是一条命令或一个脚本。
- 不让自建工具替代插件工具：插件已经有的能力（UE 编译、Lua 热重载……）`/createtool` 会先指出来，不再做一份。
- 不在工具里存凭据：要密码、令牌的从环境变量或本机设置取，定义里只写变量名。

## 3. 工具定义

一个工具一个 JSON 文件，文件名就是工具 id。zod 契约放 shared/custom-tools/schema.ts（新）（新接口在 shared 写契约，AGENTS.md）。

```jsonc
{
  "schema": 1,
  "id": "export-tables", // 英文短名，Agent 调用用；保存后不改（改名 = 新工具 + 旧名转发一个版本）
  "name": "导表", // 中文名，界面和提示词里显示
  "summary": "把策划 Excel 配置表导成游戏用的 Lua 配置",
  "useWhen": "改了 Design/Excel 下的表，或要在游戏里验证表的改动之前",
  "avoidWhen": "只想看表内容时用表格插件读，不用导",
  "tags": ["表格", "配置"],

  "run": {
    "shell": "auto", // auto = 设置里的命令行环境；也可写 cmd / powershell / bash
    "command": "python Tools/ExcelExport/export.py {{sheet}} --out {{out}}",
    // 或者 "script": "export-tables.ps1"   同目录的脚本文件，长脚本放这里
    "platforms": { "win": { "command": "Tools\\ExcelExport\\export.bat {{sheet}}" } }, // 可选：按平台覆盖
    "cwd": ".", // 相对项目根；独立分支里换成那个分支的目录
    "timeoutSec": 600,
    "background": "auto", // auto：一分钟没完就转后台作业；always / never
  },

  "params": [
    { "name": "sheet", "label": "表名", "type": "string", "desc": "只导这一张，留空导全部", "flag": "--sheet" },
    { "name": "out", "label": "输出目录", "type": "path", "default": "Content/Script/Config", "inProject": true },
    { "name": "check", "label": "只检查不写", "type": "boolean", "flag": "--dry" },
  ],

  "effect": "write", // read 只读 / write 改项目文件 / external 影响外部（提交、上传、发消息、改服务器）
  "writes": ["Content/Script/Config/**"], // 会改哪些文件：执行前按 P4 规则签出，授权卡上也写出来

  "output": {
    "okExit": [0],
    "errorPattern": "^(?<file>[^:]+\\.xlsx):(?<line>\\d+): (?<msg>.+)$", // 可选：把报错解析成「文件:行: 原因」
    "maxChars": 4000,
  },

  "capability": "apply-change:lua", // 可选：属于能力路由的哪个能力（第 7 节）
  "sources": ["Tools/ExcelExport/README.md", "Tools/ExcelExport/export.py"], // 从哪些文件总结出来的，改了提示复核
  "version": 3,
  "history": [/* 最近 5 个旧版本：version、改的人（CLI 或用户）、时间、改动摘要 */],
  "createdBy": { "cli": "claude", "at": "2026-11-25T14:30:00+08:00" },
}
```

参数类型：`string`、`number`（可带 min / max）、`boolean`（只在为真时放 `flag`）、`enum`（选项列表，可带中文 label）、`path`（`inProject: true` 时必须在项目目录里）、`file`（必须存在）。都可以带 `required`、`default`、`pattern`、`desc`。

占位符：`{{参数名}}`；面板自带 `{{projectRoot}}`、`{{docRoot}}`、`{{workDir}}`（独立分支时是分支目录）、`{{dataDir}}`。可选参数为空时连同它的 `flag` 一起去掉，不留空引号。

**转义由面板做**：参数值按目标 shell 的规则加引号（cmd、PowerShell、bash 各一套，放 `shared/custom-tools/expand.ts`；现在只有 `shared/clis.ts` 的 `quoteArg` 一个简单版本，做成按 shell 区分的共用函数后它也改用这一份），不做字符串拼接。不允许参数值里出现换行；`raw: true`（原样拼进去）只能用户在编辑页手动打开，打开时页面上标黄提示。

## 4. 存在哪

| 范围 | 位置                                                               | 说明                                                                                                                                                                               |
| ---- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 项目 | `文档根/AgentPanel/Tools/<id>.json`，脚本放同目录                  | 走 `projectData(projectId, 'Tools')`（ADR 0078）：文档根在 `ProjectDoc/docs` 或项目的 `docs/`，和收藏、表格结构文件同一处；写入按 P4 规则先签出，git 项目就是普通文件，跟着提交    |
| 全局 | `~/.agent-panel/tools/<id>.json`（数据目录，可在设置里改数据目录） | 只在这台电脑上，所有项目都能用。**建议这样定的原因**：全局工具多是个人习惯（清缓存、开某个工具），不该进任何一个仓库；数据目录已经是本机配置的家，备份、迁移、「恢复设置」都会带上 |

- 同一个 id 两处都有时，项目的优先（列表里全局那一个标「被项目覆盖」）。
- 普通 Chat 页（不在项目里）只有全局工具。
- 文件变了（同事提交了新工具、手改了 JSON）面板马上知道：注册表挂在面板统一的文件监听上（ADR 0074），文档根变了跟着 `onDocRootChange` 重读。读不进来的文件不悄悄跳过，在管理页标红写原因。

## 5. Agent 怎么用

### 5.1 面板工具 `custom_tool`

按 ADR 0067 的准入四问：CLI 自带的跑命令做不到参数校验、授权、签出、结果解析；不能并进 `run_background`（那是「任意命令放后台」，语义不同）；结果 Agent 拿得到；什么时候用写得清。一个工具、五个 action：

| action | 参数                       | 做什么                                                                                     |
| ------ | -------------------------- | ------------------------------------------------------------------------------------------ |
| `list` | `query?`                   | 列出能用的工具：id、中文名、什么时候用、参数摘要、范围（项目 / 全局）。默认不超过 4000 字  |
| `show` | `id`                       | 一个工具的完整定义（参数、命令、会改哪些文件）                                             |
| `run`  | `id`、`args`               | 执行（5.3）                                                                                |
| `test` | `draft`、`args`、`dryRun?` | 试跑还没保存的草稿：`dryRun` 只返回参数展开后的完整命令；不带就真跑，授权规则和 `run` 一样 |
| `save` | `draft`、`testRun?`        | 交给用户保存（5.2）。马上返回「已交给用户确认」，用户选完由面板推回一条消息                |

说明写全 `ToolGuide`（ADR 0064）：`useWhen` = 「要做的事和自建工具清单里某一个的『什么时候用』对得上时，先用它，不要自己拼命令」；`avoidWhen` = 「一次性的命令、几秒的查看命令直接用 CLI 的命令工具」。

### 5.2 提示词

对话、节点、子对话的用法说明里多一行（只有这个项目有工具时才出现），按工具的 `useWhen` 生成：

```
自建工具（用 custom_tool 调，参数不清楚先 action=show）：
- 导表 export-tables：改了 Design/Excel 下的表之后
- Lua 编译 lua-check：改了 Lua 之后、提交之前
- 清理中间文件 clean-intermediate：编译报莫名其妙的链接错误时
（还有 4 个，action=list 看全部）
```

最多 8 行、600 字以内（ADR 0071 的提示词预算），按最近用过的次数排。工具一个都没有时整段不出现。

**为什么不把每个工具单独做成 MCP 工具**：工具个数和长度有上限（ADR 0067、`registry.test.ts`），项目工具一多就挤掉别的；各 CLI 对 MCP 工具的延迟加载做法不同，单独的工具反而更容易被「只给名字」；参数 schema 每改一次都要 CLI 重新取清单。只有一个入口时，加减工具只改提示词里那一行。

### 5.3 执行一次

```
custom_tool run → 找定义（项目优先）→ 校验参数（类型、必填、范围、在不在项目里）
  → 展开命令（按 shell 转义）→ 守卫（Orchestra.guardCommand，和 CLI 跑命令同一套：删库、凭据守卫照旧拦）
  → 授权（effect 为 write / external 时弹卡，5.4）→ P4 签出 writes 里已有的文件
  → spawnTracked 起进程（ADR 0076，停止对话时整棵进程树结束）
  → 60 秒内结束：在工具里等到，返回结果
  → 超过 60 秒：转成后台作业（ADR 0075，侧栏和「后台任务」里看得到），马上返回作业号，跑完结果推回这个对话
```

返回（紧凑，默认不超过 4000 字）：

```
导表 export-tables · 退出码 1 · 12.4s · 失败
报错 2 处：
  Design/Excel/Item.xlsx:37: 列 Price 不是数字
  Design/Excel/Item.xlsx:52: 引用的 SkillId 2033 不存在
输出最后 40 行：…
完整日志：.agent-panel/tool-runs/export-tables-0007.log（1,284 行）
签出的文件：Content/Script/Config/Item.lua（已在 changelist 默认）
下一步：改表后用同样的参数再跑一次；只想检查不写文件加 check=true。
```

- 退出码不在 `okExit` 里就是失败，工具结果标 `isError`，对话里的工具卡片显示红色；**不按输出文字判断成没成功**（ADR 0041、0049）。
- 超时、被守卫拦、用户拒绝，各给一句「下一步怎么调」。
- 每次运行记一条运行记录（谁、什么参数、结果、耗时），管理页能看最近 20 次。

### 5.4 授权

- 新加一类授权 `ctool:<范围>:<id>`，登记进 `shared/grants/kinds.ts`：分组「其他」，默认给「本对话不再询问」，`presettable: true`（工作流可以在定义里自带，像 UE 插件的确认一样）。
- `effect: read` 的工具默认不弹卡（只读，和 CLI 读文件一样），但守卫照旧过。`write`、`external` 每个对话第一次跑时弹卡；卡片用共用的 `GrantActions`：拒绝 / 允许一次 / 本对话不再询问。
- 卡片上写清楚：工具中文名和范围、**展开后实际会跑的完整命令**、参数、会签出的文件。用户的指令优先（ADR 0070）：守卫拦下而用户坚持要跑时走 `request_override` 放行卡，不另做一套。
- 设置 →「授权卡」里自动多一行「自建工具」，能整类关掉「本对话不再询问」。

### 5.5 跨 CLI

工具在面板这边执行，CLI 只是发起调用，所以各家一样：Claude Code、Codex、Command Code 经面板 MCP；Pi 经面板的 MCP 桥接。`custom_tool` 的 `when` 只看「有没有项目或全局工具」，不看 CLI。CLI 的差异（有没有 MCP、工具名前缀）已经在 CLI 定义里，不新增字段。

## 6. `/createtool` 的流程

### 6.1 命令

加进 `shared/commands.ts` 的内置命令：

- 名字 `createtool`，参数提示 `<要做成工具的事，例如：导表>`，说明「把一个常用命令或脚本做成工具：读文档和代码总结出来，以后所有 Agent 都能直接调」。
- 没写参数时：把这次对话里跑过的命令总结成工具（适合「刚才那个命令以后还要用」）。

展开后的要求（给 Agent，不翻译）大意：

1. 先 `custom_tool list` 看有没有同类的；再看插件工具（UE 的编译、Lua 热重载这类）能不能做，能做就告诉用户直接用它，不再建。
2. 用面板的 `find` 和读文件查清：入口脚本、真正要的参数、在哪个目录跑、成功和失败分别输出什么、会改哪些文件。只读，不改项目文件。
3. 写草稿：中文名、一句话说明、什么时候用（写成具体场景）、什么时候别用、参数（中文 label 和说明）、`effect` 和 `writes` 如实写，拿不准的往严了写。
4. `custom_tool test dryRun=true` 看展开后的命令对不对；只读的工具真跑一次，会改文件的问用户要不要真跑。
5. `custom_tool save` 交给用户，结束这一轮；用户保存、改范围、要求再改的结果会推回来。

### 6.2 保存弹窗

`save` 在发起它的对话里弹出（效果图 2）：

- 上半：工具卡片预览——中文名、id、说明、什么时候用 / 别用、参数表、会改的文件、实际命令（代码块，按 shell 高亮）、试跑结果（退出码、耗时、最后几行）。每一项都能直接点开改。
- **保存到**：两张单选卡片——「加入项目（推荐）· 存进 docs/AgentPanel/Tools，跟仓库走，大家共用；P4 会先签出」、「全局 · 只在这台电脑，所有项目都能用」。默认按 `effect`：用到项目路径的默认项目，只用系统命令的默认全局。
- **重复检测**（有才出现，黄色提示条）：同 id；中文名很像；命令去掉参数值、引号和空白后一样；用同一个脚本文件。列出撞上的那一个（范围、版本），选项：「更新它（v3 → v4，看差异）」/「另存为新工具」。同 id 时只能更新或改 id。
- 按钮：取消 / 让 Agent 再改（展开一个输入框，写的话推回给 Agent）/ 保存。
- 没跑过 `test` 的草稿也能存，但弹窗顶上写「还没试跑过」。

### 6.3 用户自己也能触发

- 对话里每张「运行命令」卡片的菜单多一项「存成工具」：等于对这条命令发一次 `/createtool`。（二期）
- 管理页「新建工具」：手填一张空表单，或「让 Agent 写」（开一个新对话发 `/createtool`）。

## 7. 接进能力路由（工具大一统）

ADR 0081 把「同一件事有几条路」交给面板选。自建工具在这套里有两层：

1. **注册表同构**：`server/custom-tools/store.ts` 和插件的 `findSources` 一样是「谁登记、面板统一用」。面板工具清单、设置 →「MCP」的「Agent 拿得到什么」、能力路由都从这一份读，不各自扫文件。
2. **当成能力的一条路**：工具写了 `capability`（例如 `apply-change:lua`），等「改动生效」能力（设计稿第 8 节的下一个能力）做的时候，路由把它当一条 `RouteSource`：项目自己的 Lua 编译脚本排在插件的 Lua 热重载之后、文本兜底之前，Agent 只说「让改动生效」，不用知道背后是哪个。第一期只把字段和注册表留好，不改路由。

另外两处顺手接上：

- **经验**：`project_experience` 查到「命令」类经验，而这条命令已经有工具时，结果里写「已有工具 export-tables，直接用 custom_tool 调」。（二期）

### 8.1 「技能与 MCP」页加「工具」页签（效果图 4）

- 分区：基本（中文名、id、说明、什么时候用、什么时候别用、标签）、运行（shell、命令或脚本，带高亮和占位符补全、目录、超时、后台）、参数（表格：名字、中文、类型、必填、默认、说明，可拖动排序）、影响（只读 / 改文件 / 外部，会改的文件）、输出（成功的退出码、报错格式，带「用上次输出试一下」）。

## 9. 还缺哪些命令（用户问「要不要一起补」）

对照 Claude Code、Codex 的命令和这几个月对话里反复出现的要求，现在内置的是：compact、review、init、commit、test、fix、bug、learn、plan、explain、simplify、docs、security-review。建议补：

| 优先   | 命令                 | 做什么                                                                                               | 为什么                                                                 |
| ------ | -------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 一起做 | `/createtool`        | 本设计                                                                                               | —                                                                      |
| 一起做 | `/build [目标]`      | 编译并把报错修到通过：先找自建工具和项目说明里的编译命令，再跑、再修，直到过                         | 「编译过了没」是最常见的收尾要求；有了自建工具，它直接用项目的编译工具 |
| 一起做 | `/run [要看的]`      | 把项目跑起来看效果：起开发服务器、编辑器或游戏，看日志确认改动真的生效                               | 现在只有测试，没有「跑起来看看」；UE 项目要配合 PIE                    |
| 一起做 | `/merge <分支>`      | 合并分支并解冲突：按项目约定（不 rebase、资源文件冲突用对方的、代码冲突逐个解），合完跑检查          | 用户定过冲突规则，每次都要重说一遍                                     |
| 二期   | `/pr`                | 推送并建 PR，按项目设置「推送到远端」决定推不推、合不合                                              | 现在靠 Agent 自己记项目的发布流程                                      |
| 二期   | `/refactor <要改的>` | 按描述重构：先补测试兜底，改完行为不变                                                               | `/simplify` 只清理，不做结构调整                                       |
| 二期   | `/perf <现象>`       | 性能排查：先测量找热点，再改，再测对比                                                               | UE 项目常见，现在只能用 `/bug` 凑合                                    |
| 二期   | `/deps`              | 升级依赖并修好编译和测试                                                                             | —                                                                      |
| 二期   | `/changelog`         | 按提交整理更新说明                                                                                   | 三个仓库都有 CHANGELOG 约定                                            |
| 二期   | `/doctor`            | 面板直接执行：检查 CLI 版本、MCP 连接、IDE / VS / UE 有没有连上、文档根、P4 登录，列出不对的和怎么修 | 「为什么找不到 lua_code」这类问题现在要翻设置页                        |

不建议加的：`/clear`（面板「新建任务」已经是）、`/context`（右栏常驻上下文用量）、`/undo`（已有「撤销这一轮」）、`/model`（输入框下拉）。

## 10. 分期

**一期（和 /build、/run、/merge 一起）**

- shared/custom-tools/（新）（schema、参数校验、命令展开和按 shell 转义、重复检测）+ 单测。
- server/custom-tools/（新）（存储走 `projectData` 和数据目录、注册表 + 文件监听、执行：守卫 / 授权 / 签出 / `spawnTracked` / 转后台、运行记录）。
- 面板工具 server/panel-tools/custom-tool.ts（新）（五个 action），名字登记进 `shared/panel-tools.ts`，`ToolGuide` 写进 `panel-guides.ts`；提示词一行清单。
- 授权类型 `ctool:`；内置命令 `/createtool`、`/build`、`/run`、`/merge`。
- 界面：保存弹窗、对话里的运行结果卡片、「技能与 MCP」的「工具」页签、编辑抽屉和试运行；四个共用组件和样张。
- 演示版：`web/src/lib/demo-*` 里放两三个示例工具，演示后端调 shared 里同一份校验和展开逻辑。
- ADR：自建工具（存放、单入口工具、授权、和能力路由的关系）。

**二期**：命令卡片「存成工具」、经验命中提示已有工具、依据文件变了提示复核、`/pr` 等二期命令。

**三期**：`capability` 接进「改动生效」路由；「/」菜单里选工具直接弹参数表单运行；设置「路由记录」里显示工具运行。
