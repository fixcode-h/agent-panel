# 怎么写好测试

核心：**测代码做了什么，不测 mock 做了什么**。

## 好测试的样子

| 要求       | 好                                                                             | 差                                     |
| ---------- | ------------------------------------------------------------------------------ | -------------------------------------- |
| 一个行为   | 名字里没有「和」，一个用例一个断言主题                                         | `校验邮箱和域名和空格`                 |
| 名字说行为 | `空邮箱返回「邮箱必填」`                                                       | `test1`、`works`                       |
| 测公开行为 | 通过公开接口调用，断言返回值、输出、状态变化                                   | 断言私有字段、内部调用顺序             |
| 用真实代码 | 能用真实实现就用；只隔离慢的、不确定的外部依赖（网络、时钟、随机数、文件系统） | 把被测对象的直接依赖全 mock 掉         |
| 可重复     | 固定输入、固定时间、独立的临时目录，单独跑和一起跑结果一样                     | 依赖执行顺序、真实时间、共享的全局状态 |
| 失败可读   | 失败信息说清期望什么、得到什么                                                 | 只有 `expected true got false`         |

覆盖：正常路径之外，至少想一遍边界（空、一个、最大值、越界）、错误输入和失败路径。

## 反模式

### 1. 测 mock 的行为

```ts
// ✗ 只证明 mock 被调用了，没证明重试逻辑对
const fn = mock().fails().fails().succeeds()
await retry(fn)
expect(fn).toHaveBeenCalledTimes(3)

// ✓ 用一个真实的函数，断言结果
let n = 0
const result = await retry(async () => {
  if (++n < 3) throw new Error('x')
  return 'ok'
})
expect(result).toBe('ok')
expect(n).toBe(3)
```

断言之前问一句：「这条断言失败时，说明产品代码有问题，还是只说明 mock 配得不一样？」后者就删掉或改成测真实行为。

### 2. 为测试往产品代码里加方法

不要为了测试给产品类加 `resetForTest()`、`_internalState` 之类只有测试用的入口。需要隔离时，把依赖改成构造参数或函数参数传进来；需要清理时，用测试自己的临时实例。

### 3. 不理解依赖就 mock

mock 一个依赖前，先弄清它真实的行为：返回什么结构、什么时候抛错、有没有副作用。凭想象 mock 出来的依赖会让测试通过而真实环境失败。

### 4. mock 的数据不完整

mock 的返回值要和真实结构一致（所有字段、真实的类型和取值），不能只填这条用例碰巧用到的字段；否则下游代码读其他字段时测试发现不了。优先用项目里真实的样本数据（fixtures）。

### 5. 集成测试事后才想起

跨模块的路径（真实的读写、真实的进程、真实的序列化）只靠单元测试覆盖不到。改动涉及模块之间的契约时，至少有一条走真实组件的集成测试。

## mock 太复杂时

setup 比被测逻辑还长、要 mock 五六个东西、每改一次实现都要改 mock：这是代码耦合太紧的信号。考虑：

- 把纯逻辑抽成输入 → 输出的函数，单独测，不用 mock；
- 改用真实组件的集成测试（临时目录、内存数据库、假的 CLI 脚本），往往比堆 mock 更简单可靠；
- 把依赖改成参数传入，测试里传一个简单的假实现。

## 测试数据

- 期望值直接写字面量，让人一眼看出在测什么；不要在测试里重算一遍产品逻辑来得到期望值。
- 通用的构造放测试辅助函数（`makeTask({ ...overrides })`），每个用例只写和它相关的字段。
- 不依赖外网和本机特有的路径、账号；需要外部服务的标成集成测试或登记为延期验证。
