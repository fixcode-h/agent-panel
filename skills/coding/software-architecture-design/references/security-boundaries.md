# 安全边界

## 适用场景

外部接口、身份、敏感数据、多租户、管理面、第三方依赖和构建发布链。

## 决策问题

识别资产、数据流、身份/网络/租户/管理边界、攻击面和滥用场景。把控制映射到测试与所有者，而不是只列风险。

## 强制约束

- MUST 默认拒绝并在服务端可信层逐请求授权主体、动作、对象、字段、租户和状态。
- MUST 在边界规范化并正向校验输入，同时保护业务不变量。
- MUST 将秘密交给专用系统，使用短期、最小权限、可撤销凭据。
- MUST 为高风险变更更新威胁模型。
- MUST 保护源码、构建、依赖、制品、SBOM、签名和 provenance 链。
- MUST NOT 以“内网”、难猜 ID、客户端校验或网关鉴权代替服务端授权。
- SHOULD 让安全依赖失败时 fail closed；例外需风险批准和期限。

## 候选方案与取舍

集中身份提升一致性；细粒度授权提高安全但增加策略与缓存失效复杂度；网络分段限制爆炸半径；遥测最小化降低泄露风险但必须保留审计证据。

## 反模式

恢复流程弱于登录；跨租户缓存键缺租户；源码/镜像含秘密；默认管理员；安全扫描无范围永久忽略；生成签名但部署不验证。

## 验证方式

威胁桌演；授权正负矩阵；IDOR/跨租户测试；秘密扫描与轮换演练；全新环境安全基线；制品篡改拒绝；依赖混淆测试；例外到期检查。
