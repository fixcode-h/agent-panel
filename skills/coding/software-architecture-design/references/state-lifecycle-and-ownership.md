# 状态、生命周期与所有权

## 适用场景

长生命周期对象、资源句柄、会话、任务、订阅、游戏实体和跨线程状态。

## 决策问题

每项状态必须回答：谁创建、谁拥有、谁可修改、何时可见、何时销毁、失败时是否合法、是否共享、是否持久化。用状态机表达重要生命周期，避免布尔组合。

## 候选方案与取舍

- 不可变值：默认用于共享配置和快照。
- 单一所有者可变状态：适合聚合与会话。
- Actor/消息所有权：适合串行化状态变更。
- 共享并发状态：仅在性能证据要求时采用，并明确同步协议。

## 强制约束

- MUST 定义合法状态、转换、守卫和终止状态。
- MUST 原子构造并发布；外部不得观察半初始化对象。
- MUST 让创建者或明确生命周期容器负责清理。
- MUST 成对管理订阅、委托、Timer、句柄与后台任务。
- MUST NOT 依赖 GC 完成需要确定时序的业务清理。
- SHOULD 把资源生命周期限制在最小作用域。

## 反模式

双向所有权；全局可变单例；析构时才做关键提交；多个布尔值表达互斥状态；回调捕获对象导致意外保活；关闭时 fire-and-forget。

## 验证方式

状态转换模型测试；重复初始化/清理测试；取消、超时、异常路径资源泄漏检查；并发竞态检测；弱引用和生命周期边界测试；长时间运行后的句柄、任务和内存基线。
