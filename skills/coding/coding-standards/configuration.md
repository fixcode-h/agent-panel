# 数据配置化与单一事实源

目的：值只在一个地方定义，改一次全局生效；会被人调的数据不需要改代码。

## 先分清是哪一类

| 类别            | 例子                                     | 放在哪                                                                |
| --------------- | ---------------------------------------- | --------------------------------------------------------------------- |
| 模块内常量      | 本模块的重试次数、缓冲区大小、内部事件名 | 模块文件顶部的常量区，`UPPER_SNAKE` 或项目惯用写法，带单位和一行说明  |
| 项目级常量      | 多个模块共用的上限、路径、键名、默认值   | 项目已有的 `constants` / `config` / `shared` 文件；没有就建一个统一的 |
| 可调配置        | 超时、开关、功能参数、阈值               | 配置文件或设置项：有默认值、类型、校验，读取入口只有一个              |
| 环境相关        | 端口、地址、凭据、本机路径               | 环境变量或本机配置；凭据绝不进代码和仓库                              |
| 策划 / 内容数据 | 数值表、掉落、关卡、文案、UI 样式        | 数据表 / 资产（DataTable、JSON、CSV、DataAsset），代码只读不写死      |
| 枚举型列表      | 选项、映射、路由、命令、类型 → 处理函数  | 一张数据表（数组 / 字典），逻辑遍历它                                 |

判断要不要提出来：**用到第二次、有人可能要调、含义不是一眼能看出**，满足任一条就提。

## 写法

- 名字说清含义和单位：`MAX_RETRY = 3`、`REQUEST_TIMEOUT_MS = 30_000`、`ICON_SIZE_PX`，不叫 `NUM`、`VALUE2`。
- 相关的值放在一起成组（一个对象 / 结构体 / 命名空间），不散成十几个全局变量。
- 配置从一个入口读：一个 `getConfig()` / 一个设置对象 / 一个子系统，入口里统一处理默认值、类型转换、校验和缺失；业务代码不各自读文件、各自 `parseInt`。
- 配置结构用 schema 或类型描述（zod、JSON Schema、`USTRUCT`、强类型类），读入时校验，错了给出明确错误，不悄悄用一个错的值跑下去。
- 派生值在一处计算（函数或 getter），不在各处各算一遍。
- 前后端 / 多语言共用的定义放共享位置，由一份生成或导入另一份，不手抄两份。
- 配置在运行中会变时，明确是**快照**（这次任务开始时定下来）还是**实时读**；同一次处理里只用同一个版本，避免一半新一半旧。

## 列表写成表

```ts
// ✗ 每加一种格式要改三处
function ext(kind: string) {
  if (kind === 'image') return '.png'
  if (kind === 'video') return '.mp4'
  return '.bin'
}
function mime(kind: string) {
  /* 又一串 if */
}

// ✓ 一张表，加一种格式只加一行
const FORMATS = {
  image: { ext: '.png', mime: 'image/png' },
  video: { ext: '.mp4', mime: 'video/mp4' },
} as const
type Kind = keyof typeof FORMATS
const ext = (k: Kind) => FORMATS[k].ext
```

同样的思路：错误码 → 文案、命令名 → 处理函数、平台 → 参数、状态 → 显示样式，都是表。

## 各技术栈的落点

- **TypeScript / JavaScript**：模块顶部 `const`；共享的放 `shared/constants.ts` 一类文件，`as const` 让类型从数据推出来；配置用 zod 等 schema 校验。
- **C++**：`constexpr` / `static constexpr` 成员 / 匿名命名空间里的常量，不用 `#define`；可调参数放配置结构体。
- **Unreal Engine**：可调的数值做成 `UPROPERTY(EditDefaultsOnly / Config)`、`UDeveloperSettings`、`DataTable` / `DataAsset`，策划能在编辑器里改；资产路径用软引用集中配置，不在代码里写死 `/Game/...` 字符串。
- **Lua**：模块顶部 `local` 常量表；共享配置放统一的配置模块，`require` 取用；策划数据从表里读。
- **C#**：`const` / `static readonly`，配置用 Options 模式或 ScriptableObject。
- **样式 / 界面**：颜色、间距、字号用设计令牌（CSS 变量、主题、样式表），不在组件里写死色值和像素。

## 不需要提常量的

- 含义一目了然的 `0`、`1`、`-1`、`''`、`true`，以及数学公式里的系数（`/ 2` 求中点）。
- 只在一处出现、紧挨着有说明、且没人会调的值。
- 测试里的期望值和输入数据（测试要直白，提成常量反而看不出在测什么）。
