# 契约、适配器与代码生成

## 适用场景

HTTP/RPC/消息入口、持久化适配器、第三方接口、schema 和生成代码。

## 决策问题

外部契约与内部模型是否独立演进？若是，建立 DTO/映射和适配器；若简单且同生命周期，可减少映射但记录耦合。

## 强制约束

- 契约和 schema 作为明确输入，生成过程可复现。
- 生成目录禁止手工修改；扩展通过 partial、插件点或独立包装。
- 适配器转换协议错误、超时和外部模型，不把 SDK 类型传入核心。
- 提供最小契约测试和兼容检查。

## 反模式

ORM 实体直接作为 API；生成文件与手写逻辑混杂；反射扫描代替明确注册却无启动/裁剪验证；客户端与服务端复制两套 schema。

## 验证方式

重新生成后工作区无 diff；历史契约兼容；真实序列化路径；外部错误映射；AOT/裁剪目标构建（适用时）。
