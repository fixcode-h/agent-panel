# 测试框架与适应度门禁

## 适用场景

为新骨架建立最小但真实的验证能力。

## 强制约束

至少提供：

- 核心规则的聚焦测试入口；
- 一个跨边界 smoke test；
- 关键模块/依赖架构测试；
- 与 CI 相同的 build/test/lint/typecheck 命令；
- 外部契约存在时的契约或真实适配器测试。

测试必须走真实组合根或明确的测试组合根，不靠生产全局单例。每个门禁说明保护风险，避免只追覆盖率。

## 反模式

只有 Hello World；所有依赖 mock；E2E 承担全部分支；测试配置与生产装配完全不同；架构规则从未证明会失败。

## 验证方式

从干净 checkout 执行；故意制造非法依赖确认失败；替换真实外部依赖测试序列化/事务；统计测试稳定性和时长。
