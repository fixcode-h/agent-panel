# 布局与模块边界

## 适用场景

建立目录、项目、程序集、包、UE Module/Plugin 或 Lua 模块结构。

## 决策问题

物理结构应让职责、公开接口、所有权与依赖方向可见。按业务能力优先组织；技术层只在模块内部有独立意义时使用。

## 强制约束

- 公共入口最小，内部实现默认隐藏。
- 测试与被测模块邻近或有清晰映射。
- 生成代码、手写代码和扩展点分离。
- 共享代码必须有明确所有者和稳定职责。
- 用构建引用和架构测试阻止反向依赖。

## 反模式

按文件类型全局分桶；Common/Utils 垃圾桶；循环依赖靠更大的 Shared 解决；每层一个项目但只有透传；公开所有类型方便调用。

## 验证方式

依赖图、循环检测、公开 API 审计、非法引用测试、删除一个模块后的影响面检查。
