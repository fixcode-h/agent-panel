# 任务记录

任务规模（Micro、Standard、Complex）由工作流或调用方的参数给出；没有给出时按下面的描述判断，拿不准先按更高一档处理。规模只决定记录和验证的成本，不决定要不要拆分或并行——那由工作流安排。

## 任务规模

- **Micro**：只读问答、状态查询、单文件文字修改、低风险可逆调整。读取必要上下文，执行一条能证明结果的检查；不创建任务目录。
- **Standard**：单模块修复、小功能、配置或文档行为变化。读取项目文档，在已有 acceptance.md 中追加限定验证与未验证风险；确需跨会话恢复且没有记录入口时才新建任务目录。
- **Complex**：跨模块、架构、P4/UE 资源、长任务或外部工具。建立完整任务目录，使用 tasks.md、design.md、acceptance.md 和 handoff.md；每个里程碑都必须形成验证证据。

自行判断规模时，完成影响面和验证边界判断后可以降级；降级必须留下理由，升级不需要重新开始已完成的读取。

## 执行要求

1. 读取项目入口、模块地图和工作区基线，确认 VCS、已有改动和允许范围。
2. 明确目标、非目标、成功标准和当前里程碑。
3. 批量完成同一验收边界内的变更，再立即运行限定验证；不要连续执行没有新证据的探索。
4. 将命令、结果、文件和时间写入 acceptance.md。失败记录实际输出、根因假设和下一次最小诊断动作。
5. 中断、上下文压缩或准备交接时更新 handoff.md：最后确认事实、未完成项、阻塞、下一动作和恢复入口。
6. 交付前重新读取任务清单，确认文档、验证和 VCS 收尾已完成；无法验证的项目明确标记为 N/A，不得写成通过。

## 低打断规则

- 只有会改变范围、不可逆操作、需求冲突或缺少外部事实时才请求用户选择；可逆的实现细节由 Agent 自行决定。
- Micro 任务保持短路径；Standard 任务只保留能复现和验收的证据；Complex 任务才使用完整状态文件。
- 同一事实只在一个文件记录，回复中引用路径和证据，不复制第二份任务清单。
- 发现重复读取、重复失败或验证结果没有变化时，先回到工作区状态和最近证据，改做最小诊断。

## 记录与恢复

普通长任务位于 `DOC_ROOT/worklog/<task-id>/`；已有 OpenSpec change 或 P4 台账时复用原位置。

- **tasks.md 是唯一勾选清单**；勾选 `[x]` 必须能在 acceptance.md 中找到对应的验收证据，没有证据不勾选。
- design.md 记录目标、范围与决策。
- acceptance.md 记录命令、退出码、时间和风险。
- handoff.md 只记录当前状态及一个最小下一动作。
- 不要新建 plan.md / evidence.md 复制同一事实。

本技能目录下的 `templates/` 提供上述四个文件。恢复时先读 handoff.md、tasks.md、最近验收证据，再用工作区 status/diff 核对实际状态；只扩大有变化的上下文，不重复完整探索。

## 退出条件

当前验收边界全部通过且无已复现问题时停止本轮；剩余外部依赖写入 handoff.md，不以「完美」作为无限循环条件，不自行改变模型、权限、凭据或远端发布策略。
