# 拷问（grilling）

一直追问，直到和用户对一件事达成共识。把要定的事画成一棵**设计树**：每个决策下面挂着依赖它的决策，上面的定了，下面的才问得出来。

## 先分清事实和决策

- **事实归你查**：代码怎么写的、文件在不在、命令输出什么、文档和 ADR 怎么定的，都自己查，不拿去问用户。查的时候不要卡住整棵树：还在查的事实只挡住依赖它的那几个问题，其余的照常问。
- **机械决策自己定**：命名、目录布局、格式这类按项目约定就能定的，自己定，记进「我按规则定的」，最后一起给用户看，不单独打断。
- **决策交给用户**：偏好、范围、取舍、不可逆的事，每一个都问用户并等回答。

## 一次问一个

**前沿**是所有前置条件都已定的决策，也就是现在问不用猜用户答案的问题。每次从前沿里挑**最上游的一个**问：答案会改变最多后续问题的那个先问，细节放后面。依赖还没回答的问题的，留到后面再问。

每个问题用提问工具弹窗问（Claude Code 用自带的 `AskUserQuestion`，其他 CLI 用面板的 `ask_user`），不要把问题写成普通文字：

- 一次只放**一个问题**，问题本身写清楚背景，短标题（header）几个字。
- 给 **2–4 个选项**，每个选项的 description 写清选它的后果和代价。
- 推荐的放第一位，label 末尾标「（推荐）」，`recommended` 写它的序号；理由写进问题或选项说明里，一句话。
- 能同时选好几项的问题（「要包含哪些」「先做哪几个」）把 `multiSelect` 设为 true。
- 选错了改回来不费事的写 `reversible: true`；删除、推送、发布、改用户数据这类收不回的写 false。
- 用户可以不选选项、自己写答案：照他写的为准，不要再把同一个问题换个说法问一遍。

用户回答后，设计树随之变化：定了的决策把前沿往外推，解锁依赖它的问题，也可能让某些分支不用再问。重新算前沿，再问下一个。

## 在等确认的工作流节点里

节点给了 `submit_report` 面板工具（节点勾了「完成后等我确认」）时，不逐个弹窗，每一轮用 `submit_report` 交：前沿上的问题各写成 `decisions` 的一项（2–4 个 `options`、你推荐的 `pick` 和理由），机械决策也列进去并标 `self: true`，要等这一轮答完才能问的写进 `next`。面板会把决策画成可勾选的卡片，并告诉你用户改了哪几项；按用户的选择接着下一轮。

## 收尾

- 前沿空了才算完：设计树每个分支都走到了，没有悄悄假设的地方。
- 收尾时把共识整理成一份清单：每个决策写「问题 → 结论」，用户定的和你按规则定的分开列，没定的写进「待确认」。
- 最后用提问工具问一次「以上共识对不对」（选项如「确认，按这个做」「还有要改的」），用户确认之前不按它动手。
- 要落盘（例如 OpenSpec 的 `grilling.md`）时只记结论不记过程：每个决策写问题、候选项（`- [ ]` / `- [x]` 勾选列表，选中的打勾）和结论，用户自己填的答案直接替换对应的候选项。
