# Lua luac 编译

## 通用 Lua 语法检查

本技能目录下的 `scripts/check_lua_syntax.py` 是内置的语法检查脚本，后续检查 Lua 源码时直接复用，不要在临时目录重复创建同名脚本。该脚本使用已安装的 `lupa` 运行时调用 `load`，支持多个文件、UTF-8 BOM，并在任一文件失败时返回非零退出码：

```powershell
python <本技能目录>/scripts/check_lua_syntax.py path\to\file.lua another\file.lua
```

`lupa` 未安装或目标 Lua 版本与项目运行时不一致时，不得将该检查结果当作目标运行时兼容性证明；应记录工具链差异并使用项目目标运行时复核。

本技能的目标是使用项目选定的 VS Code `LuacPacker` 扩展完成可重复、可验证的 Lua 字节码构建；不替代项目的 Lua/宿主架构设计。P4 任务中，只有本技能前置条件全部满足时才允许编译 `.luac`；生成的 `.luac` 必须由 `project-vcs` 的 P4 细则纳入与源 `.lua` 相同的 Lua pending。Git 等其他版本控制下，`.luac` 是否入库按项目的忽略规则（如 `.gitignore`）和既有约定处理，不擅自改忽略规则。

## 前置检查

先确认：

- VS Code 已安装并启用 `LuacPacker`；
- 项目使用的 Lua 实现和版本：PUC Lua 5.1/5.2/5.3/5.4、LuaJIT 或宿主定制版本；
- 目标运行时加载的是哪一种字节码格式；
- 编译器、运行时和目标平台的架构/ABI 约束；
- 源码根目录、输出目录、需要排除的测试/工具/开发脚本；
- 是否需要保留源码、调试信息或进行发布压缩。

`luac` 字节码通常与 Lua 主版本、LuaJIT/PUC Lua 实现及构建选项相关。不得使用任意机器上的 `luac` 编译后直接交付；编译器版本必须与目标运行时兼容并纳入构建记录。

## LuacPacker 使用流程

在 P4 任务中，如果以下任一条件不满足，立即停止本技能的编译部分，只把源 Lua 文件交给 `project-vcs` 的 P4 细则处理，并记录原因：VS Code 已安装并启用 `LuacPacker`、扩展实际编译入口已确认、编译器可执行、目标 Lua 实现/版本已确认且兼容、输出目录和排除规则已确认。

1. 在 VS Code 扩展面板确认 `LuacPacker` 的安装版本和可用命令。
2. 打开项目根目录，不要以单个 Lua 文件作为工作区根目录。
3. 使用扩展提供的命令面板入口或项目设置配置编译根目录、输出目录和排除规则。
4. 首次配置前读取扩展实际显示的 setting key、命令名和参数；不要凭记忆创建不存在的 `luacpacker.*` 配置。
5. 先对一个最小 Lua 文件执行编译，确认输出位置、文件名、字节码格式和错误日志。
6. 再执行全量编译；输出目录必须独立于源码目录，避免把 `.luac` 当作下一轮输入。
7. 对输出目录做清单、数量、路径映射和时间戳检查；确认没有把测试、编辑器工具或秘密文件编译进发布包。
8. 用**目标运行时本身**加载代表性 `.luac`，验证模块入口、宿主绑定、require 路径、协程和资源访问。
9. 在 P4 任务中，将每个生成 `.luac` 文件纳入与对应源 `.lua` 相同的 Lua pending；不得把生成物留在工作区外或只记录不纳入。
10. 将 VS Code 扩展版本、编译器来源/版本、Lua 版本、源码提交、输出目录和验证命令记录到构建产物或项目文档。

## 推荐项目配置原则

具体键名必须以本机 LuacPacker 扩展设置和项目现有配置为准。配置应表达以下语义：

```text
source roots       = Lua 源码根目录
output root        = 独立的 luac 输出目录
include patterns   = 需要发布的 .lua 文件
exclude patterns   = tests、tools、examples、开发脚本、临时文件、输出目录
module mapping     = 源码模块路径到输出模块路径的一致映射
compiler           = 与目标运行时匹配的 luac/编译器
strip/debug       = 按调试或发布构建选择，并记录选择
```

不要把绝对路径、用户目录、机器私有编译器路径或秘密写入共享配置。优先使用工作区相对路径和可复现的工具安装方式。

## 版本与运行时规则

- PUC Lua 5.x 的字节码不应默认跨主版本复用。
- LuaJIT 字节码与 PUC Lua 字节码不是同一种格式；不要交叉加载。
- 不同目标平台或宿主定制 Lua 可能需要目标平台编译器。
- 变更 Lua/宿主版本后必须清空旧输出并全量重编译。
- 发布构建可以移除调试信息，但必须保留开发构建验证路径。
- 字节码不是加密；敏感信息、密钥和安全逻辑不能依赖编译隐藏。
- 若宿主依赖源码扫描、热更新或错误行号，先确认 `.luac` 是否兼容这些能力。

## 失败排查

### 找不到 LuacPacker 命令

确认扩展安装、扩展是否被工作区禁用、VS Code 命令面板中的实际命令名和工作区是否信任。不要直接猜命令字符串。

### 找不到编译器或编译失败

记录扩展输出面板的完整错误，确认编译器路径、权限、目标版本、源码编码和工作区根目录。优先修复工具链，不要用另一版本 `luac` 静默替换。

### 运行时加载失败

检查生成物的 Lua 实现/版本、模块路径映射、`package.path`/宿主加载器、大小端/架构限制和是否混入旧输出。用目标运行时执行最小加载测试。

### 只编译部分文件

检查 include/exclude 规则、大小写敏感路径、输出目录是否被排除、软链接和生成文件策略。用源码与输出清单差异定位，不手工补复制文件。

### 热更新或调试异常

确认目标宿主是否支持字节码热加载、错误行号和调试信息。必要时保留开发构建的 debug 信息，发布构建单独验证。

## 验证清单

- [ ] LuacPacker 扩展版本和实际命令/setting key 已确认；
- [ ] P4 任务中，若编译已执行，对应 `.luac` 已纳入与源 `.lua` 相同的 Lua pending；若未满足前置条件，已记录未编译原因；
- [ ] 编译器与目标 Lua 实现及版本匹配；
- [ ] 输出目录独立且已排除自身；
- [ ] 源码到 `.luac` 的路径映射完整且无意外文件；
- [ ] 测试、工具和秘密未进入发布输出；
- [ ] 最小模块可由目标运行时加载；
- [ ] 代表性入口、require、宿主绑定和协程通过运行时测试；
- [ ] 旧版本输出已清理，未发生混版；
- [ ] 构建版本、工具版本和验证证据已记录；
- [ ] 失败时保留扩展日志和首个根因，不用降级编译器掩盖问题。
