# 项目版本控制与交付

本技能是版本控制与交付的唯一入口：先识别项目工作区模型，再按识别结果读本技能目录下的对应细则，不把各工具的命令、状态和验收规则混在一起。

- Git：本技能目录下的 `git.md`（基线、限定范围 diff、本地提交、分支与合并方向、worktree 管理）。
- Perforce：本技能目录下的 `p4.md`（client/stream、default changelist、pending 分桶、中文描述编码）。
- SVN：本技能目录下的 `svn.md`（简易规则：更新、状态、diff、提交、冲突和边界）。
- 其他工具没有细则时，按项目自己的脚本和文档操作，并在结果里写明用的是哪套命令。

项目任务开始时使用本技能：先执行只读入口判断，不等待「任务是否会修改文件」的事前判断；任何可能修改文件的任务在完成文件操作后再次执行本技能的最终收尾。即使项目没有版本控制，也必须执行通用收尾检查。

提交收尾采用「本地先行」策略：属于任务范围的改动，只要能纳入版本控制，就先纳入本地（Git 的 commit、P4 的 pending、SVN 的待提交清单、其他工具的等价操作），不主动推送到远端。纳入前先核对本地归属：只处理当前用户、当前工作区 / client 下的文件；别人已经打开或纳入的文件不代表本地已处理，也不能因为他人持有而跳过，但也不抢占、不强制移动、不绕过锁。工具实际拒绝时记录单文件阻塞并继续其他文件。

## 入口判断

开始只读确认，结果记录在结果开头：

- 项目根目录和文档根目录；
- 版本控制类型、仓库 / 客户端身份和当前分支、stream、工作副本或等价状态；
- 工作区已有的改动、已纳入的文件和未纳管的文件；
- 任务允许的文件范围、验收命令和不可执行操作；
- 本次要用的模式：Git 的分支 / worktree 模式和合并方向，由项目配置或调用方参数决定（见 `git.md` 的「模式」一节），没有配置时按细则里的默认值。

按识别结果读对应细则；都没有时按通用收尾检查，不需要专项。检测到未适配的其他版本控制工具，或者两套同时存在且无法确认任务边界时，停止需要专用命令的步骤，报告事实并请求选择。

## 通用安全边界

- 修改前保留并区分已有用户改动，不覆盖、不认领、不清理。
- 变更以明确文件清单和任务范围为边界，不扫描或修改整个项目作为快捷方式。
- 设计、任务和验收文档按 `project-documentation` 规则落在正确 `DOC_ROOT`，不混入代码变更集合。
- **VCS 完成硬门禁**：凡本轮新增、修改或删除了属于任务范围且应纳入版本控制的文件，验证通过后按工作流或调用方要求的提交方式收尾（本地提交时按限定范围创建本地提交；只检查时核对限定范围的 diff 并报告）。凡本轮修改了需要显式纳入的文件（例如 P4 的 edit / add），必须完成纳入核对并形成最终的提交 / pending 分桶。未完成上述动作，不得宣布任务完成、归档或交付。
- 推送、创建 PR、修改远端、发布、submit、同步整个工作区、切换分支 / 客户端和破坏性清理仍需明确授权；本地提交 / pending 收尾不等于远端推送或提交。细则里的更严格限制优先。
- 工具导出或自动生成的文件不得手动修改后作为正式变更提交；优先修改源数据、配置或生成命令，再由工具重新生成并验证结果。
- 测试、故障复现或验证允许临时修改生成文件，但必须在修改前记录基线、文件清单和原因；结束后必须恢复原文件或从源头重新生成等价结果，并用限定范围的 diff、文件校验或版本控制状态确认没有残留。未恢复的临时修改不得结束任务、提交、推送、shelve 或发布。
- 每个里程碑必须有实际验证证据；计划不等于完成。

## 变更账本

涉及跨文件、外部台账、迁移或复杂交付时，记录：需求、基线、文件路径、版本控制状态、命令范围、验证结果、未完成风险和最终结论。账本只追加事实，不复制代码、不把猜测写成结果。P4 项目的台账位置和格式见 `p4.md`。

## 版本控制专项

| 版本控制 | 本技能内的细则 | 负责内容                                                                                                      |
| -------- | -------------- | ------------------------------------------------------------------------------------------------------------- |
| Git      | `git.md`       | status/diff、分支与 worktree、合并方向、提交、提交前验证与安全边界                                            |
| Perforce | `p4.md`        | client/stream、pending 分桶、p4 edit/add、一次编译验收、外部 ProjectDoc；shelve/unshelve 仅按用户明确要求执行 |
| SVN      | `svn.md`       | 工作副本状态、限定路径 update/diff/commit、冲突处理和不推远端的边界                                           |

其他工具没有细则时，按项目自己的脚本和文档操作，并在结果里写明用的是哪套命令。

新增 VCS 适配器时只加一张本技能目录下的细则文件并扩展本表，不把专用规则塞回本文件。

## 完成前检查

- [ ] 只读入口判断已在任务开始时执行；
- [ ] 项目身份、基线与变更文件范围已确认；
- [ ] 用户既有改动已隔离；
- [ ] 已按识别结果读了对应细则并按其规则处理，或已确认无需 VCS 专项；
- [ ] 分支 / worktree 和合并方向按配置的模式执行，没有临时改默认流程；
- [ ] 没有执行细则禁止的全库、同步、清理或远端操作；
- [ ] 验收证据、文档路径和剩余风险已记录。
