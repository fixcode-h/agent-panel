# 项目工作流

本技能负责识别项目工作区模型并选择对应的版本控制专项，不把 Git 与 P4 的命令、状态和验收规则混在一起。

项目任务开始时使用本技能：先执行只读入口判断，不等待「任务是否会修改文件」的事前判断；任何可能修改文件的任务在完成文件操作后再次执行本技能的最终收尾。即使项目没有 Git 或 P4，也必须执行通用收尾检查。

P4 任务采用非阻塞 pending 策略：修改前以当前用户和当前 client 的限定路径 `p4 opened` 核对本地归属；其他用户或其他 client 的 changelist、`p4 opened -a` 和 `otherOpen` 记录不代表本地已纳入。只要本地尚未加入自己的 changelist，就必须对明确文件执行限定路径 `p4 edit/add`，默认进入 default changelist（已明确指定本任务 pending 时使用 `-c <pending>`），不能因他人已打开而跳过；执行后回读本地 opened 核对实际归属。本地打开不等于抢占或移动他人的 changelist；只有 Perforce 实际拒绝时才记录单文件阻塞并继续其他文件，不抢占、不强制移动、不绕过锁。同一用户和同一 client 已有 changelist 的文件及本次修改继续归入原 changelist。任务完成并验证通过后，本次纳入 default 的文件按 C++/XLSX/Lua/Other 分桶；当前用户和当前 client 既有 changelist 的文件以原 changelist 作为最终分桶，不擅自移动。

## 入口判断

开始只读确认：

- 项目根目录和文档根目录；
- 版本控制类型、仓库/客户端身份和当前分支或 stream；
- 工作区已有改动、已打开文件和未纳管文件；
- 任务允许的文件范围、验收命令和不可执行操作。

检测到 Git 时配合 `git-workflow` 技能；检测到 P4 时先配合 `p4-workflow` 技能，确认 default changelist、客户端和任务文件范围；未检测到 Git/P4 时按通用收尾检查，不需要 VCS 专项。若检测到未适配的其他 VCS，或 Git/P4 同时存在且无法确认任务边界，停止需要专用命令的步骤，报告事实并请求选择。

## 通用安全边界

- 修改前保留并区分已有用户改动，不覆盖、不认领、不清理。
- 变更以明确文件清单和任务范围为边界，不扫描或修改整个项目作为快捷方式。
- 设计、任务和验收文档按 `project-documentation` 规则落在正确 `DOC_ROOT`，不混入代码变更集合。
- **VCS 完成硬门禁**：凡本轮新增、修改或删除了属于任务范围且应纳入 Git 的文件，验证通过后按工作流或调用方要求的提交方式收尾（见 `git-workflow`：本地提交时按限定范围创建本地 commit，只检查时核对限定 diff 并报告）；凡本轮修改了 P4 文件，必须完成 default changelist 核对并按 `p4-workflow` 形成最终 pending 分桶。未完成上述动作，不得宣布任务完成、归档或交付。
- 推送、创建 PR、修改远端、发布、P4 submit、同步整个工作区、切换分支/客户端和破坏性清理仍需明确授权；本地 commit/pending 收尾不等于远端推送或提交。专项技能的更严格限制优先。
- 工具导出或自动生成的文件不得手动修改后作为正式变更提交；优先修改源数据、配置或生成命令，再由工具重新生成并验证结果。
- 测试、故障复现或验证允许临时修改生成文件，但必须在修改前记录基线、文件清单和原因；结束后必须恢复原文件或从源头重新生成等价结果，并用限定范围的 diff、文件校验或版本控制状态确认没有残留。未恢复的临时修改不得结束任务、提交、推送、shelve 或发布。
- 每个里程碑必须有实际验证证据；计划不等于完成。

## 变更账本

涉及跨文件、P4 台账、迁移或复杂交付时，记录：需求、基线、文件路径、版本控制状态、命令范围、验证结果、未完成风险和最终结论。账本只追加事实，不复制代码、不把猜测写成结果。

## 版本控制专项

| 版本控制     | 专项技能           | 负责内容                                                                       |
| -------- | -------------- | -------------------------------------------------------------------------- |
| Git      | `git-workflow` | status/diff、分支、提交、rebase/merge、提交前验证与安全边界                                  |
| Perforce | `p4-workflow`  | client/stream、pending 分桶、p4 edit/add、一次编译验收、外部 ProjectDoc；shelve/unshelve 仅按用户明确要求执行 |

新增 VCS 适配器时只扩展本表和对应专项技能，不把专用规则塞回本文件。

## 完成前检查

- [ ] 只读入口判断已在任务开始时执行；
- [ ] 项目身份、基线与变更文件范围已确认；
- [ ] 用户既有改动已隔离；
- [ ] 已按正确的 VCS 专项规则处理，或已确认无需 VCS 专项；
- [ ] 没有执行专项禁止的全库、同步、清理或远端操作；
- [ ] 验收证据、文档路径和剩余风险已记录。
