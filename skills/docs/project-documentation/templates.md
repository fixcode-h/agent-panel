# 文档骨架

初始化和补文档时照着这些骨架写。尖括号是要替换的内容；某一段没有内容依据时整段删掉，不留「暂无」「TODO」占位。推断出来、还没核实的内容在句末标「（待确认）」。

## AGENTS.md

~~~markdown
# <项目名> · 开发约定

<一句话：这个项目是做什么的、给谁用。>

## 项目

- 技术栈：<语言、框架、主要依赖>
- 目录：<一级目录各一行，写职责>
- 版本控制：<Git / P4 / SVN；默认分支、提交约定（看最近的提交说明）>

## 硬规则

- <从现有约定、格式配置、CI 检查里读出来的必须遵守的规则，每条一行>

## 常用命令

```bash
<安装依赖的命令>
<开发 / 运行>
<构建>
<测试、类型检查、lint>
```

## 文档地图

| 要做的事 | 先读 |
| --- | --- |
| 了解项目、找模块 | [<DOC_ROOT>/README.md](<相对路径>)、[MODULE-MAP.md](<相对路径>) |
| <某个专题> | <对应文档> |

## 提交前

1. <提交前必须通过的检查命令>
~~~

已有 AGENTS.md 时不套这个骨架重写：保留原来的标题和顺序，只把缺的段落补到合适的位置。

## DOC_ROOT/README.md

```markdown
# <项目名>

<两三句：项目是做什么的、主要使用者、当前状态。>

## 快速开始

1. <环境要求>
2. <安装依赖>
3. <运行 / 构建 / 测试的命令>

## 文档索引

- [模块地图](MODULE-MAP.md)：各模块的路径、职责和入口
- <其他已经存在的文档，一行一个>
```

## DOC_ROOT/MODULE-MAP.md

```markdown
# 模块地图

只做导航：模块的细节在各自的 README 里。状态说明见 project-documentation 技能。

| 模块 | 路径 | 职责 | 入口 | 文档 | 状态 |
| --- | --- | --- | --- | --- | --- |
| <模块名> | `<源码路径>` | <一句话职责> | `<入口文件或符号>` | [README](modules/<模块名>/README.md) | inferred |

## 不建文档的目录

- `<目录>`：<资源 / 生成物 / 第三方代码，一句话说明>
```

## modules/<模块名>/README.md

```markdown
# <模块名>

> status: inferred · source_paths: `<路径>` · entry: `<入口>` · analyzed_at: <YYYY-MM-DD> · verified_commit: <提交号或 CL 号>

## 职责

<这个模块负责什么、不负责什么。>

## 入口与关键符号

- `<文件>`：<作用>

## 依赖与边界

- 依赖：<它用到的其他模块、外部服务>
- 被依赖：<谁调用它>

## 数据流

<关键的输入、处理和输出；没读代码前删掉这段。>

## 常见陷阱

- <踩过的坑或容易出错的地方；没有就删掉这段>

## 回归验证

- <改了这个模块后要跑的测试或检查命令>

## 待确认

- <扫描推断、还没核实的事项>
```

