# 文档骨架

初始化和补文档时照着这些骨架写。尖括号是要替换的内容；某一段没有内容依据时整段删掉，不留「暂无」「TODO」占位。推断出来、还没核实的内容在句末标「（待确认）」。

## AGENTS.md

````markdown
# <项目名> · 开发约定

<一句话：这个项目是做什么的、给谁用。>

## 项目

- 技术栈：<语言、框架、主要依赖>
- 目录：<一级目录各一行，写职责>
- 版本控制：<Git / P4 / SVN；默认分支、提交约定（看最近的提交说明）>

## 硬规则

- <从现有约定、格式配置、CI 检查里读出来的必须遵守的规则，每条一行>

## 常用命令

```bash
<安装依赖的命令>
<开发 / 运行>
<构建>
<测试、类型检查、lint>
```

## 文档地图

| 要做的事         | 先读                                                        |
| ---------------- | ----------------------------------------------------------- |
| 了解项目、找模块 | [<DOC_ROOT>/README.md](相对路径)、[MODULE-MAP.md](相对路径) |
| <某个专题>       | <对应文档>                                                  |

## 提交前

1. <提交前必须通过的检查命令>
````

已有 AGENTS.md 时不套这个骨架重写：保留原来的标题和顺序，只把缺的段落补到合适的位置。

## DOC_ROOT/README.md

```markdown
# <项目名>

<两三句：项目是做什么的、主要使用者、当前状态。>

## 快速开始

1. <环境要求>
2. <安装依赖>
3. <运行 / 构建 / 测试的命令>

## 文档索引

- [模块地图](MODULE-MAP.md)：各模块的路径、职责和入口
- <其他已经存在的文档，一行一个>
```

## DOC_ROOT/MODULE-MAP.md

模块表是生成物：按各模块 README 开头的元数据生成，不手写、不手改，地图不存在时也不自己建（面板在每轮结束时生成；仓库有生成脚本时跑脚本）。手写的只有表格外的说明段落。

```markdown
# 模块地图

只做导航：模块的细节在各自的 README 里。模块表只列已经写了模块文档的模块。

<!-- 模块表：由各模块 README 的元数据生成，不要手改（npm run docs:modules） -->

（生成的表格：模块 / 源码 / 职责 / 入口 / 关键词 / 文档 / 状态）

<!-- /模块表 -->

## 不建文档的目录

- `<目录>`：<资源 / 生成物 / 第三方代码，一句话说明>
```

## modules/<模块名>/README.md

元数据头写在标题之后、第一个 `## ` 之前，一行一个字段；正文只写下面几节，写不出内容的节整段删掉，总共约 80 行以内。

```markdown
# <模块名>：<一句话说明>

- 状态：documented
- 职责：<一句话：这个模块负责什么>
- 源码：`<路径>`、`<路径>`
- 入口：`<入口文件或关键符号>`
- 关键词：<业务术语、类名、日志类别，最多 20 个，用顿号隔开>
- 依赖：<它用到的其他模块>
- 更新：<YYYY-MM-DD> · <提交号或 CL 号>

## 做什么 / 不做什么

<职责边界，和相邻模块怎么分，5 行以内。>

## 关键文件

- `<文件或区域目录>`：<作用>（按「先读哪个」排，最多 15 条；大模块写成区域，一行一个目录）

## 对外接口与数据流

<别的模块怎么调它、数据从哪来到哪去，8 行以内。>

## 改这里要注意

- <易错点、隐含约束，最多 8 条>

## 怎么验证

- <改了这个模块后要跑的测试或检查命令>
```

## modules/<模块名>/bugs.md（第一次记录用户报的 Bug 时才建）

```markdown
# <模块名> · Bug 索引

| ID       | 症状             | 关键词       | 入口     | 根因类型              | 状态   | 文档                     |
| -------- | ---------------- | ------------ | -------- | --------------------- | ------ | ------------------------ |
| <bug-id> | <用户看到的现象> | <搜索用的词> | `<文件>` | <并发 / 边界 / 配置…> | 已修复 | [详情](bugs/<bug-id>.md) |
```
