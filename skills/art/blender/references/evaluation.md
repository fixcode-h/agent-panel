# 多视角评估

> 目的：**不允许只看一个视角就下结论**。固定视角集 + 逐视角清单 + 强制迭代闭环，让「是否合理、是否需要改」有据可查。
> 脚本：`capture_views.py`；记录模板：`templates/evaluation-template.md`。

## 视角集（自动生成，≥6 张）

| 视角             | 相机位置                             | 主要用途                   |
| ---------------- | ------------------------------------ | -------------------------- |
| `front` / `back` | 正前 / 正后，仰角 12°                | 正面轮廓与对称性           |
| `left` / `right` | 正左 / 正右，仰角 12°                | 侧向比例、厚度、连接结构   |
| `top`            | 近正上方（89°）                      | 布局、对齐、遮挡关系       |
| `three_quarter`  | 45° 方位 + 30° 仰角                  | 整体观感与立体关系（主图） |
| `closeup`        | 主体特写（`--focus` 时为聚焦组整体） | 局部细节、接缝、倒角质量   |

- 渲染基线：**默认双引擎 `--engine both`**——Workbench（快、稳定、cavity 看几何转折）+ EEVEE（材质/光照/投影的真实观感）；**只看一种引擎不得下评估结论**。
- 取景：默认按全场景包围盒；环境远大于主体时用 `--focus "名称前缀1,名称前缀2"` 聚焦（否则主体只有几个像素，无法评估）。
- 读图：逐张读取截图（一次读多张可能不进入视觉通道），每张给出逐视角结论。
- 统一分辨率（默认 1024）与背景；输出：both 模式为 `view_*.png`（Workbench）+ `view_*_eevee.png`（EEVEE），附 `views.json`（视角、引擎、相机参数与路径）。

## 逐视角审查清单（七维）

对每个视角逐项给出「通过 / 不通过 + 修改动作」：

1. **比例与尺寸**：与规格（`spec-template`）的尺寸一致；部件相对比例合理。
2. **轮廓可读性**：剪影清晰、主体突出、没有视觉噪声。
3. **结构完整与穿模**：无缺失部件、无穿插/悬空、连接处贴合。
4. **法线与平滑**：无黑面/翻面、平滑组正确（硬边硬、曲面顺）。
5. **材质与 UV**：材质分配正确、无拉伸/接缝错位；有参考图时，在相近机位与光照/色彩管理下逐项对照纹理图案、尺度、方向、颜色关系、反射与旧化，记录差异。Workbench 颜色不能证明真实材质匹配。
6. **动画姿态**（渲染时帧）：姿态自然、无关节撕扯、无物体飞出。
7. **物理与结构逻辑**：结构连接合理（轮轴穿轮心、叉/撑走外侧、留间隙）、无结构性穿透（用 `inspect_scene.py --intersect-report` 逐对复核）；接地/支撑正确；运动预览的位移与轮转一致（Δx = 2πr × 圈数）。

- 相交复核：环境/装配场景在评估阶段运行 `inspect_scene.py --intersect-report`，逐对判断「有意接触」与「结构性穿透」。

## 迭代闭环

- 流程：渲染 → 逐视角审查 → 记录问题与修改动作 → 修改 → **复渲受影响视角** → 直到全部通过。
- 任一视角不通过即不得声明完成；需求方豁免必须写入评估记录（时间、理由、范围）。
- 每轮次保留渲染产物，用同一视角前后对比验证修改效果。

## 注意事项

- 空场景（无可见网格）时脚本会直接报错（退出码非 0）——先确认场景里有内容。
- 视角是「检查工具」不是「渲染出图」：不需要打光/后期，只要几何与材质信息可判读。
- 动画场景建议在关键帧（含首尾）多渲一轮，静态与动态分开审查；逐帧对比用 `capture_views.py --frames`（默认右侧视，`--frame-view` 可换方向，密集场景用 quarter 越过遮挡）。
