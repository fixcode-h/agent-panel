# Blender 工作流（端到端）

> 适用：用 Blender 完成建模 / 动画 / 渲染 / 导出（以 UE 交付为标准）的任务。
> 配套：命令速查见 `commands.md`；指标定义见 `metrics.md`；模块/动画契约见 `model-animation-contract.md`；多视角评估见 `evaluation.md`；导出细则见 `export-ue.md`；易错点见 `pitfalls/`。

## 阶段 0 · 规格先行（Spec）

- 用 `templates/spec-template.md` 固化：用途、参考、尺寸（真实单位）、组成件、风格/材质、拓扑目标、禁止项、验收标准。
- 没有规格不动手：规格缺失时先补齐最小集（用途 + 尺寸 + 组成 + 验收）。
- 规格是后续「多视角评估」与「导出」的对齐基准。
- 有参考素材（视频/图片/参考模型）时：先做**参考解析**——`reference_frames.py` 出元数据/接触表/关键帧/放大裁切，转写「部件清单表」（每件标注参考来源），再进入建模；全流程见 `reference-rebuild.md`。参考里不存在的细节不臆造。
- 参考图复刻需把“可见面匹配”和“结构性补全”分开写：单张图不能证明背面、遮挡面或内部连接逐像素一致；未知项保留为待确认，不用想象细节填空。
- 对每个模块补充局部原点、轴向、父级、允许接触、禁止穿透和可拆装验收；水轮这类旋转件必须先确定轮心和轮轴方向。

## 阶段 1 · 场景搭建（Modeling / Animation）

- 单位与尺度：公制、缩放 1.0、按真实尺寸建模；命名用前缀约定（见 `metrics.md`）。
- 变换纪律：及时应用变换（scale/rotation）；不要用物体 scale 当尺寸。
- 拓扑目标：四边面优先、禁 n-gon（圆盖用 TRIFAN 或切分）、非流形 = 0。
- 物理与结构逻辑：结构件按现实规则连接（轮轴穿轮心、叉/撑走外侧、间隙 ≥ 5 mm，按外包尺寸校核）；整体可运动时位移与轮转一致（v = ω·r）。
- 参数化与组组织：关键尺寸集中为脚本顶部锚点变量（改一处全联动）；运动件按 `GRP_` 空组分层——局部旋转挂小空组、整体位移挂根空组（如 `GRP_Ride`），相机跟随同一位移或用固定机位覆盖活动范围。
- 分件装配：屋顶、墙面、木梁、门窗、水轮、引水槽、平台和装饰件按功能放在独立 Collection，由 `GRP_*` 根 Empty 控制；单件脚本负责几何，装配表负责实例、位置、旋转和父级，二者不要混成一个巨型脚本。
- 数据驱动与一致性核对（还原参考布局/关卡数据的场景）：把「坐标换算公式 + 源数据」集中放在脚本顶部，别散落魔数；生成后做一次**产物-数据一致性核对**——按格距把产物聚合回网格/表格（如把砖块占用还原成 26×26 ASCII 网格）与源数据逐格比对。派生尺寸变量注意单位（若「大格 = 1 m」，别用「大格数 × 半格尺寸」算总宽）。
- 动画：先定帧率（30fps 对齐 UE）；每个动画组织为独立 action；循环动画首尾帧一致；提交前用多帧对比复核（`capture_views.py --frames "1,16,31,46"`，默认右侧视、`--frame-view` 可切方向）确认跟随、相位与首尾连续。刚体旋转和位移打在模块根 Empty/轮心控制器上，网格本身保持单位缩放。
- 大任务分块：每次聚焦一个组成件，完成一块就做一次体检（把阶段 2 提前执行）。**复杂模型不分件必翻车**：按 `part-workshop.md` 拆成小件（一件一脚本 + 单件预览），件内精修到位再装配——整模一把梭时小件问题在整机视角根本看不清。

## 阶段 2 · 场景体检（Inspect）

- 最终体检前先减面：保存原模型、三角数及参考机位/局部特写/动画关键帧渲染；在候选副本逐件清理冗余几何、溶解共面边，必要时局部重拓扑或小步 Decimate，不统一套比例。保护剪影、孔洞、厚度、倒角高光、硬边、UV、材质边界和骨骼权重。
- 减面前后以同机位、分辨率、光照、曝光与色彩管理对照；纹理、材质、颜色和动画变形均无可见退化且实际面数降低才保留。出现损失则调整力度或恢复原网格，不能安全减面的部件记录原因并保留原状。报告记录每件/整场景前后三角数、原始/求值后统计口径、方法和对照证据。
- 后续验收针对减面后的最终模型，不能用减面前体检或渲染结论代替。
- 运行 `inspect_scene.py` 得到五组指标 JSON（网格 / UV·材质 / 动画 / 场景 / 导出前）。
- FAIL 必须先修再继续；WARN 记录并判断是否可接受。
- 体检同时是「导出门槛」：存在 FAIL 时 `export_ue.py` 会拒绝导出（除非显式 `--exempt` 并在评估记录中说明）。
- 相交报告只说明 evaluated 世界坐标三角面的表面重叠；把轮毂-轴、轴承-轮缘、落水-水斗等预期接触列入允许表，把支撑穿轮体、椽子穿屋面等列入结构性穿透并修复。必要时用 `diagnose_overlap.py` 输出相交三角中心定位。

## 阶段 3 · 多视角自评（Evaluate）

- 运行 `capture_views.py` 生成 ≥6 视角截图（默认双引擎：Workbench 看几何轮廓 + EEVEE 看材质光照；环境远大于主体时用 `--focus` 聚焦，两者都要逐视角审查）。
- 按 `evaluation.md` 的逐视角清单审查，逐项记录结论与修改动作；**不允许只看一个视角下结论**。
- 修改后复渲受影响视角，直到全部通过或需求方显式豁免；评估记录用 `templates/evaluation-template.md`。
- 动画资产增加“模块可操作性”检查：保存后重新打开 `.blend`，逐个平移模块根 Empty 再恢复，确认所有子件跟随且世界位置恢复；这项测试不能由 Collection 数量替代。

## 阶段 4 · 视口展示（Viewport）

- 运行 `setup_viewport.py --gui`：GUI 打开场景 + **单视口（相机视角）** + 材质预览 + 循环播放。
- 展示前确认场景有相机；没有时先补一个 `CAM_` 开头的相机（低机位、距主体约 1.5 m、35 mm 左右），脚本会给出警告提示。
- 运动场景要有「在走」的位移（Δx = 2πr × 圈数，与轮转一致）；通过相机跟随同一位移、或固定机位覆盖其活动范围，保证主体在播放期间始终位于画面内。
- 用于人工确认与交付演示；脚本只配置视图，不修改、不保存场景数据。

## 阶段 5 · 导出（Export，可选，以 UE 为标准）

- **这是可选步骤，不是必经流程**：默认不导出，只在用户明确需要 UE 交付时执行。
- **执行前必须询问用户**是否导出（以及交付目录与命名）；未获确认不得自动导出。
- 执行时：运行 `export_ue.py`：体检门槛 → FBX 导出 → 自动重导入自检（尺寸 / 网格数 / 材质数 / 动作数）。
- 自检 PASS 后按 `export-ue.md` 的 UE 导入清单在 UE 侧核对（本机无 UE 时登记为延期验证）。
- 参数细节与常见坑见 `export-ue.md` 与 `pitfalls/export.md`。

## 现场经验回流

- 具体项目中遇到的问题与经验：先记录在项目自身的 `docs/blender/`（如有），现场优先、快速落笔。
- 成熟且可复用的结论：再整理进本技能 `references/pitfalls/`（统一模板 + 症状索引），让后续所有项目受益。
- 两边独立演进：现场文档不需要链接技能文档，技能文档也不需要复述项目细节。
