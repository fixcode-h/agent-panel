# 易错点：动画（animation）

## 症状：FBX 导出后动画丢失（动作数 0）

### 症状

- 关键词：动画丢失 / action_count 0 / bake / 游离 action
- 导出自检 `[FAIL] action_count: 动作数 1 -> 0`。

### 错误做法

- 用 NLA 条带模式导出游离（未入 NLA）的 action；以为「有 keyframe 就会导出」。

### 正确做法

- 默认用 All Actions 模式（`bake_anim_use_all_actions=True`、`bake_anim_use_nla_strips=False`，`export_ue.py` 已固化）。
- 或者把动画整理进 NLA 条带后再用 NLA 模式导出。

### 为什么

FBX 导出器按「模式」收集动作：NLA 模式只收集 NLA 条带；游离 action 在该模式下被忽略。

### 验证方式

`export_ue.py` 自检 `action_count` 通过（原始与重导入数量一致）。

### 相关

`export-ue.md`（动画模式实测结论）；`pitfalls/export.md`

## 症状：动画变短 / 丢关键帧

### 症状

- 关键词：丢帧 / simplify / 帧率 / 时长缩短
- 导出后动画时长比 Blender 里短，或关键帧被抽稀。

### 错误做法

- 保持默认简化系数（`bake_anim_simplify_factor=1.0`）。
- 场景帧率与交付约定不一致（如 24fps 导出 30fps 素材）。

### 正确做法

- `bake_anim_simplify_factor=0.0`（`export_ue.py` 已固化）。
- 交付前统一帧率（UE 建议 30fps），并核对该 action 的帧范围。

### 为什么

简化会合并近似关键帧；帧率不一致会让时长换算错误。

### 验证方式

自检 `action_count` 通过；在 UE/重导入中核对时长与关键姿态。

## 症状：Blender 5.x 读取动作曲线报 `AttributeError: 'Action' object has no attribute 'fcurves'`

### 症状

- 关键词：fcurves / slotted action / channelbag / Action object has no attribute / 插值设置失败
- 对动作统一设插值、读取关键帧时抛 `AttributeError`；脚本在 4.x 正常、升级 5.x 后崩溃，或相关检查字段静默变成空值。

### 错误做法

- 直接访问 `action.fcurves`（5.x 动作改为 slotted 结构，旧属性被移除）。
- 用 `try/except AttributeError` 包住后直接跳过——检查会「看似通过」但数据缺失。

### 正确做法

```python
if hasattr(action, 'fcurves'):                      # 4.x 兼容
    fcurves = list(action.fcurves)
else:                                               # 5.x slotted
    fcurves = [fc for layer in action.layers
               for strip in layer.strips
               for bag in strip.channelbags
               for fc in bag.fcurves]
for fc in fcurves:
    for kp in fc.keyframe_points:
        kp.interpolation = 'LINEAR'
```

### 为什么

Blender 4.4 起动作引入槽（slot）与通道包（channelbag）分层结构，5.x 移除了 `Action.fcurves` 直达属性。

### 验证方式

同一段脚本在 5.2 无头运行通过；体检 `actions` 报告中的 `fcurves` 计数与插值字段非空。

### 相关

`pitfalls/scripting.md`；`metrics.md`（`actions` 检查项）

## 症状：预览动画原地播放（轮子空转、主体不动）

### 症状

- 关键词：原地 / 空转 / 不位移 / 预览不真实 / treadmill
- 视口播放时轮子和曲柄在转，但整体停在原地，缺少「在走」的观感。

### 错误做法

- 只给轮子/曲柄加旋转关键帧，不给整体加位移；或位移与轮转周长不匹配（轮转 1 圈却走 8 m）。

### 正确做法

- 给运动组件挂一个根组（如 `GRP_Ride`），按物理一致方式加位移：**Δx = 2πr × 圈数**（与轮转圈数一致），插值 LINEAR。
- 相机跟随同一位移（同一 Δx、LINEAR），保证主体始终在画面内。
- 循环回绕处会跳变，属循环预览的固有限制，可在评估记录注明。

### 为什么

「在走」由整体位移体现；位移与轮转不一致（速度 v = ω·r）一眼就能看出假。

### 验证方式

校验脚本：Δx 与 2πr × 圈数 的误差 < 2 cm；`capture_views.py --frames` 多帧对比确认跟随与相位；播放时环境（树/灯/路面）在画面中掠过。

### 相关

`workflow.md` 阶段 4；`evaluation.md`

## 症状：滚动方向与前进方向不一致（轮子倒转）

### 症状

- 关键词：倒转 / 转向反 / rolling direction / 轮子转反
- 播放下轮子视觉上「倒着转」，或与整体位移方向矛盾。

### 错误做法

- 凭感觉设旋转符号；轮子与位移在不同轴向/符号上各设各的。

### 正确做法

- 按物理关系定符号：`v = ω × r`，接触点在轮底时 **+X 前进配 +Y 轴正转**（`rotation_euler[1]` 递增）。
- 圈数取整（如 4 圈 = 8π），保证循环首尾相位连续；位移 Δx = 2πr × 圈数，与轮转同帧数、LINEAR。

### 为什么

滚动无滑动条件 v = ω·r 同时约束了转向与转速；符号错了或圈数不整，播放时一眼可辨。

### 验证方式

位移/转角校验脚本（Δx 与 2πr × 圈数 的误差 < 2 cm）；播放中轮辐朝向与前进方向一致。

### 相关

`workflow.md` 阶段 4；`commands.md`

## 症状：肢体不跟运动件（脚不随踏板 / 腿不蹬）

### 症状

- 关键词：脚飞 / 腿不蹬 / 肢体不同步 / 脚脱离腿
- 机械循环动画（骑行等）里脚随踏板绕圈、腿却静止——脚与腿末端脱开，一眼看出「脚异常」。

### 错误做法

- 只把脚 parent 到曲柄（脚随踏板公转），腿保持静止：脚会离开腿的末端。
- 或反过来把整条腿挂上曲柄：大腿根随踏板画大圆，脱离身体。

### 正确做法

- 两骨 IK 逐帧烘焙：髋 / 膝空组分层（绕髋、绕膝各一层），按帧用余弦定理解出膝位（|髋−膝|、|膝−足| 两段固定长），逐帧写空组旋转关键帧。
- 足的 IK 目标 = 踏板同相圆（与曲柄同一 θ、同一几何偏移），保证脚始终贴踏板；下段（膝→足）可加「踝点」外弓，绕开静止的车架件（后下叉）。

### 为什么

踏板是圆周运动、骨长固定：解三角即可逐帧求关节角；直线骨无法拉伸，只能靠关节转动跟随。

### 验证方式

脚−踏板距离全程恒定（示例 0.023 m）；多帧专项相交（腿 vs 后叉）全帧为 0；`capture_views.py --frames` 侧视逐帧对比蹬踏相位与首尾连续。

### 相关

`workflow.md` 阶段 1；`pitfalls/animation.md`（原地播放 / 滚动方向）

## 症状：履带/链条细节在预览里频闪（想让它滚却像噪声）

### 症状

- 关键词：频闪 / 抖动 / 履带不滚 / chain flicker / wagon wheel
- 车辆类动画里，履带板、链条等「等距重复细节」按车速滚动时，在 30fps 下看起来乱跳或闪烁，不像在滚。

### 错误做法

- 给等距重复细节（如 3.6 cm 板距的履带板）直接写「真实滚动」位移关键帧——1 m/s 时相当于每帧换近一整块板。
- 或者干脆让所有细节静止，完全丢失运动信息。

### 正确做法

- 让「能被采样的特征」承载运动：①整体位移承载速度；②低频特征（6 分度螺栓/齿轮、大间距花纹）随轮同轴旋转；③等距重复细节（履带板阵列）保持静态几何，或只做低幅度重复动作。
- 判据：细节间距 p（m）× 帧率 ≥ 可见速度（m/s）才会被采样成连续运动——p = 0.036 m 在 30fps 下可连续表现的速度上限约 0.5 m/s。

### 为什么

低帧率对移动图案的采样率有限：每帧位移超过约半个间距即发生相位跳变（类 wagon-wheel 效应），密集重复细节退化为闪烁。

### 验证方式

`capture_views.py --frames "1,2,3"` 连续帧对比：低频特征相位可辨（能读出转动），细节层无噪声感；播放主观检查无频闪。

### 相关

`pitfalls/animation.md`（原地播放 / 转向）；`workflow.md` 阶段 4

## 症状：轮子转速与整车位移不符（打滑 / 滑行感）

### 症状

- 关键词：打滑 / 滑行 / 转速不匹配 / effective radius / slip
- 播放时轮子像在冰上滑行（转数偏多/偏少），即便 Δx = 2πr × 圈数 的公式「看起来」用了。

### 错误做法

- 用轮子几何半径直接算转速，忽略轮外还有一圈履带板/胎面厚度；或反过来把链轮齿尖半径当接触半径。

### 正确做法

- 用「有效接触半径」：`r_eff = 轮半径 + 履带板半厚`（即板中心线到轮心的距离；平带取带中心线半径）。
- 所有滚动件用同一线速度换算：`角位移 = 位移 / r_eff`；不同半径的轮角位移不同、线速度一致。

### 为什么

纯滚动条件 v = ω·r 中的 r 是接触点半径（含外层厚度），不是零件本体半径；几个百分点的误差累积成肉眼可见的打滑。

### 验证方式

多帧对比轮上标记（螺栓/齿）相位与位移的比例；数值检查 fcurve 终值 = dist / r_eff。

`pitfalls/animation.md`（滚动方向 / 原地播放）

## 症状：履带链板「不动」与「逐帧烘焙爆炸」两难

### 症状

- 关键词：履带运动 / 链板循环 / 相位 / 圆弧切角 / 逐帧烘焙 / 文件臃肿
- 近景能看出履带是死的（车动、轮转、链板原地）；想逐块补关键帧又怕关键帧爆炸。

### 错误做法

- 全链板逐帧烘焙（112 块 × 330 帧 ≈ 十万级关键帧，文件臃肿、保存缓慢）；
- 或大间隔等距采样：直线段看不出问题，圆弧（主动轮/诱导轮绕行）段的链板会「切角」飞出路径。

### 正确做法

- **相位驱动**：链板以初始相位 `u_i=(i+0.5)/N` 沿闭合路径取点，随时间 `u=(u_i + s(t)/L) mod 1`；`s(t)` 与车轮用同一条速度剖面（同源即同速，不可能打滑，无需额外校正）。
- **自适应采样**：直线段 10 帧一步（线性插值精确无损）；圆弧段 1–2 帧一步（弦切角 < 5 mm）。实测 56 块/侧、每块约 50 键，总计约 3 万键即够。
- 路径方向即履带相对车体的运动方向：底边向后、顶边向前，链板自会绕过主动轮/诱导轮。

### 为什么

链板在直线上是匀速平移，线性插值无损；圆弧上的位置对时间是三角函数，粗采样必把弧切成弦——链板就穿出轮缘。

### 验证方式

数值检查：抽帧取链板世界坐标到路径的最近距离（实测 1.6 mm），并核相邻链板相位差恒为 1/N；`--frames` 多帧渲染看绕轮处不切角。

### 相关

`pitfalls/animation.md`（轮子打滑 / 低频承载）；`references/part-workshop.md`

## 症状：碎块/烟团穿地或「提前出现在出生点」

### 症状

- 关键词：穿地 / 落到地下 / 提前可见 / 出生帧 / 烟团在车头前
- 撞墙碎块播放到底有半截沉到地面以下；烟团在第 1 帧就出现在它「将要」生成的位置（车还没开到）。

### 错误做法

- 抛体只采样到理论落地时刻、不做落地夹紧；
- 生成物只从出生帧开始打关键帧，忽略出生前 Blender 会用首帧值做**常量外推**。

### 正确做法

- 落地判定按**半高**：中心 z ≤ 半高 + 5 mm 视为落地，落地键写 z = 半高（实测砖块 0.09 m）；落地后一次小反弹 + 前滑，旋转按 15% 衰减到停。
- 生成物在出生帧之前补一个**不可见关键帧**（scale 0.001）：烟团在 f-1 与 f=1 各补一枚，既有出生弹出感、又不会提前出现在世界里。

### 为什么

无落地夹紧会一路穿地；无前置隐藏键则首帧值被向前外推，观众看到「还没发生就已摆放好的碎片」。

### 验证方式

数值检查：结束时所有碎块 `z ≥ 半高 - 1 mm`（实测最小 z = 0.090）；抽查生成物出生前缩放 ≈ 0；多帧渲染确认出现时机。

### 相关

`pitfalls/animation.md`（关键帧插值）

## 症状：体检查出 transform_applied FAIL（某对象 scale ≠ 1）

### 症状

- 关键词：scale 不为 1 / transform_applied FAIL / 缩放动画 / 烟团
- 给烟团/尘团做「从小到大」的缩放动画后，`inspect_scene.py` 的 scale 检查失败。

### 错误做法

- 把缩放动画直接挂在网格对象上（动画首帧值即非 1 缩放，体检当场 FAIL）。

### 正确做法

- 让**空物体承载缩放动画**，网格作为子件保持 scale=1（不设 matrix_parent_inverse，让父级变换整体生效）：

```python
pivot = empty('GRP_Smoke_012', loc=spawn)     # 关键帧打在空物体：location + scale + rotation
mesh_obj.parent = pivot                        # 网格自身 scale 恒为 1
```

- 空物体不是网格对象，体检的 transform_applied 不检查它；渲染/导出仍继承世界缩放。

### 为什么

体检按网格对象的 `scale` 判定；动画缩放的容器不该是网格本身。

### 验证方式

`inspect_scene.py` 的 transform_applied 恢复 PASS，且多帧渲染能看到烟团尺寸随时间增长。

### 相关

`references/metrics.md`；`pitfalls/animation.md`
