# 易错点：多视角评估（evaluation）

## 症状：截图里主体只有几个像素，无法评估

### 症状
- 关键词：主体太小 / 取景 / frame / 看不清 / 几个像素
- 含大环境（地形/海面/马路）的场景里，7 张视角图只看到地面板块，角色/道具难以判读。

### 错误做法
- 直接按全场景包围盒取景；环境尺寸远大于内容主体。

### 正确做法
```powershell
python blender_cli.py capture_views.py <scene.blend> --out renders --focus "SM_Pelican,SM_Rear,SM_Front"
```
- 主体用名称或前缀指定（逗号分隔）；环境本身要评估时再单独全额取景。
- 全场景模式下脚本会在「场景包围盒远大于最大对象」时打印提示。

### 为什么
相机距离由包围盒半径决定；海面/马路把半径放大一个量级，主体在画面中的占比随之坍缩。

### 验证方式
特写与 3/4 视角中主体占据画面主要区域，可判读部件连接与接缝。

### 相关
`evaluation.md`

## 症状：只渲染一种引擎，漏掉材质/光照问题

### 症状
- 关键词：只看一种引擎 / only workbench / 材质发灰 / 没有阴影
- 评估结论「通过」，但材质配色、光照与投影问题在评审时才被暴露。

### 错误做法
- 只用 Workbench（无材质观感、无光照投影）或只用 EEVEE（几何转折判断不如 cavity 直观）就下结论。

### 正确做法
- 默认双引擎：`--engine both`（Workbench 看几何轮廓 + EEVEE 看材质光照），两套图都要逐视角审查。
- Workbench 渲染前会自动同步 `diffuse_color`（避免全灰）；EEVEE 需要场景里有灯（如太阳光）。

### 为什么
两种引擎互补：几何缺陷在 cavity 下最明显，材质/光照/阴影只能由真实渲染引擎暴露。

### 验证方式
输出目录同时存在 `view_*.png` 与 `view_*_eevee.png`，两套图的审查结论都写入评估记录。

### 相关
`evaluation.md`；`pitfalls/materials-uv.md`

## 症状：批量读取多张截图看不到图

### 症状
- 关键词：多图读取 / 附件为空 / 没看到图片 / 单张才可见
- 一次读取多张 PNG 时只返回文件大小说明，无法进行视觉审查。

### 错误做法
- 把 7 张截图放进一次批量读取，然后当作已经完成「视觉评估」。

### 正确做法
- 逐张读取（一次一张，单文件读取才会作为图片进入视觉通道）；每张给出逐视角结论。

### 为什么
批量读取不会把图片内容附给模型；只有单张读取走视觉附件通道。

### 验证方式
审查记录能指出具体缺陷（如「喙根部有穿插」「翼尖悬空」），而不是泛泛「看起来正常」。

### 相关
`evaluation.md`

## 症状：动画帧对比被前景遮挡（密集场景侧视）

### 症状
- 关键词：动画帧遮挡 / 前景挡住 / 砖墙遮挡 / frame occluded
- `--frames` 默认右侧视，在砖墙/植被/家具密集的场景里主体下半身被前景挡住，难以判读轮子/履带相位。

### 错误做法
- 只用默认侧视拍多帧，把遮挡当成「没法验证」。

### 正确做法
- 换俯角更大的方向，让视线越过遮挡物：
```powershell
python blender_cli.py capture_views.py <scene.blend> --out renders\anim --frames "1,31,61,91,121" --focus "SM_主体前缀" --frame-view quarter
```
- `--frame-view` 可选 front/right/back/left/quarter(45°,30°)/top；遮挡严重时配合 `--focus` 缩小取景。
- 转动物相位类验证可再放大：`--focus "SM_XX_WheelR_01"` 拍连续帧（如 "1,2,3"）对比螺栓/齿的相位变化。

### 为什么
侧视的视线在主体高度上会穿过同高遮挡物；提高俯角（quarter 30°）后视线从遮挡物上方越过。

### 验证方式
多帧图中主体完整可见、可读出轮上标记的相位差。

### 相关
`evaluation.md`；`commands.md`（--frame-view）
