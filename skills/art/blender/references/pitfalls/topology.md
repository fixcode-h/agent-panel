# 易错点：拓扑 / 法线 / 平滑（topology）

## 症状：体检报 `ngons` > 0（n-gon）

### 症状

- 关键词：n-gon / ngons / 多边形端盖 / 倒角
- 体检输出 `[FAIL] ngons: n-gon（>4 边）面数：N`。

### 错误做法

- 直接用默认参数创建圆柱/圆锥（端盖是 n-gon）。
- 倒角用多段（segments ≥ 2）不做处理。

### 正确做法

```python
bpy.ops.mesh.primitive_cylinder_add(radius=0.05, depth=0.8, end_fill_type='TRIFAN')
bpy.ops.mesh.primitive_cone_add(radius1=0.1, radius2=0.03, depth=0.16, end_fill_type='TRIFAN')
# 倒角用单段，或对局部做切分后再检查
mod = obj.modifiers.new('Bevel', 'BEVEL'); mod.width = 0.015; mod.segments = 1
```

### 为什么

n-gon 在导出/引擎中会被三角化，结果不可控；UE 管线更希望可控的三角/四边形。

### 验证方式

重跑 `inspect_scene.py`，`ngons` 为 PASS。

### 相关

`metrics.md`（网格组）

## 症状：体检报 `non_manifold` > 0（非流形）

### 症状

- 关键词：non-manifold / 非流形 / 布尔 / 重复面
- 体检输出非流形边数量大于 0。

### 错误做法

- 布尔运算后不清理；两份面重合；开放边被误当非流形。

### 正确做法

- 布尔后用 bmesh 检查并清理重复面/孤边；确认开放边界是设计需要（如薄片）。
- 对封闭件检查 `e.is_manifold and not e.is_boundary`。

### 为什么

非流形几何在导出、法线计算、引擎导入中都可能报错或显示异常。

### 验证方式

`inspect_scene.py` 中 `non_manifold` 为 PASS。

`pitfalls/scripting.md`

## 症状：体检报 `loose_verts` > 0（松散顶点）

### 症状

- 关键词：loose vertices / 孤立顶点 / 删除残留
- 删除面后残留顶点/边。

### 错误做法

- 只删面不清理顶点；手工建模后从不做清理。

### 正确做法

- 编辑模式：`bpy.ops.mesh.delete_loose(use_verts=True, use_edges=True, use_faces=False)`。

### 为什么

松散几何会污染统计、增加面数口径差异，导出可能产生异常节点。

### 验证方式

`loose_verts` 为 PASS（或 0）。

### 相关

`metrics.md`

## 症状：平滑异常（硬边变糊 / 曲面有棱）

### 症状

- 关键词：shade smooth / shading / 平滑组 / 硬边
- 曲面出现棱线，或该硬的地方变糊。

### 错误做法

- 全选一键 shade smooth，不区分硬边。

### 正确做法

- 按部件设置平滑；硬边用自动平滑（5.x：`shade_auto_smooth`）或标记锐边。

### 为什么

平滑决定法线插值方式，直接影响渲染与 UE 中的观感。

### 验证方式

多视角渲染中「法线与平滑」一项通过（无黑面、曲面顺滑、硬边清晰）。

### 相关

`evaluation.md`

## 症状：结构件穿透（车架/前叉插进轮胎）

### 症状

- 关键词：穿透 / 穿模 / intersect / 车架插进轮胎 / 间隙
- 侧视图能看到车架管、叉管或支架从轮胎/轮毂里穿过去；`inspect_scene.py --intersect-report` 报告相关对象对相交。

### 错误做法

- 只按「中心线/坐标」摆件，不按部件的外包尺寸留间隙：细管走在轮胎宽度范围内（|y| < 轮胎半宽 + 管半径）就会从轮胎里穿过。
- 后下叉过短（真实约 0.42–0.45 m）、头管过低，让五通/下管落进车轮外径范围。

### 正确做法

- 外侧件（前叉 / 后下叉 / 座叉）走「轮胎半宽 + 自身半径 + ≥5 mm」以外：示例轮胎半宽 0.042 → 叉/撑走 y = ±0.08。
- 居中件（头管 / 下管 / 座管 / 曲柄扫掠）与轮轴的距离 ≥ 轮胎外半径 + 自身半径 + ≥5 mm（示例：0.382 + 0.024 + 0.02）。
- 用 `inspect_scene.py --intersect-report` 逐对复核（眼/头盔/脚踩踏板等装配体内的有意接触需人工判断）。

### 为什么

卡通/胖胎模型的外包尺寸比真实件大，「看起来差不多」的中心线间距会直接变成穿透；结构件必须按现实逻辑分层（轴心、外侧、间隙）。

### 验证方式

侧视/前视截图中管件与轮胎之间可见间隙；`--intersect-report` 不再出现「车架系 vs 轮胎」的配对。

`evaluation.md`（物理与结构逻辑）；`commands.md`

## 症状：沿路径阵列的凸起件方向装反（朝内 / 戳穿邻件）

### 症状

- 关键词：路径阵列 / 履带齿 / 凸起朝内 / normal side / 戳地
- 沿跑道/曲线路径摆放的凸起件（履带导齿、装饰块、链条销）朝向了路径内侧：与相邻轮件相交（Track×Wheel），或下段的凸起戳进地面。

### 错误做法

- 用切线方向构造旋转（`Matrix.Rotation(atan2(dz, dy), 4, 'X')`）后，默认局部 +z 就是「朝路径外侧」，把凸起直接放在 +z 偏移；本案例上下直线段的局部 +z 实际都朝环内，导齿因此全部装反。

### 正确做法

- 先判定法向侧：在直线段取一点验算（切线 = -y 时 Rx(π) 把局部 +z 转到 -z，即朝内），偏移量取负（本案例 `Translation((0, 0, -0.008))`）。
- 或显式构造法向：`n = 切线旋转 90°`，按绕向标定符号后沿 n 施加偏移。
- 偏移量要同时校核「路径两侧」的最近件：向外的凸起不得戳地（下段齿底 ≥ 离地 1 mm）。

### 为什么

切线角只编码「沿路径的方向」，不编码「哪一侧是外」；符号取决于路径绕向与采样顺序，凭直觉假设 +z 朝外有 50% 概率装反。

### 验证方式

`--intersect-report` 不再出现「路径件 × 相邻轮」对；`diagnose_overlap.py` 复查确认无残留。

### 相关

`pitfalls/scripting.md`（相交定位）；`pitfalls/topology.md`（结构件穿透）

## 症状：新增轮件与相邻轮相交（轴距无解）

### 症状

- 关键词：托带轮 / 轮距 / 间隙不足 / return roller / 轴距
- 在既有轮系中插入新轮（托带轮、辅助轮）或加大轮径后，与相邻轮的轴距小于「半径和 + 间隙」，相交报告出现 Wheel×Wheel / Wheel×Roller 对。

### 错误做法

- 只按视觉位置摆放不校核轴距；出现相交后继续硬塞，或把间隙压到 0 假装通过。

### 正确做法

- 先列可行区间：相邻轴距 ≥ r1 + r2 + 5 mm。本案例在 0.13 m 空档里需同时留出「与驱动轮 + 与负重轮」两段间隙，直接无解——改为缩小「视觉损失最小」的件：驱动/诱导轮 0.059 → 0.055、托带轮半径取 0.012 并放在 ±0.215，才同时满足两端。
- 校核时把「新增件 vs 所有邻域件」逐对列出（含履带板内侧等另一侧包络）。
- 改一处后**重跑全量相交**：本案例导齿修向后，上段齿顶又顶到挡泥板（1 mm），需要再抬挡泥板——递进出现的对要一次清完。

### 为什么

轮系是密集约束布局：新件的可行区间由左右邻居半径与履带包络共同夹逼，单点调整常把问题挤到下一个邻接件。

### 验证方式

`--intersect-report` 中轮系对只剩「有意啮合」（链轮齿 × 履带板）并记录；全量报告刷新后无新增未解释对。

`pitfalls/topology.md`（结构件穿透）；`metrics.md`
