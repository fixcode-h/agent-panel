# 建模参考图文生图 Prompt 文档模板

按执行范围和参考类型裁剪模板；没有参考图时写“按文字需求生成”，没有图片时只检查规格完整性，图片实测全部标为待验证；未知参数标待适配，不支持项标 N/A。部件拆分方案未获用户明确答复前不输出本文档的最终版本。

## 验收清单

规格交付检查：
- [ ] 部件拆分方案已获用户明确答复，部件图张数等于部件数
- [ ] 执行范围、参考类型与用途分开写明
- [ ] 图片清单逐图写明是否单独成图，合计张数与交付规格一一对应
- [ ] 视图集合、投影方式、比例尺与中线规则无冲突
- [ ] 整体尺寸表与部件尺寸表来源明确，未确认项已标待确认
- [ ] 材质键名与项目清单一致
- [ ] 参数未超出已确认工具能力
- [ ] 正交视图与部件图 prompt 已排除透视、阴影、环境与风格化

图片实测（无图片或证据时标待验证，不勾选）：
- [ ] 精确像素与单格有效像素达标；证据：待验证
- [ ] 各视图与部件图共用比例尺、中线对齐；证据：待验证
- [ ] 无透视污染，背景纯净无地面阴影；证据：待验证
- [ ] 与参考图逐项比对的可见面与部件清单一致；证据：待验证
- [ ] 部件图逐件核对接口位置与安装面；证据：待验证
- [ ] 尺寸标注正确或已改为后期叠加；证据：待验证
- [ ] 文件名、版本与生成/后处理记录可追溯；证据：待验证
- [ ] 打包内容与图片清单一致（张数、文件名、目录结构）；证据：待验证

## 打包交付

全部图片按图片清单命名后，可以打包为一个压缩包交付，便于整包转交建模师或归档：

- 包名：`<主体名>_建模参考图_<版本>.zip`（或项目约定的压缩格式与命名）
- 包内结构：
  - `ortho/`、`parts/`、`three_quarter/`、`closeups/`、`material/`（按图片清单出现的类型建目录，没内容的目录不建）；也可以按图号前缀平铺，但要与清单顺序一致
  - `<主体名>_建模参考图_prompt.md`（本提示词文档）
  - `manifest.txt`：图号、文件名、参考类型、是否单独成图、像素、归属部件 ID
- 校验：包内图片张数等于图片清单合计张数，其中 `parts/` 下的张数等于部件数；文件名与清单逐项一致；候选图、拼版底稿、逐视图源图等中间产物放单独的 `_works/` 目录并注明，不混进交付目录
- 压缩包只是传输形式，不改变单张图片的交付规格：解包后仍逐张按上面的验收清单检查
