# 建模参考原画文生图工作流

输入是用户给的参考图和要求，输出是一份能直接交给设计者执行的建模参考图提示词文档，并落盘为 Markdown 文件（路径与命名见阶段 6）。不自动调用生图服务；收到生成结果后再复盘，只有明确要求生成且工具可用时才执行对应操作。

## 执行与交付边界

先区分两个独立维度：

- 执行范围：仅提示词规格、已有成图复盘、实际生成/后处理。没有图片时只能交付规格和待执行验收项，不能声称图片已通过检查。
- 参考类型：**正交视图板**是贴在 Blender/UE 建模模式里量比例、描轮廓的作业底图，必须正交投影、共用比例尺、纯色背景、无装饰；**3/4 透视彩图**只用来看体块关系、轮廓感觉和配色，不参与量比例；**局部特写**与**材质/配色板**各自独立交付。把这几类混进同一张图，建模师就无法使用。

确定视图组成与交付格式前必须读取 [references/model-reference-delivery.md](references/model-reference-delivery.md)；输出最终文档前必须读取 [references/prompt-output-template.md](references/prompt-output-template.md)。

## 工作阶段

沿用已提供的答案，不重复询问。只对会改变视图组成、部件拆分、比例口径或可执行性的未知项提问，每轮优先一个问题；需要选择时使用当前 CLI 的提问方式。明确且完整的需求直接进入规格整理，不强制走方案选择。

部件拆分方案是硬门禁：用户已指定时按指定执行，未指定时先给出基于参考图的推荐拆分并等待明确答复，然后才输出最终文档。

### 0. 确定边界、单位与工具

提取并确认：

- 执行范围、参考类型和用途：给建模师做底图、给材质师做分区参照，还是给评审做展示图。
- 尺寸口径：总长/宽/高与关键部件尺寸，单位统一；UE 侧按 1 unit = 1 cm 换算并同时给出 unit 值。
- 视图清单：正、侧、俯（载具加背视）；是否接受最低组合，是否逐视图单独出图。
- 排布：单张四宫格还是分图；四宫格必须共用同一比例尺、中线对齐、视图间距一致。
- 交付格式：分辨率（每边 ≥2048）、PNG/TGA、背景色、命名与版本；文档交付形式见阶段 6。
- 目标生图工具能力：多宫格布局、正交/透视控制、参考图与结构控制、局部重绘、seed、文字与数字渲染质量。

目标工具未知时直接交付通用规格，不为此阻塞；专用参数标“待适配”。只填写已确认支持的参数，不猜测 API 字段、seed 或模型能力。

不虚构装备型号、口径、吨位或尺寸。用户未给尺寸时列成待确认项交回设计者，不凭印象填写；复刻真实装备时以权威来源为准，找不到就明说。

### 1. 解析用户提供的参考图

用户给了照片、概念图或视频帧时，先用当前 CLI 的图片读取能力逐张实际查看，记录观察事实，再决定哪些内容可以进 prompt：

- **来源性质**：实物照片、概念插画、游戏截图还是视频抽帧；单张还是多角度。
- **可见面清单**：每个面能证明的轮廓、部件、开口、分缝逻辑；对应的视角和朝向。
- **比例读数**：在同一张图内可测的相对比例（车体长高比、炮塔占比、轮径与轮距）；实测值以像素比为准，标注测量依据。
- **遮挡与不可见面**：背面、底面、内部结构只能按结构逻辑补全，明确标为待确认，不猜成事实。
- **材质与配色分区**：装甲、金属件、边缘、凹槽、履带等各自的位置、颜色、旧化程度。
- **细节区**：炮塔、悬挂、履带、舱盖、铰链、工具挂点等需要单独出特写的部位。

实物照片自带透视和镜头畸变，不能直接当作比例依据：任何一组视图都必须重新按正交投影生成，尺寸以用户给的实测值或权威图纸为准。用户只给照片、不给尺寸时，把“照片可推得的相对比例”和“必须由设计者确认的绝对尺寸”分开列。

没有参考图而只有文字需求时跳过本阶段的图片解析，直接按描述建立 brief，并在文档中注明“无参考图，形态按文字描述生成”。

### 2. 建立建模参考 brief

记录已确认项、默认项、待确认项和风险：

- 主体与来源：虚构设计、概念稿还是复刻真实装备；以什么为准。
- 尺寸表：总长/总宽/总高、离地间隙、轮径、履带宽度、炮塔座圈直径、炮管长度与口径、关键附件尺寸。
- 视图与遮挡：能证明的可见面；需要按结构逻辑补全的面，标为待确认。
- 部件清单：用户已指定的拆分，或依据参考图推断出的候选拆分；粒度、命名和接口关系在阶段 3 与用户确认。
- 材质分区清单：项目已有清单（如 rig-manifest.json 的 Armor / Hardware / Edges / Recess / Tracks）时按它的键名逐项对应，不另造命名；并注明每个分区归属哪些部件。
- 局部特写清单：逐项写清要看清什么。
- 真实装备路径：用照片代替手绘视图时（8 方向环绕照 + 局部特写），交付物是拍摄与标注清单，不生成参考图。

### 3. 确定部件拆分方案（输出文档前的硬门禁）

部件图的数量由拆分方案决定，方案没定下来就不写文档：

- **用户已指定拆分**：直接沿用用户给出的部件数量和名称，逐项复述确认，不自行增删；部件图数量等于部件数。
- **用户未指定**：根据参考图的可见结构和建模需要推荐一套拆分方案（建议 3–6 件，按功能边界、可运动/可拆装件、材质分区和单独建模成本划分），每件写明拆分依据；再用当前客户端原生选择交互给出 2–4 个可比较粒度，推荐项置于首位，例如“按大件拆：车体/炮塔/火炮/行走机构”“按可动件拆：再拆出舱盖、悬挂臂、负重轮”“按材质分区拆”。同时说明粒度代价：越细部件图越多、单件尺寸表条目越多、总张数越多。
- **用户明确答复前不得输出最终 Markdown 文档**：可以先交付参考图解析结论和推荐拆分，但图片清单、部件图 prompt 与合计张数都依赖这份答复。
- 方案落到文档时至少包含：部件 ID、名称、拆分依据、是否运动件/可拆装件、单独成图的文件名、与相邻件的接口或装配标注。

### 4. 按需收敛方案

存在影响结果的视图组合分歧时，给出 2–3 个可比较方向（推荐项置于选择控件首位），等待选择或修正：

- 最低套：侧 + 俯 + 前 正交视图 + 一张 3/4 彩图 + 每个部件一张部件图。
- 标准套：加背视与局部特写。
- 完整套：加材质/配色板与补充角度。

形成短规格：视图组成、部件拆分、比例口径、尺寸表、材质分区、交付格式和验收标准。参考图、部件拆分和视图组成已经明确时跳过本阶段。

### 5. 压测

只检查适用且会改变 prompt 或交付边界的分支；已知答案不重复问，不适用项标 N/A：

- 正交污染：prompt 是否显式排除透视、缩短变形、地面、环境、投影阴影和景深；四宫格里是否混进透视格。
- 共比例尺与对齐：各视图能否互相对齐量取；模型是否会把四宫格画成四张互不一致的图。
- 部件拆分：粒度是否与建模和装配计划一致；部件图与整体视图板能否按同一比例尺对齐，接口、安装面和相邻件关系是否标清。
- 视图对应关系：左右视图是否互为对应且无遮挡，隐藏面如何标注。
- 尺寸标注责任：由模型写数字还是后期叠加；不确定时按后期叠加设计。
- 材质分区：分区边界在多视图下是否一致、材质师能否辨识。
- 交付格式与分辨率：是否满足每边 ≥2048、纯色背景、可描线。
- 不达标时的替代路径：逐视图单独生成后拼版、加结构控制、改用照片或线稿外包。

主 prompt 里的正交、比例尺和排布是目标约束，不是模型的精确保证。严格几何优先用结构控制或参考图；没有控制手段时必须说明风险和后处理路径。

### 6. 输出提示词文档

部件拆分方案未获用户明确答复时，不输出本文档的最终版本。按 [references/prompt-output-template.md](references/prompt-output-template.md) 的模板输出一份 Markdown 文档，非适用章节省略：

1. **设计结论与状态**：执行范围、参考类型、视图组成、部件数与比例口径、交付格式；分别标明确认项、默认项和待适配项。
2. **部件拆分方案**：部件 ID、名称、拆分依据、是否运动件/可拆装件、单独成图的文件名、与相邻件的接口与装配标注。用户指定的方案原样复述；未指定时写明这是本次推荐方案，并记录用户确认的结论。
3. **图片清单**：逐图一行，写明图号、文件名、参考类型、是否单独成图、内容与视图构成、像素与格式，并给出交付合计张数。类型覆盖正交视图板、部件图、3/4 彩图、局部特写、材质板；部件图按拆分方案逐件一行，行数等于部件数。一个 prompt 只生成其中一张图，不能只写“若干张”。
4. **参考图解析记录**：来源、视角、可见面、实测相对比例、遮挡与待确认项；无参考图时写“按文字需求生成”。
5. **尺寸表**：整体总尺寸与逐部件尺寸、接口尺寸分开列；实际尺寸、UE unit 值、来源三项齐全，未确认的标待确认。
6. **视图与排布规格**：每个视图的投影方式、宫格位置、必须匹配面和允许补全面；共用比例尺与中线规则。
7. **主 prompt**：按图片清单逐张给可复制提示词，每张标注对应图号，含每个部件图；一个 prompt 只对应一张图、一种用途。
8. **负面约束**：正交视图禁止透视、缩短、阴影、地面、环境元素、装饰和风格化。按工具能力提供独立负面 prompt 或整合进主 prompt。
9. **生成参数**：目标工具/模型、尺寸/比例、参考图与结构控制、候选数量、seed 策略、局部重绘和后处理；不支持项标 N/A，未知项标待适配。
10. **交付规格**：逐文件的分辨率、格式、背景、标注责任、命名与版本，与图片清单一一对应。
11. **验收清单**：规格交付检查与图片实测分开；缺图片、元数据或对照证据的项目标“待验证”，不能勾选通过。
12. **打包交付**（文档最后说明）：全部图片按清单命名后打包为一个压缩包交付，写明包名、包内目录结构、随包文档与清单，以及“包内张数等于清单合计张数、中间产物不混入”的校验规则。

文档一律落盘为文件，不只在会话中输出：写入 `<输出目录>/<主体名>_建模参考图_prompt.md`。输出目录由调用方（工作流或 Agent 参数）指定；没有指定时，项目里已有该主体的型号目录就用 `<型号>/设计图/`，否则用项目的 `docs/model-reference-prompts/`（不存在时先创建）。文件使用 UTF-8 无 BOM；写入后在回复中给出文件路径与一句话摘要，不创建无必要的流程文档。

### 7. 成图复盘与修复

只有收到图片或实际生成结果后才执行。先记录观察事实，再给建议：

- **保留项**：已成立的轮廓、体块比例、配色和分区，不预设具体型号细节。
- **硬失败**：带透视或缩短、各视图比例尺不一致、中线不对齐、视图互相矛盾、缺件或多余件、尺寸数字与标注乱码、背景出现地面/阴影/杂物、分辨率或格式不符。
- **软问题**：线宽不均、分区颜色接近、局部特写信息不足、旧化程度与参照不符。
- **修复动作**：工具支持时优先局部重绘；比例尺或视图矛盾时逐视图重生成后拼版；尺寸、数字和文字问题一律改为后期叠加，不靠重绘碰运气。

没有原始文件时，不凭预览判断精确像素或比例尺；没有对照尺寸表时，不声称已通过比例验收。硬失败未修复的图只能称为候选，不能称为建模师可用底图。

## Prompt 与实际生成约束

- 用可观察的几何、投影方式、光照和材质替代“精细、写实、大气”等空泛要求。
- 正交视图 prompt 写 flat orthographic projection、no perspective、no foreshortening、even flat lighting、plain background；不写氛围光、戏剧性光照、景深和材质噪点。
- 3/4 透视图允许材质、光照和旧化，但必须写明它不用于量比例；不要在同一张图里同时要求正交和透视。
- 精确尺寸、编号、文字、徽标和水印不让模型生成；需要时后期叠加，或明确标注为不可读数的装饰。
- 多视图一致性差时退回逐视图生成 + 人工拼版，不反复用同一条 prompt 抽卡。
- 生成尺寸与最终交付尺寸分开记录；模型不能精确输出目标像素时等比缩放或补边，不拉伸，缩放后重新核对比例尺。
- 探索构图时可建议 2–3 个不同 seed 的候选；对比单一参数时才固定 seed 并记录变量，不支持 seed 时标 N/A。
- 图片交付前检查精确尺寸、比例尺、中线对齐、视图对应关系和背景纯净度；缺证据的项标待验证。

## 交付边界

提示词文档不等于已生成图片，已生成候选不等于建模师可用底图，底图通过比例验收也不等于模型已经建好。后续 Blender 建模、分件装配、FBX/UE 导出由 `blender-model-animation-workflow` 和对应项目流程负责；真实装备照片采集与拍摄清单属于项目资料工作，不由本技能执行。图片可按清单打包为一个压缩包交付，但打包只是传输形式，不替代逐张验收。
