# 游戏 UI 文生图提示词工作流

把自然语言描述整理成可以生成、比较和交付的游戏 UI 规格。默认交付提示词文档，不自动调用生图服务或进入资源制作。收到生成结果时再复盘；只有明确要求生成或制作且工具可用时，才执行对应操作。

## 执行与交付边界

先区分两个独立维度：

- 执行范围：仅提示词规格、已有成图复盘、实际生成/后处理。没有图片时只能交付规格和待执行验收项，不能声称图片已通过检查。
- 目标用途：**效果图**是用于展示的完整合成界面；**UMG 资源**是用于运行时实现的独立素材。两者都要时共用设计约束，但分别输出效果图 prompt 和逐资源 prompt，不能把准确文字与无烘焙文字混进同一个生成请求。

确定画布或验收标准前必须读取 [references/industrial-ui-delivery.md](references/industrial-ui-delivery.md)；输出最终文档前必须读取 [references/prompt-output-template.md](references/prompt-output-template.md)。

## 工作阶段

沿用已提供的答案，不重复询问。只对会改变构图、模式或可执行性的未知项提问，每轮优先一个问题；需要选择时使用当前 CLI 的提问方式。明确且完整的需求直接进入规格整理，不强制走方案选择。

### 0. 确定边界、画布和工具

提取并确认：

- 执行范围及目标用途；“直接能用”必须区分可展示效果图和可导入 UE 的资源。
- 最终像素尺寸、比例、平台、横竖屏和显示环境；只给比例不等于确定最终尺寸。
- Safe Area、允许的裁切/补边、透明背景、场景背景、设备边框和色彩要求。
- 单张界面、独立状态图或状态对照板；单个生成请求不能暗中混入多个运行时状态。
- 目标生图工具/模型及已知能力：尺寸、中文文字、负面 prompt、参考图、结构控制、seed、局部重绘和透明输出。

目标工具未知时可直接交付通用规格，不为此阻塞；专用参数标为“待适配”。只填写已确认支持的参数，不猜测 API 字段、seed 或模型能力。不支持独立负面 prompt 时，把必要禁止项整合进主 prompt，并把负面约束标为非独立输入。

不虚构游戏设定或平台。画布未知且影响布局时先确认；用户授权采用默认值时，可按参考规范中的平台默认值规划，并明确标注，不能列为用户已确认事实。

### 1. 建立 UI brief

记录已确认项、默认项、待确认项和风险：

- 用途：主菜单、HUD、背包、商城、弹窗、加载页或其他画面。
- 视觉主题、材质、色彩、光照、风格化程度和参考作品。
- 信息层级、主要操作、区域布局、对齐、留白、网格和可扩展区域。
- 背景、面板、边框、图标、装饰、按钮、状态和文字的责任边界。
- 中文文案及数值白名单、禁止项和可接受的简化版本。

效果图默认以简体中文为主要 UI 语言，列出实际短文案，不仅写“Chinese style UI”。准确文字由后期覆盖时，记录每个区域的文案、字数和留白要求；主 prompt 只要求空文字区域，不同时要求生成真实文字。

UMG 素材不烘焙文字、动态数值、进度或列表。中文文案表只供 UMG 排版，不要求出现在素材图片中；记录独立透明素材、九宫格边界及可替换文字区域。

未经提供或确认的品牌、型号、道具名、金额、时间、等级和属性值使用中性占位符，不让模型自行编造关键内容。

### 2. 按需收敛方案

存在影响结果的布局或风格分歧时，给出 2–3 个可比较方向，推荐项置于选择控件首位，等待选择或修正。已有明确参考和布局时跳过；明确授权自主选择时采用一个标注为默认的方向，不强制等待。

形成短规格：画布、构图区域、网格、主次视觉、色彩 Token、材质语言、组件/资源清单和验收标准。

### 3. 压测设计

只检查适用且会改变 prompt 或交付边界的分支；已知答案不重复问，不适用项标为 N/A：

- 目标设备和缩小预览下的主要信息可读性。
- 需要本地化时的长文案余量。
- 需要运行时实现时的输入方式、焦点及普通/悬停/按下/禁用/锁定/错误/空状态。
- 实际背景和光照变化下的对比度。
- UMG 素材的独立生成、透明边界和九宫格复用。
- 准确文字、徽标和数值是否必须后期覆盖。
- 模型不支持结构控制或生成失败时的布局重建、文字覆盖或简化方案。

像素坐标和网格计数是目标约束，不是模型精确遵守的保证。严格布局优先采用结构参考图；没有结构控制时说明风险和后处理路径。

### 4. 输出提示词规格

按模板顺序输出，非适用章节省略：

1. **设计结论与状态**：执行范围、目标用途、尺寸/比例、Safe Area、布局、风格、信息层级；分别标明确认项、默认项和待适配项。
2. **中文文案表**：区域、逐字文案、渲染责任（模型短文本/后期覆盖/UMG）；关键数值另列白名单。
3. **主 prompt**：画布、区域、层级、风格、材质、光照、文字策略、背景及单一状态。双模式分别输出；UMG 按独立资源或明确的切图板输出，切图板不等于独立资源成品。
4. **负面约束**：公共项为乱码、未授权内容、错误状态、重复控件、错误比例和拉伸；效果图允许完整合成背景，只禁止非预期背景；UMG 才要求无烘焙文字、无场景背景和无多余素材。按工具能力提供独立负面 prompt 或整合进主 prompt。
5. **生成参数**：目标工具/模型、支持的尺寸/比例、参考图、结构控制、候选数量、seed 策略、重绘和后处理；不支持项标 N/A，未知项标待适配。生成尺寸与最终交付尺寸分开记录。
6. **效果图交付规格**（效果图模式）：文件名、最终像素、色彩空间、Alpha、文字覆盖/校对、裁切和缩小预览要求。
7. **逐资源规格与 UMG 落地提示**（UMG 模式）：资源 ID、尺寸、状态、独立 prompt、透明要求、格式、切片边界和 UMG 重建责任。SVG 必须经矢量重绘，不把栅格生图描述为矢量输出。
8. **验收清单**：规格交付检查与图片实测分开；图片、元数据或设备证据缺失的项目标“待验证”，不能勾选通过。

### 5. 成图复盘与修复

只有收到图片或实际生成结果后才执行。先记录观察事实，再给建议：

- **保留项**：已成立的布局、主体、材质、视觉风格和信息层级，不预设三栏、坦克或玻璃。
- **硬失败**：与已确认规格不符的比例、区域、网格、栏位、关键文本、数字、物体数量或状态。
- **软问题**：材质、图标一致性、留白、背景抢焦或次要信息可读性。
- **修复动作**：工具支持时优先局部重绘；文字问题可后期覆盖；结构整体失败时重建布局或重新生成。

没有原始文件/元数据时，不凭预览判断精确像素、色彩空间或 Alpha；没有目标设备预览时，不声称完成设备验收。硬失败未修复只能称为候选，不能称为可直接使用。

### 6. Markdown 交付

按模板返回 Markdown。每个主 prompt、独立负面 prompt 和生成参数分别放入可复制代码块，解释不混入 prompt；不支持独立负面输入时明确说明。

仅在要求保存文件时写入 `*_prompt.md`，使用 UTF-8 无 BOM；否则直接回复。不创建无必要的流程文档。

## Prompt 与实际生成约束

- 用可观察的布局、材质、色彩和光照替代“漂亮、炫酷、高级”等空泛要求。
- 先画布和布局，再风格；严格布局列出区域坐标或明确行列数，并检查区域不重叠、不越过安全区。
- 中文为主体；英文结构词仅在目标工具需要时补充，不替换应出现的中文文案。
- 效果图允许真实短中文文本或后期覆盖，两种策略明确择一；UMG 素材统一无烘焙文字。不要无条件给所有模式添加 empty text placeholders。
- 透明、分层和九宫格是素材制作要求；模型不支持时通过独立生成、抠图、切片或重绘完成，不承诺直接得到可编辑图层。
- 仅提示词交付时，候选生成和图片验收只是建议步骤。实际生成需有明确授权和可用工具，遵守用户数量与成本限制。
- 探索构图时可建议 2–3 个不同 seed 的候选；对比单一参数时才固定 seed 并记录变量。不支持 seed 时标 N/A，不要求同参数同 seed 重复出三张图。
- 图片交付前检查精确尺寸、比例、安全区、文字/网格/数字和适用状态；检查原尺寸、50% 缩放及目标设备预览，缺失证据标待验证。
- 模型不支持精确尺寸时，按合适比例生成，再等比缩放、裁切或补边；不得拉伸，不得裁掉关键区域。后处理后重新核对布局和 Safe Area。

## 交付边界

提示词规格不等于已生成图片，设计候选不等于已验收素材，已验收素材不等于完成 UE 集成。正式 UE 交付仍需验证文字、本地化、交互状态、焦点、DPI、Safe Area、九宫格和性能；仅在明确要求时进入 Figma、Photoshop、Blender 或 UE 制作。
