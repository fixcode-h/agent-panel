# 工业级游戏 UI 效果图交付参考

这份参考用于确定尺寸、布局和验收，不替代具体项目的 UI 规范。没有项目规范时可以采用下列默认值，但要在最终结果中标记为默认值。

## 执行范围

仅提示词任务交付的是生成与验收规格，不要求实际生成图片。以下文件尺寸、色彩、Alpha 和可读性检查仅在取得图片及必要证据后执行；没有证据的项标为待验证。目标工具未知时使用通用描述，负面 prompt、seed、结构控制和重绘均按已确认能力适配，不虚构参数。

两种用途同时需要时分别输出完整效果图和独立素材的 prompt。效果图允许合成背景与短文本；UMG 素材不烘焙文字，文案由 UMG 渲染。

## 交付模式

### 效果图交付

目标是得到一张可以直接用于评审、宣传、原型展示或视频合成的完整界面图。默认使用简体中文作为主要 UI 语言，允许合成背景、面板、图标和短文本，但必须指定最终像素尺寸、画幅、Safe Area、色彩空间和中文文字校对方式。

### UMG 资源交付

目标是得到可以进入 UE 资源管线的素材集合。背景、面板、边框、图标和装饰分层；动态文字、数值、进度、列表和交互状态由 UMG/CommonUI 重建。

## 尺寸规划

优先让用户给出项目的原生画布。用户未指定时，只能从目标平台选择一个明确默认值：

| 场景 | 推荐默认画布 | 说明 |
| --- | --- | --- |
| PC/主机 16:9 | 1920x1080 | 评审和原型的通用基准 |
| PC/主机高分辨率 | 2560x1440 | 适合高分辨率展示，但不能替代运行时 DPI 测试 |
| 手机竖屏 | 1080x1920 | 需要额外检查刘海、圆角和底部手势区 |
| 手机横屏 | 1920x1080 | 仍需按具体设备 Safe Area 缩放 |
| 正方形头像/图鉴 | 2048x2048 | 适合单卡片或图标板，不等同于全屏 UI |
| 超宽屏 | 按项目原生宽度 | 中央信息区和两侧扩展区必须分开描述 |

规则：

- AI 模型的 `aspect ratio` 只约束比例，不能保证输出精确像素；最终必须无拉伸裁切、补边或超分到目标尺寸。
- 默认使用 4 或 8 的像素网格；组件间距优先使用 8 的倍数，文字基线和图标尺寸以项目设计规范覆盖默认值。
- 默认将画布分为 12 列构图网格；全屏功能 UI 可采用 24 px 外边距、16 px 栏间距作为 1920x1080 的起始值，再按信息密度调整。
- Safe Area 没有平台规范时，效果图默认四边预留 5%；移动端必须额外预留刘海、圆角和手势区，不能只按画布边缘排版。
- 不把 Safe Area 当作美术留白。关键标题、按钮、货币、任务目标和交互焦点必须位于安全区内，背景装饰可以延伸到出血区。

## 效果图 Prompt 的最小尺寸字段

```text
最终画布：1920x1080 px，16:9，sRGB，不透明 PNG
主要语言：简体中文；所有可见标题、栏目、按钮、状态、物品名和操作提示使用中文
安全区：四边 5% 外边距；所有可读文字和主要操作位于安全区内
布局网格：12 列，8 px 间距节奏，左信息区、中主操作区、右辅助信息区
输出：一张完整游戏 UI 效果图，无设备边框，无展示相框，无额外截图
```

如果用户选择移动端、超宽屏或带透明通道，替换对应字段，不要同时保留冲突的画布描述。

## 文字和组件策略

- 先输出中文文案表并确定渲染责任。效果图选择模型短文本时，把相同文案写入主 prompt；选择后期覆盖时，主 prompt 只保留空文字区域，文案单独用于排版。UMG 文案由运行时渲染，不写入素材生图要求；不得只写“Chinese UI”或让模型自行生成关键文案。
- 默认中文短文案示例为“装备”“背包”“容器”“负重”“搜索”“维修”“装备”“检查”“关闭”；具体游戏名、物品名和数值必须以用户确认内容为准。
- 坦克背包类界面可优先使用“坦克”“装备”“炮塔”“主炮”“车体装甲”“履带”“发动机”“燃油”“弹药架”“背包”“容器”“负重”“维修”“装备”“检查”“关闭”等短中文词，并在主 prompt 中逐字列出。
- 英文只可作为模型结构控制词或技术参数，不能替代画面中应出现的中文 UI 文本。
- 效果图需要可读文字时，只要求短标题、短按钮词和少量数值；长段落改成文字占位或后期叠加。
- 任何必须百分百准确的中文、品牌名、道具名、数值和版本号，都要在生成后人工校对或在 Figma/UE 重做。
- 一个 prompt 只生成一个界面状态。默认状态、悬停、按下、禁用、锁定和错误状态应分别生成，或明确输出状态对照板。
- 面板和背景需要无缝扩展时，明确“tileable background”或“9-slice friendly panel”，但不能把模型生成的边缘直接当作九宫格切片成品。

## 像素级布局锁定

只写“左中右三栏”不足以约束图像模型。对于需要接近成品的效果图，主 prompt 应同时给出区域坐标、宽高、间距和网格计数。以 1920x1080 的坦克背包页面为例，可以采用：

```text
content area: x=96..1824, y=112..1010
left equipment panel: x=96, y=112, width=432, height=880
center backpack panel: x=552, y=112, width=696, height=880
right container panel: x=1272, y=112, width=552, height=880
panel gap: 24 px
backpack grid: exactly 8 columns by 5 rows
container grid: exactly 4 columns by 4 rows
```

如果生成结果的行列数不一致，先使用布局控制图或局部重绘修复；不要通过文字解释把错误网格当成可接受的自由变化。

## 文案和数值白名单

生成前列出可见文案和数字白名单。未提供的内容使用占位符，例如“坦克名称”“金额”“倒计时”“等级”，不要让模型自行生成真实型号、品牌、货币或战局数字。对于坦克背包页面，白名单可以是：

```text
坦克、装备、炮塔、主炮、车体装甲、履带、发动机、燃油、弹药架、背包、容器、负重、耐久、维修、弹药、零件、补给、搜索获得的物资、全部拾取、拾取、装备、检查、移动物品、拆分数量、关闭
```

生成后逐项核对：错别字、英文替代、重复字、数字格式、单位和文案是否出现在正确区域。模型自动生成的“主战坦克 T-14”或随机金额、时间，除非在白名单中，否则应视为硬失败。

## 最终验收

交付前记录以下结果：

1. 文件尺寸是否精确匹配目标像素，是否存在非等比拉伸；
2. 画布比例、Safe Area 和关键组件位置是否正确；
3. 原尺寸、50% 缩放和目标设备预览下，中文标题、按钮和主要数值是否可读；
4. 是否出现英文替代中文、乱码、错别字、重复控件、错位图标、脏边缘、透明漏底或不应该出现的水印；
5. 效果图模式是否明确为单张最终界面，UMG 模式是否有独立图层和透明边界；
6. 颜色是否按 sRGB 交付，透明素材是否保留 Alpha，文件命名和版本是否可追溯。

发现硬失败时按优先级处理：

1. 布局/网格错误：使用结构控制或局部重绘；
2. 中文文字错误：使用短词局部重绘，仍不稳定时后期覆盖；
3. 未授权数字或型号：替换为白名单文本，不允许保留随机内容；
4. 风格和玻璃问题：只重绘对应面板或背景，保留已通过的布局。

“看起来好”不能替代尺寸和可读性验收。任一硬性项目失败时，只能报告为设计候选，不能称为可直接使用。
