# Blender 创建模型与模型动画工作流

这是面向任务的 workflow 编排层，负责把“想做一个模型/动画”收敛为可执行规格、阶段产物和验收证据；具体的 Blender 启动器、脚本参数、指标阈值和导出规则由 `blender` 技能提供。默认以可拆分、可继续编辑和可复查为交付目标。

## 参考图片决定制作标准

- 以用户提供的参考图片实际内容作为建模与外观验收依据，不划分高模/低模档位，不要求用户选择档位，也不建立两套生成开关。
- 模型比例、轮廓、部件数量、曲面分段、硬边与倒角，以及纹理图案、尺度、方向、材质分区、颜色、粗糙度、金属感和旧化程度，都按参考中可观察的特征逐项还原。参考呈现棱面就保留棱面，呈现连续曲面就重建连续曲面；不得统一加密、平滑、简化或替换为通用材质。
- 同一资产不同部件分别按其参考细节制作；背景和小件也按图核对，不因远景或“游戏资产”用途自动降低细节。
- 几何和贴图的实现方式由可见轮廓、遮挡、近景细节和表面表现决定；面数多、材质数量多或使用程序化纹理本身不代表匹配。明确的性能/导出限制若与参考还原冲突，记录具体差异并向用户确认取舍，不自行降档。
- 参考未显示或分辨率不足的区域保留补全/待确认标记；只有已经实际对照的可见区域才能写成匹配，不能把“尽可能一致”写成未经验证的完全一致。

## 何时使用

- 用户要求根据图片、视频或概念图创建建筑、机械、道具、角色部件或场景模型。
- 用户要求模型按屋顶、墙面、水轮、门窗、轮轴等功能拆分，后续可以单独替换、移动或导出。
- 用户要求给模型添加旋转、开合、行进、循环或控制器驱动的动画。
- 用户要求渲染结果、多视角检查、动画预览或 Blender 文件交付。

只要用户明确要求的是一张静态图片或提示词，不要自动扩展成完整 Blender 资产；先确认是否需要 `.blend`、脚本和可编辑模块。

## 型号目录与产物落位

当输入是一个型号参考目录（例如 `SourceArt/Tank/M10/`：内含 `设计图/`、可选的 `扩展部件/`、原图与设计图册），本次任务的产物全部围绕该型号目录组织，不放散到仓库根或会话临时目录；`M10` 只是示例名称，规则适用于任意型号目录：

- `设计图/`：建模参考来源（四视图、部件图与局部特写），由项目方整理。
- **Blender 工作区**：在该型号目录下建独立文件夹（如 `<型号>/Blender/`），脚本、`.blend`、渲染和体检报告都收在里面，不散落到型号目录根。
- **UE 导出落位**：模型与动画分别导出到该型号目录的 `Asset/` 下——模型 FBX 放 `Asset/Mesh/`，动画 FBX 放 `Asset/Anim/`，分开存放，再由项目导入流程导入 UE。
- **进度文档**：该型号目录下维护一个进度文档（如 `<型号>/制作进度.md`），逐项记录部件的实现状态（已实现 / 未实现 / 进行中）；开始制作前先读，完成或新增部件后立即更新，方便后续扩展时对照。
- **扩展部件（可选）**：`扩展部件/` 存在时，其中每张图对应一个需要单独制作的可替换部件（不同尺寸或类型）；这类部件单独导出为独立部件文件，不与主体合并。
- **骨架与可替换部件**：坦克等可动资产必须建骨架；可替换部件与主体共用同一套骨骼（骨名、原点、坐标系一致），以组装式交付——在 UE 中替换原部件后，共享动画继续可用；扩展部件导出时带全部骨骼，部件自身不带动画。

## 阶段 0：需求边界与参考解析

先记录以下内容：

- 交付用途：静态渲染、可继续编辑的 `.blend`、游戏资产、动画预览或 UE 导出。
- **复刻目标**：尽可能复刻参考图（设计图）的实际内容——形体、纹理、材质、颜色和风格逐项对照，以可见特征的匹配程度验收。
- **可验证与补全边界**：明确哪些面是参考图中可见且必须匹配的，哪些是遮挡/背面/内部结构——后者只能按结构逻辑补全并标为推断，不要把“一比一”解释成对没有证据的背面逐像素复制。
- **可见特征**：逐件记录参考图中的轮廓转折、曲面连续性、孔洞/接缝、纹理图案与颗粒尺度、材质分区、主辅颜色和表面反射；信息不足时只针对缺失信息补充参考，不以高模/低模分类代替读图。
- 尺寸锚点：主体宽/深/高、关键轮径、轮距、轴高、屋顶坡度、开口尺寸和场景地面标高，统一用米。
- 验收边界：模型、动画、渲染、参考对照、模块可操作性和导出分别是否必需。

图片/视频参考先做元数据、接触表、关键帧和局部裁切，再生成部件清单。看不清的细节要标为待确认，不用猜测填空。

## 阶段 1：规格、命名与模块契约

建立规格文件和装配表，至少包含：

- Collection 与 `GRP_*` 根 Empty：例如 `COL_Building` / `GRP_Building`、`COL_WaterWheel` / `GRP_WaterWheel`。
- 网格、材质、相机和动作命名：`SM_*`、`M_*`、`CAM_*`、`A_*`，不要保留 `Cube`、`Sphere` 或 `.001` 默认名。
- 每个模块的局部原点、旋转轴、父级、尺寸锚点、允许接触、禁止穿透和可拆装边界。
- 组成件清单：屋顶、墙面、梁柱、门窗、水轮、轮轴、轴承、引水槽、平台、装饰等按功能列出；每件注明是否运动。
- 参考对照表：每件列出来源图片/局部裁切、几何特征、纹理尺度与方向、颜色/材质特征、实现方式和对应验收视角；推断项单独标注，不设置精细度档位字段。

先决定局部坐标约定。例如水轮轮心为原点、轮轴沿局部 Y；屋顶根 Empty 位于建筑屋脊基准点。尺寸写入锚点或装配表，不使用对象 `Scale` 当尺寸。

## 阶段 2：分件建模与单件验收

复杂资产必须走“单件脚本 → 单件预览 → 精修 → 装配”的分件工坊：

1. 一个功能部件一个构建入口，局部坐标中完成几何；不要一开始写整栋建筑或整台机械的巨型脚本。
2. 先完成形体、孔洞、轮廓、纹理、颜色、材质分区和局部原点，再装配到场景；用参考裁切与单件预览并排检查，避免整机远景掩盖比例和表面细节差异。
3. 重复件使用共享网格实例；需要多颜色时优先用材质槽，避免把一个链板、轮或门拆成大量对象。
4. 生成后应用旋转/缩放、重算法线、创建 UV 和 Principled BSDF；圆盖用三角扇或三角化。分段数、平滑边界和倒角宽度按参考轮廓与高光特征逐件调整，不套统一参数；影响剪影或遮挡的细节使用几何，表面图案和微小起伏用贴图/着色表达并渲染核对。
5. 旋转嵌套件优先使用真正的环形几何并留出结构间隙；不要把轮毂、轴承和辐条插进实心轮体。

单件完成后记录单件预览和体检结果，再进入装配。单件未通过时，不用整场景渲染掩盖问题。

## 阶段 3：装配与材质/场景组织

装配脚本只负责实例、位置、旋转和父级关系，不重新生成几何。父级前刷新依赖图，保持需要保留的世界变换；要让父级缩放生效的子件不要用错误的 `matrix_parent_inverse` 抵消父级。

材质逐件复刻参考图的纹理图案、尺度、方向、配色、粗糙度、金属感、透明/发光表现和旧化程度；项目材质清单用于命名与交付映射，与参考外观冲突时先确认取舍，不直接覆盖参考配色。程序化 Noise/ColorRamp/Bump 或图片贴图都可以使用，但必须对照参考验证，不能用通用噪声替代有明确图案的表面。贴图使用相对路径并打包或随工程交付，重新打开后核对无缺失。

Workbench 用于检查几何、材质分区和视口颜色；EEVEE/Cycles 的实际渲染用于检查纹理、材质和颜色。参考对照时尽量匹配机位、光照方向、曝光和色彩管理设置，区分阴影/反光与物体底色，避免把照片光照烘成材质或通过后期调色掩盖材质差异。

## 阶段 4：模型动画与控制器

- 刚体旋转、位移和开合打在模块根 Empty、轮心 Empty 或专用控制器上；网格保持 `scale = 1`。
- 每个动作使用独立 `A_*` Action，写明帧范围、是否循环、控制器和局部轴；默认 30 fps，其他帧率要记录原因。
- 循环动画验证首尾姿态、位置、相位和相机覆盖。整圈旋转按 `2π` 连续变化检查，不能只比较欧拉数字是否相等。
- 行进/滚动使用有效接触半径 `r_eff`：`位移 = 2π × r_eff × 圈数`；轮转、履带相位和主体位移使用同一速度源，避免打滑感。
- 角色或复杂机械用父级/控制器层级统一驱动；缩放动画放在 Empty 上，避免网格本身非单位缩放导致体检失败。

## 阶段 5：保持质量的模型减面

参考还原完成后、最终验收前，必须执行一次逐件减面评估与优化；目标是在保持参考匹配和可编辑/可动画能力的前提下降低实际三角数，不设统一减面比例或目标档位。

1. 保存独立的原始 `.blend` 基线，记录每件及整场景的三角数、修改器状态；保存参考机位、剪影、局部特写和动画关键帧的原始渲染。共享网格按数据块优化，不能把实例当重复面删除。
2. 在候选副本中逐件清理重复/退化几何，溶解不影响形体的共面边；必要时局部重拓扑或使用 Decimate，小步调整并预览。保护剪影、孔洞、接缝、薄件厚度、倒角高光、硬边、UV 接缝、材质边界及骨骼权重/变形区域；不能直接对整机套统一比例。
3. 使用相同机位、分辨率、光照、材质、曝光和色彩管理，对照减面前后及参考图；检查轮廓、比例、可见细节、纹理尺度/方向、UV 拉伸、颜色、材质反射、法线与阴影。动画资产追加首/中/尾及关键变形帧对照，检查权重、运动和连接关系。
4. 只有实际面数降低且上述质量检查均无可见退化时才保留候选。出现损失就降低减面力度或恢复该件原网格；无法安全减面的部件保留原状，记录原因，不为完成步骤牺牲质量。
5. 记录每件与场景的减面前后三角数、统计口径（原始/修改器求值后）、方法、对照图、检查结论及恢复项。减面后的最终模型进入后续体检和验收；不能复用减面前的通过结论。

## 阶段 6：体检、静态视角和动画视角

按以下顺序验收，证据不能互相替代：

1. 运行 `inspect_scene.py`：检查 n-gon、非流形、法线、UV、材质、命名、变换、动作、帧率和待应用修改器，并记录三角数。`--max-tris` 按参考实现需求及明确的交付限制设置并记录依据，不把工具默认值当建模目标；未约定面数上限时，不为通过默认预算检查牺牲参考细节。
2. 用世界坐标三角化 BVH 检查相交；把轮毂-轴、轴承-轮缘、落水-水斗等列为预期接触，把支撑穿轮体、椽子穿屋面等列为结构性穿透。必要时用 `diagnose_overlap.py` 定位相交中心。
3. 用 Workbench + EEVEE 生成 front/back/left/right/top/three-quarter/closeup；额外匹配参考机位生成并排对照图，逐项检查比例、轮廓、部件数量、孔洞/接缝、穿模、法线、纹理图案/尺度/方向、颜色关系、材质反射、旧化和风格。每项记录参考来源、差异及修正结果；背面/遮挡补全仅验证结构，不标为参考匹配。体检通过不能替代外观对照。
4. 用 `capture_views.py --frames` 渲染首帧、中帧、尾帧和关键动作帧；确认控制器跟随、局部轴、循环相位、运动范围和相机覆盖。
5. 保存并重新打开 `.blend`，逐个把 `GRP_*` 平移约 15 m 再恢复；检查所有子件跟随、恢复位置、根对象数量和 Collection 归属。该测试是“可拆分”的证据。

任一 FAIL 先修复再进入下一阶段；WARN 必须记录是否接受。多视角或动画只完成一部分时，交付状态写“部分验收”，不能写完整通过。

## 阶段 7：交付物与记录

默认交付：

- `<asset>.blend`：可打开、模块根对象和父子关系保留。
- `scripts/` 或等价构建脚本：锚点、部件入口、装配表和动画控制器可追溯。
- `renders/`：静态多视角、动画关键帧和必要的参考并排对照。
- `reports/`：减面前后统计与质量对照、体检 JSON、Action 清单、相交分类、模块平移/恢复结果和剩余风险。
- 规格与评估记录：逐项记录几何、纹理、材质、颜色与风格的参考匹配证据，区分结构性补全、默认项、WARN 和待验证项；保留未解决差异，不以高模/低模标签或面数证明还原质量。

FBX/UE 导出是可选后续步骤：只有用户明确授权时才执行；导出前必须通过体检和多视角门禁，并单独记录 FBX 重导入和 UE 导入证据。

在型号目录约定下（见「型号目录与产物落位」）：上述 Blender 侧产物收进 `<型号>/Blender/`，UE 导出按用途落位 `<型号>/Asset/Mesh/` 与 `<型号>/Asset/Anim/`，并同步更新型号目录的进度文档。

## 停止条件

- 参考图无法证明的结构被要求逐像素一致，但没有更多视角或尺寸依据。
- 模块边界、运动轴或有效接触半径未定义，继续建模会导致返工。
- 体检仍有未解释的 FAIL、结构性穿透或父级漂移。
- 只生成了一张主视角或静态首帧，缺少多视角/多帧证据。
- 用户未授权却要求导出、发布或覆盖外部资产。
